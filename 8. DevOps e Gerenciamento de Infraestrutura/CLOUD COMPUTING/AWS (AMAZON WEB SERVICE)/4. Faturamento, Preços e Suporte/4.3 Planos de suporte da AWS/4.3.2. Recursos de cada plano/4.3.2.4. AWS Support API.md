### 4.3.2.4. AWS Support API — abrir e gerenciar casos por código, Trusted Advisor programático, Health API, automações e ChatOps

> [!warning] Aviso
> Nomes de operações, parâmetros, endpoints e requisitos de plano abaixo são **de memória e conceituais**; a API evolui (inclusive com a reorganização dos planos de suporte, novas operações e o **AWS Support App**). **Confirme na referência oficial da AWS Support API e do Trusted Advisor API.** Os comandos e códigos são ilustrativos e não foram executados. Automações que abrem casos podem gerar **ruído e custos de atenção**: use limites e deduplicação.

## 1. O que é a AWS Support API

A **AWS Support API** é a interface **programática** do **AWS Support Center**: permite **criar, consultar, atualizar e resolver casos de suporte**, **consultar as severidades e serviços disponíveis**, e **acessar as verificações do Trusted Advisor** por código (CLI, SDKs ou REST), em vez de usar apenas o console web.

Ela **requer um plano de suporte pago** — tradicionalmente **Business, Enterprise On-Ramp ou Enterprise** (confirme os planos vigentes). Chamadas feitas em contas Basic/Developer retornam erro de **assinatura necessária** (`SubscriptionRequiredException`).

```
Alarme / ferramenta interna ──▶ Support API (CreateCase) ──▶ Caso aberto no Support Center
Sistema de tickets (Jira/ServiceNow) ◀── sincroniza ◀── DescribeCases / comunicações
Dashboards ◀── DescribeTrustedAdvisorChecks / Results
```

## 2. Pontos de acesso e conceitos básicos

| Item | Detalhe |
|---|---|
| **Endpoint** | A API fica em **`us-east-1`** (endpoint global; para algumas variantes, também `us-gov-west-1` e `cn-north-1` em partições específicas). Use `--region us-east-1` na CLI |
| **Namespace IAM** | Ações **`support:*`** (por exemplo, `support:CreateCase`, `support:DescribeCases`) |
| **Autenticação** | Credenciais AWS padrão (IAM user/role/Identity Center) |
| **Plano exigido** | Business ou superior |
| **Quem vê os casos** | Por padrão, casos criados por usuários da **conta**; permissões controlam quem enxerga e atualiza |
| **Idiomas** | Parâmetro `language` (por exemplo, `en`, `ja`; português pode não estar disponível em todas as operações) |

## 3. Principais operações

### 3.1 Casos

| Operação | Função |
|---|---|
| **`CreateCase`** | Abre um caso (assunto, serviço, categoria, severidade, mensagem, CCs) |
| **`DescribeCases`** | Lista casos (filtros por ID, datas, resolvidos ou não, idioma) |
| **`AddCommunicationToCase`** | Adiciona uma **resposta/atualização** ao caso, com CCs e anexos (via conjunto de anexos) |
| **`DescribeCommunications`** | Lê o histórico de comunicações |
| **`ResolveCase`** | Marca o caso como resolvido |
| **`AddAttachmentsToSet` / `DescribeAttachment`** | Cria conjunto de anexos (arquivos) e lê anexos |
| **`DescribeServices`** | Lista **códigos de serviço** e **categorias** válidos (usados em `CreateCase`) |
| **`DescribeSeverityLevels`** | Lista os **níveis de severidade** disponíveis para o plano |
| **`DescribeSupportedLanguages`** | Idiomas suportados por serviço/categoria |
| **Operações de "case" mais novas** (por exemplo, `DescribeCreateCaseOptions`, `DescribeSupportedLanguages`) | Ajudam a montar casos válidos |

### 3.2 Trusted Advisor (via Support API clássica)

| Operação | Função |
|---|---|
| **`DescribeTrustedAdvisorChecks`** | Lista as **verificações** disponíveis (por categoria) |
| **`DescribeTrustedAdvisorCheckResult`** | Resultado de uma verificação (**status**, recursos sinalizados) |
| **`DescribeTrustedAdvisorCheckSummaries`** | **Resumos** de várias verificações |
| **`RefreshTrustedAdvisorCheck`** | **Atualiza** uma verificação (sujeito a limite de frequência) |
| **`DescribeTrustedAdvisorCheckRefreshStatuses`** | Estado do refresh |

> Nota: a AWS também oferece a **Trusted Advisor API** mais nova (`trustedadvisor`) com recursos de **recomendações organizacionais**, **priorização** e ciclo de vida; consulte a documentação do Trusted Advisor.

## 4. Exemplos de CLI (ilustrativos)

### 4.1 Descobrir códigos válidos

```bash
# Lista serviços e categorias (para usar em create-case)
aws support describe-services --region us-east-1 --language en \
  --query 'services[?code==`amazon-relational-database-service`]'

# Níveis de severidade do seu plano
aws support describe-severity-levels --region us-east-1 --language en
```

### 4.2 Abrir um caso

```bash
aws support create-case --region us-east-1 \
  --subject "Produção: latência elevada no cluster Aurora db-prod" \
  --service-code amazon-relational-database-service \
  --category-code performance \
  --severity-code high \
  --language en \
  --cc-email-addresses oncall@empresa.com sre@empresa.com \
  --communication-body "Desde 14:05 UTC, latência p95 subiu de 30 ms para 900 ms no cluster db-prod (us-east-1). Impacto: ~40% das requisições do checkout excedem timeout. Mudanças recentes: nenhuma. Anexamos métricas e logs. IDs: db-prod-instance-1, db-prod-instance-2."
```

### 4.3 Acompanhar e atualizar

```bash
aws support describe-cases --region us-east-1 --include-resolved-cases false \
  --query 'cases[].[caseId,subject,status,severityCode]' --output table

aws support add-communication-to-case --region us-east-1 \
  --case-id case-123456789012-muen-2026-abcdef1234567890 \
  --communication-body "Atualização 14:40 UTC: failover manual não resolveu; impacto estável em 40%."

aws support resolve-case --region us-east-1 --case-id case-123456789012-muen-2026-abcdef1234567890
```

### 4.4 Trusted Advisor

```bash
# Verificações da categoria de custo
aws support describe-trusted-advisor-checks --region us-east-1 --language en \
  --query 'checks[?category==`cost_optimizing`].[id,name]' --output table

# Resultado de uma verificação (substitua pelo ID real)
aws support describe-trusted-advisor-check-result --region us-east-1 \
  --check-id Qch7DwouX1 --language en
```

## 5. Exemplo em Python (boto3)

```python
import boto3

# A Support API fica em us-east-1
support = boto3.client("support", region_name="us-east-1")

def abrir_caso_producao(titulo: str, descricao: str) -> str:
    resp = support.create_case(
        subject=titulo,
        serviceCode="amazon-elastic-compute-cloud-linux",
        categoryCode="instance-issue",
        severityCode="high",
        communicationBody=descricao,
        ccEmailAddresses=["oncall@empresa.com"],
        language="en",
        issueType="technical",
    )
    return resp["caseId"]

def listar_casos_abertos():
    paginator = support.get_paginator("describe_cases")
    for page in paginator.paginate(includeResolvedCases=False):
        for c in page["cases"]:
            print(c["caseId"], c["severityCode"], c["status"], c["subject"])
```

## 6. Automação: padrões úteis

| Caso de uso | Desenho |
|---|---|
| **Alarmes críticos abrem caso automaticamente** | CloudWatch Alarm → SNS → Lambda (`CreateCase`) com **deduplicação** (uma chave por incidente) |
| **Sincronização com ITSM** | Lambda agendada com `DescribeCases` → Jira/ServiceNow; comentários via `AddCommunicationToCase` |
| **Painel de saúde da conta** | `DescribeTrustedAdvisorCheckSummaries` → S3/Athena/QuickSight |
| **Notificações de mudanças de caso** | EventBridge (eventos de Support, conforme disponibilidade) → SNS/Chatbot |
| **ChatOps** | **AWS Support App** no Slack/Teams para criar, responder e acompanhar casos |
| **Relatórios de SLA** | Lê casos e comunicações para medir tempos de primeira resposta e resolução |
| **Limpeza de alertas** | `RefreshTrustedAdvisorCheck` periódico + ticket para itens críticos |

Exemplo de Lambda (esqueleto) com deduplicação:

```python
import boto3, os, hashlib
support = boto3.client("support", region_name="us-east-1")
ddb = boto3.resource("dynamodb").Table(os.environ["TABELA_DEDUP"])

def handler(event, ctx):
    alarme = event["detail"]["alarmName"]
    chave = hashlib.sha256(alarme.encode()).hexdigest()
    if "Item" in ddb.get_item(Key={"id": chave}):
        return {"status": "ja-aberto"}
    caso = support.create_case(
        subject=f"[AUTO] {alarme}",
        serviceCode="general-info", categoryCode="using-aws", severityCode="high",
        communicationBody=f"Alarme crítico disparou: {alarme}. Ver CloudWatch para métricas.",
        language="en")
    ddb.put_item(Item={"id": chave, "caso": caso["caseId"], "ttl": 3600*6})
    return {"status": "aberto", "caso": caso["caseId"]}
```

## 7. AWS Health API

A **AWS Health API** (também requer Business+) permite **consultar eventos de saúde** programaticamente:

| Operação | Função |
|---|---|
| **`DescribeEvents` / `DescribeAffectedEntities`** | Eventos e recursos afetados (conta) |
| **`DescribeEventDetails`** | Descrição, atualizações e ações recomendadas |
| **Organizational view** (`DescribeEventsForOrganization`) | Eventos de **todas as contas** da organização |
| **EventBridge** | Eventos do **AWS Health** para disparar automações (disponível também no Basic para eventos da conta) |

Padrão recomendado: **EventBridge (eventos de Health) → SNS/Chatbot/Lambda**, para saber **antes** do cliente quando uma **manutenção** ou **degradação** afetar seus recursos — e, se necessário, abrir um caso com `CreateCase` já referenciando o evento.

## 8. Permissões IAM

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "OperarSuporte",
    "Effect": "Allow",
    "Action": [
      "support:CreateCase", "support:DescribeCases", "support:DescribeCommunications",
      "support:AddCommunicationToCase", "support:ResolveCase",
      "support:DescribeServices", "support:DescribeSeverityLevels",
      "support:DescribeTrustedAdvisorChecks", "support:DescribeTrustedAdvisorCheckResult",
      "support:DescribeTrustedAdvisorCheckSummaries", "support:RefreshTrustedAdvisorCheck"
    ],
    "Resource": "*"
  }]
}
```

A AWS fornece a política gerenciada **`AWSSupportAccess`**. Boas práticas:

- **Separe perfis**: **leitura** (Describe*), **operação** (CreateCase/AddCommunication) e **administração**.
- Dê `support:CreateCase` apenas a **pessoas e automações autorizadas** (evita abusos e casos duplicados).
- **Não inclua dados sensíveis** (segredos, PII) nas descrições de casos.
- Audite com **CloudTrail** (eventos `support`).

## 9. Limites, custos e cuidados

| Tema | Observação |
|---|---|
| **Custo** | **Não há cobrança por chamada** à Support API; o custo é o do **plano de suporte** |
| **Limites de taxa** | Há **throttling** (limites de requisições); implemente **retentativas com backoff** |
| **Refresh do Trusted Advisor** | Limite de **frequência** (por exemplo, a cada 5 minutos por verificação, e algumas só atualizam periodicamente) |
| **Região** | Sempre `us-east-1` (exceto partições específicas) |
| **Disponibilidade por plano** | Business+; verifique mudanças com os novos planos |
| **Ruído** | Casos automáticos mal desenhados geram **tickets inúteis** que reduzem a atenção do suporte |
| **Idioma** | Verifique idiomas suportados no `DescribeSupportedLanguages` |
| **Sensibilidade** | Descrições e anexos são visíveis ao suporte AWS: **mascare dados sensíveis** |

## 10. Support API vs Support App vs Console

| Canal | Melhor para |
|---|---|
| **Console (Support Center)** | Abertura manual, anexos, navegação visual |
| **Support API/CLI/SDK** | **Automação**, integrações e relatórios |
| **AWS Support App (Slack/Teams)** | **ChatOps**: criar e responder casos, ver Trusted Advisor e receber notificações no chat |
| **Telefone/chat** | Incidentes de produção (acelera a triagem) |

## 11. Erros comuns

> [!bug] Erros comuns
> 1. **Chamar a API na região errada** (precisa ser `us-east-1`).
> 2. **Usar em conta Basic/Developer** e receber `SubscriptionRequiredException`.
> 3. **Automação sem deduplicação**, abrindo dezenas de casos para o mesmo alarme.
> 4. **Códigos de serviço/categoria inválidos** (use `describe-services` para obtê-los).
> 5. **Colocar dados sensíveis** (senhas, PII) na descrição.
> 6. **Dar `support:*` amplamente** a todos os desenvolvedores.
> 7. **Não tratar throttling** e falhar em picos.
> 8. **Ignorar o Support App** e reinventar ChatOps.
> 9. **Abrir casos automáticos de severidade alta para tudo**, perdendo credibilidade.
> 10. **Confiar só na API** e não ligar em incidentes graves.

## 12. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| `SubscriptionRequiredException` | Plano sem Support API | Fazer o upgrade para Business+ |
| `AccessDeniedException` | Falta de `support:*` | Anexar `AWSSupportAccess` ou a política mínima |
| `InvalidParameterValue` em `create-case` | Códigos incorretos | Consultar `describe-services` e `describe-severity-levels` |
| `ThrottlingException` | Muitas chamadas | Usar backoff exponencial e reduzir a frequência |
| Refresh do Trusted Advisor falha | Limite de frequência | Aguardar o intervalo mínimo |
| Casos duplicados | Sem deduplicação | Implementar chave de incidente e TTL |
| Caso sem resposta | Severidade/escopo | Ligar e escalar com o TAM/case manager |

## 13. Resumo rápido

- **Support API** (`us-east-1`, `support:*`) abre e gerencia **casos** e acessa o **Trusted Advisor** por código; exige **Business ou superior**.
- Operações-chave: **CreateCase, DescribeCases, AddCommunicationToCase, ResolveCase, DescribeServices, DescribeSeverityLevels** e as de **Trusted Advisor**.
- Use para **automação, integração com ITSM, painéis e ChatOps** (**AWS Support App**).
- **Health API** e **EventBridge** complementam a visibilidade de eventos.
- Cuidados: **deduplicação, backoff, mínimo privilégio, dados sensíveis** e **ligar em incidentes graves**.
