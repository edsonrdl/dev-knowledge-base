### 4.1.2.2. Preços de transferência de dados — entrada, saída, entre AZs e regiões, NAT Gateway, CloudFront e como reduzir o custo de rede

> [!warning] Aviso
> Os valores em dólar são **ordens de grandeza aproximadas, de memória, para ensinar o raciocínio**; preços reais variam por região, têm faixas de volume e mudam. **Consulte a página de preços de cada serviço (EC2 Data Transfer, NAT Gateway, CloudFront, VPC) e use a AWS Pricing Calculator** antes de orçar. Comandos e exemplos são ilustrativos e não foram executados.

## 1. A regra de ouro: o dado entra de graça, sai caro

O modelo de cobrança de rede da AWS tem uma assimetria deliberada:

> **Entrada de dados (inbound) na AWS é, em geral, gratuita. Saída (outbound) tem custo.**

Isso incentiva trazer dados para a AWS e desencoraja levá-los embora. Mas a fatura de rede é mais sutil do que "entra grátis, sai caro": **o preço depende de para onde o dado vai**. Existem pelo menos cinco "destinos" com tarifas diferentes:

```
                    ┌───────────────────────────── Internet (saída): US$ ~0,09/GB (faixas)
                    │
 Sua carga ─────────┼───────────────────────────── Outra Região AWS: ~US$ 0,02/GB
 (EC2, S3, RDS...)  │
                    ├───────────────────────────── Outra AZ (mesma região): ~US$ 0,01/GB em CADA direção
                    │
                    ├───────────────────────────── Mesma AZ, IP privado: US$ 0,00
                    │
                    └───────────────────────────── Serviços via NAT Gateway: +US$ ~0,045/GB de processamento
```

## 2. Tabela de referência de cobranças

| Tipo de tráfego | Cobrança típica |
|---|---|
| **Internet → AWS (entrada)** | **Gratuito** |
| **AWS → Internet (saída)** | Primeiros **100 GB/mês gratuitos** (agregados na conta), depois por faixas (~US$ 0,09/GB nos primeiros 10 TB, caindo com o volume) |
| **Entre regiões AWS** | ~US$ 0,02/GB (varia por par de regiões) |
| **Entre AZs da mesma região** (IP privado) | ~US$ 0,01/GB **em cada direção** (efetivo ~US$ 0,02/GB) |
| **Mesma AZ, IP privado** | Gratuito |
| **Mesma AZ, via IP público ou Elastic IP** | Cobrado como se fosse entre AZs |
| **S3/DynamoDB via Gateway VPC Endpoint** | Gratuito (sem custo por GB) |
| **Interface VPC Endpoint (PrivateLink)** | Por hora do endpoint + por GB processado |
| **NAT Gateway** | Por hora (~US$ 0,045) + **por GB processado** (~US$ 0,045) |
| **S3 → CloudFront** | Gratuito (origem S3 para o CloudFront) |
| **CloudFront → Internet** | Mais barato que EC2/S3 direto; 1 TB/mês gratuito no plano free |
| **Direct Connect** | Porta por hora + saída por GB **menor** que internet (~US$ 0,02/GB) |
| **Transit Gateway** | Por anexo por hora + por GB processado |
| **VPN Site-to-Site** | Por conexão por hora + saída de dados |
| **S3 Transfer Acceleration** | Taxa adicional por GB |
| **Elastic Load Balancer** | Hora + LCU (inclui dados processados) |

> [!tip] Memorize o essencial
> (1) **Entrada grátis**. (2) **Saída para a internet é a mais cara**. (3) **Entre AZs custa nos dois sentidos**. (4) **NAT Gateway cobra por GB processado e é uma fonte clássica de contas-surpresa**. (5) **Gateway endpoints de S3 e DynamoDB são gratuitos**.

## 3. Saída para a internet em detalhe

A saída é cobrada **por GB**, em faixas decrescentes por volume mensal agregado da conta:

| Faixa mensal (ordem) | Tarifa aproximada |
|---|---|
| Primeiros 100 GB | Grátis |
| Até 10 TB | ~US$ 0,09/GB |
| Próximos 40 TB | ~US$ 0,085/GB |
| Próximos 100 TB | ~US$ 0,07/GB |
| Acima de 150 TB | ~US$ 0,05/GB ou negociado |

Exemplo: servir 20 TB/mês direto do S3 ou EC2:

```
100 GB grátis
até 10 TB:   (10.240 − 100) GB × 0,09  ≈ US$ 913
próximos 10 TB: 10.240 GB × 0,085       ≈ US$ 870
TOTAL ≈ US$ 1.783/mês
```

Pela **CloudFront**, a tarifa por GB é normalmente menor, a origem S3→CloudFront é gratuita e o **cache** reduz o tráfego de origem; para volumes altos, há **preços por compromisso** (CloudFront Security Savings Bundle) e **negociação**. Por isso "conteúdo estático pela CDN" é uma das primeiras recomendações de custo.

## 4. Entre Availability Zones

Alta disponibilidade pede **múltiplas AZs**, e o preço é a transferência entre elas:

```
Serviço A (AZ-a) ──► Serviço B (AZ-b):  US$ 0,01/GB saindo de A  + US$ 0,01/GB entrando em B
                                          = ~US$ 0,02/GB de custo efetivo
```

Cenários onde isso explode:

- **Banco Multi-AZ** com replicação síncrona intensa (parte já incluída no preço do RDS, mas não o tráfego de aplicação entre AZs).
- **Microsserviços** conversando em malha entre AZs com payloads grandes.
- **Kafka/Kinesis/EKS** com tráfego de réplicas e consumidores em AZs diferentes.
- **Load balancers cross-zone** (ALB: tráfego entre AZs do balanceador para os alvos **não** é cobrado; NLB/GLB e inter-AZ podem ser, conforme configuração).

Estratégias: **afinidade de AZ** (topology-aware routing, consumo na mesma AZ), **cache local**, **compressão** e reduzir chamadas "chatty".

## 5. Entre regiões

Replicação (S3 CRR, DynamoDB Global Tables, RDS cross-region, backups) e arquiteturas multi-região pagam **~US$ 0,02/GB** (variável) **além** do armazenamento duplicado e das requisições. Em cargas pesadas, replicar tudo para todas as regiões é caro; **replique seletivamente** e comprima.

## 6. NAT Gateway: a armadilha mais comum

O **NAT Gateway** dá saída para a internet a instâncias em sub-redes privadas e cobra:

1. **Por hora** de existência (~US$ 0,045/h, ≈ US$ 33/mês por NAT; multiplique pelo número de AZs).
2. **Por GB processado** (~US$ 0,045/GB) — **em qualquer direção, para qualquer destino**, inclusive para serviços AWS como S3 e DynamoDB **se você os acessa pela internet via NAT**.

Cenário típico de conta-surpresa:

```
Instâncias privadas em 3 AZs leem 50 TB/mês do S3 pela internet (via NAT):
  NAT processamento: 51.200 GB × 0,045 ≈ US$ 2.304
  + horas dos 3 NATs ≈ US$ 100
  → US$ 2.400/mês POR NADA — o Gateway Endpoint do S3 seria GRATUITO
```

**Correção:** criar **Gateway VPC Endpoints** para S3 e DynamoDB (gratuitos) e **Interface Endpoints** quando o volume justificar (cobra por hora e GB, mas costuma ser menor que o NAT). Também: um NAT por AZ **só se necessário**, e avaliar **NAT instances** ou **IPv6 + Egress-only Internet Gateway** (sem cobrança de NAT) em cenários adequados.

```bash
# Gateway endpoint do S3 (gratuito) para a VPC
aws ec2 create-vpc-endpoint \
  --vpc-id vpc-0abc --service-name com.amazonaws.us-east-1.s3 \
  --vpc-endpoint-type Gateway --route-table-ids rtb-0def
```

## 7. Acelerar e reduzir com CloudFront, Direct Connect e compressão

| Estratégia | Efeito no custo |
|---|---|
| **CloudFront na frente de S3/ALB** | Tarifa de saída menor, origem gratuita (S3→CF), menos requisições à origem |
| **Direct Connect** | Saída por GB menor que a internet; compensa em volumes altos e constantes (mais custo fixo de porta) |
| **Compressão (gzip/brotli)** | Reduz GB transferidos |
| **Cache** (CDN, aplicação, API Gateway) | Menos bytes de saída |
| **Imagens/vídeos otimizados** (WebP/AVIF, codecs) | Menos GB |
| **Região certa** | Processar na mesma região do dado evita transferência inter-região |
| **PrivateLink/endpoints** | Substitui NAT para serviços AWS |
| **Rede interna AWS** | Tráfego dentro da AWS (mesma região, mesmo serviço) costuma ser gratuito (S3→EC2 mesma região) |

## 8. Casos que costumam ser gratuitos (e valem lembrar)

- **S3/DynamoDB → EC2 na mesma região** (sem NAT): transferência de dados gratuita.
- **Entrada de dados** (upload) na AWS.
- **Tráfego entre instâncias na mesma AZ por IP privado.**
- **S3 → CloudFront.**
- **Dados entre serviços AWS da mesma região** que não cobram transferência (conforme o serviço; confirme).

## 9. Como encontrar o custo de rede na fatura

1. **Cost Explorer**: agrupe por **Usage Type** (procure `DataTransfer-Out-Bytes`, `DataTransfer-Regional-Bytes`, `NatGateway-Bytes`, `...-AWS-In/Out`).
2. **Cost and Usage Report (CUR)** com Athena para detalhar por recurso e tag.
3. **VPC Flow Logs** + Athena para descobrir **quem está gerando o tráfego**.
4. **CloudWatch**: métricas `BytesOutToDestination`, `BytesInFromSource` do NAT Gateway; `NetworkOut` das instâncias.
5. **Trusted Advisor/Cost Optimization Hub** para recomendações de NAT e endpoints.

Exemplo de consulta no Athena (CUR) para ver o top de custos de transferência (ilustrativa):

```sql
SELECT line_item_usage_type, SUM(line_item_unblended_cost) AS custo
FROM cur_db.cur_tabela
WHERE line_item_usage_type LIKE '%DataTransfer%' OR line_item_usage_type LIKE '%NatGateway%'
GROUP BY line_item_usage_type
ORDER BY custo DESC LIMIT 20;
```

## 10. Boas práticas de arquitetura para custo de rede

1. **CDN na frente de tudo que é público**.
2. **Endpoints** para S3/DynamoDB (e interface endpoints para serviços de alto volume).
3. **Co-localizar** produtores e consumidores na mesma AZ/região quando possível.
4. **Comprimir e cachear**.
5. **Evitar replicação multi-região desnecessária**.
6. **Revisar NATs**: número, necessidade e alternativas.
7. **Monitorar com alarmes de Budgets** por usage type de transferência.
8. **Planejar migrações** (DataSync/Snow) considerando que a **entrada é grátis**, mas a saída para sair da AWS não.

## 11. Erros comuns

> [!bug] Erros comuns
> 1. **Esquecer que entrar é grátis e sair é caro**, e planejar "sair" da AWS sem calcular a saída.
> 2. **Acessar S3 pelo NAT Gateway** em vez de usar o Gateway Endpoint gratuito.
> 3. **Ignorar o custo entre AZs** em arquiteturas "chatty".
> 4. **Usar IP público/Elastic IP para falar entre instâncias da mesma VPC**, pagando como inter-AZ.
> 5. **Servir arquivos grandes direto do S3/EC2** sem CDN.
> 6. **Replicar tudo para outra região** sem avaliar o custo.
> 7. **Subir NATs em todas as AZs** sem necessidade.
> 8. **Não acompanhar usage types de transferência** e descobrir o custo no fim do mês.
> 9. **Esquecer a saída de dados em cenários de DR** e egress em ferramentas de terceiros.

## 12. Resumo rápido

- **Entrada: grátis. Saída para a internet: a mais cara** (100 GB/mês grátis, depois ~US$ 0,09/GB em faixas).
- **Entre AZs**: ~US$ 0,01/GB em cada direção; **entre regiões**: ~US$ 0,02/GB; **mesma AZ por IP privado**: grátis.
- **NAT Gateway** cobra por hora e **por GB processado** — use **Gateway Endpoints** (S3/DynamoDB, gratuitos) para evitá-lo.
- **CloudFront**, **compressão**, **cache** e **co-localização** reduzem a conta.
- Investigue com **Cost Explorer (usage type)**, **CUR**, **VPC Flow Logs** e métricas de NAT.
