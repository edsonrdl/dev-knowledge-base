### 4.2.1.3. AWS Cost and Usage Report — o relatório mais detalhado de custo e uso, entrega no S3, colunas, Athena e Data Exports

> [!warning] Aviso
> A AWS está migrando o **Cost and Usage Report (CUR) clássico** para o **Data Exports** (incluindo **CUR 2.0** e o formato **FOCUS**). Nomes de colunas, opções de entrega e a situação do CUR legado **mudam**; o que segue é uma visão conceitual, de memória. **Confirme na documentação de Cost and Usage Reports e Data Exports.** SQL e comandos são ilustrativos e não foram executados.

## 1. O que é o CUR

O **AWS Cost and Usage Report (CUR)** é o **conjunto de dados mais completo e granular** de custos e uso da AWS. Ele entrega, em um bucket **S3**, arquivos com **uma linha por item de cobrança** — detalhando **serviço, recurso, operação, tipo de uso, quantidade, tarifa, descontos, tags e muito mais**. É a **fonte da verdade** para análises financeiras profundas, **chargeback/showback**, conciliação com a fatura e FinOps em escala.

Se o **Cost Explorer** é o painel visual rápido (agregado), o **CUR** é o **"data lake de custo"**: você o consulta com **SQL (Athena)**, o carrega em **BI** ou **warehouse** e cruza com dados de negócio.

```
 AWS Billing ──(a cada ~24h)──▶ Bucket S3 (CUR: Parquet/CSV, particionado por mês)
                                    │
                    ┌───────────────┼────────────────┐
                    ▼               ▼                ▼
                 Athena         QuickSight/BI     Redshift/Glue
              (consulta SQL)    (dashboards)    (pipelines FinOps)
```

## 2. CUR vs Cost Explorer vs Billing

| Característica | Cost Explorer | CUR / Data Exports | Billing (faturas) |
|---|---|---|---|
| **Granularidade** | Agregada (serviço, conta, tag...) | **Linha a linha** (item de cobrança), horária ou diária | Totais por serviço e conta |
| **Nível de recurso** | Limitado (14 dias, se habilitado) | **Sim, por ID de recurso** (todo o histórico exportado) | Não |
| **Histórico** | 13 meses | **Ilimitado** (você retém no S3) | Faturas anteriores |
| **Consulta** | Interface e API | **SQL/ferramentas de dados** | Console/PDF |
| **Customização** | Filtros e agrupamentos | **Total** (qualquer cruzamento) | Mínima |
| **Custo** | Gratuito (UI) | **Gratuito** (paga-se S3/Athena) | Gratuito |
| **Melhor para** | Investigação rápida | **FinOps profundo, chargeback, conciliação** | Pagamento e auditoria |

## 3. Configurando um relatório

O CUR clássico é criado em **Billing → Cost & Usage Reports** (ou no **Data Exports**, a interface moderna). Principais opções:

| Opção | Descrição |
|---|---|
| **Nome do relatório** | Identificador |
| **Granularidade temporal** | **Horária**, **diária** ou **mensal** (horária gera **muito mais** dados) |
| **Incluir IDs de recursos** | **Sim** (recomendado) — adiciona `line_item_resource_id` |
| **Dividir dados de alocação de custo** | *Split cost allocation data* para **ECS/EKS** (custo por pod/tarefa) |
| **Versionamento** | Criar novo relatório vs **sobrescrever** o anterior |
| **Formato** | **Parquet** (recomendado, colunar e compacto) ou CSV (gzip/zip) |
| **Integração Athena** | Gera o template do **CloudFormation** com tabela Glue e partições |
| **Bucket S3 e prefixo** | Destino com **política** permitindo `billingreports.amazonaws.com` |
| **Atualização** | O relatório é **atualizado várias vezes ao dia**; os arquivos do mês corrente são **reescritos** |

Política de bucket necessária (ilustrativa):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow",
      "Principal": { "Service": "billingreports.amazonaws.com" },
      "Action": ["s3:GetBucketAcl","s3:GetBucketPolicy"],
      "Resource": "arn:aws:s3:::meu-bucket-cur" },
    { "Effect": "Allow",
      "Principal": { "Service": "billingreports.amazonaws.com" },
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::meu-bucket-cur/*" }
  ]
}
```

```bash
# Cria um CUR (ilustrativo; a API fica na região us-east-1)
aws cur put-report-definition --region us-east-1 --report-definition '{
  "ReportName":"cur-empresa",
  "TimeUnit":"DAILY",
  "Format":"Parquet",
  "Compression":"Parquet",
  "AdditionalSchemaElements":["RESOURCES","SPLIT_COST_ALLOCATION_DATA"],
  "S3Bucket":"meu-bucket-cur","S3Prefix":"cur","S3Region":"us-east-1",
  "AdditionalArtifacts":["ATHENA"],
  "RefreshClosedReports":true,
  "ReportVersioning":"OVERWRITE_REPORT"
}'
```

## 4. Estrutura dos dados e principais colunas

As colunas são prefixadas por **categoria**:

| Prefixo | Conteúdo | Exemplos |
|---|---|---|
| **identity_** | Identificadores da linha | `identity_line_item_id`, `identity_time_interval` |
| **bill_** | Dados da fatura | `bill_payer_account_id`, `bill_billing_period_start_date`, `bill_invoice_id` |
| **line_item_** | O **item de cobrança** | `line_item_usage_account_id`, `line_item_product_code`, `line_item_usage_type`, `line_item_operation`, `line_item_resource_id`, `line_item_usage_amount`, `line_item_unblended_cost`, `line_item_line_item_type` |
| **product_** | Atributos do produto | `product_region`, `product_instance_type`, `product_operating_system` |
| **pricing_** | Tarifas e termos | `pricing_term`, `pricing_unit`, `pricing_public_on_demand_cost` |
| **reservation_** | Detalhes de RIs | `reservation_effective_cost`, `reservation_reservation_arn` |
| **savings_plan_** | Detalhes de Savings Plans | `savings_plan_savings_plan_effective_cost`, `savings_plan_savings_plan_a_r_n` |
| **discount_** | Descontos (EDP, etc.) | `discount_total_discount` |
| **resource_tags_user_** | **Tags definidas pelo usuário** (ativas) | `resource_tags_user_projeto` |
| **resource_tags_aws_** | Tags geradas pela AWS | `resource_tags_aws_created_by` |
| **cost_category_** | Cost Categories | `cost_category_unidade_negocio` |

### 4.1 Tipos de item (`line_item_line_item_type`)

| Valor | Significado |
|---|---|
| **Usage** | Uso normal cobrado |
| **Tax** | Impostos |
| **Credit** | Créditos aplicados |
| **Refund** | Reembolsos |
| **Fee** | Taxas (por exemplo, de suporte ou do Marketplace) |
| **RIFee** | Taxa recorrente de Reserved Instances |
| **DiscountedUsage** | Uso coberto por RI/Savings Plan |
| **SavingsPlanCoveredUsage / SavingsPlanRecurringFee / SavingsPlanNegation** | Linhas associadas a Savings Plans |
| **EdpDiscount / PrivateRateDiscount** | Descontos contratuais |
| **BundledDiscount** | Descontos embutidos |

**Cuidado essencial:** ao somar custos para chargeback com RIs/Savings Plans, use as **colunas de custo efetivo** (`reservation_effective_cost`, `savings_plan_savings_plan_effective_cost`, ou colunas "amortizadas") e trate **linhas de negação/taxa** corretamente para **não contar duas vezes**.

## 5. Consultas com Athena

O CUR com Athena é a combinação clássica de FinOps. Exemplos (ilustrativos):

```sql
-- Top 10 serviços por custo no mês
SELECT line_item_product_code AS servico,
       ROUND(SUM(line_item_unblended_cost), 2) AS custo
FROM cur_db.cur_tabela
WHERE year = '2026' AND month = '11'
GROUP BY 1 ORDER BY custo DESC LIMIT 10;

-- Custo por tag de projeto
SELECT COALESCE(NULLIF(resource_tags_user_projeto, ''), '(sem tag)') AS projeto,
       ROUND(SUM(line_item_unblended_cost), 2) AS custo
FROM cur_db.cur_tabela
WHERE year = '2026' AND month = '11'
GROUP BY 1 ORDER BY custo DESC;

-- Custo diário de transferência de dados e NAT Gateway
SELECT date(line_item_usage_start_date) AS dia, line_item_usage_type,
       ROUND(SUM(line_item_unblended_cost), 2) AS custo
FROM cur_db.cur_tabela
WHERE year = '2026' AND month = '11'
  AND (line_item_usage_type LIKE '%DataTransfer%' OR line_item_usage_type LIKE '%NatGateway%')
GROUP BY 1, 2 ORDER BY dia, custo DESC;

-- Recursos EC2 mais caros (precisa de IDs de recurso habilitados)
SELECT line_item_resource_id, product_instance_type,
       ROUND(SUM(line_item_unblended_cost), 2) AS custo
FROM cur_db.cur_tabela
WHERE year = '2026' AND month = '11' AND line_item_product_code = 'AmazonEC2'
GROUP BY 1, 2 ORDER BY custo DESC LIMIT 20;
```

Boas práticas de consulta: **filtre por partições** (`year`, `month`) para reduzir o custo do Athena; use **Parquet**; crie **views** com a lógica de rateio.

## 6. Data Exports e CUR 2.0

O **Data Exports** é a interface atual para criar exportações de dados de custo. Tipos disponíveis (conforme a disponibilidade vigente):

| Exportação | Descrição |
|---|---|
| **CUR 2.0** | Evolução do CUR: **esquema fixo e estável**, colunas aninhadas (tags e atributos em mapas), inclusão de colunas extras |
| **FOCUS 1.0** | Formato aberto **FinOps Open Cost and Usage Specification** — esquema **padronizado entre provedores** de nuvem, facilitando multi-nuvem |
| **Cost optimization recommendations** | Exporta recomendações do Cost Optimization Hub |
| **Carbon emissions** | Dados de pegada de carbono |
| **Legacy CUR** | O CUR clássico (com possível descontinuação futura) |

Vantagens do CUR 2.0/Data Exports: **esquema estável** (menos quebra de consultas), **mesmas colunas todos os meses** (o CUR legado muda colunas conforme tags ativas), e **colunas de custos mais claros**. Para novos projetos, **prefira CUR 2.0/FOCUS** e planeje a migração do legado.

## 7. Cost and Usage Dashboards e ferramentas prontas

- **CUDOS / Cloud Intelligence Dashboards** (do **Well-Architected Labs**): dashboards do **QuickSight** open source baseados em CUR para custos, **cobertura de RI/SP**, rightsizing, transferência de dados, etc.
- **Cost and Usage Dashboards Operations Solution (CUDOS)**: implantação via CloudFormation com CUR + Athena + QuickSight.
- **Integrações de terceiros** (CloudHealth, Apptio Cloudability, Vantage, Datadog Cloud Cost, Kubecost): consomem o CUR.

## 8. Custos e retenção

- **Gerar o CUR é gratuito**, mas você paga **S3** (armazenamento), **Athena** (por TB lido), **Glue** (catálogo/crawlers) e **QuickSight** (usuários).
- **Retenção:** configure **S3 Lifecycle** para mover relatórios antigos a classes mais baratas ou expirar; mantenha o que a **auditoria e a contabilidade** exigem.
- **Compressão/Parquet** reduz custo e acelera consultas. A granularidade **horária** com IDs de recurso pode gerar **dezenas/centenas de GB por mês** em contas grandes: escolha a granularidade pelo caso de uso.

## 9. Segurança e governança

| Tema | Prática |
|---|---|
| **Acesso ao bucket** | Mínimo privilégio; apenas FinOps e engenharia de dados |
| **Dados sensíveis** | CUR revela **arquitetura e hábitos de uso**; trate como dado confidencial |
| **Criptografia** | SSE-S3 ou SSE-KMS no bucket; **Block Public Access** |
| **Contas** | Entregar na **conta de gerenciamento**/payer e compartilhar com contas de análise via S3/Athena/Lake Formation |
| **Tags** | Defina **padrões de tags** e **ative-as** para aparecerem como colunas |
| **Auditoria** | CloudTrail para `cur:*` e acesso ao bucket |

## 10. Casos de uso típicos

1. **Showback/chargeback:** ratear custo por equipe/produto com tags e Cost Categories.
2. **Unit economics:** custo por cliente, por transação ou por usuário (cruzando CUR com métricas de negócio).
3. **Conciliação:** comparar CUR com fatura e identificar divergências.
4. **Análise de compromissos:** cobertura e utilização de RIs/Savings Plans, por conta e tipo.
5. **Rightsizing e ociosidade:** recursos caros com baixa utilização (cruzando com CloudWatch).
6. **Detecção de anomalias customizada.**
7. **Kubernetes:** custo por namespace/pod com **split cost allocation data**.
8. **Multi-nuvem (FOCUS):** unificar dados de AWS, Azure e GCP.

## 11. Erros comuns

> [!bug] Erros comuns
> 1. **Não habilitar IDs de recurso** e depois não conseguir investigar por recurso.
> 2. **Somar tudo sem tratar tipos de item**, contando duas vezes linhas de RIs/Savings Plans.
> 3. **Consultar no Athena sem filtrar partições**, pagando por TB desnecessário.
> 4. **Usar CSV bruto** em vez de Parquet.
> 5. **Granularidade horária** sem necessidade, inflando custo e tempo.
> 6. **Bucket sem política** para `billingreports.amazonaws.com`, e o relatório não entregar.
> 7. **Esquecer de ativar as tags** de alocação e nunca vê-las como colunas.
> 8. **Contar com colunas fixas no CUR legado**, e quebrar consultas quando tags mudam (use CUR 2.0).
> 9. **Deixar o bucket de CUR acessível a muitos**, expondo informações sensíveis.
> 10. **Esquecer a retenção** e acumular dados caros sem utilidade.

## 12. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| Relatório não chega ao S3 | Política do bucket incorreta | Aplicar a política com `billingreports.amazonaws.com` |
| Athena sem dados | Partições não carregadas ou tabela errada | Rodar o crawler/`MSCK REPAIR TABLE` ou usar o template de integração |
| Coluna de tag ausente | Tag não ativada | Ativar a tag em Billing e aguardar |
| Totais diferentes da fatura | Tipos de item/descontos/impostos | Filtrar por tipo de item e usar as colunas corretas |
| Consulta lenta/cara | Sem partições ou CSV | Converter para Parquet e filtrar por ano/mês |
| Esquema mudou | CUR legado reorganiza colunas | Migrar para CUR 2.0/FOCUS |

## 13. Resumo rápido

- **CUR** é o dataset **mais granular** de custo e uso, entregue no **S3** (**Parquet** recomendado), com **IDs de recurso, tags, descontos e compromissos**.
- Consulte com **Athena** (e BI), **filtrando partições**; entenda os **tipos de item** para não duplicar.
- **Data Exports (CUR 2.0, FOCUS)** é a evolução, com **esquema estável** e padrão multi-nuvem.
- Gerar o CUR é gratuito; paga-se **S3, Athena e BI**; trate os dados como **sensíveis**.
- Casos de uso: **showback/chargeback, unit economics, conciliação, compromissos, Kubernetes e multi-nuvem**.
