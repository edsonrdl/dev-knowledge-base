## 1. O que é o Amazon Bedrock

O **Amazon Bedrock** é um serviço **totalmente gerenciado** que dá acesso, por **uma API única**, a **modelos fundacionais (FMs)** de várias empresas (Anthropic, Amazon, Meta, Mistral, Cohere, AI21, Stability AI, entre outros — **confirmar catálogo atual**), mais recursos para construir **aplicações de IA generativa**: RAG, agentes, guardrails, avaliação e personalização.

| Característica | Significado |
|---|---|
| **Serverless** | Sem provisionar GPUs/servidores no modo on-demand |
| **API única** | `bedrock-runtime` (inferência) e `bedrock` (gestão); Converse API padroniza chamadas |
| **Vários provedores** | Troca de modelo com poucas mudanças de código |
| **Dados do cliente** | Pela documentação, **prompts e respostas não são usados para treinar os modelos base** nem compartilhados com provedores (**confirmar a política atual**) |
| **Integração AWS** | IAM, KMS, VPC/PrivateLink, CloudTrail, CloudWatch, S3, Lambda |
| **Recursos** | **Knowledge Bases** (RAG gerenciado), **Agents**, **Guardrails**, **Flows**, **Prompt Management**, **Model Evaluation**, **Fine-tuning/Continued pre-training**, **Custom Model Import**, **Batch inference**, **Prompt caching**, **AgentCore** (infraestrutura para agentes) |

> [!info] Em uma frase
> **Bedrock = “API de modelos de IA generativa como serviço”, com os controles de segurança, rede e governança da AWS, sem você hospedar o modelo.**

## 2. Conceitos fundamentais de IA generativa

| Conceito | Explicação |
|---|---|
| **Modelo fundacional (FM)** | Modelo grande, pré-treinado, adaptável a muitas tarefas (texto, imagem, embeddings) |
| **LLM** | FM de linguagem: prevê o **próximo token** |
| **Token** | Unidade de texto (pedaço de palavra); **preço e limites são em tokens** (entrada + saída) |
| **Janela de contexto** | Máximo de tokens que o modelo “enxerga” por requisição (prompt + histórico + resposta) |
| **Prompt** | Instrução + contexto + exemplos enviados ao modelo |
| **System prompt** | Instruções de papel/regras de alto nível |
| **Temperatura / top-p** | Controlam **aleatoriedade** (baixa = mais determinístico) |
| **Max tokens** | Limite de saída |
| **Embedding** | Vetor numérico que representa significado; base da **busca semântica** |
| **Alucinação** | Resposta plausível porém **errada/inventada** |
| **RAG** | Recuperar **documentos relevantes** e incluí-los no prompt para **fundamentar** a resposta |
| **Fine-tuning** | Ajustar pesos do modelo com **seus dados** |
| **Agente** | LLM que **planeja** e **chama ferramentas/APIs** para cumprir uma meta |
| **Tool use / function calling** | O modelo pede a execução de uma função definida por você |
| **Guardrail** | Camada de **políticas** (filtros de conteúdo, PII, tópicos negados) na entrada/saída |

## 3. Como o Bedrock é usado (visão rápida)

```
Aplicação (Lambda/ECS/EC2) ──SDK──▶ bedrock-runtime ──▶ Modelo (Claude, Nova, Llama, Mistral…)
        │                                   ▲
        │  RAG: busca vetorial (Knowledge Base / OpenSearch / Aurora pgvector)
        │  Guardrails: filtra entrada/saída
        └─ IAM (bedrock:InvokeModel), KMS, VPC endpoint, CloudWatch/CloudTrail
```

| Etapa | O que acontece |
|---|---|
| 1. **Habilitar acesso aos modelos** | Em muitas contas/regiões é necessário **solicitar/habilitar o acesso** ao modelo (ou aceitar o EULA) — a falta gera `AccessDeniedException` (**confirmar fluxo atual**) |
| 2. **Escolher modelo/região** | Disponibilidade **varia por região**; há **inference profiles** (cross-region) |
| 3. **Chamar** | `InvokeModel`/`Converse` (com ou sem streaming) |
| 4. **Fundamentar** | RAG com Knowledge Bases ou seu próprio pipeline |
| 5. **Proteger** | Guardrails + IAM + rede |
| 6. **Operar** | Métricas, logs de invocação, custos |

## 4. Modos de consumo e preço (visão geral)

| Modo | Como funciona | Quando usar |
|---|---|---|
| **On-demand** | Paga **por token** (entrada/saída) ou por imagem; sem compromisso; **cotas** por região/modelo | Começar, cargas **variáveis/imprevisíveis** |
| **Batch inference** | Processa grandes volumes **assíncronos** (S3 → S3) com **desconto** (confirmar) | Classificação/enriquecimento **em massa**, sem urgência |
| **Provisioned Throughput** | Compra **unidades de modelo** por hora (compromisso 1/6 meses ou sem) para **throughput garantido** | Carga **alta e estável**; **modelos customizados** (fine-tuned) normalmente **exigem** |
| **Cross-region inference** | **Inference profiles** distribuem pedidos entre regiões | Aumentar **resiliência/cota** |
| **Prompt caching** | Reutiliza prefixos de prompt para **reduzir custo/latência** | Prompts longos e repetidos |
| **Latency-optimized** (onde existir) | Menor latência em alguns modelos | Interatividade |

**Fatores de custo**: modelo escolhido, **tokens de entrada e saída**, tamanho do contexto, **Knowledge Base** (armazenamento vetorial + consultas), **Guardrails** (cobrança por unidade de texto avaliado — **confirmar**), **Provisioned Throughput**, **agentes** e **transferência**.

> [!tip] Regra de bolso de custo
> **Custo ≈ (tokens de entrada × preço de entrada) + (tokens de saída × preço de saída)**. **Saída costuma ser mais cara**. **Limite `maxTokens`**, **compacte o contexto** e **escolha o menor modelo** que cumpre a tarefa.

## 5. Escolhendo o modelo

| Critério | Pergunta |
|---|---|
| **Capacidade** | A tarefa exige raciocínio complexo ou é **extração/classificação** simples? |
| **Custo** | Modelos menores/“lite” custam **muito menos** por token |
| **Latência** | Chat interativo precisa de **resposta rápida** (streaming ajuda) |
| **Contexto** | Documentos longos exigem **janela maior** |
| **Modalidade** | Texto, **imagem (multimodal)**, áudio, geração de imagem, **embeddings** |
| **Idioma** | Qualidade em **português** varia por modelo |
| **Ferramentas** | Suporte a **tool use/Converse** e **saída estruturada** |
| **Região/residência** | Disponibilidade e **compliance** |
| **Customização** | Fine-tuning disponível? |
| **Segurança** | Guardrails e políticas compatíveis |

Boa prática: **avaliar com seus dados** (Model Evaluation/golden set) e **começar pelo menor modelo** que atinja a qualidade; **roteamento** (modelo barato para fácil, forte para difícil).

## 6. Bedrock × SageMaker × serviços de IA prontos

| Necessidade | Escolha | Por quê |
|---|---|---|
| **Texto/imagem generativos com FMs prontos** | **Bedrock** | API pronta, sem infraestrutura |
| **Treinar/ajustar modelos próprios (ML tradicional ou deep learning)**, controle total de infraestrutura/frameworks | **SageMaker AI** | Notebooks, treino, endpoints, pipelines MLOps |
| **Hospedar modelo aberto com controle fino de GPU/containers** | **SageMaker** (JumpStart/endpoints) ou **EC2/EKS** | Controle e custo previsível em grande escala |
| **Visão: detectar objetos/rostos/moderação** | **Amazon Rekognition** | API pronta |
| **Extrair texto/tabelas/formulários de documentos** | **Amazon Textract** | OCR estruturado |
| **NLP clássico: entidades, sentimento, PII** | **Amazon Comprehend** | API pronta |
| **Voz → texto** | **Amazon Transcribe** | |
| **Texto → voz** | **Amazon Polly** | |
| **Tradução** | **Amazon Translate** | |
| **Chatbots por intenções/voz** | **Amazon Lex** | |
| **Busca corporativa inteligente** | **Amazon Kendra / Amazon Q Business** | |
| **Assistente para desenvolvedores** | **Amazon Q Developer / Kiro** (ver nota de IA no desenvolvimento) | |
| **Recomendação/previsão** | **Personalize / Forecast** (confirmar status) | |

> [!tip] Pegadinha de prova (DVA-C03)
> “Aplicação precisa **gerar texto/resumos** sem gerenciar infraestrutura” → **Bedrock**. “Extrair **dados de formulários/PDF**” → **Textract**. “Detectar **sentimento/PII** em texto” → **Comprehend**. “**Treinar** modelo próprio” → **SageMaker**. “Responder com base em **documentos da empresa**” → **RAG (Knowledge Bases)**.

## 7. Serviços gerenciados de IA (“AI services”) em aplicações

Padrão comum: **combinar** serviços para um pipeline:

```
Upload no S3 ──▶ Textract (extrai texto/tabelas) ──▶ Comprehend (PII/entidades)
              ──▶ Bedrock (resume/classifica) ──▶ DynamoDB/OpenSearch (resultado)
                                   ▲ Guardrails (remover PII/validar)
```

| Serviço | Chamada típica (SDK) | Observação |
|---|---|---|
| **Rekognition** | `detect_labels`, `detect_moderation_labels` | S3 ou bytes; cobrança por imagem |
| **Textract** | `analyze_document` (síncrono), `start_document_analysis` (assíncrono, SNS) | PDFs multipágina → **assíncrono** |
| **Comprehend** | `detect_sentiment`, `detect_pii_entities` | Limite de tamanho por chamada |
| **Transcribe** | `start_transcription_job` (S3→S3/JSON) | **Assíncrono** |
| **Polly** | `synthesize_speech` | Retorna **stream de áudio** |
| **Translate** | `translate_text` | |
| **Bedrock** | `converse`/`invoke_model` | Tokens e guardrails |

Para o desenvolvedor, o ponto central é: **chamar APIs com SDK**, **tratar erros/throttling**, **respeitar IAM**, **usar fluxo assíncrono para trabalhos longos** e **proteger dados**.

## 8. Permissões básicas (IAM)

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "InvocarModelosEspecificos",
    "Effect": "Allow",
    "Action": ["bedrock:InvokeModel", "bedrock:InvokeModelWithResponseStream"],
    "Resource": [
      "arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-3-haiku-*",
      "arn:aws:bedrock:us-east-1:123456789012:inference-profile/*"
    ]
  }]
}
```

| Ponto | Detalhe |
|---|---|
| **Ações** | `bedrock:InvokeModel`, `InvokeModelWithResponseStream`, e as de **Converse** usam as mesmas permissões de invocação (**confirmar**) |
| **Recurso** | ARN do **modelo** (`foundation-model/...`) e/ou **inference profile** |
| **Menor privilégio** | Permitir **só os modelos** usados |
| **Acesso ao modelo** | Além de IAM, o **acesso ao modelo** precisa estar habilitado na conta/região |
| **Função da aplicação** | **Role do Lambda/ECS** (sem chaves) |
| **Gestão** | `bedrock:*` de gestão (criar guardrail, agent, KB) separado da **invocação** |

## 9. Primeiro exemplo (Python/Boto3)

```python
import boto3, json
brt = boto3.client("bedrock-runtime", region_name="us-east-1")

resposta = brt.converse(
    modelId="us.anthropic.claude-3-haiku-20240307-v1:0",         # exemplo ilustrativo; confirmar ID/profile
    system=[{"text": "Você resume textos em português, em no máximo 3 frases."}],
    messages=[{"role": "user", "content": [{"text": "Resuma: ... texto longo ..."}]}],
    inferenceConfig={"maxTokens": 300, "temperature": 0.2},
)
print(resposta["output"]["message"]["content"][0]["text"])
print(resposta["usage"])        # inputTokens, outputTokens, totalTokens
```

## 10. Limites e cuidados de IA generativa

| Limite | Consequência | Mitigação |
|---|---|---|
| **Alucinação** | Informação falsa | **RAG**, citar fontes, **verificação**, humano no loop |
| **Não determinismo** | Respostas variam | `temperature` baixa, **saída estruturada**, testes de avaliação |
| **Janela de contexto** | Documentos grandes não cabem | **Chunking**, resumo hierárquico, RAG |
| **Latência** | Segundos para respostas longas | **Streaming**, modelos menores, cache |
| **Cotas/throttling** | `ThrottlingException` | **Retries com backoff**, Provisioned, cross-region |
| **Custo** | Cresce com tokens | Limites, caching, modelo menor |
| **Segurança** | Prompt injection, vazamento de dados | **Guardrails**, IAM, validação de saída |
| **Dados sensíveis** | PII no prompt | **Mascarar/anonimizar**, VPC endpoint, KMS |
| **Direitos autorais/licenças** | Conteúdo gerado | Políticas internas |

## 11. Erros comuns

- **Não habilitar o acesso ao modelo** (e culpar o IAM).
- **Usar a região errada** (modelo indisponível).
- **Sem limite de `maxTokens`** (custo e latência).
- **Colocar PII/segredos no prompt**.
- **Confiar na resposta sem validar** (alucinação).
- **Usar o maior modelo para tudo**.
- **Esquecer retries/backoff** em throttling.
- **Chamar síncrono** para trabalhos longos (timeout do Lambda/API Gateway).
- **Confundir Bedrock com SageMaker**.
- **Escopo IAM `bedrock:*` em produção**.

## 12. Troubleshooting inicial

| Sintoma | Causa provável | Ação |
|---|---|---|
| `AccessDeniedException` ao invocar | Acesso ao modelo não habilitado; IAM sem permissão; região errada | Habilitar modelo; revisar policy/ARN |
| `ValidationException` | Corpo/parâmetros inválidos para o modelo; `modelId` errado | Usar **Converse** ou o schema do modelo |
| `ThrottlingException` | Cota excedida | Backoff, cross-region, Provisioned, pedir aumento |
| `ModelTimeoutException`/timeout | Resposta longa/contexto grande | Streaming, reduzir tokens, modelo menor |
| Resposta cortada | `maxTokens` baixo | Aumentar |
| Resposta em outro idioma | Prompt/sistema ambíguo | Instruir idioma no **system prompt** |

## 13. Resumo rápido

- **Bedrock** = FMs de vários provedores via **API gerenciada**, com **IAM/KMS/VPC**, **Knowledge Bases**, **Agents**, **Guardrails** e mais.
- **Tokens** definem **custo e limites**; **janela de contexto** limita o que cabe.
- **On-demand** (por token) × **Batch** × **Provisioned Throughput** (garantido; modelos customizados).
- **Bedrock** (FMs prontos) × **SageMaker** (treinar/hospedar) × **serviços prontos** (Textract, Comprehend, Rekognition, Transcribe, Polly, Translate, Lex).
- **IAM**: `bedrock:InvokeModel*` por modelo + **acesso ao modelo habilitado**.
- Riscos: **alucinação, custo, throttling, privacidade, prompt injection** → **RAG, limites, backoff, Guardrails**.

3. Quando usar Provisioned Throughput?
4. Quando escolher SageMaker em vez de Bedrock?
5. Qual serviço extrai dados estruturados de documentos?

**Respostas:**

1. Serviço gerenciado que oferece modelos fundacionais de vários provedores por API única, com recursos como RAG, agentes e guardrails.
2. Unidade de texto processada pelo modelo; custo, limites de contexto e de saída são medidos em tokens.
3. Para carga alta e estável com throughput garantido e para modelos customizados, que normalmente exigem capacidade provisionada.
4. Para treinar ou hospedar modelos próprios com controle de infraestrutura e MLOps.
5. Amazon Textract.
6. Porque o acesso ao modelo pode não estar habilitado na conta/região ou o ARN do modelo/inference profile não está na policy.
7. Com RAG (fundamentar em documentos), temperatura baixa, citação de fontes, validação e humano no loop.
