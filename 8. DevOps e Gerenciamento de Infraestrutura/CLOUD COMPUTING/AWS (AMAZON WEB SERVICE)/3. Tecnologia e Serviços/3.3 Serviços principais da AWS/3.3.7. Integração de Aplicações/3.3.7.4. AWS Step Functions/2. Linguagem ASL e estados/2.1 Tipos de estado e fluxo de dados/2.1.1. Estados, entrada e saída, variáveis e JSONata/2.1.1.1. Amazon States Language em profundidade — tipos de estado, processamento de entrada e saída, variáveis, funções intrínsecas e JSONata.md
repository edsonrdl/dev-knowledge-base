### Amazon States Language em profundidade — tipos de estado, processamento de entrada e saída, variáveis, funções intrínsecas e JSONata

> [!warning] Aviso
> A ASL evolui (por exemplo, com **variáveis (`Assign`)** e a linguagem de consulta **JSONata** como alternativa ao JSONPath). Campos, funções intrínsecas, limites e recomendações mudam. Os exemplos aqui são referências de estudo; confirme na documentação. As definições **não foram executadas**.

A **Amazon States Language (ASL)** é o **vocabulário** do Step Functions: um **JSON** que descreve **estados**, **transições** e **como os dados fluem** entre eles. Dominar a ASL significa dominar **três coisas**: **(1) os tipos de estado** e o que cada um faz; **(2) o processamento de entrada e saída** (como o JSON **entra** num estado, **é transformado**, **chamado** e **sai**); e **(3) como guardar e reutilizar dados** (**variáveis** e **JSONata**). A maioria dos **bugs de Step Functions** nasce em **erros de manipulação de JSON** (campo que não existe, resultado que **sobrescreve** a entrada, payload que **cresce demais**). Esta folha cobre **cada tipo de estado**, o **pipeline de dados** (`InputPath`, `Parameters`, `ResultSelector`, `ResultPath`, `OutputPath`), **variáveis**, **funções intrínsecas**, **JSONata** e **boas práticas**.

**Analogia:** o JSON que circula é **uma pasta de documentos** passada de mesa em mesa. Cada **mesa (estado)** pode **receber só parte da pasta** (`InputPath`), **montar um formulário próprio** (`Parameters`), **anexar o resultado** em algum lugar da pasta (`ResultPath`) e **entregar à próxima mesa apenas as folhas relevantes** (`OutputPath`). Quem **não controla** o que anexa **perde** documentos importantes ou **enche a pasta** até estourar o limite.

## Estrutura de uma máquina de estados

```json
{
  "Comment": "Descrição",
  "StartAt": "PrimeiroEstado",
  "TimeoutSeconds": 3600,
  "Version": "1.0",
  "States": {
    "PrimeiroEstado": { "Type": "Task", "Resource": "...", "Next": "Fim" },
    "Fim": { "Type": "Succeed" }
  }
}
```

| Campo de topo | Função |
|---|---|
| **`StartAt`** | **Nome** do estado inicial |
| **`States`** | **Mapa** de nome → definição do estado |
| **`TimeoutSeconds`** | **Tempo máximo** da execução inteira |
| **`Comment`** | Descrição |
| **`QueryLanguage`** | `JSONPath` (padrão) ou **`JSONata`** (por máquina ou por estado) |

| Campos comuns a vários estados | Função |
|---|---|
| **`Type`** | Tipo do estado |
| **`Next`** ou **`End: true`** | Próximo estado **ou** fim do ramo |
| **`Comment`** | Descrição |
| **`InputPath` / `OutputPath`** | Filtros de entrada/saída (JSONPath) |
| **`Parameters` / `ResultSelector` / `ResultPath`** | Construção de entrada e tratamento do resultado (Task, Map, Parallel) |
| **`Retry` / `Catch`** | Tratamento de erros (Task, Map, Parallel) |
| **`TimeoutSeconds` / `HeartbeatSeconds`** | Limites de tempo (Task) |
| **`Assign`** | Atribui **variáveis** |

## Os tipos de estado

### Task: faz o trabalho

```json
"CalculaFrete": {
  "Type": "Task",
  "Resource": "arn:aws:states:::lambda:invoke",
  "Parameters": {"FunctionName": "calcula-frete", "Payload": {"cep.$": "$.endereco.cep", "peso.$": "$.peso"}},
  "ResultSelector": {"frete.$": "$.Payload.valor", "prazo.$": "$.Payload.dias"},
  "ResultPath": "$.entrega",
  "TimeoutSeconds": 30,
  "Retry": [{"ErrorEquals": ["Lambda.ServiceException","Lambda.TooManyRequestsException"], "IntervalSeconds": 2, "MaxAttempts": 4, "BackoffRate": 2}],
  "Next": "Escolhe"
}
```

| Campo | Função |
|---|---|
| **`Resource`** | **O que executar**: ARN de **integração otimizada** (`arn:aws:states:::lambda:invoke`), **SDK** (`arn:aws:states:::aws-sdk:...`), **activity**, ou **função Lambda direta** (forma antiga) |
| **`Parameters`** | **Entrada** enviada ao recurso (com referências `"campo.$": "$.x"`) |
| **`TimeoutSeconds`** | Tempo máximo da tarefa |
| **`HeartbeatSeconds`** | Intervalo máximo entre **batimentos** (activities/callbacks longos) |

### Choice: decisão

```json
"Escolhe": {
  "Type": "Choice",
  "Choices": [
    {"Variable": "$.valor", "NumericGreaterThan": 10000, "Next": "AprovacaoHumana"},
    {"And": [{"Variable": "$.cliente.tipo", "StringEquals": "premium"},
             {"Variable": "$.valor", "NumericGreaterThan": 1000}], "Next": "FluxoPremium"},
    {"Not": {"Variable": "$.cupom", "IsPresent": true}, "Next": "SemCupom"}
  ],
  "Default": "FluxoPadrao"
}
```

| Operadores | Exemplos |
|---|---|
| **Comparação** | `StringEquals`, `StringMatches` (curingas), `NumericEquals/LessThan/GreaterThan(Equals)`, `BooleanEquals`, `TimestampEquals/LessThan…` |
| **Entre campos** | `StringEqualsPath`, `NumericLessThanPath` (compara com **outro campo**) |
| **Tipo/existência** | `IsPresent`, `IsNull`, `IsString`, `IsNumeric`, `IsBoolean`, `IsTimestamp` |
| **Lógicos** | `And`, `Or`, `Not` |
| **`Default`** | Caminho quando **nada casa** (**sempre defina**) |

> [!warning] Choice sem `Default` falha em silêncio... ruidoso
> Se **nenhuma condição** casa e **não há `Default`**, a execução **falha** com `States.NoChoiceMatched`. **Sempre defina `Default`** (ao menos para um estado `Fail` explicativo).

### Parallel: ramos simultâneos

```json
"VerificacoesEmParalelo": {
  "Type": "Parallel",
  "Branches": [
    {"StartAt": "ReservaEstoque", "States": {"ReservaEstoque": {"Type": "Task", "Resource": "...", "End": true}}},
    {"StartAt": "AnaliseFraude",  "States": {"AnaliseFraude":  {"Type": "Task", "Resource": "...", "End": true}}}
  ],
  "ResultPath": "$.verificacoes",
  "Next": "Decide"
}
```

| Aspecto | Detalhe |
|---|---|
| **Entrada** | **Cada ramo recebe a mesma entrada** |
| **Saída** | **Array** com a saída de **cada ramo**, **na ordem dos ramos** |
| **Falha** | Se **um ramo falha**, **os demais são cancelados** e o estado falha (use `Catch`) |
| **Uso** | **Tarefas independentes**, reduzindo latência |

### Map: iteração sobre listas

**Map inline** (cada item é processado por um **sub-fluxo**, em paralelo controlado):

```json
"ProcessaItens": {
  "Type": "Map",
  "ItemsPath": "$.itens",
  "ItemSelector": {"item.$": "$$.Map.Item.Value", "pedido.$": "$.pedido_id", "indice.$": "$$.Map.Item.Index"},
  "MaxConcurrency": 10,
  "ItemProcessor": {
    "ProcessorConfig": {"Mode": "INLINE"},
    "StartAt": "ProcessaItem",
    "States": {"ProcessaItem": {"Type": "Task", "Resource": "arn:aws:states:::lambda:invoke",
                "Parameters": {"FunctionName": "processa-item", "Payload.$": "$"}, "End": true}}
  },
  "ResultPath": "$.resultados",
  "Next": "Consolida"
}
```

| Modo | Escala | Uso |
|---|---|---|
| **INLINE** | Até **40 iterações simultâneas** (referência); itens **dentro do histórico** da execução pai | **Listas pequenas/médias** (dezenas a centenas) |
| **DISTRIBUTED** | Até **10.000 execuções-filhas em paralelo**; itens vindos de **S3 (CSV/JSON/inventário/listas)**; **resultados** gravados no S3 | **Milhões de itens**, **processamento em lote massivo** (detalhes na folha de padrões) |

| Campo | Função |
|---|---|
| **`ItemsPath` / `ItemReader`** | Fonte da lista (JSON da entrada, ou **S3** no modo distribuído) |
| **`ItemSelector`** | Monta a **entrada de cada item** (`$$.Map.Item.Value`, `$$.Map.Item.Index`) |
| **`MaxConcurrency`** | **Limite de paralelismo** (0 = ilimitado no máximo suportado) |
| **`ToleratedFailurePercentage/Count`** | **Tolerância a falhas** (distribuído) |
| **`ResultWriter`** | Onde gravar resultados (distribuído) |

### Wait: esperar

```json
"Espera24h":   {"Type": "Wait", "Seconds": 86400, "Next": "Lembrete"},
"EsperaAte":   {"Type": "Wait", "TimestampPath": "$.data_entrega", "Next": "Notifica"},
"EsperaDinam": {"Type": "Wait", "SecondsPath": "$.aguardar_s", "Next": "Verifica"}
```

| Variante | Uso |
|---|---|
| **`Seconds`** | Duração fixa |
| **`SecondsPath`** | Duração vinda da entrada |
| **`Timestamp`** | Até uma data/hora ISO 8601 |
| **`TimestampPath`** | Data/hora vinda da entrada |

> [!tip] Wait é barato em Standard
> Em workflows **Standard**, **esperar não consome recursos nem cobra duração** (cobra apenas as **transições**). Esperas de **horas ou dias** são **econômicas**, ao contrário de manter **uma Lambda dormindo**.

### Pass, Succeed e Fail

```json
"MontaContexto": {"Type": "Pass", "Parameters": {"pedido.$": "$.id", "origem": "checkout", "ts.$": "$$.State.EnteredTime"}, "ResultPath": "$.ctx", "Next": "Proximo"},
"Concluido":     {"Type": "Succeed"},
"Reprovado":     {"Type": "Fail", "Error": "PedidoReprovado", "Cause": "Fraude detectada"}
```

| Estado | Uso |
|---|---|
| **Pass** | **Injetar/renomear/reestruturar** dados; **depurar**; **stubs** em desenvolvimento |
| **Succeed** | Fim **bem-sucedido** (em ramos de `Choice`/`Parallel`) |
| **Fail** | Fim **com erro nomeado** (`Error`, `Cause`) para **tratamento a montante** |

## Objeto de contexto e dados de execução

O **contexto** (`$$`) traz **metadados** da execução:

| Caminho | Conteúdo |
|---|---|
| **`$$.Execution.Id`** | ARN da execução |
| **`$$.Execution.Name`** | Nome da execução |
| **`$$.Execution.StartTime`** | Início |
| **`$$.Execution.Input`** | **Entrada original** da execução |
| **`$$.StateMachine.Id` / `.Name`** | Máquina |
| **`$$.State.Name` / `.EnteredTime`** | Estado atual |
| **`$$.Task.Token`** | **Task token** (callbacks) |
| **`$$.Map.Item.Index` / `.Value`** | Item do Map |

```json
"Parameters": {"Mensagem": "Pedido processado", "ExecutionId.$": "$$.Execution.Id", "Entrada.$": "$$.Execution.Input"}
```

## O pipeline de entrada e saída (JSONPath)

Para estados **Task, Map e Parallel**, o JSON passa por **etapas na ordem**:

```
 Entrada do estado
     │ 1. InputPath      → filtra QUAL parte da entrada será usada
     ▼
     │ 2. Parameters     → monta a ENTRADA do recurso (com referências "$.x" via "campo.$")
     ▼
   [ EXECUTA a tarefa ]  → resultado bruto
     │ 3. ResultSelector → escolhe/renomeia campos do RESULTADO
     ▼
     │ 4. ResultPath     → ONDE colocar o resultado dentro da entrada original ($.caminho, ou null/descartar)
     ▼
     │ 5. OutputPath     → filtra o que SAI para o próximo estado
     ▼
 Saída do estado (entrada do próximo)
```

| Campo | Função | Valor padrão |
|---|---|---|
| **`InputPath`** | Seleciona parte da **entrada** | `$` (tudo) |
| **`Parameters`** | **Constrói** a entrada do recurso; chaves com **`.$`** usam **JSONPath** | — |
| **`ResultSelector`** | **Transforma** o **resultado** (extrai/renomeia) | — |
| **`ResultPath`** | **Onde** o resultado é **anexado** à entrada | **`$`** (**substitui** a entrada inteira!) |
| **`OutputPath`** | Seleciona parte do que **sai** | `$` |

### O erro nº 1: `ResultPath` ausente sobrescreve a entrada

```json
// Entrada: {"pedido_id": 999, "valor": 50}
// Task retorna: {"frete": 12.5}

// Sem ResultPath (padrão "$"): a SAÍDA vira {"frete": 12.5}  → pedido_id e valor SE PERDERAM
// Com "ResultPath": "$.entrega": SAÍDA = {"pedido_id":999,"valor":50,"entrega":{"frete":12.5}}  ✔
// Com "ResultPath": null: o resultado é DESCARTADO e a SAÍDA = entrada original (útil para "side effects")
```

| `ResultPath` | Efeito |
|---|---|
| **`"$"`** (padrão) | Resultado **substitui** a entrada |
| **`"$.campo"`** | Resultado **adicionado** em `campo` (entrada **preservada**) |
| **`null`** | **Descarta** o resultado; mantém a entrada |

### Exemplo completo

```json
"CobraPedido": {
  "Type": "Task",
  "Resource": "arn:aws:states:::lambda:invoke",
  "InputPath": "$.pedido",                                    // só o pedido
  "Parameters": {
    "FunctionName": "cobra-pedido",
    "Payload": {"id.$": "$.id", "valor.$": "$.valor", "execucao.$": "$$.Execution.Name"}
  },
  "ResultSelector": {"transacao.$": "$.Payload.transacao_id", "status.$": "$.Payload.status"},
  "ResultPath": "$.pagamento",                                // anexa ao ESTADO inteiro? (veja a nota)
  "OutputPath": "$",
  "Next": "Emite"
}
```

> [!warning] `InputPath` + `ResultPath` interagem
> O **`ResultPath`** é aplicado sobre **a entrada original do estado** (antes do `InputPath`? **não**: sobre **a entrada efetiva depois de `InputPath`**, de acordo com a ordem acima). Se você usa **`InputPath: "$.pedido"`** e **`ResultPath: "$.pagamento"`**, o resultado é **anexado ao objeto `pedido`**, **não** ao estado completo. Para **preservar o estado inteiro**, **evite `InputPath`** e use apenas **`Parameters`** para montar a entrada.

## Variáveis (`Assign`) e `$states`

As **variáveis** permitem **guardar valores** em **um estado** e **usá-los** em **estados posteriores**, **sem** precisar **carregá-los** no JSON que **flui** (reduzindo **o tamanho do payload** e **simplificando caminhos**).

```json
"ObtemCliente": {
  "Type": "Task",
  "Resource": "arn:aws:states:::dynamodb:getItem",
  "Parameters": {"TableName": "clientes", "Key": {"id": {"S.$": "$.cliente_id"}}},
  "Assign": {
    "nomeCliente": "{% $states.result.Item.nome.S %}",
    "tipoCliente": "{% $states.result.Item.tipo.S %}"
  },
  "Next": "Decide"
},
"Notifica": {
  "Type": "Task",
  "Resource": "arn:aws:states:::sns:publish",
  "Arguments": {"TopicArn": "arn:aws:sns:us-east-1:123456789012:avisos",
                "Message": "{% 'Olá, ' & $nomeCliente & '! Seu pedido foi recebido.' %}"},
  "End": true
}
```

| Conceito | Descrição |
|---|---|
| **`Assign`** | Define **variáveis** (visíveis a **estados seguintes** na mesma execução/escopo) |
| **Referência** | `$nomeVariavel` (em JSONata) ou `$variavel` em expressões |
| **`$states.input`** | A **entrada** do estado |
| **`$states.result`** | O **resultado** da tarefa |
| **`$states.errorOutput`** | A saída de **erro** em `Catch` |
| **`$states.context`** | Objeto de **contexto** |
| **Limites** | Tamanho de **variáveis** (por execução) é limitado (centenas de KB, ver documentação) |
| **Escopo** | Variáveis de **estados dentro de Map/Parallel** têm **escopo local** do ramo |

## JSONata: a linguagem de consulta moderna

A **JSONata** é uma linguagem **expressiva** de consulta e transformação de JSON, disponível como **alternativa ao JSONPath** (`"QueryLanguage": "JSONata"`).

| Aspecto | **JSONPath** (clássico) | **JSONata** |
|---|---|---|
| **Campos de dados** | `InputPath`, `Parameters`, `ResultSelector`, `ResultPath`, `OutputPath` | **`Arguments`**, **`Output`**, **`Assign`** |
| **Sintaxe** | `"campo.$": "$.x"` + **funções intrínsecas** (`States.*`) | **`"{% expressão %}"`** em qualquer valor |
| **Poder** | Seleção simples; **funções limitadas** | **Aritmética, strings, arrays, agregações, condicionais, lambdas** |
| **Choice** | `Variable` + operadores | **`Condition`**: `"{% $states.input.valor > 1000 and $states.input.tipo = 'premium' %}"` |
| **Reduz estados `Pass`** | Não | **Sim** (transformações **inline**) |
| **Recomendação** | **Legado** | **Preferida** em fluxos novos |

```json
{
  "QueryLanguage": "JSONata",
  "StartAt": "Calcula",
  "States": {
    "Calcula": {
      "Type": "Pass",
      "Output": {
        "total": "{% $sum($states.input.itens.(preco * quantidade)) %}",
        "quantidade": "{% $count($states.input.itens) %}",
        "resumo": "{% 'Pedido ' & $states.input.id & ' com ' & $count($states.input.itens) & ' itens' %}"
      },
      "Next": "Decide"
    },
    "Decide": {
      "Type": "Choice",
      "Choices": [{"Condition": "{% $states.input.total > 1000 %}", "Next": "Premium"}],
      "Default": "Padrao"
    },
    "Premium": {"Type": "Succeed"},
    "Padrao": {"Type": "Succeed"}
  }
}
```

| Funções JSONata úteis | Exemplos |
|---|---|
| **Agregação** | `$sum`, `$count`, `$average`, `$min`, `$max` |
| **Strings** | `$uppercase`, `$substring`, `$split`, `$join`, `$replace` |
| **Arrays/objetos** | `$map`, `$filter`, `$reduce`, `$keys`, `$merge`, `$sort` |
| **Datas** | `$now()`, `$fromMillis`, `$toMillis` |
| **Específicas do Step Functions** | `$partition`, `$range`, `$hash`, `$random`, `$uuid`, `$parse` |

> [!tip] JSONata reduz estados e Lambdas
> Muitas **Lambdas "de transformação"** e **estados `Pass`** existem **apenas para reformatar JSON**. Com **JSONata**, essa lógica vai **dentro do próprio estado**, **simplificando o fluxo**, **reduzindo transições (custo)** e **removendo código**.

## Funções intrínsecas (JSONPath)

Para JSONPath, as **funções intrínsecas** (`States.*`) fazem **transformações simples** em **`Parameters`** (chaves terminadas em `.$`):

| Categoria | Funções | Exemplo |
|---|---|---|
| **Arrays** | `States.Array`, `States.ArrayPartition`, `States.ArrayContains`, `States.ArrayRange`, `States.ArrayGetItem`, `States.ArrayLength`, `States.ArrayUnique` | `"lista.$": "States.Array($.a, $.b)"` |
| **Dados/Codificação** | `States.Base64Encode/Decode`, `States.Hash`, `States.JsonMerge`, `States.StringToJson`, `States.JsonToString` | `"obj.$": "States.StringToJson($.texto)"` |
| **Texto** | `States.Format` | `"msg.$": "States.Format('Pedido {} criado', $.id)"` |
| **Matemática** | `States.MathRandom`, `States.MathAdd` | `"n.$": "States.MathAdd($.a, 1)"` |
| **Utilidades** | `States.UUID` | `"id.$": "States.UUID()"` |

## Tamanho de payload e referência por S3

| Problema | Solução |
|---|---|
| **Limite de 256 KB** por entrada/saída de estado | **Não circule dados grandes**: guarde no **S3/DynamoDB** e passe **referências** |
| **Resultado de Lambda grande** | A Lambda **grava no S3** e devolve a **chave** |
| **Muitos campos desnecessários** | **`OutputPath`/`ResultSelector`/`Output` (JSONata)** para **limpar** |
| **Listas enormes** | **Distributed Map** com `ItemReader` do **S3** |
| **Variáveis** | Guardar valores fora do payload (respeitando seus limites) |

```json
"Parameters": {"bucket": "meu-bucket", "chave.$": "States.Format('relatorios/{}.json', $$.Execution.Name)"}
```

## Boas práticas de ASL

| Prática | Motivo |
|---|---|
| **`ResultPath` (ou `Output`/`Assign`) sempre definido** | Não perder dados |
| **Entradas mínimas e explícitas** (`Parameters`/`Arguments`) | Contratos claros |
| **`Default` em todo `Choice`** | Evitar `NoChoiceMatched` |
| **`TimeoutSeconds` em toda `Task`** | Evitar execuções penduradas |
| **Nomes de estado descritivos** | Legibilidade do histórico |
| **Preferir integrações diretas a Lambdas** | Menos código |
| **JSONata em fluxos novos** | Menos estados e Lambdas |
| **Dados grandes fora do payload** | Limite de 256 KB |
| **Definições em Git/IaC** (CloudFormation/CDK/SAM) | Versionamento |
| **Testar estados isoladamente** (`TestState`) | Ciclo rápido |
| **Evitar lógica de negócio nos estados** | Mantê-la nas funções/serviços |

## Exemplo prático: pipeline de dados e transformação de entrada

1. **Entrada**: `{"pedido": {"id": 999, "itens": [{"sku": "A", "preco": 10, "qtd": 2}, {"sku": "B", "preco": 30, "qtd": 1}], "cliente_id": 42}}`.
2. **Estado 1** (Task DynamoDB `getItem`) busca o cliente e **`Assign`** `nomeCliente`, `tipoCliente` (variáveis), **sem poluir** o JSON.
3. **Estado 2** (Pass com **JSONata**) calcula **`total = $sum(itens.(preco*qtd))`** e **`quantidade`**.
4. **Estado 3** (Choice com **`Condition` JSONata**): `total > 1000 e $tipoCliente = 'premium'` → fluxo premium; caso contrário padrão.
5. **Estado 4** (Task SNS) monta a mensagem com **variáveis** (`$nomeCliente`) e **Arguments**.
6. **Saída** final com **`Output`** enxuto (apenas `pedido_id`, `total`, `status`).
7. Ao evitar **`Lambda` de transformação** e **`Pass` repetidos**, o fluxo tem **menos transições**, **menos código** e **menos pontos de falha**.

## Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| **Campos da entrada "sumiram" depois de uma Task** | `ResultPath` padrão (`$`) substituiu a entrada | Definir `ResultPath` (ex.: `$.resultado`) ou usar `Assign`/`Output` |
| **`States.Runtime`: "The JSONPath ... could not be found"** | Caminho inexistente na entrada | Validar o caminho; usar `Choice` com `IsPresent`; `Default` |
| **`States.NoChoiceMatched`** | `Choice` sem `Default` e sem condição casando | Adicionar `Default` |
| **`States.DataLimitExceeded`** | Payload > 256 KB | Guardar no S3/DynamoDB; limpar com `ResultSelector`/`Output` |
| **Parâmetro não resolvido (`"campo.$"` ausente)** | Esqueceu `.$` no nome da chave para valores dinâmicos | Usar `"campo.$": "$.x"` |
| **`Parameters` envia texto literal `$.x`** | Chave sem `.$` | Adicionar o sufixo `.$` |
| **Ramos de `Parallel` com saída inesperada** | Saída é **array** na ordem dos ramos | Tratar o array; `ResultSelector`/JSONata |
| **Map "não itera"** | `ItemsPath` apontando para algo que não é array | Verificar o tipo; `ItemsPath` correto |
| **Variável não encontrada** | Escopo (Map/Parallel) ou estado ainda não executou | Rever onde foi atribuída |
| **Erro de sintaxe JSONata** | Expressão inválida; `{% %}` mal fechado | Testar a expressão (console/`TestState`) |
| **Misturou JSONPath e JSONata** | Campos de linguagens diferentes no mesmo estado | Definir `QueryLanguage` consistente por estado |
| **Histórico "grande demais"** | Muitos eventos | Dividir fluxo; Distributed Map; workflows aninhados |

## Erros comuns e armadilhas

- **Esquecer o `ResultPath`** e perder o contexto.
- **Esquecer `.$`** em parâmetros dinâmicos.
- **`Choice` sem `Default`.**
- **Carregar dados grandes** no payload.
- **Criar vários `Pass`/Lambdas** só para transformar JSON (use JSONata).
- **Misturar linguagens de consulta** sem critério.
- **Colocar lógica de negócio** na definição em vez de nas funções.
- **Não testar** transformações isoladamente.

## 🧩 Quiz de Fixação

1. Quais são os tipos de estado da ASL?
2. O que acontece se uma Task não define `ResultPath`?
3. Qual a diferença entre Parallel e Map?
4. Para que servem as variáveis (`Assign`)?
5. Quais vantagens da JSONata sobre o JSONPath?
6. Como contornar o limite de 256 KB de payload?

**Respostas:**
1) Task, Choice, Parallel, Map, Wait, Pass, Succeed e Fail.
2) O padrão (`$`) faz o resultado da tarefa substituir a entrada inteira, perdendo os demais campos.
3) Parallel executa ramos diferentes (e fixos) ao mesmo tempo com a mesma entrada; Map itera um mesmo sub-fluxo sobre os itens de uma lista.
4) Guardar valores para uso em estados posteriores sem carregá-los no JSON que flui, reduzindo o payload e simplificando os caminhos.
5) Expressões mais poderosas (aritmética, strings, arrays, condições, funções) dentro do próprio estado, reduzindo estados Pass e Lambdas de transformação, e simplificando Choice com Condition.
6) Guardando dados grandes no S3 ou DynamoDB e passando referências, limpando campos com ResultSelector/OutputPath/Output e usando Distributed Map para listas enormes.
