### Notificações a pessoas com SNS — SMS, push móvel (APNs e FCM), e-mail, identidades de origem, limites de gasto, opt-out, conformidade e quando usar SES, Pinpoint ou End User Messaging

> [!warning] Aviso
> Regras de SMS por país, registro de números (10DLC, sender ID), preços, limites, nomes de serviços de mensageria (a AWS reorganizou Pinpoint e SMS sob **AWS End User Messaging**) e requisitos das lojas de aplicativos mudam constantemente. Os valores aqui são referências de estudo; confirme na documentação e na regulação local. Os comandos **não foram executados**.

Até aqui o SNS foi visto como **barramento entre sistemas (A2A)**. Mas ele também **alcança pessoas (A2P)**: **SMS** no celular, **notificações push** no aplicativo e **e-mails**. Esse lado traz **desafios que não existem entre sistemas**: **regulação** (cada país tem regras de SMS), **consentimento e opt-out**, **reputação do remetente**, **custos por mensagem**, **fraude** (pumping de SMS), **tokens de dispositivo que expiram** e **limites de provedores** (operadoras, Apple, Google). Esta folha cobre **como cada canal funciona no SNS**, **as configurações essenciais** (identidades de origem, limites de gasto, tipos de mensagem), **conformidade e boas práticas** e **quando migrar para serviços mais especializados** (SES, Pinpoint/End User Messaging).

**Analogia:** o SNS A2P é a **assessoria de comunicação** da empresa: pode **mandar recado por telegrama (SMS)**, **aviso no celular (push)** e **carta (e-mail)**. Mas cada canal tem **regras legais, custos e etiqueta**: não se manda mensagem a quem **pediu para não receber**, não se usa **nome falso**, e **grandes campanhas** pedem uma **agência especializada** (SES, Pinpoint).

## Os canais A2P do SNS

| Canal | Como funciona | Quando é adequado |
|---|---|---|
| **SMS** | Mensagem de texto a um número de telefone | **Códigos de verificação (OTP)**, **alertas críticos**, **avisos transacionais** |
| **Push móvel** | Notificação no app (iOS/Android/Windows/…) via **APNs, FCM, ADM, Baidu, WNS** | **Engajamento e avisos** a usuários com o app |
| **E-mail / E-mail-JSON** | E-mail via SNS para **assinantes confirmados** | **Alertas operacionais internos**, **baixo volume** |

> [!info] Não é substituto de plataformas de marketing
> O SNS entrega **notificações simples**. Para **e-mail em volume/transacional**, use **Amazon SES**; para **campanhas multicanal e segmentação**, use **Amazon Pinpoint/AWS End User Messaging** (ver abaixo).

## SMS com SNS

### Modelos de envio

| Modelo | Como | Uso |
|---|---|---|
| **Direto a um número** | `Publish` com `PhoneNumber` (sem tópico) | **OTP**, mensagens individuais |
| **Para um tópico** | Assinantes com protocolo `sms` | Alertas para **grupos** (ex.: plantão) |

```bash
# SMS direto (formato E.164: +5511999999999)
aws sns publish --phone-number +5511999999999 \
  --message "Seu código de verificação é 482913. Válido por 5 minutos." \
  --message-attributes '{
    "AWS.SNS.SMS.SMSType":{"DataType":"String","StringValue":"Transactional"},
    "AWS.SNS.SMS.SenderID":{"DataType":"String","StringValue":"MinhaLoja"}
  }'

# SMS para assinantes de um tópico
aws sns subscribe --topic-arn $TOPIC --protocol sms --notification-endpoint +5511988887777
```

### Tipos de mensagem SMS

| Tipo | Característica | Uso |
|---|---|---|
| **`Transactional`** | **Maior confiabilidade/prioridade** de entrega (rotas otimizadas), custo mais alto | **OTP, alertas, confirmações** |
| **`Promotional`** | **Custo menor**, **menor prioridade** de entrega | **Marketing**, avisos não críticos |

### Identidades de origem (*origination identities*)

A **identidade de origem** é **de quem a mensagem parece vir**:

| Identidade | Descrição | Observações |
|---|---|---|
| **Número de telefone longo (long code)** | Número **comum** de 10–11 dígitos | Baixo volume; **requer registro** em alguns países (EUA: **10DLC**) |
| **Toll-free** | Número gratuito | EUA/Canadá; **verificação** |
| **Short code** | Número **curto** (5–6 dígitos) | **Alto volume**, alta vazão; **aprovação demorada** e **custo mensal** |
| **Sender ID** (remetente alfanumérico) | **Nome** (ex.: `MinhaLoja`) em vez de número | **Unidirecional** (sem resposta); **exigido ou proibido** conforme o país; **registro** em vários |
| **Número de origem aleatório (pool)** | O serviço escolhe | Padrão em alguns países |

| Aspecto | Detalhe |
|---|---|
| **Regras por país** | Cada país define **tipos permitidos**, **registro prévio**, **templates**, **horários** e **conteúdo** |
| **Brasil** | Em geral, **sender ID e registro** são requeridos conforme a rota/operadora; confirme as regras vigentes |
| **EUA** | **10DLC** (registro de marca e campanha) para long codes de aplicações; **toll-free verification**; **short code** |
| **Prazos** | Registros podem levar **dias a semanas**; **planeje antes do lançamento** |

> [!warning] Sem registro, o SMS pode ser bloqueado
> Em muitos países (e nos EUA para long codes comerciais), **mensagens sem registro/identidade adequada** são **filtradas ou bloqueadas** pelas operadoras. **Comece o registro cedo**, com **antecedência** ao lançamento.

### SMS sandbox

Contas novas ficam em **sandbox de SMS**:

| Característica | Detalhe |
|---|---|
| **Destinos** | Só **números verificados** (até 10) |
| **Limites** | Baixos |
| **Saída** | **Solicitar a saída do sandbox** (via suporte/console) para produção |
| **Dica** | Peça a saída **antes** de testar em escala |

### Limites e gasto

| Configuração | Função |
|---|---|
| **Limite de gasto mensal de SMS** (`MonthlySpendLimit`) | **Teto** em USD; ao atingi-lo, o envio é **bloqueado** (proteção contra abuso) |
| **Taxa de envio** | Mensagens/segundo por identidade/rota |
| **Tipo padrão** (`DefaultSMSType`) | Transactional/Promotional |
| **Sender ID padrão** (`DefaultSenderID`) | Remetente padrão |
| **Relatórios de uso** (`UsageReportS3Bucket`) | **Relatório diário** em S3 |
| **Logs de entrega** | `DeliveryStatusIAMRole`, `DeliveryStatusSuccessSamplingRate` |

```bash
aws sns set-sms-attributes --attributes '{
  "MonthlySpendLimit":"500",
  "DefaultSMSType":"Transactional",
  "DefaultSenderID":"MinhaLoja",
  "DeliveryStatusIAMRole":"arn:aws:iam::123456789012:role/SNSSMSLogs",
  "DeliveryStatusSuccessSamplingRate":"10",
  "UsageReportS3Bucket":"meu-bucket-relatorios-sms"
}'
aws sns get-sms-attributes
```

### Opt-out, opt-in e consentimento

| Prática | Detalhe |
|---|---|
| **Opt-out** | O usuário responde **STOP/PARE** (palavras-chave conforme o país): o número entra na **lista de opt-out** |
| **Listas de opt-out** | `list-phone-numbers-opted-out`, `check-if-phone-number-is-opted-out`, `opt-in-phone-number` (reativar a pedido do usuário) |
| **Consentimento** | Obtenha **consentimento explícito** antes de enviar (LGPD, TCPA, GDPR, regras locais) |
| **Mensagens obrigatórias** | Identificar a marca e informar **como cancelar** em marketing |
| **Horários** | Respeitar **janelas permitidas** (alguns países restringem horários) |
| **Conteúdo** | Evitar **conteúdo proibido** e **links encurtados suspeitos** |
| **Registros** | Guardar **prova de consentimento** e histórico |

### Fraude e abuso: *SMS pumping*

O **SMS pumping** (ou **toll fraud**) ocorre quando **atacantes** disparam **muitos pedidos de OTP** para **números premium** que **eles controlam**, gerando **receita para si** e **custo para você**.

| Defesa | Descrição |
|---|---|
| **Limite de gasto mensal** | Teto financeiro |
| **Rate limiting** por **usuário, IP e dispositivo** | Evita rajadas |
| **CAPTCHA/verificações** antes de enviar OTP | Barrar bots |
| **Allow-list de países** | Enviar **somente** para países onde há clientes |
| **Bloqueio de faixas/números de risco** | Listas de bloqueio |
| **Monitoramento** | Alarmes de **picos de envio** e de **custo** por país |
| **Detecção de anomalias** | Padrões (muitos números sequenciais, taxa de conversão do OTP baixa) |
| **Proteção do SNS** | **Regras de proteção de SMS** (*SMS protect*), quando disponíveis (confirme em End User Messaging) |
| **Alternativas ao SMS** | **App authenticator/TOTP**, **passkeys**, **push** |

> [!warning] OTP por SMS é um alvo de fraude
> **Todo endpoint** que **envia SMS sem autenticação** é um **vetor de abuso**. Combine **limites**, **CAPTCHA**, **filtros por país** e **alarmes de custo**. Se possível, **prefira autenticadores (TOTP) ou passkeys**.

## Push móvel

### Arquitetura

```
 App no celular ──(registra no APNs/FCM)──► recebe DEVICE TOKEN
        │
        └─► seu backend ──► SNS: CreatePlatformEndpoint(token, PlatformApplication) ──► ENDPOINT ARN
                                   │
 Publicador ─► SNS ─► (tópico com assinatura "application" OU Publish direto ao endpoint)
                                   │
                                   ▼
                        APNs (iOS) / FCM (Android) / ... ──► dispositivo
```

| Conceito | Descrição |
|---|---|
| **Platform application** | Configuração por plataforma, com **credenciais** (APNs: **chave/certificado**; FCM: **credenciais do projeto/HTTP v1**) |
| **Platform endpoint** | **Um dispositivo** (token) registrado em uma platform application |
| **Plataformas** | **APNs** (iOS/macOS), **APNs Sandbox**, **FCM** (Android/iOS via Firebase), **ADM** (Amazon), **Baidu**, **WNS/MPNS** (Windows) |
| **Publicação** | Direta (`TargetArn` = endpoint) ou por **tópico** (assinar endpoints) |
| **`MessageStructure: json`** | **Payload por plataforma** (formato diferente em APNs e FCM) |
| **Atributos do endpoint** | `Token`, `Enabled`, `CustomUserData` |

```bash
# Cria a platform application FCM
aws sns create-platform-application --name MeuApp-FCM --platform GCM \
  --attributes PlatformCredential=<credencial-fcm>

# Registra um dispositivo (token)
aws sns create-platform-endpoint \
  --platform-application-arn arn:aws:sns:us-east-1:123456789012:app/GCM/MeuApp-FCM \
  --token <token-do-dispositivo> --custom-user-data "usuario=123"

# Publica push com payload por plataforma
aws sns publish --target-arn <endpoint-arn> --message-structure json --message '{
  "default":"Seu pedido foi enviado",
  "GCM":"{\"notification\":{\"title\":\"Pedido enviado\",\"body\":\"Chega amanhã\"},\"data\":{\"pedido\":\"999\"}}",
  "APNS":"{\"aps\":{\"alert\":{\"title\":\"Pedido enviado\",\"body\":\"Chega amanhã\"},\"sound\":\"default\"},\"pedido\":\"999\"}"
}'
```

### Gestão de tokens (o ponto crítico)

| Problema | Descrição | Solução |
|---|---|---|
| **Tokens mudam** | O sistema operacional **renova** tokens (reinstalação, atualização) | App **reenvia o token** ao backend a cada abertura; **atualize** o endpoint |
| **Endpoint desabilitado** | O APNs/FCM informa **token inválido**; SNS marca `Enabled=false` | **Remover/atualizar** o endpoint; tratar eventos de **falha** |
| **Duplicação de endpoints** | Registrar o mesmo token várias vezes | `CreatePlatformEndpoint` é **idempotente por token** (retorna o existente), mas com **atributos diferentes** gera **erro**: trate |
| **Muitos endpoints** | Um por **dispositivo** (e usuário com vários dispositivos) | Mapear **usuário → N endpoints**; limpeza periódica |
| **Segmentação** | SNS não segmenta por perfil | Usar **tópicos por segmento** ou **Pinpoint** |
| **Credenciais expiradas** | Certificados/chaves APNs **expiram** | Renovar e **atualizar** a platform application |

> [!tip] Eventos de falha de endpoint
> Configure **`EventEndpointDeleted`, `EventEndpointUpdated`, `EventDeliveryFailure`** na platform application (tópico de eventos) para **limpar tokens inválidos** automaticamente e **economizar** envios inúteis.

### Limitações do push via SNS

| Limitação | Alternativa |
|---|---|
| **Sem segmentação/jornadas** | **Amazon Pinpoint / End User Messaging** |
| **Sem testes A/B, agendamento avançado, analytics de engajamento** | Pinpoint ou ferramentas de marketing |
| **Gerenciar tokens manualmente** | Pinpoint gerencia endpoints e segmentos |
| **Notificações silenciosas e dados** | Suportado via payload (`content-available`, `data`) |
| **Limite de payload** | **~4 KB** (APNs/FCM) |

## E-mail com SNS

| Aspecto | Detalhe |
|---|---|
| **Protocolos** | **`email`** (texto) e **`email-json`** (JSON com metadados) |
| **Confirmação** | O destinatário **clica** no link; sem isso, **nada é entregue** |
| **Remetente** | Endereço **do SNS** (`no-reply@sns.amazonaws.com`): **sem personalização de domínio** |
| **Formato** | **Texto simples** (sem HTML) |
| **Volume** | Baixo; **sem métricas de bounce/complaint** detalhadas |
| **Uso ideal** | **Alertas operacionais internos** (CloudWatch Alarms, Budgets, deploys) |
| **Não use para** | **E-mail transacional/marketing** ao cliente final |

> [!warning] Para e-mail ao cliente, use o SES
> O **Amazon SES** oferece **domínio próprio** (SPF/DKIM/DMARC), **HTML**, **templates**, **métricas de entrega**, **gestão de bounces e reclamações** e **alto volume**. Use **SNS apenas** como **mecanismo de notificação de eventos do SES** (bounces, entregas), não como motor de e-mail.

## SNS A2P vs SES vs Pinpoint/End User Messaging vs Cognito

| Critério | **SNS** | **Amazon SES** | **Pinpoint / End User Messaging** | **Cognito (MFA/verificação)** |
|---|---|---|---|---|
| **Foco** | **Notificações simples** multicanal | **E-mail** em escala | **Comunicação com clientes**: SMS, push, e-mail, voz, in-app | **Autenticação** (OTP por SMS/e-mail) |
| **SMS** | Sim (transacional/promocional) | Não | **Sim**, com **números dedicados**, **proteção contra fraude**, registro | Usa SNS/End User Messaging para SMS |
| **Push** | Sim (manual por endpoint) | Não | **Sim**, com **segmentos e campanhas** | Não |
| **E-mail** | Básico (texto) | **Completo** | Via SES | Via SES |
| **Segmentação/jornadas/analytics** | Não | Limitado | **Sim** (campanhas, jornadas, A/B, analytics) | Não |
| **Ideal para** | **Alertas e avisos** de sistema; OTP simples | **E-mail transacional e marketing** | **Engajamento e marketing multicanal** | **Login e MFA** de usuários |

```
 Alerta operacional para a equipe (e-mail/SMS) a partir de um alarme?          ─► SNS
 E-mail de confirmação de pedido com a identidade da marca, em escala?          ─► SES
 Campanha de push/SMS segmentada, jornadas e medição de resultados?             ─► Pinpoint / End User Messaging
 Código de verificação no login/cadastro de usuários?                           ─► Cognito (ou SNS/End User Messaging com proteções)
 Notificar um sistema (A2A)?                                                    ─► SNS + SQS/Lambda
```

> [!info] AWS End User Messaging
> A AWS vem **reorganizando** os serviços de mensageria ao cliente sob **AWS End User Messaging** (SMS, voz, push, WhatsApp, entre outros), e **descontinuando partes do Pinpoint**. **Confirme o estado atual** dos serviços e **planeje migrações** conforme a documentação vigente.

## Segurança e privacidade nos canais A2P

| Tema | Prática |
|---|---|
| **Dados pessoais** (telefone, e-mail, token) | **Minimizar**; **criptografar**; **retenção limitada** |
| **LGPD/GDPR** | Base legal, **consentimento**, **direitos do titular** (exclusão de tokens/números) |
| **Conteúdo de SMS** | **Texto simples, sem criptografia ponta a ponta**: **nunca** enviar **senhas, dados financeiros completos, dados sensíveis** |
| **OTP** | **Curta validade**, **uso único**, **limite de tentativas** |
| **Push** | **Evitar dados sensíveis** no corpo (podem aparecer na tela bloqueada) |
| **IAM** | **Publicar** direto a `PhoneNumber` é **sensível**: restringir quem pode (`sns:Publish` sem `TopicArn`) |
| **Auditoria** | CloudTrail (`Publish`), logs de SMS, relatórios de uso |
| **Custos** | **Alarmes** de gasto e por país |

```json
{
  "Sid": "NegarSMSDiretoExcetoServicoDeAutenticacao",
  "Effect": "Deny",
  "Action": "sns:Publish",
  "Resource": "*",
  "Condition": {"Null": {"sns:Protocol": "false"}, "StringEquals": {"sns:Protocol": "sms"}}
}
```
(Exemplo ilustrativo: restrinja `sns:Publish` com `PhoneNumber` a **roles específicas**; verifique as condições suportadas na documentação.)

## Custos e controles

| Canal | Principais custos | Controles |
|---|---|---|
| **SMS** | **Por mensagem** (varia por país/operadora), **por segmento** (mensagens longas = mais segmentos), números dedicados/short code | **Limite mensal**, **allow-list de países**, mensagens curtas, monitoramento |
| **Push** | **Por milhão** de notificações (primeiras grátis) | Limpar tokens inválidos |
| **E-mail (SNS)** | Por 100 mil | Uso interno |
| **Logs e relatórios** | CloudWatch/S3 | Sampling |

| Dica | Efeito |
|---|---|
| **Mensagens SMS ≤ 160 caracteres GSM-7** (70 em Unicode) | **Um segmento** (mais barato) |
| **Evitar emojis/acentos** em SMS quando custo importa | Unicode reduz o limite por segmento |
| **Short links** (de domínio próprio) | Menos caracteres e melhor entregabilidade |
| **Alarmes de custo por país** | Detecta fraude cedo |

## Exemplo prático: OTP e alertas com proteção

1. **Cadastro/login** envia **OTP por SMS** via SNS (`Transactional`, sender ID registrado) **depois de CAPTCHA** e **limite de 3 envios/hora por usuário/IP/dispositivo**.
2. **Allow-list de países**: só o Brasil e países onde há clientes.
3. **Limite mensal de gasto** de **US$ 300** e alarmes de **custo por país** e **envios/min**.
4. **Opt-out** respeitado; consentimento registrado no cadastro.
5. Alertas operacionais usam **tópico SNS** com **e-mail** (equipe) e **SMS** (plantão) com **filtros** por severidade.
6. **Push** para clientes (pedido enviado) via **platform application** FCM/APNs, com **limpeza de tokens** por eventos de falha.
7. **E-mails transacionais** ao cliente saem do **SES**; eventos de bounce/complaint chegam por **SNS** para tratamento.
8. A equipe planeja **migrar campanhas** de push/SMS para **End User Messaging/Pinpoint**, onde há segmentação e métricas.

## Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| **SMS não entregue** | Sandbox, opt-out, país bloqueado, sem registro/identidade, limite de gasto | Sair do sandbox; checar opt-out; registro por país; limites |
| **SMS chega como "spam"/atrasa** | Rota Promotional; conteúdo suspeito; sem registro | Usar Transactional; registrar; revisar conteúdo |
| **`Spend limit reached`** | Teto mensal atingido | Investigar uso/fraude; ajustar com critério |
| **Pico de custo de SMS** | **Pumping** | Rate limit, CAPTCHA, allow-list de países, alarmes |
| **Push não chega** | Token inválido/expirado; credenciais da plataforma; app desinstalado | Atualizar tokens; renovar credenciais; limpar endpoints |
| **`Endpoint is disabled`** | Token marcado como inválido | Reabilitar (se válido) ou recriar |
| **Push formatado errado** | Payload não adequado à plataforma | `MessageStructure: json` com payload APNs/FCM corretos |
| **E-mail não chega** | Assinatura pendente; spam | Confirmar; usar SES para produção |
| **Mensagens SMS truncadas/dobradas** | Unicode e múltiplos segmentos | Reduzir tamanho; evitar caracteres especiais |
| **`InvalidParameter: PhoneNumber`** | Formato inválido | Usar **E.164** (`+55…`) |
| **Usuário não consegue reativar** | Opt-out | `opt-in-phone-number` a pedido do usuário (ou STOP/START) |

## Erros comuns e armadilhas

- **Lançar sem registrar** números/sender IDs exigidos pelo país.
- **Esquecer de sair do sandbox** de SMS.
- **Sem limites de gasto, rate limit e CAPTCHA** no envio de OTP.
- **Tokens de push nunca atualizados**, acumulando endpoints inválidos.
- **Dados sensíveis em SMS e push.**
- **Usar SNS e-mail** para comunicação ao cliente final.
- **Ignorar consentimento e opt-out** (risco regulatório).
- **Usar SNS para campanhas** que exigem segmentação e métricas.

## 🧩 Quiz de Fixação

1. Qual a diferença entre SMS Transactional e Promotional?
2. O que é SMS pumping e como mitigá-lo?
3. Por que gerenciar os tokens de dispositivo no push móvel?
4. Quando usar SES em vez de SNS para e-mail?
5. O que é o sandbox de SMS?
6. Qual formato de número é exigido para SMS?

**Respostas:**
1) Transactional tem maior prioridade e confiabilidade de entrega (OTP, alertas), com custo maior; Promotional é mais barato, com menor prioridade (marketing).
2) Fraude em que atacantes disparam muitos OTPs para números premium que controlam, gerando custo; mitiga-se com limite de gasto, rate limiting, CAPTCHA, allow-list de países e alarmes de custo.
3) Porque tokens mudam ou expiram; endpoints inválidos geram falhas e envios inúteis, e é preciso atualizá-los e removê-los com base em eventos de falha.
4) Para e-mail transacional ou marketing ao cliente final, com domínio próprio, HTML, templates, métricas e gestão de bounces e reclamações.
5) Um ambiente inicial de contas novas em que só se pode enviar SMS a números verificados e com limites baixos, até solicitar a saída para produção.
6) O formato E.164, como +5511999999999.
