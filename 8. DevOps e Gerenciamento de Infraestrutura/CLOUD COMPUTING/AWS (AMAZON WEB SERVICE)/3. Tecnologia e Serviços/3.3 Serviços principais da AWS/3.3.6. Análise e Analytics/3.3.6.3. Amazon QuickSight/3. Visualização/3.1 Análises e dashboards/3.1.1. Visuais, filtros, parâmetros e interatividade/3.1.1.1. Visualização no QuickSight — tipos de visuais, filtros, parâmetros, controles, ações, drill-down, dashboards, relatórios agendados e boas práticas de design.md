### Visualização no QuickSight — tipos de visuais, filtros, parâmetros, controles, ações, drill-down, dashboards, relatórios agendados e boas práticas de design

> [!warning] Aviso
> Tipos de visuais, opções de formatação, recursos de relatório (pixel-perfect, e-mail, alertas) e limites mudam. Os detalhes aqui são referências de estudo; confirme na documentação. As expressões **não foram executadas**.

Com os dados bem modelados, a etapa seguinte é **contar a história**: transformar **datasets** em **visuais** que **respondem a perguntas de negócio**, organizá-los em **análises** interativas e **publicá-los como dashboards**. No QuickSight, isso envolve **escolher o visual certo**, usar **filtros, parâmetros e controles** para dar **autonomia ao leitor**, configurar **ações** (drill-down, navegação, URLs), aplicar **formatação condicional** e seguir **princípios de design** que tornam o dashboard **claro e acionável**. Esta folha também cobre **relatórios agendados**, **alertas** e a **publicação**.

**Analogia:** os dados são **matéria-prima**; os visuais são **os instrumentos do painel de um avião**: cada um deve mostrar **a informação certa, no formato certo, na hora certa**. Um painel com 40 ponteiros iguais confunde o piloto; um painel **bem desenhado** mostra o essencial no topo, permite **detalhar** quando necessário e **acende um alerta** quando algo foge do normal.

## Análise e dashboard: o ciclo

```
 DATASET ──► ANÁLISE (autor)  ──► PUBLICAR ──► DASHBOARD (leitores)
              │ visuais, filtros,           │ somente leitura, interativo
              │ parâmetros, controles       │ alertas, e-mails, embedding
              └─ pode ter várias SHEETS (abas) e layouts diferentes
```

| Elemento | Descrição |
|---|---|
| **Análise** | Ambiente de **edição** com **sheets** (abas), **visuais**, **filtros**, **parâmetros**, **controles** e **ações** |
| **Sheet** | Uma "página" (interativa ou de relatório *pixel-perfect*) |
| **Visual** | Componente gráfico alimentado por **campos** (dimensões, medidas) |
| **Dashboard** | Cópia **publicada** da análise (com versões); leitores **filtram e exploram**, mas não editam |
| **Template** | Esqueleto de análise reutilizável (para promover entre contas) |

## Tipos de visuais

| Categoria | Visuais | Quando usar |
|---|---|---|
| **Comparação** | **Barras** (horizontal/vertical, empilhadas, 100%), **colunas agrupadas** | Comparar categorias |
| **Tendência no tempo** | **Linhas**, **áreas**, linhas com marcadores, **gráfico de colunas + linha** (combo) | Evolução e sazonalidade |
| **Composição** | **Rosca/pizza** (poucas categorias), **treemap**, **barras empilhadas** | Partes de um todo |
| **Distribuição** | **Histograma**, **box plot**, **dispersão (scatter)** | Dispersão e outliers |
| **Relacionamento** | **Dispersão**, **bolhas**, **mapa de calor (heat map)** | Correlação entre variáveis |
| **KPI e medidores** | **KPI** (valor + comparação), **gauge** (medidor), **donut com meta** | Indicadores-chave |
| **Tabelas** | **Tabela**, **tabela dinâmica (pivot)** | Detalhe e valores exatos |
| **Geográficos** | **Mapa de pontos**, **mapa preenchido (filled map)** | Dados com localização |
| **Fluxo e processos** | **Sankey**, **funil**, **waterfall (cascata)** | Fluxos, conversão, variações |
| **Texto e narrativa** | **Caixa de texto**, **insights automáticos**, **narrativas** | Contexto e explicação |
| **Outros** | **Word cloud**, **radar**, **visuais personalizados (custom visual content)**, **Python/R no Sagemaker via embed** | Casos específicos |

> [!tip] Escolha o visual pela pergunta, não pelo estilo
> | Pergunta | Visual |
> |---|---|
> | "Qual categoria vende mais?" | Barras ordenadas |
> | "Como evoluiu ao longo do ano?" | Linha |
> | "Qual a participação de cada canal?" | Barras 100% ou treemap (evite pizzas com muitas fatias) |
> | "Há relação entre preço e quantidade?" | Dispersão |
> | "Estamos acima da meta?" | KPI com comparação |
> | "Onde está o problema?" | Mapa de calor / tabela com formatação condicional |
> | "Como o total mudou de A para B?" | Waterfall |

### Campos e "field wells"

| Área do visual | O que recebe |
|---|---|
| **Eixo X / Categoria / Linhas** | **Dimensão** (texto, data) |
| **Valor / Medida** | **Medida** agregada (soma, média, contagem) |
| **Cor / Agrupar** | Dimensão para segmentar (série) |
| **Tamanho** | Medida (bolhas) |
| **Detalhe (tooltip)** | Campos extras na dica de ferramenta |
| **Ordenação** | Por campo/medida, crescente/decrescente |

```
 Barras: Eixo X = regiao ; Valor = sum(receita) ; Cor = canal ; Ordenar por Valor desc
 Linha:  Eixo X = mes (data agregada por mês) ; Valor = sum(receita) ; Cor = ano
 KPI:    Valor = sum(receita) ; Comparação = mesmo período do ano anterior
```

## Filtros

| Tipo de filtro | Escopo | Exemplo |
|---|---|---|
| **Filtro de visual** | Um visual | Mostrar só o top 10 produtos |
| **Filtro de sheet** | Toda a sheet | Apenas região = Sul |
| **Filtro de análise (todas as sheets)** | Análise inteira | Ano ≥ 2025 |
| **Top/Bottom N** | Limita ao N maiores/menores | Top 5 clientes por receita |
| **Filtro de data** | Intervalos, relativos (últimos 30 dias, mês atual) | Janela dinâmica |
| **Filtro de texto** | Contém, começa com, igual | Produto contém "Pro" |
| **Filtro numérico** | Maior que, entre | Receita > 1000 |
| **Filtro condicional** | Por condição sobre medida | Clientes com margem < 10% |
| **Filtros "aplicar a"** | Define quais visuais/sheets recebem | Escopo seletivo |

| Boa prática | Motivo |
|---|---|
| **Filtrar no dataset** o que é **permanente** | Reduz dados e custo |
| **Filtros de sheet** para recortes padrão | Clareza |
| **Preferir filtros relativos de data** | Dashboard "sempre atual" |
| **Evitar excesso de filtros ativos escondidos** | O leitor deve saber o que está filtrado |
| **Mostrar o contexto do filtro** (texto/título dinâmico) | Evita interpretação errada |

## Parâmetros e controles

**Parâmetros** são **valores nomeados** (texto, número, data) que o autor **define** e o leitor **muda por meio de controles**, influenciando **filtros, campos calculados e títulos**.

| Elemento | Função |
|---|---|
| **Parâmetro** | Armazena um valor (ex.: `p_metrica`, `p_data_inicial`, `p_meta`) |
| **Controle** | **Interface** para o leitor alterar: lista suspensa, botões, caixa de texto, slider, seletor de datas |
| **Controles em cascata** | Uma seleção filtra as opções do próximo (país → estado → cidade) |
| **Valores padrão/dinâmicos** | Padrão fixo ou vindos de um campo |
| **Uso em cálculos** | `${p_meta}` dentro de campos calculados e títulos |

```text
# Seletor de métrica: o leitor escolhe "Receita", "Margem" ou "Pedidos"
metrica_escolhida = ifelse(${p_metrica} = 'Receita', sum({receita}),
                    ifelse(${p_metrica} = 'Margem',  sum({margem}), count({pedido_id})))

# Título dinâmico
"Faturamento de " + ${p_regiao} + " em " + formatDate(${p_data_inicial}, 'MMM yyyy')

# Filtro dinâmico: receita acima da meta digitada pelo usuário
{receita} >= ${p_meta}
```

> [!tip] Um dashboard, várias perguntas
> Com **controles de parâmetro** (ex.: trocar métrica, agrupar por região/canal), **um só visual** responde a muitas perguntas, reduzindo a **proliferação de gráficos** e dando **autoatendimento**.

## Ações (interatividade)

| Ação | Efeito |
|---|---|
| **Filtrar visuais ao clicar (*filter action*)** | Clicar em um item filtra os demais visuais (**filtro cruzado**) |
| **Navegar para outra sheet** | Salta para outra aba, opcionalmente com valores passados |
| **Navegar para outra análise/dashboard** | Detalhamento em outro painel |
| **Abrir URL** | Abre sistemas externos (CRM, tickets) com parâmetros do campo |
| **Enviar e-mail** | Link `mailto:` com campos |
| **Drill-down e drill-up** | Navegar por **hierarquias** (ano → trimestre → mês → dia) |
| **Destacar (*highlight*)** | Destaca elementos relacionados |
| **Insights e "explicar"** | Sugere fatores que explicam uma variação |

```
 Hierarquia: pais > estado > cidade
 Clicar em "Brasil" → drill-down para estados → clicar em "SP" → cidades
 Ação de URL: https://crm.empresa.com/clientes/${cliente_id}
```

## Formatação condicional e design

| Recurso | Uso |
|---|---|
| **Formatação condicional** | Cores, ícones e fundos por regra (ex.: vermelho se margem < 10%) |
| **Linhas de referência** | Meta, média, limites |
| **Anotações e rótulos** | Contexto e destaques |
| **Eixos e formatos** | Moeda, percentuais, casas decimais, abreviações (K, M) |
| **Temas** | Paleta, fontes e estilos corporativos |
| **Layouts: *Tiled*, *Free-form*, *Classic*** | Organização automática ou livre dos visuais |
| **Tooltips personalizados** | Informação adicional ao passar o mouse |
| **Responsivo (mobile)** | Layout para telas pequenas |

### Princípios de design de dashboards

| Princípio | Aplicação |
|---|---|
| **Responda a uma pergunta por dashboard** | "Como estão as vendas?", não "tudo sobre tudo" |
| **Pirâmide invertida** | **KPIs no topo**, tendências no meio, detalhes embaixo |
| **Poucos visuais** (6 a 10 por página) | Menos ruído |
| **Hierarquia visual** | Tamanho e posição indicam importância |
| **Cores com propósito** | Poucas cores; vermelho/verde só para status (e considere daltonismo) |
| **Rótulos claros e títulos informativos** | "Receita caiu 12% em out." > "Gráfico 3" |
| **Ordenar categorias** | Por valor, não alfabética |
| **Eixos honestos** | Evitar truncar eixos de barras |
| **Consistência** | Mesmas cores/formatos para as mesmas medidas |
| **Evitar 3D e pizzas complexas** | Distorcem a leitura |
| **Acessibilidade** | Contraste, texto alternativo, navegação por teclado |

```
 ┌────────────── Dashboard de Vendas ──────────────┐
 │ [KPI Receita] [KPI Margem %] [KPI Pedidos] [Meta]│  ← o que importa primeiro
 │ [Linha: receita por mês, vs ano anterior       ]│  ← tendência
 │ [Barras: top 10 produtos] [Mapa: por região    ]│  ← composição/geografia
 │ [Tabela detalhada com formatação condicional   ]│  ← detalhe
 │  Controles: período | região | canal            │
 └──────────────────────────────────────────────────┘
```

> [!warning] Dashboards "enciclopédia" não são lidos
> Páginas com dezenas de gráficos e filtros escondidos **ninguém interpreta**. Se há muito conteúdo, **divida em sheets** por tema ou público.

## Publicação, versões e compartilhamento

| Ação | Descrição |
|---|---|
| **Publicar dashboard** | Cria uma **versão** somente leitura da análise |
| **Versões** | Histórico; é possível **reverter** para uma versão anterior |
| **Compartilhar** | Com **usuários e grupos**, como **leitor** ou **co-proprietário** |
| **Opções do leitor** | Permitir **baixar dados (CSV)**, **exportar PDF**, **ad hoc filtering**, **drill**, **fazer anotações** |
| **Pastas (folders)** | Organizar e herdar permissões |
| **Link público (anonymous)** | Disponível só via **embedding** configurado (não é link aberto) |
| **Favoritos e pesquisa** | Facilita a descoberta |

## Alertas, e-mails e relatórios

| Recurso | Descrição |
|---|---|
| **Alertas por limite (threshold alerts)** | Notifica quando um **KPI/visual** cruza um valor (ex.: receita diária < meta) |
| **Alertas de anomalias** | Notificações de **ML Insights** (detecção de anomalias) |
| **E-mails agendados** | **Resumo do dashboard** (imagem + link) enviado por e-mail, diário/semanal/mensal |
| **Relatórios pixel-perfect (paginated)** | **Layout fixo** (PDF/CSV) para **impressão e distribuição em lote**, com **burst** por destinatário |
| **Exportação** | PDF, imagem, CSV, Excel (conforme permissão) |
| **Integração** | E-mail, SNS, Slack (via automação) |

```bash
# Gera um PDF de um dashboard por API (exemplo de fluxo de exportação)
aws quicksight start-dashboard-snapshot-job --aws-account-id 123456789012 \
  --dashboard-id vendas --snapshot-job-id snap-1 \
  --user-configuration file://user.json --snapshot-configuration file://snap.json
```

| Relatórios interativos (dashboards) | Relatórios paginados (pixel-perfect) |
|---|---|
| Exploração, filtros, drill | **Layout fixo**, página a página |
| Leitura na tela | **Impressão, PDF, e-mail** |
| Autoatendimento | Documentos **formais e recorrentes** (extratos, faturas, relatórios regulatórios) |

## Insights automáticos (resumo)

O QuickSight oferece **insights gerados por ML** diretamente nos visuais (detalhados em outra folha): **detecção de anomalias**, **previsões (forecast)**, **narrativas automáticas** ("a receita subiu 8% impulsionada por…"), **principais contribuintes** e **perguntas em linguagem natural (Q)**.

## Desempenho do dashboard

| Prática | Efeito |
|---|---|
| **SPICE** em vez de Direct Query | Respostas em segundos |
| **Menos visuais por sheet** | Menos consultas simultâneas |
| **Filtros no dataset** | Menos linhas |
| **Pré-agregar** campos pesados | Evita cálculos caros em tempo de consulta |
| **Evitar campos calculados muito complexos** em tabelas grandes | CPU |
| **Limitar linhas em tabelas** (paginação) | Renderização |
| **Evitar muitos controles em cascata** sobre grandes dimensões | Latência |
| **Usar o "perfil de desempenho"** (query/render time) | Achar visuais lentos |

## Exemplo prático: dashboard executivo de vendas

1. **Dataset** certificado `vendas` (SPICE, refresh por evento).
2. **Sheet 1 — Visão geral**: 4 KPIs (receita, margem %, pedidos, ticket médio) com **comparação ao ano anterior**; linha de receita por mês; barras dos 10 principais produtos; mapa por região.
3. **Controles**: período (data relativa), região, canal (em cascata) e um **seletor de métrica** (parâmetro).
4. **Formatação condicional**: margem < 10% em vermelho; meta como linha de referência.
5. **Ações**: clicar em uma região **filtra** os demais visuais; **drill-down** de ano → mês → dia; **URL** para abrir o cliente no CRM.
6. **Sheet 2 — Detalhe**: tabela dinâmica com valores exatos.
7. **Alerta** quando a receita do dia cair mais de 20%; **e-mail semanal** para a diretoria; **relatório pixel-perfect** mensal em PDF.
8. Publicado e compartilhado com o **grupo Comercial** (leitores).

## Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| Visual **vazio** | Filtros muito restritivos, tipo de dado incorreto, RLS | Revisar filtros, tipos e regras de segurança |
| **Totais diferentes** entre visuais | Agregações/filtros distintos ou fan-out | Padronizar cálculos no dataset; LAC |
| Controle não filtra um visual | Escopo "aplicar a" não inclui o visual | Ajustar escopo do controle |
| **Dashboard lento** | Direct Query, muitos visuais, cálculos pesados | SPICE; reduzir visuais; pré-agregar |
| Datas em ordem errada | Campo como texto | Converter para data; ordenar por data |
| **Percentuais somam ≠ 100%** | Arredondamento ou agregação por linha | Calcular pelo total correto (`sumOver`) |
| Drill-down não funciona | Hierarquia não definida | Criar hierarquia no dataset/análise |
| Leitor vê dados que não deveria | Sem RLS/CLS | Aplicar segurança no dataset |
| E-mail agendado não chega | Usuário sem e-mail/permissão | Verificar assinatura e acesso |
| Cores confusas | Paleta inconsistente | Usar tema padronizado |
| Mapa sem pontos | Campo geográfico não classificado | Definir tipo geográfico no dataset |

## Erros comuns e armadilhas

- **Dashboards gigantes** com dezenas de visuais.
- **Pizzas** com muitas fatias e **gráficos 3D**.
- **Eixos truncados** que exageram diferenças.
- **Filtros escondidos** que deixam o leitor sem saber o que vê.
- **Cálculos diferentes** em cada análise.
- **Não usar Top N** e renderizar milhares de categorias.
- **Esquecer controles de data relativos**, gerando dashboards "congelados".
- **Misturar dashboard operacional e relatório formal** (use pixel-perfect para o segundo).

## 🧩 Quiz de Fixação

1. Qual a diferença entre análise e dashboard?
2. Para que servem parâmetros e controles?
3. Qual visual usar para mostrar a evolução ao longo do tempo?
4. O que é uma ação de filtro cruzado?
5. Quando usar relatórios pixel-perfect?
6. Que princípios tornam um dashboard mais claro?

**Respostas:**
1) A análise é o ambiente de criação do autor; o dashboard é a versão publicada, somente leitura e interativa, compartilhada com os leitores.
2) O parâmetro guarda um valor usado em filtros e cálculos; o controle é a interface com que o leitor o altera, permitindo autoatendimento.
3) Gráfico de linhas (ou áreas/combo).
4) Clicar em um elemento de um visual filtra os demais visuais do dashboard.
5) Para documentos de layout fixo e distribuição formal em lote, como PDFs recorrentes, extratos e relatórios regulatórios.
6) Responder a uma pergunta, KPIs no topo, poucos visuais, cores com propósito, títulos informativos, categorias ordenadas, eixos honestos e consistência.
