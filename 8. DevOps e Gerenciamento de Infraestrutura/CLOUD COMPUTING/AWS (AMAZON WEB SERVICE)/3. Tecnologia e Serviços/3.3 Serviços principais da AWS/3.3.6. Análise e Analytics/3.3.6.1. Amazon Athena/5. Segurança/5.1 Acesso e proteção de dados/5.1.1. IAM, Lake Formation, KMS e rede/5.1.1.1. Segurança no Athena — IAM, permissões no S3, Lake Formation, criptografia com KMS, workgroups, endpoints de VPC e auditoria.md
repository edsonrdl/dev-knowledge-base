### Segurança no Athena — IAM, permissões no S3, Lake Formation, criptografia com KMS, workgroups, endpoints de VPC e auditoria

> [!warning] Aviso
> Modelos de permissão (IAM vs Lake Formation), nomes de ações, opções de criptografia e comportamentos de acesso entre contas mudam. Os exemplos aqui são referências de estudo; confirme na documentação. As políticas e comandos **não foram executados**.

O Athena **não guarda dados próprios**: ele **lê o S3** e **escreve resultados no S3**, usando **metadados do Glue**. Por isso, **segurança no Athena é segurança em camadas** que se cruzam: **quem pode executar consultas** (IAM do Athena), **quem pode ler os dados** (S3 e KMS), **quem pode ver tabelas, colunas e linhas** (Glue e **Lake Formation**), **onde os resultados ficam** (bucket de resultados e criptografia), **por onde o tráfego passa** (VPC endpoints) e **como tudo é auditado** (CloudTrail e workgroups). Esta folha explica **cada camada** e como combiná-las para **dar acesso certo a cada pessoa**.

**Analogia:** o Athena é um **leitor de arquivos com acesso a um cofre (S3)**. Para ler um documento, é preciso **três chaves**: o **crachá para entrar na sala de leitura** (permissão do Athena), a **chave do cofre** (permissão do S3 e da chave KMS) e a **autorização do catálogo** (Glue/Lake Formation), que diz **quais gavetas, colunas e linhas** podem ser vistas. Faltou uma chave? A leitura falha.

## As camadas de controle

```
 Usuário/aplicação
      │
      ├─1─► IAM: pode chamar athena:StartQueryExecution neste workgroup?
      │
      ├─2─► Glue Data Catalog / Lake Formation: pode ver este banco, tabela, coluna, linha?
      │
      ├─3─► S3: pode ler os objetos de dados (s3:GetObject / s3:ListBucket)?
      │
      ├─4─► KMS: pode descriptografar os dados (kms:Decrypt)?
      │
      └─5─► S3 de resultados: pode gravar o resultado (e criptografá-lo)?
```

| Camada | O que controla | Ferramenta |
|---|---|---|
| **1. Execução de consultas** | Quem usa o Athena e em qual workgroup | **IAM** (ações `athena:*`) |
| **2. Catálogo e dados lógicos** | Acesso a bancos, tabelas, **colunas e linhas** | **Glue** + **Lake Formation** |
| **3. Armazenamento** | Leitura dos arquivos de dados | **Políticas do S3/IAM** |
| **4. Criptografia** | Descriptografia dos dados | **KMS** |
| **5. Resultados** | Onde e como os resultados são gravados | **Workgroup** + S3 + KMS |
| **6. Rede** | Caminho do tráfego | **VPC endpoints**, SGs |
| **7. Auditoria** | Quem consultou o quê | **CloudTrail**, métricas de workgroup |

## Modelo 1: controle por IAM e S3

No modelo **clássico**, o acesso é decidido pelas **políticas IAM** (do usuário) e do **S3**.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ExecutarConsultasNoWorkgroup",
      "Effect": "Allow",
      "Action": ["athena:StartQueryExecution","athena:GetQueryExecution","athena:GetQueryResults",
                 "athena:StopQueryExecution","athena:GetWorkGroup"],
      "Resource": "arn:aws:athena:us-east-1:123456789012:workgroup/analistas"
    },
    {
      "Sid": "LerCatalogo",
      "Effect": "Allow",
      "Action": ["glue:GetDatabase","glue:GetTable","glue:GetTables","glue:GetPartitions"],
      "Resource": [
        "arn:aws:glue:us-east-1:123456789012:catalog",
        "arn:aws:glue:us-east-1:123456789012:database/lake",
        "arn:aws:glue:us-east-1:123456789012:table/lake/*"
      ]
    },
    {
      "Sid": "LerDados",
      "Effect": "Allow",
      "Action": ["s3:GetObject","s3:ListBucket"],
      "Resource": ["arn:aws:s3:::meu-datalake","arn:aws:s3:::meu-datalake/curado/*"]
    },
    {
      "Sid": "GravarResultados",
      "Effect": "Allow",
      "Action": ["s3:PutObject","s3:GetObject","s3:ListBucket","s3:GetBucketLocation","s3:AbortMultipartUpload"],
      "Resource": ["arn:aws:s3:::meu-bucket-resultados","arn:aws:s3:::meu-bucket-resultados/analistas/*"]
    }
  ]
}
```

| Limitação do modelo IAM | Implicação |
|---|---|
| **Granularidade grossa** | Controle por bucket/prefixo/tabela, **não por coluna ou linha** |
| **Muitas políticas** | Difícil de manter em escala |
| **Acesso entre contas** | Exige políticas no bucket e na chave |
| **Views** | Quem consulta a view precisa de acesso às tabelas base |

> [!tip] O prefixo S3 é a unidade de controle
> No modelo IAM, **organize o data lake por prefixos** (por domínio, sensibilidade, tenant) para poder conceder acesso por prefixo. Misturar dados sensíveis e públicos no mesmo prefixo inviabiliza controle fino.

## Modelo 2: AWS Lake Formation

O **Lake Formation** adiciona uma **camada de permissões centralizada** sobre o Glue Data Catalog e o S3, com **controle fino**.

| Recurso | Descrição |
|---|---|
| **Permissões em banco/tabela/coluna** | `SELECT` apenas em colunas específicas |
| **Filtros de linha** (*row filters*) | Cada usuário vê só **certas linhas** (ex.: sua região) |
| **Células** (*cell-level*) | Combinação de colunas e linhas |
| **Tags LF-Tags (ABAC)** | Permissões por **tags** (sensibilidade, domínio), escaláveis |
| **Registro de locais do S3** | O LF **acessa o S3 em nome** do usuário (credenciais temporárias) |
| **Compartilhamento entre contas** | Concede acesso a bancos/tabelas para outras contas/organização |
| **Auditoria** | Registra quem acessou quais recursos |
| **Tabelas governadas / Iceberg** | Integração com formatos transacionais |

```
 Usuário (Athena) ──► Lake Formation ──► verifica permissões (coluna/linha)
                                │
                                └─► entrega credenciais temporárias de acesso ao S3 (só os dados permitidos)
```

```bash
# Concede SELECT em colunas específicas (Lake Formation)
aws lakeformation grant-permissions \
  --principal DataLakePrincipalIdentifier=arn:aws:iam::123456789012:role/Analistas \
  --permissions SELECT \
  --resource '{"TableWithColumns":{"DatabaseName":"lake","Name":"clientes",
               "ColumnNames":["cliente_id","pais","segmento"]}}'

# Filtro de linhas: analista só vê o Brasil
aws lakeformation create-data-cells-filter --table-data '{
  "TableCatalogId":"123456789012","DatabaseName":"lake","TableName":"clientes",
  "Name":"somente-brasil",
  "RowFilter":{"FilterExpression":"pais = '\''BR'\''"},
  "ColumnWildcard":{}}'
```

| IAM puro | Lake Formation |
|---|---|
| Controle por bucket/prefixo | Controle por **banco, tabela, coluna, linha, célula** |
| Descentralizado | **Centralizado** |
| Sem ABAC nativo de dados | **LF-Tags** (ABAC) |
| Difícil de escalar | Escala para muitos domínios |
| Menos recursos de governança | **Compartilhamento e auditoria** |

> [!warning] Lake Formation e IAM se combinam
> Com o Lake Formation habilitado, o usuário precisa **das duas coisas**: permissão **do Lake Formation** nos recursos e permissões **IAM** básicas (para chamar Athena/Glue). Um erro comum é **conceder no LF** e esquecer o IAM do Athena (ou o inverso). Também é preciso **registrar a localização S3** no Lake Formation e configurar o **modo de controle** do banco (híbrido ou somente LF).

## Criptografia

| Ponto | Opções |
|---|---|
| **Dados no S3** (em repouso) | **SSE-S3**, **SSE-KMS** (chave gerenciada pela AWS ou do cliente) ou **CSE-KMS** |
| **Resultados do Athena** | Configurado no **workgroup** ou por consulta: `SSE_S3`, `SSE_KMS`, `CSE_KMS` |
| **Metadados no Glue** | Criptografia do catálogo com KMS |
| **Em trânsito** | **TLS** entre cliente, Athena e S3 |
| **Resultados em cache/reuso** | Seguem a criptografia configurada |

```bash
aws athena update-work-group --work-group analistas \
  --configuration-updates '{
    "ResultConfigurationUpdates": {
      "OutputLocation": "s3://meu-bucket-resultados/analistas/",
      "EncryptionConfiguration": {"EncryptionOption":"SSE_KMS","KmsKey":"arn:aws:kms:us-east-1:123456789012:key/abc-123"}
    },
    "EnforceWorkGroupConfiguration": true
  }'
```

| Cuidado com KMS | Motivo |
|---|---|
| **Política da chave** deve permitir `kms:Decrypt` e `kms:GenerateDataKey` aos usuários/roles | Sem isso: `AccessDenied` ao ler/gravar |
| **Chaves entre contas** | Exige política da chave **e** do IAM no consumidor |
| **Custo de requisições KMS** | Muitos objetos pequenos geram muitas chamadas; use **S3 Bucket Keys** |
| **Chaves distintas por sensibilidade** | Separação de acesso |

## Workgroups como fronteira de segurança

| Controle | Efeito |
|---|---|
| **Imposição de configurações** (`EnforceWorkGroupConfiguration`) | Usuários **não podem** mudar local de resultados/criptografia |
| **Local de resultados por workgroup** | Isola resultados entre times |
| **Permissões IAM por workgroup** | `athena:*` restrito ao ARN do workgroup |
| **Limites de dados e métricas** | Controle de custo e comportamento |
| **Tags** | ABAC (`aws:ResourceTag`) e rateio |
| **Workgroup por sensibilidade** | `pii` com políticas e auditoria mais rígidas |

> [!tip] Resultados são dados
> O **bucket de resultados** contém **cópias dos dados consultados** (inclusive de colunas sensíveis). Trate-o como **dado sensível**: criptografia, acesso restrito, **ciclo de vida** (expiração) e proibição de acesso público.

## Rede e acesso privado

| Mecanismo | Função |
|---|---|
| **VPC endpoint de interface (PrivateLink) para Athena** | Chamadas de API sem passar pela Internet |
| **VPC endpoint de gateway para S3** | Leitura/gravação de dados sem NAT |
| **VPC endpoint para Glue, KMS, STS, Lake Formation** | Fluxo completo privado |
| **Políticas de endpoint** | Restringem quais buckets/contas podem ser acessados |
| **Conexões JDBC/ODBC** | Via endpoint privado ou rede corporativa (VPN/Direct Connect) |
| **Bloqueio de acesso público ao S3** | Defesa em profundidade |

```json
{
  "Sid": "SomenteBucketsDaOrganizacao",
  "Effect": "Allow",
  "Principal": "*",
  "Action": ["s3:GetObject","s3:ListBucket"],
  "Resource": ["arn:aws:s3:::meu-datalake","arn:aws:s3:::meu-datalake/*"],
  "Condition": {"StringEquals": {"aws:PrincipalOrgID": "o-abc123xyz"}}
}
```

## Acesso entre contas

| Cenário | Solução |
|---|---|
| **Consultar dados de outra conta** | Política do bucket + chave KMS permitindo a role consumidora; **ou** compartilhamento via **Lake Formation** |
| **Catálogo compartilhado** | Recursos do Glue compartilhados (RAM/Lake Formation) com **resource links** |
| **Organização com vários times** | **Conta de data lake** (produtor) + **contas de consumo** com LF |
| **Resultados de consultas** | Gravados no S3 **da conta consumidora** |

```
 Conta PRODUTORA (data lake)  ──Lake Formation share──►  Conta CONSUMIDORA (analistas)
   S3 + Glue + KMS                                           Athena + workgroup + bucket de resultados
```

## Proteção de dados sensíveis

| Técnica | Uso |
|---|---|
| **Lake Formation (colunas e linhas)** | Ocultar PII de quem não precisa |
| **Mascaramento** | Views com `regexp_replace`/UDF de mascaramento |
| **Tokenização/pseudonimização** | Na ingestão (Glue/Lambda), preservando utilidade analítica |
| **Amazon Macie** | Descobrir dados sensíveis no S3 |
| **Particionar por sensibilidade/tenant** | Controle por prefixo |
| **Retenção e exclusão** | Atender **LGPD** (direito ao esquecimento) com Iceberg `DELETE` |
| **Resultados efêmeros** | Ciclo de vida curto no bucket de resultados |

```sql
-- View que mascara CPF para analistas
CREATE VIEW lake.vw_clientes_analista AS
SELECT cliente_id,
       regexp_replace(cpf, '^(\d{3})\d{3}\d{3}(\d{2})$', '$1.***.***-$2') AS cpf_mascarado,
       pais, segmento
FROM lake.clientes;
```

## Auditoria e monitoramento

| Fonte | O que registra |
|---|---|
| **CloudTrail** | Chamadas do Athena (`StartQueryExecution`, `GetQueryResults`), do Glue e do Lake Formation |
| **Histórico de consultas do Athena** | Texto SQL, usuário, bytes escaneados, estado (limitado no tempo) |
| **Lake Formation (logs de acesso)** | Concessões e acessos a recursos |
| **S3 server access logs / CloudTrail data events** | Quais objetos foram lidos |
| **CloudWatch (métricas de workgroup)** | Volume, tempo, falhas |
| **EventBridge** | Eventos de mudança de estado de consultas |

```sql
-- CloudTrail: consultas do Athena por usuário nas últimas 24 h
SELECT useridentity.arn, count(*) AS consultas
FROM cloudtrail_logs
WHERE eventsource = 'athena.amazonaws.com' AND eventname = 'StartQueryExecution'
  AND year='2026' AND month='11' AND day='09'
GROUP BY useridentity.arn ORDER BY consultas DESC;
```

> [!tip] Registre o SQL
> O texto da consulta aparece em `requestParameters.queryString` no CloudTrail. É essencial para investigar **quem consultou dados sensíveis**, mas também pode conter **valores sensíveis** nos filtros; proteja o acesso aos logs.

## Modelo de acesso recomendado

| Perfil | Workgroup | Acesso a dados | Outros controles |
|---|---|---|---|
| **Analistas de negócio** | `analistas` | Camada **curada**, colunas sem PII (Lake Formation) | Limite de dados por consulta; resultados criptografados |
| **Cientistas de dados** | `ciencia` | Curada + amostras pseudonimizadas | Spark habilitado; capacidade controlada |
| **BI / QuickSight** | `bi` | Tabelas agregadas | Reuso de resultados; capacidade provisionada |
| **Engenharia (ETL)** | `etl` | Bruta → curada | Janelas e limites próprios |
| **Segurança/auditoria** | `auditoria` | Logs (CloudTrail, flow) | Somente leitura; retenção; acesso restrito |
| **Terceiros** | Conta separada | Compartilhamento por Lake Formation | Colunas/linhas limitadas |

## Exemplo prático: dados de clientes com PII

1. Os dados de clientes ficam em `s3://datalake/curado/clientes/` com **SSE-KMS** (chave dedicada).
2. O prefixo é **registrado no Lake Formation**; os usuários **perdem** acesso direto ao S3.
3. O grupo `Analistas` recebe `SELECT` **só nas colunas não sensíveis** e um **filtro de linha** por região.
4. O grupo `Privacidade` recebe acesso às colunas completas, via workgroup `pii`.
5. O workgroup `analistas` **impõe** resultados criptografados em um bucket com ciclo de vida de 7 dias.
6. O **CloudTrail** e os logs do Lake Formation alimentam um painel de **quem acessou o quê**.
7. Um **VPC endpoint** garante que o tráfego não atravesse a Internet.

## Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| `AccessDeniedException` ao iniciar consulta | Falta `athena:StartQueryExecution` ou acesso ao workgroup | Ajustar IAM e ARN do workgroup |
| `Insufficient permissions to execute the query` | Falta acesso ao S3 de dados/resultados | Conceder `s3:GetObject`/`PutObject` nos prefixos corretos |
| `Access denied` com KMS | Política da chave | Permitir `kms:Decrypt`/`GenerateDataKey` à role |
| Tabela "não existe" para o usuário | Sem permissão no Glue/Lake Formation | Conceder `DESCRIBE`/`SELECT` no LF e IAM do Glue |
| LF concede mas não funciona | Local do S3 não registrado ou modo híbrido | Registrar o local; revisar o modo de controle |
| Resultados em local inesperado | Workgroup sem imposição | `EnforceWorkGroupConfiguration=true` |
| Acesso entre contas falha | Faltam políticas de bucket/chave ou share | Ajustar ambos os lados |
| Dados sensíveis expostos em resultados | Bucket de resultados sem controle | Restringir acesso; ciclo de vida; criptografia |
| Chamadas pela Internet | Sem VPC endpoints | Criar endpoints e políticas |
| Custo KMS alto | Muitas requisições | S3 Bucket Keys |

## Erros comuns e armadilhas

- **Acesso direto ao S3** para todos, anulando o Lake Formation.
- **Dados sensíveis e públicos no mesmo prefixo.**
- **Bucket de resultados sem criptografia e sem ciclo de vida.**
- **Workgroup único** para todos, sem limites nem imposição.
- **Esquecer a chave KMS** na concessão de acesso.
- **Misturar IAM e Lake Formation** sem entender o modo de controle.
- **Não auditar** consultas a dados de PII.
- **Chaves de acesso de longa duração** em clientes BI em vez de roles/SSO.

## 🧩 Quiz de Fixação

1. Quais camadas de permissão se cruzam em uma consulta do Athena?
2. Qual a vantagem do Lake Formation sobre o IAM puro?
3. Por que o bucket de resultados precisa de proteção?
4. O que faz `EnforceWorkGroupConfiguration`?
5. Que ação KMS é necessária para ler dados criptografados?
6. Como auditar quem consultou dados sensíveis?

**Respostas:**
1) IAM do Athena, catálogo (Glue/Lake Formation), S3 dos dados, KMS e o S3 de resultados.
2) Controle centralizado e fino por banco, tabela, coluna, linha e célula, com LF-Tags (ABAC), compartilhamento entre contas e auditoria.
3) Porque contém cópias dos dados consultados, inclusive sensíveis; precisa de criptografia, acesso restrito e ciclo de vida.
4) Impõe as configurações do workgroup (local e criptografia dos resultados), impedindo que usuários as alterem por consulta.
5) `kms:Decrypt` (e `kms:GenerateDataKey` para gravar), concedidos pela política da chave e do IAM.
6) Com o CloudTrail (eventos do Athena, incluindo o texto da consulta), os logs do Lake Formation e métricas e histórico dos workgroups.
