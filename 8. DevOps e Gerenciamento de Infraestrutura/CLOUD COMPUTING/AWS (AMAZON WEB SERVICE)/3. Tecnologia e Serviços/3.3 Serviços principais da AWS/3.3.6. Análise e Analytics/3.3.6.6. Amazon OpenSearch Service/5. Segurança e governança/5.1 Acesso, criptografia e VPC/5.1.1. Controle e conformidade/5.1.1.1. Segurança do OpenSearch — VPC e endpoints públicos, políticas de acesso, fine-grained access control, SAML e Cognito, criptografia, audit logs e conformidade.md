### 5.1.1.1. Segurança do OpenSearch — VPC e endpoints públicos, políticas de acesso, fine-grained access control, SAML e Cognito, criptografia, audit logs e conformidade

> [!warning] Aviso
> Opções de autenticação, recursos do fine-grained access control, requisitos de versão, nomes de ações IAM (`es:*`/`aoss:*`) e detalhes de VPC/Serverless abaixo são **de memória e mudam**. **Confirme na documentação do OpenSearch Service e do OpenSearch Security.** Políticas e comandos são ilustrativos e **não foram executados**. Domínios abertos à internet com política permissiva foram uma **causa clássica de vazamentos de dados**: trate segurança como requisito inicial, não como ajuste posterior.

## 1. Por que o OpenSearch é um alvo

O OpenSearch costuma guardar **logs**, **dados de clientes**, **trilhas de auditoria** e **conteúdo de busca**. Falhas frequentes:

| Falha | Consequência |
|---|---|
| **Endpoint público com política aberta** (`Principal: *`) | Qualquer pessoa na internet lê/apaga índices |
| **Sem autenticação/autorização granular** | Todos os usuários veem todos os índices |
| **Dados sensíveis em logs** | Senhas, tokens, PII pesquisáveis por muitos |
| **Sem criptografia** | Exposição de dados em disco/rede |
| **Credenciais de admin compartilhadas** | Sem rastreabilidade |
| **Dashboards exposto** | Acesso à interface sem controle |
| **Snapshots acessíveis** | Cópia completa dos dados |
| **Ransomware em clusters expostos** | Índices apagados e resgate |

Camadas: **rede** (VPC) → **identidade e autorização** (IAM, FGAC, SAML/Cognito) → **dados** (criptografia, mascaramento) → **auditoria** → **governança**.

## 2. Rede: VPC vs endpoint público

### 2.1 Comparação

| | **Acesso via VPC** | **Endpoint público** |
|---|---|---|
| **Exposição** | **Privado** (ENIs em subnets da VPC); acessível por rede privada | **Internet** (com controle por política/IP) |
| **Controle de rede** | **Security groups**, NACLs, subnets | **Política de acesso** baseada em recurso/IP |
| **Mudança** | **Definido na criação** (migrar exige processo; confirmar) | Pode mudar com restrições |
| **Recomendação** | **Padrão para produção** | Só com **forte justificativa** e controles |
| **Dashboards** | Acesso via **VPN/Direct Connect/bastion/proxy/SSM** ou Cognito/SAML por trás de proxy | Direto (autenticação) |

### 2.2 Boas práticas de rede

1. **Domínios em VPC** (subnets **privadas**, em **múltiplas AZs**).
2. **Security group** permitindo **443** apenas das **origens necessárias** (apps, Firehose, bastions).
3. **VPC endpoints** para serviços que interagem (S3, KMS, STS) quando aplicável.
4. **Sem IP público** para clientes: **PrivateLink/peering/Transit Gateway** para acesso de outras VPCs.
5. **Acesso humano ao Dashboards**: **VPN**, **SSM port forwarding**, **proxy autenticado (ALB + OIDC/Cognito)**.
6. Se for **público**: **política restritiva** (IAM + IP), **FGAC**, **HTTPS obrigatório** e **WAF** na frente (via proxy/CloudFront) quando possível.
7. **Firewall/Network Firewall** para controlar **egress** (ex.: não permitir snapshot para destinos externos).

## 3. Autenticação e autorização em camadas

```
Requisição ──▶ (1) Rede (SG/VPC) ──▶ (2) Política de acesso do domínio (IAM/IP)
           ──▶ (3) Autenticação (SigV4/IAM, usuário interno, SAML, Cognito)
           ──▶ (4) FGAC: roles → permissões por cluster/índice/documento/campo
```

### 3.1 Política de acesso baseada em recurso (domain access policy)

Política **anexada ao domínio** que define **quem** (principais IAM, contas, IPs) pode chamar a API (`es:ESHttpGet/Post/Put/Delete`).

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": { "AWS": "arn:aws:iam::123456789012:role/AppBuscaRole" },
    "Action": ["es:ESHttpGet", "es:ESHttpPost"],
    "Resource": "arn:aws:es:us-east-1:123456789012:domain/busca-prod/produtos*/*"
  }]
}
```

| Padrão | Observação |
|---|---|
| **Baseada em identidade (IAM)** | Políticas IAM nas roles/usuários com `es:*`; requisições **assinadas (SigV4)** |
| **Baseada em IP** | **Sem** assinatura; só para endpoints **públicos** com **IPs fixos**; fraca isoladamente |
| **Mista** | IAM + FGAC (recomendado) |

> [!warning] Nunca `Principal: "*"` sem condições em endpoint público
> Uma política com `"Principal": {"AWS": "*"}` e `Action: es:*` em endpoint **público** é **acesso aberto à internet**. Prefira **VPC**, **principais específicos** e **FGAC**.

### 3.2 Fine-grained access control (FGAC)

O **FGAC** (plugin de segurança do OpenSearch) adiciona **autorização granular**:

| Nível | Exemplo |
|---|---|
| **Cluster** | Permissões administrativas (`cluster_monitor`, `cluster_composite_ops`) |
| **Índice** | Leitura/escrita por **padrão de índice** (`logs-app-*`) |
| **Documento (DLS)** | **Filtro por documento** (`{"term": {"tenant":"acme"}}`) — **multi-tenancy** |
| **Campo (FLS)** | **Incluir/excluir campos** (esconder `cpf`) |
| **Mascaramento de campo** | **Hash/mascarar** valores (ex.: e-mail) para certos roles |
| **Tenants (Dashboards)** | Espaços de trabalho separados (dashboards, visualizações) |
| **Role mapping** | Mapeia **usuários/roles IAM/grupos SAML** a **roles do OpenSearch** |

```json
PUT _plugins/_security/api/roles/analista-vendas
{
  "cluster_permissions": ["cluster_composite_ops_ro"],
  "index_permissions": [{
     "index_patterns": ["vendas-*"],
     "allowed_actions": ["read"],
     "dls": "{\"term\": {\"regiao\": \"sudeste\"}}",
     "fls": ["~cpf", "~email"],
     "masked_fields": ["telefone"]
  }]
}
PUT _plugins/_security/api/rolesmapping/analista-vendas
{ "backend_roles": ["arn:aws:iam::123456789012:role/AnalistaVendas"], "users": [] }
```

| Ponto | Detalhe |
|---|---|
| **Requisitos** | **Criptografia node-to-node**, **em repouso** e **HTTPS obrigatório** (pré-requisitos do FGAC) |
| **Usuário master** | **IAM role/ARN** (preferível) ou **usuário/senha interno** (guardar em Secrets Manager; **uso mínimo**) |
| **Habilitar** | **Na criação** (ou com restrições depois; confirmar) |
| **Interação com IAM** | **Duas camadas**: a política do domínio **e** as permissões FGAC precisam permitir |
| **Auditoria** | **Audit logs** do plugin de segurança |

### 3.3 Autenticação de pessoas (Dashboards)

| Opção | Detalhe (de memória — confirmar) |
|---|---|
| **SAML** | **SSO** com IdP corporativo (Okta, Entra ID, AD FS, IAM Identity Center); **grupos → backend roles** |
| **Amazon Cognito** | Autenticação ao Dashboards com **user pools** (e federação) |
| **Usuário interno** | Banco de usuários do plugin (evitar em produção, exceto admin de emergência) |
| **OpenID Connect (OIDC)** | Suporte em versões recentes (confirmar) |
| **IAM Identity Center** | Integração para acesso às aplicações OpenSearch (confirmar) |
| **MFA** | Via **IdP** |

### 3.4 Autenticação de aplicações

| Opção | Detalhe |
|---|---|
| **IAM + SigV4** | **Padrão AWS**: roles de execução (Lambda, ECS, EC2) assinam requisições; **sem senha** |
| **Usuário interno + senha** | Para clientes que **não** suportam SigV4 (ex.: Logstash/Beats antigos); **segredo no Secrets Manager** e rotação |
| **Roles de serviço** | **Firehose**, **OSI**, **CloudWatch Logs** usam **roles** com permissão de escrita |

### 3.5 OpenSearch Serverless: segurança

| Elemento | Detalhe (de memória) |
|---|---|
| **Data access policies** | Quem acessa **coleções/índices** (permissões `aoss:*` por recurso) |
| **Network policies** | **Public** vs **VPC endpoints** (por coleção); controlar o acesso ao **Dashboards** |
| **Encryption policies** | **KMS** (chave AWS ou CMK) por coleção — **obrigatória na criação** |
| **Security policies como código** | CloudFormation/Terraform |
| **Auditoria** | CloudTrail para operações de controle; logs de dados conforme disponível |

## 4. Criptografia

| Camada | Opção | Recomendação |
|---|---|---|
| **Em repouso** | **KMS** (chave AWS-owned ou **CMK**) para dados, índices, snapshots automatizados, logs | **Habilitar sempre**; **CMK** onde houver requisito |
| **Node-to-node** | **TLS** entre nós do cluster | **Habilitar sempre** (requisito de FGAC) |
| **Cliente ↔ domínio** | **HTTPS obrigatório** (`EnforceHTTPS`), **política TLS mínima** (ex.: TLS 1.2) | **Habilitar** |
| **Domínio customizado** | **Certificado ACM** + domínio próprio | Opcional |
| **Snapshots manuais (S3)** | **SSE-KMS** no bucket; **Block Public Access**; **Object Lock** | **Habilitar** |
| **Chaves** | **Rotação**, key policy mínima, alarmes de `DisableKey` | Governança |

Cuidados: **desabilitar/apagar a CMK** torna o domínio **inacessível**; habilitar **criptografia em repouso** em um domínio **existente** pode exigir **recriação** (de memória; verificar para sua versão).

## 5. Dados sensíveis: minimização e controle

| Prática | Detalhe |
|---|---|
| **Não indexar** o que não é necessário | Filtrar/mascarar **na origem** (agente/OSI/Firehose/Lambda) |
| **Redação de logs** | Remover **tokens, senhas, PII** antes da ingestão (processadores `grok`/`substitute`/`delete_entries`) |
| **FLS/DLS/mascaramento** | Limitar o que cada role **vê** |
| **Índices por sensibilidade** | Separar logs “restritos” em índices/roles próprios |
| **Retenção** | **ISM** com **delete** conforme política (LGPD: minimização e prazo) |
| **Direito ao esquecimento** | Processo para **localizar e apagar** documentos de um titular (`delete_by_query`; planejar reindex) |
| **Snapshots** | **Contêm** dados pessoais: aplicar as mesmas regras de retenção/acesso |
| **Macie/Config** | **Macie** nos buckets de snapshots/exports; **Config** para configurações do domínio |

## 6. Auditoria e monitoramento de segurança

| O que | Fonte |
|---|---|
| **Chamadas de API do serviço** (criar/alterar/excluir domínio, políticas) | **CloudTrail** (`es:*`/`opensearch:*`) |
| **Acesso aos dados** (autenticações, falhas, acessos a índices) | **Audit logs** do OpenSearch (**para CloudWatch Logs**) — configurável por categorias (AUTHENTICATED, FAILED_LOGIN, GRANTED_PRIVILEGES, MISSING_PRIVILEGES, INDEX_EVENT…) |
| **Logs de erro e lentos** | **Error logs**, **search/index slow logs** → CloudWatch Logs |
| **Mudanças de configuração** | **AWS Config** (regras: domínio em VPC, criptografia em repouso/node-to-node, logging habilitado — **verificar regras disponíveis**) |
| **Detecção de ameaças** | **GuardDuty** (CloudTrail/VPC), **Security Hub**; **Security Analytics** do OpenSearch (para logs de segurança) |
| **Exposição pública** | **IAM Access Analyzer** (recursos com acesso externo), **Config** |

```bash
# Habilitar audit logs e slow logs para o CloudWatch Logs (ilustrativo)
aws opensearch update-domain-config --domain-name busca-prod --log-publishing-options '{
  "AUDIT_LOGS": {"CloudWatchLogsLogGroupArn":"arn:aws:logs:us-east-1:123456789012:log-group:/aws/opensearch/busca-prod/audit","Enabled":true},
  "SEARCH_SLOW_LOGS": {"CloudWatchLogsLogGroupArn":"arn:aws:logs:us-east-1:123456789012:log-group:/aws/opensearch/busca-prod/slow","Enabled":true}}'
```

Alarmes úteis: **picos de `FAILED_LOGIN`**, **`MISSING_PRIVILEGES`**, **mudanças de role/mapping**, **acessos de IPs/roles inesperados**, **exclusão de índices** em massa.

## 7. IAM para administração

| Papel | Pode | Não deve |
|---|---|---|
| **Administrador de plataforma** | Criar/atualizar domínios (`es:CreateDomain`, `UpdateDomainConfig`), snapshots | Acessar dados de negócio |
| **Engenharia de busca/dados** | `ESHttp*` em **índices específicos** + roles FGAC | `DeleteDomain` |
| **Analistas** | Dashboards (SAML/Cognito) com roles FGAC de leitura | Admin |
| **Auditoria/SOC** | Leitura de configuração e logs | Escrita |
| **Pipeline (IaC)** | Criar/alterar recursos do domínio (escopo) | Excluir em produção sem aprovação |

**SCPs** para impedir **domínios públicos** e **sem criptografia**:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "ExigirDominioEmVPC",
    "Effect": "Deny",
    "Action": ["es:CreateDomain", "opensearch:CreateDomain"],
    "Resource": "*",
    "Condition": { "Null": { "es:VpcOptions": "true" } }
  }]
}
```

(Condição ilustrativa; **confirme as chaves de condição suportadas** na documentação.)

## 8. Checklist de endurecimento

- [ ] **VPC** (subnets privadas, SG restrito, 3 AZs) — **sem endpoint público**
- [ ] **FGAC** habilitado; **master por IAM**; **roles mínimas** com DLS/FLS/mascaramento quando preciso
- [ ] **Política do domínio** com **principais específicos** (nunca `*` público)
- [ ] **HTTPS obrigatório**, **TLS ≥ 1.2**, **node-to-node**, **criptografia em repouso (KMS/CMK)**
- [ ] **SAML/Cognito** para pessoas; **IAM/SigV4** para aplicações; segredos no **Secrets Manager**
- [ ] **Audit logs** + **slow/error logs** no CloudWatch; **CloudTrail**; **Config/GuardDuty/Security Hub**
- [ ] **Redação/minimização** de dados na ingestão; **retenção (ISM)**
- [ ] **Snapshots** em bucket **privado, KMS, Object Lock**, acesso mínimo
- [ ] **SCP/IAM** impedindo **domínios públicos/sem criptografia**; **IaC** e revisão
- [ ] **Acesso humano** ao Dashboards por **VPN/SSM/proxy autenticado**
- [ ] **Revisões** periódicas de roles, mapeamentos e acessos

## 9. Erros comuns

- **Domínio público com `Principal: *`**.
- **FGAC desabilitado** (todos veem tudo).
- **Usuário master interno compartilhado** com senha em wiki.
- **Sem HTTPS/TLS mínimo**.
- **Logs com PII/segredos** indexados.
- **Dashboards exposto** à internet sem SSO.
- **Snapshots** em bucket sem proteção.
- **Sem audit logs**.
- **Não restringir `es:*`** (ações de administração) a muitos.
- **CMK apagada** sem plano.
- **Política baseada só em IP** em endpoint público.

## 10. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| `403 Forbidden` com IAM correto | **FGAC** sem mapeamento de role; política do domínio | Mapear `backend_roles`; revisar a política |
| `Signature does not match` | SigV4 (região/serviço `es`, relógio, proxy alterando headers) | Corrigir a assinatura/região/NTP |
| Não alcança o domínio da VPC | SG/rota/DNS | Verificar SG 443, rotas, resolução do endpoint |
| SAML falha | Metadados/atributos/roles; relógio | Revisar o IdP, o `roles_key` e os grupos |
| Usuário vê dados de mais | DLS/FLS ausente; role ampla | Revisar as permissões |
| Audit logs não aparecem | Log group/resource policy; não habilitado | Ajustar a policy e a configuração |
| Domínio inacessível após mexer na chave | CMK desabilitada/permissões | Reabilitar/ajustar a key policy |
| Cognito/Dashboards loop de login | Configuração de domínio/URLs de callback | Revisar o user pool e os redirects |

## 11. Resumo rápido

- **Rede**: **VPC privada** como padrão; **SG 443**; acesso humano por **VPN/SSM/proxy**; endpoint público só com forte justificativa.
- **Autorização em camadas**: **política do domínio** (IAM/IP) + **FGAC** (cluster/índice/**DLS**/**FLS**/mascaramento/tenants) com **role mapping**.
- **Autenticação**: **IAM/SigV4** (apps), **SAML/Cognito/OIDC** (pessoas), usuário interno só em exceção (segredos no Secrets Manager).
- **Criptografia**: **KMS em repouso**, **node-to-node**, **HTTPS + TLS 1.2+**, snapshots em S3 com KMS/Object Lock.
- **Dados sensíveis**: minimizar/redigir **na origem**, FLS/DLS, **ISM** para retenção, processo de apagamento.
- **Auditoria**: **audit/slow/error logs** (CloudWatch), **CloudTrail**, **Config/GuardDuty/Security Hub**; **SCPs** contra domínios públicos.
- **Serverless**: **data access**, **network** e **encryption policies**.

## 🧩 Quiz de Fixação

1. Por que preferir domínio em VPC em vez de endpoint público?
2. O que o FGAC adiciona à política de acesso do domínio?
3. Para que servem DLS e FLS?
4. Quais as opções de autenticação para pessoas no Dashboards?
5. Que criptografias devem estar habilitadas e quais são pré-requisitos do FGAC?
6. Por que audit logs e CloudTrail são complementares?
7. Como reduzir o risco de dados sensíveis em logs indexados?

**Respostas:**

1. Porque a VPC mantém o domínio privado, controlado por security groups e rede, reduzindo a exposição à internet; endpoint público exige controles extras e é causa clássica de vazamentos.
2. Autorização granular por cluster, índice, documento e campo, mascaramento, tenants e role mapping, além da política baseada em IAM/IP do domínio.
3. DLS filtra quais documentos um role pode ver; FLS inclui ou exclui campos, escondendo dados como CPF.
4. SAML (SSO com IdP corporativo), Amazon Cognito, OIDC e usuários internos (este último evitado em produção).
5. Criptografia em repouso (KMS), node-to-node e HTTPS obrigatório com TLS mínimo; node-to-node, em repouso e HTTPS são pré-requisitos do FGAC.
6. O CloudTrail registra chamadas de API de controle (configuração do domínio); os audit logs registram autenticações e acessos aos dados dentro do cluster.
7. Minimizar e redigir na origem (agente/OSI/Firehose), usar FLS/DLS/mascaramento, aplicar retenção via ISM e manter processo para apagar dados de um titular.
