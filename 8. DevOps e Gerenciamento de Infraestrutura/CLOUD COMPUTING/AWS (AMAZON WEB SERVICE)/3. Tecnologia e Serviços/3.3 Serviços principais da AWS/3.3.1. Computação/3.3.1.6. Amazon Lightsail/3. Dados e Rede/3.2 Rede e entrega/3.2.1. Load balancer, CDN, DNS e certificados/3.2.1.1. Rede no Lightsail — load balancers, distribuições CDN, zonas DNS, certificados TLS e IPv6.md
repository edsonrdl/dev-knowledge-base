### Rede no Lightsail — load balancers, distribuições CDN, zonas DNS, certificados TLS e IPv6

> [!warning] Aviso
> Planos de load balancer e de CDN, limites de certificados/domínios, regras de validação e preços mudam. Os valores são referências de estudo; confirme na documentação. Os comandos **não foram executados**.

A rede do Lightsail reúne, em um só lugar, as peças que fazem uma aplicação pequena parecer **profissional**: um **load balancer** para distribuir tráfego e tolerar falhas, uma **distribuição CDN** para acelerar e proteger a origem, **zonas DNS** para gerenciar o domínio, **certificados TLS** gratuitos para HTTPS e **IPv6** para alcançar mais usuários. Tudo com preço previsível e configuração simplificada.

**Analogia:** é a **recepção de um prédio comercial**: o **load balancer** é o recepcionista que encaminha cada visitante a um atendente livre; a **CDN** é o balcão avançado em vários bairros que entrega os itens mais pedidos sem ir até o escritório central; o **DNS** é o painel de endereços do prédio; o **certificado** é o crachá que prova a identidade do prédio para quem entra.

---

## Mapa das peças

```
 Usuário ──DNS──► app.exemplo.com
                        │ (zona DNS do Lightsail)
                        ▼
                Distribuição CDN (cache + HTTPS + WAF básico)
                        │ cache miss
                        ▼
                  Load balancer (HTTPS, health check, sticky opcional)
                  ┌────┴─────┐
                  ▼          ▼
            Instância 1   Instância 2        ← em AZs diferentes
                  └────┬─────┘
                       ▼
              Banco gerenciado (privado)
```

| Peça | Função | Onde ajuda |
|---|---|---|
| Load balancer | Distribui requisições entre instâncias saudáveis | Disponibilidade e capacidade |
| Distribuição CDN | Cache global e HTTPS na borda | Latência e economia de transferência |
| Zona DNS | Registros do domínio (A, AAAA, CNAME, MX, TXT) | Gestão centralizada |
| Certificado TLS | HTTPS gratuito com validação por DNS | Segurança e SEO |
| IPv6 | Endereço adicional para instâncias/serviços | Alcance e custo |

## Load balancers

O **load balancer do Lightsail** opera na **camada 7 (HTTP/HTTPS)**, com preço mensal fixo (inclui uma franquia de transferência). Distribui requisições entre **instâncias anexadas**, faz **health check** e pode encerrar **TLS** com certificados do Lightsail.

| Recurso | Detalhe |
|---|---|
| Instâncias alvo | Da mesma região; anexe e remova a qualquer momento |
| Health check | Caminho HTTP; instâncias não saudáveis saem da rotação |
| Persistência de sessão | Opcional (cookie) para apps com estado local |
| HTTPS | Termina TLS no balanceador; pode redirecionar HTTP→HTTPS |
| Política TLS | Define versões e *ciphers* mínimos |
| Métricas | Contagem de requisições, hosts saudáveis, tempos de resposta, 4xx/5xx |

```bash
# Cria o balanceador apontando a porta da instância e o caminho de health check
aws lightsail create-load-balancer --load-balancer-name lb-site \
  --instance-port 80 --health-check-path /health

# Anexa as instâncias
aws lightsail attach-instances-to-load-balancer \
  --load-balancer-name lb-site --instance-names web-1 web-2

# Ativa persistência de sessão por cookie (1 hora)
aws lightsail update-load-balancer-attribute --load-balancer-name lb-site \
  --attribute-name SessionStickinessEnabled --attribute-value true
aws lightsail update-load-balancer-attribute --load-balancer-name lb-site \
  --attribute-name SessionStickiness_LB_CookieDurationSeconds --attribute-value 3600

# Redireciona HTTP para HTTPS
aws lightsail update-load-balancer-attribute --load-balancer-name lb-site \
  --attribute-name HttpsRedirectionEnabled --attribute-value true

# Saúde dos alvos
aws lightsail get-load-balancer --load-balancer-name lb-site \
  --query 'loadBalancer.instanceHealthSummary'
```

### Árvore de decisão: preciso de load balancer?

```
Um único servidor e tolero indisponibilidade em manutenção? ─► não precisa
Quero 2+ instâncias (HA/capacidade)? ─► SIM, load balancer
A app guarda sessão em memória local? ─► sticky temporário e planejar sessão externa
Preciso de HTTPS com certificado gerenciado e redirect? ─► load balancer facilita
```

> [!tip] Alta disponibilidade de verdade
> Instâncias atrás do balanceador devem estar em **AZs diferentes**; do contrário, uma falha de AZ derruba tudo.

## Distribuições CDN

A **distribuição** do Lightsail é uma CDN (baseada na rede de borda da AWS) que fica na frente de uma **origem**: uma instância, um load balancer, um container service ou um bucket. Ela **cacheia** conteúdo estático, **termina HTTPS** na borda e reduz transferência e carga na origem. Vem com **pacote de transferência** incluso.

| Configuração | Opções |
|---|---|
| Origem | Instância, load balancer, container service ou bucket |
| Cache behavior | Padrão e por caminho: cachear tudo, cachear só estáticos, não cachear |
| Cabeçalhos/cookies/strings | O que encaminhar à origem (menos itens = melhor cache) |
| Certificado | TLS para domínios alternativos |
| Pacote | Faixas de transferência incluída |

```
 Antes (sem CDN):  todos os usuários ──────────────────► instância (sobrecarga)
 Depois (com CDN): usuários ─► borda (cache hit ~90% estáticos) ──miss──► instância
```

```bash
# Cria distribuição com origem em um load balancer, cache só de estáticos
aws lightsail create-distribution --distribution-name cdn-site \
  --origin name=lb-site,regionName=sa-east-1,protocolPolicy=https-only \
  --default-cache-behavior behavior=dont-cache \
  --cache-behavior-settings '{"defaultTTL":86400,"allowedHTTPMethods":"GET,HEAD,OPTIONS,PUT,PATCH,POST,DELETE","forwardedCookies":{"option":"none"},"forwardedQueryStrings":{"option":false}}' \
  --cache-behaviors '[{"path":"/static/*","behavior":"cache"}]' \
  --bundle-id small_1_0

# Limpa o cache de um caminho (após publicar nova versão)
aws lightsail reset-distribution-cache --distribution-name cdn-site

# Estado e domínio
aws lightsail get-distributions --distribution-name cdn-site \
  --query 'distributions[0].[status,domainName]'
```

| Cuidado | Por quê |
|---|---|
| Não cachear áreas autenticadas/dinâmicas | Evita servir dados de um usuário a outro |
| Encaminhar menos cookies | Mais cache hits |
| Versionar arquivos estáticos (hash no nome) | Evita depender de invalidação |
| Restringir a origem à CDN | Impede acesso direto ao servidor |

## Zonas DNS

A **zona DNS** do Lightsail permite gerenciar os registros do seu domínio (A, AAAA, CNAME, MX, TXT, SRV, NS). Você pode **registrar o domínio** pela AWS ou usar um domínio de outro registrador, apontando os **servidores de nomes** para os do Lightsail.

| Registro | Uso típico |
|---|---|
| A / AAAA | Apontar nome para IP estático (IPv4/IPv6) |
| CNAME | Apontar `www` para outro nome (balanceador, CDN) |
| Registro especial para recurso | Apontar o apex (`exemplo.com`) para load balancer/CDN do Lightsail |
| MX | E-mail |
| TXT | SPF, DKIM, verificação de domínio |

```bash
# Cria a zona e registros
aws lightsail create-domain --domain-name exemplo.com
aws lightsail create-domain-entry --domain-name exemplo.com \
  --domain-entry name=www.exemplo.com,type=CNAME,target=<dominio-da-cdn>

# Servidores de nomes que o registrador deve usar
aws lightsail get-domain --domain-name exemplo.com \
  --query 'domain.domainEntries[?type==`NS`]'
```

> [!warning] Limite de zonas
> O Lightsail limita o número de zonas DNS por conta (poucas). Para muitos domínios ou recursos avançados (políticas de roteamento, health checks), use **Route 53**.

## Certificados TLS

Os **certificados do Lightsail** são gratuitos e validados **por DNS**: o Lightsail informa um registro CNAME que você cria na zona; ao validar, o certificado é emitido e **renovado automaticamente**. Podem ser associados a **load balancers, container services e distribuições**.

```
 1. create-certificate (domínio + SANs)
 2. criar o CNAME de validação na zona DNS
 3. status: PENDING_VALIDATION ──► ISSUED
 4. anexar ao load balancer / distribuição / container service
 5. renovação automática (enquanto o CNAME existir)
```

```bash
# Solicita o certificado
aws lightsail create-certificate --certificate-name cert-site \
  --domain-name exemplo.com --subject-alternative-names www.exemplo.com

# Obtém os registros de validação
aws lightsail get-certificates --certificate-name cert-site \
  --query 'certificates[0].certificateDetail.domainValidationRecords'

# Anexa ao load balancer
aws lightsail attach-load-balancer-tls-certificate \
  --load-balancer-name lb-site --certificate-name cert-site
```

| Sintoma | Causa | Ação |
|---|---|---|
| Fica em `PENDING_VALIDATION` | CNAME de validação ausente/incorreto | Criar o registro exato na zona ativa |
| Falha na renovação | CNAME removido | Restabelecer o registro |
| Erro de nome no navegador | Domínio fora do certificado | Incluir como SAN e reemitir |

## IPv6 e firewall

- **IPv6** pode ser habilitado por instância/balanceador/distribuição; crie registros **AAAA**. Há planos de instância **somente IPv6** mais baratos, adequados quando os clientes e dependências suportam IPv6.
- O **firewall** das instâncias deve ser coerente com a arquitetura: com load balancer/CDN, **restrinja** HTTP/HTTPS às origens necessárias e feche acesso direto desnecessário; mantenha SSH restrito ao seu IP.

## Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| 502/503 no load balancer | Nenhuma instância saudável | Verificar health check, porta e firewall da instância |
| Instância "unhealthy" | Caminho do health check retorna erro | Ajustar caminho e resposta 200 |
| Usuário "perde a sessão" | Sem sticky e sessão local | Sticky ou sessão externa |
| Conteúdo antigo na CDN | Cache vigente | `reset-distribution-cache` ou versionar arquivos |
| CDN devolve erro de origem | Protocolo/porta/host incorretos | Ajustar origem e protocolo |
| Domínio não resolve | NS do registrador diferentes | Atualizar para os NS da zona |
| HTTPS inválido | Certificado não anexado ou pendente | Validar e anexar |

## Custo

| Componente | Observação |
|---|---|
| Load balancer | Preço mensal fixo + franquia de transferência |
| Distribuição CDN | Plano fixo com pacote de transferência |
| Zona DNS | Normalmente sem custo adicional no Lightsail (verificar) |
| Certificados | Gratuitos |
| IPv4 público/estático | Cobrança por IP não anexado |

**Raciocínio:** uma CDN costuma **reduzir custo** ao absorver tráfego estático e permitir plano menor de instância; o load balancer só vale a pena quando você realmente tem 2+ instâncias.

## Exemplo prático: site em alta disponibilidade

1. Duas instâncias `web-1` (AZ-a) e `web-2` (AZ-b) com o mesmo conteúdo (ou conteúdo em bucket).
2. Load balancer `lb-site` com health check `/health`, redirecionamento HTTPS.
3. Certificado `cert-site` para `exemplo.com` e `www.exemplo.com`, validado por DNS e anexado.
4. Distribuição `cdn-site` na frente do balanceador, cacheando `/static/*`.
5. Zona DNS: apex e `www` apontando para a distribuição.
6. Firewall das instâncias restrito ao necessário; banco gerenciado privado.

## Erros comuns e armadilhas

- **Load balancer com instâncias na mesma AZ** (falsa alta disponibilidade).
- **Health check apontando para página pesada/inexistente.**
- **Cachear páginas autenticadas na CDN.**
- **Encaminhar todos os cookies à origem**, destruindo o cache.
- **Esquecer o CNAME de validação** e perder a renovação do certificado.
- **Deixar a instância acessível direto**, ignorando a CDN/WAF.
- **Usar zona DNS do Lightsail para muitos domínios** e bater no limite.
- **Esperar políticas avançadas de DNS** (latência, failover) que são do Route 53.

## 🧩 Quiz de Fixação

1. Em que camada o load balancer do Lightsail atua e o que ele faz com instâncias não saudáveis?
2. Por que as instâncias do balanceador devem estar em AZs diferentes?
3. O que a distribuição CDN cacheia e o que não deve cachear?
4. Como é validado um certificado do Lightsail e o que garante a renovação?
5. Quando migrar do DNS do Lightsail para o Route 53?
6. Como limpar conteúdo desatualizado da CDN?

**Respostas:**
1) Na camada 7 (HTTP/HTTPS); instâncias que falham no health check saem da rotação até voltarem a ficar saudáveis.
2) Para que a falha de uma AZ não derrube todas as instâncias; sem isso a alta disponibilidade é ilusória.
3) Cacheia conteúdo estático (imagens, CSS, JS); não deve cachear áreas autenticadas ou dinâmicas, para não servir dados de um usuário a outro.
4) Por DNS: cria-se o CNAME de validação na zona; mantê-lo garante a renovação automática.
5) Quando precisar de muitos domínios, políticas de roteamento (latência, failover, ponderado), health checks ou recursos avançados que o Lightsail não oferece.
6) Com `reset-distribution-cache` ou, preferencialmente, versionando os arquivos estáticos para não depender de invalidação.
