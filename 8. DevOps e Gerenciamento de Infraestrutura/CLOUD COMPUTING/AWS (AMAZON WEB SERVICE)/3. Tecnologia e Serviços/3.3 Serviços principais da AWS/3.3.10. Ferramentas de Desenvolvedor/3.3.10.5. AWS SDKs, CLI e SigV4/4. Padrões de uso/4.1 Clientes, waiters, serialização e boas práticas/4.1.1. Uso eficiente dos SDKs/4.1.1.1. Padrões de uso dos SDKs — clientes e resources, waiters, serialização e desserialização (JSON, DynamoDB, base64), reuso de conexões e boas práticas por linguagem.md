### 4.1.1.1. Padrões de uso dos SDKs — clientes e resources, waiters, serialização e desserialização (JSON, DynamoDB, base64), reuso de conexões e boas práticas por linguagem

> [!warning] Aviso
> Nomes de classes/pacotes, comportamento de clientes “high-level”, tipos suportados por serializadores e opções de HTTP client variam por **SDK e versão**. **Confirme na documentação do SDK da sua linguagem.** Código e exemplos são ilustrativos e **não foram executados**. Esta folha cobre o ponto **“Serialização e desserialização”** (Task 1.1 do DVA-C03) e padrões práticos de uso.

## 1. Camadas de API nos SDKs

A maioria dos SDKs oferece **mais de um nível de abstração**:

| Nível | Descrição | Exemplos |
|---|---|---|
| **Baixo nível (clients)** | **1:1** com a **API do serviço**: você passa **parâmetros** no formato do **protocolo** e recebe **respostas brutas** | `boto3.client("dynamodb")`, `DynamoDBClient`, `S3Client` |
| **Alto nível (resources/enhanced/document)** | **Conveniência**: converte tipos, esconde paginação/formatos | `boto3.resource("dynamodb")`, **DynamoDB Document Client** (JS), **Enhanced Client** (Java), **S3 Transfer Manager** |
| **Utilitários** | **Waiters**, **paginators**, **presigners**, **serializers** | `get_waiter`, `get_paginator`, `generate_presigned_url` |
| **Frameworks** | **Powertools**, **Amplify**, **Spring Cloud AWS**, **AWS CDK** | — |

### 1.1 Quando usar cada um

| Critério | **Client (baixo nível)** | **Alto nível** |
|---|---|---|
| **Controle** | **Total** (todos os parâmetros) | Menor |
| **Verbosidade** | **Alta** (tipos DynamoDB `{"S": "x"}`) | **Baixa** (tipos nativos) |
| **Cobertura de operações** | **Completa** | Parcial/foco em **casos comuns** |
| **Evolução** | Novos recursos **imediatos** | Pode **atrasar** |
| **Recomendação** | **Operações avançadas**, **precisão** | **CRUD simples**, **produtividade** |

> Nota: no **Boto3**, os **resources** estão em **modo de manutenção** para alguns serviços (a AWS recomenda **clients**); o **resource do DynamoDB** continua amplamente usado (confirmar).

## 2. Serialização e desserialização

### 2.1 O que é

**Serializar** = converter **estruturas em memória** (objetos, dicts) em **formato de transporte** (JSON/XML/binário/bytes). **Desserializar** = o caminho inverso. No contexto AWS aparece em **quatro lugares**:

| Local | Exemplo |
|---|---|
| **Protocolo da API do serviço** | O SDK **serializa** os parâmetros em **JSON/XML/Query** automaticamente |
| **Payloads de aplicação** | Corpo de **SQS/SNS/EventBridge/Kinesis/Lambda** (você **serializa** JSON, Avro, Protobuf) |
| **Atributos do DynamoDB** | Formato **tipado** (`{"S":"…"}`, `{"N":"…"}`) |
| **Dados binários** | **Base64** em JSON/Lambda/API Gateway/KMS; **bytes** |

### 2.2 JSON: armadilhas comuns

| Armadilha | Detalhe |
|---|---|
| **Números** | JSON **não distingue** inteiros de decimais; **`float`** em Python **vs** **`Decimal`** no DynamoDB (o **resource** exige **`Decimal`**, **não aceita `float`**) |
| **Datas** | **Sem tipo** de data em JSON: padronizar **ISO 8601 (UTC)** ou **epoch** |
| **Precisão** | `long` > 2^53 **perde precisão** em **JavaScript** (`number`) — usar **string**/**BigInt** |
| **Binário** | Não representável: **base64** |
| **Charset/Unicode** | **UTF-8** consistente |
| **Campos desconhecidos** | **Evolução de schema**: **ignorar** campos novos; **valores padrão** |
| **Nulos** | `null` vs **ausente** (DynamoDB: `NULL` type vs atributo inexistente) |
| **Tamanho** | Limites: **Lambda 6 MB síncrono/256 KB assíncrono**, **SQS 1 MiB (Extended Client > )**, **SNS 256 KB**, **EventBridge 256 KB**, **Kinesis 1 MB/registro**, **DynamoDB item 400 KB** |

### 2.3 DynamoDB: attribute values

O **cliente de baixo nível** exige **tipos explícitos**:

| Tipo | Código | Exemplo |
|---|---|---|
| **String** | `S` | `{"S": "Ana"}` |
| **Number** | `N` (**string**!) | `{"N": "42.5"}` |
| **Binary** | `B` | `{"B": b"..."}` (base64 no wire) |
| **Boolean** | `BOOL` | `{"BOOL": true}` |
| **Null** | `NULL` | `{"NULL": true}` |
| **List** | `L` | `{"L": [{"S":"a"},{"N":"1"}]}` |
| **Map** | `M` | `{"M": {"k": {"S":"v"}}}` |
| **String/Number/Binary Set** | `SS`, `NS`, `BS` | `{"SS": ["a","b"]}` |

```python
# Client (baixo nível): tipos explícitos
ddb = boto3.client("dynamodb")
ddb.put_item(TableName="pedidos", Item={
    "pedido_id": {"S": "123"}, "total": {"N": "199.90"}, "itens": {"L": [{"S": "A"}, {"S": "B"}]},
    "pago": {"BOOL": True}, "endereco": {"M": {"cidade": {"S": "SP"}}}})

# Resource (alto nível): tipos nativos; números = Decimal
from decimal import Decimal
tabela = boto3.resource("dynamodb").Table("pedidos")
tabela.put_item(Item={"pedido_id": "123", "total": Decimal("199.90"), "itens": ["A", "B"], "pago": True})
```

```python
# Converter entre os formatos (útil em Lambda com DynamoDB Streams)
from boto3.dynamodb.types import TypeSerializer, TypeDeserializer
ser, des = TypeSerializer(), TypeDeserializer()
tipado = {k: ser.serialize(v) for k, v in {"id": "1", "valor": Decimal("10.5")}.items()}
nativo = {k: des.deserialize(v) for k, v in tipado.items()}
```

```javascript
// JS v3: marshall / unmarshall (@aws-sdk/util-dynamodb)
import { marshall, unmarshall } from "@aws-sdk/util-dynamodb";
const tipado = marshall({ pedido_id: "123", total: 199.9, itens: ["A", "B"] }, { removeUndefinedValues: true });
const nativo = unmarshall(tipado);
// Ou usar o DynamoDBDocumentClient (já converte)
```

> [!tip] DynamoDB Streams, Lambda e S3 events
> Os registros de **DynamoDB Streams** chegam **no formato tipado** (`{"S":…}`): use **`TypeDeserializer`/`unmarshall`** para **voltar a dicts nativos**.

### 2.4 Base64 e dados binários

| Contexto | Regra |
|---|---|
| **`lambda invoke --payload` (CLI v2)** | Usar `--cli-binary-format raw-in-base64-out` para **JSON cru** (senão espera **base64**) |
| **Resposta de `Lambda Invoke`** | `Payload` é **stream de bytes** (`.read()`), depois **`json.loads`** |
| **API Gateway (proxy)** | Corpo **binário** vem com `isBase64Encoded: true` → **decodificar** |
| **KMS** `Encrypt/Decrypt` | **Blob** (bytes); em JSON/CLI, **base64** |
| **SQS MessageAttributes (Binary)** | **Bytes**; `String` para JSON |
| **S3 `GetObject`** | `Body` é **stream** (`StreamingBody`/`ReadableStream`) → **ler/decodificar** |
| **Kinesis `Data`** | **Blob** (bytes); **base64** na entrega a Lambda |
| **Secrets Manager** | `SecretString` (JSON) ou `SecretBinary` |

```python
import base64, json
corpo = event["body"]
if event.get("isBase64Encoded"):
    corpo = base64.b64decode(corpo).decode("utf-8")
dados = json.loads(corpo)

r = lambda_client.invoke(FunctionName="processar", Payload=json.dumps({"id": 42}).encode())
resultado = json.loads(r["Payload"].read())            # stream → bytes → JSON
```

### 2.5 Formatos de serialização para mensagens e dados

| Formato | Vantagens | Desvantagens | Uso |
|---|---|---|---|
| **JSON** | **Legível**, universal | **Verboso**, sem tipos ricos, sem schema | APIs, eventos simples |
| **Avro** | **Compacto**, **schema** + evolução, **Schema Registry** | Menos legível | **Streaming** (Kinesis/MSK), data lakes |
| **Protobuf** | **Muito compacto**, rápido, schema forte | Exige **código gerado** | RPC/gRPC, eventos eficientes |
| **Parquet/ORC** | **Colunar**, compressão | Não é para mensagens | **Analytics** (S3/Athena) |
| **CSV** | Simples | Sem tipos/aninhamento | Interoperabilidade |
| **XML** | Padrões legados (**S3 API**, SOAP) | Verboso | Legado |
| **MessagePack/CBOR** | Compactos, binários | Menos ferramentas | Sistemas específicos (**IoT: CBOR**) |

Boas práticas de **schema**: **versionar** (`schema_version`), **compatibilidade retroativa/futura** (campos **opcionais**, **valores padrão**), **validar** na **entrada** (JSON Schema, **Pydantic**, **EventBridge Schema Registry**, **Glue Schema Registry**).

### 2.6 Serialização de eventos (EventBridge/SNS/SQS)

| Serviço | Estrutura |
|---|---|
| **EventBridge** | Envelope com `source`, `detail-type`, `detail` (JSON) |
| **SNS → SQS** | A mensagem SQS **contém o envelope SNS** (JSON com `Message` **string** que **contém JSON**) a menos que **raw message delivery** esteja habilitado → **dupla desserialização** |
| **SQS → Lambda** | `event["Records"][i]["body"]` é **string** → `json.loads(body)` |
| **S3 → Lambda** | Chaves de objeto **URL-encoded** (`urllib.parse.unquote_plus`) |
| **Kinesis → Lambda** | `record["kinesis"]["data"]` **base64** → decodificar |
| **API Gateway proxy** | `body` **string** (JSON ou base64) |

```python
# SNS → SQS → Lambda (sem raw delivery): dupla desserialização
for rec in event["Records"]:
    envelope = json.loads(rec["body"])              # envelope SNS
    mensagem = json.loads(envelope["Message"])      # payload real
```

## 3. Waiters

### 3.1 O que são

**Waiters** fazem **polling** de uma operação **até** que um **estado** seja atingido (ou **falha/timeout**), com **intervalo** e **tentativas** configuráveis.

```python
ec2 = boto3.client("ec2")
ec2.start_instances(InstanceIds=["i-0abc123"])
waiter = ec2.get_waiter("instance_running")
waiter.wait(InstanceIds=["i-0abc123"], WaiterConfig={"Delay": 5, "MaxAttempts": 40})   # ≤ 200 s
```

| Exemplos de waiters | Uso |
|---|---|
| `instance_running`, `instance_stopped`, `instance_terminated` | EC2 |
| `bucket_exists`, `object_exists`, `object_not_exists` | S3 |
| `table_exists`, `table_not_exists` | DynamoDB |
| `stack_create_complete`, `stack_update_complete` | CloudFormation |
| `db_instance_available` | RDS |

| Boa prática | Detalhe |
|---|---|
| **Limites** | Definir **Delay/MaxAttempts** (evita **espera infinita**) |
| **Lambda** | Não **bloquear** o Lambda aguardando **minutos** — usar **Step Functions** (`.sync`/**Wait**) ou **eventos** (EventBridge) |
| **Tratamento** | `WaiterError` em **timeout/estado de falha** |
| **Alternativas** | **Eventos de mudança de estado** (EventBridge) em vez de polling |

## 4. Reuso de clientes e conexões

### 4.1 Por que reusar

Criar um cliente é **caro**: resolve credenciais/região/endpoint, **carrega modelos** de serviço, cria **pools** de conexão e **TLS handshakes**.

| Prática | Detalhe |
|---|---|
| **Instanciar fora do handler (Lambda)** | **Escopo global** → reaproveitado entre **invocações** (warm) |
| **Cliente singleton** (serviços/containers) | Um por **serviço/região/config** |
| **Pool de conexões** | Dimensionar `max_pool_connections` (**Boto3**), `maxSockets` (Node), conexões do HTTP client (Java) à **concorrência** |
| **Keep-alive** | Habilitado por padrão; **reduz latência** |
| **Thread safety** | **Clients** do Boto3 são **thread-safe**; **resources/sessions** **não** (criar por thread) |
| **Credenciais** | Providers com **cache e refresh** (não recriar a cada chamada) |
| **Config compartilhada** | Timeouts/retries **centralizados** |
| **HTTP/2, CRT** | **AWS CRT** (Common Runtime) melhora **S3** (throughput) em Java/Python (**S3 Transfer Manager/CRT client**) |

```python
# Lambda: fora do handler
import boto3
from botocore.config import Config
_cfg = Config(connect_timeout=2, read_timeout=5, retries={"mode": "standard", "max_attempts": 3}, max_pool_connections=20)
dynamodb = boto3.client("dynamodb", config=_cfg)
s3 = boto3.client("s3", config=_cfg)

def handler(event, context):
    ...   # usa os clientes já criados (menor cold-start impact nas invocações seguintes)
```

### 4.2 Cuidados em Lambda

- **Cold start**: importar **só o necessário** (JS v3 **modular**; Python **imports tardios** de serviços raros).
- **Conexões persistentes** podem **expirar** entre invocações (**retry** do SDK cobre).
- **Variáveis de ambiente** para **configuração** (`TABLE_NAME`).
- **Parâmetros/segredos**: **cachear** (Powertools **Parameters**, **Lambda extension**) para reduzir chamadas.

## 5. Transferência de objetos (S3): alto nível

| Recurso | Uso |
|---|---|
| **`upload_file`/`download_file` (Boto3)** | **Multipart automático**, **retries**, **paralelismo** (`TransferConfig`) |
| **`upload_fileobj`/`download_fileobj`** | **Streams** |
| **S3 Transfer Manager** (Java/JS lib-storage) | **Multipart** concorrente, **progresso** |
| **Presigned URLs** | **Acesso temporário** sem credenciais ao cliente |
| **Streaming** | **Não carregar tudo na memória** (`Body.iter_chunks()`) |
| **Checksums** | **CRC32/CRC32C/SHA-1/SHA-256** (integridade) |
| **Select/Range GET** | Ler **parte** do objeto |

```python
from boto3.s3.transfer import TransferConfig
cfg = TransferConfig(multipart_threshold=64*1024*1024, multipart_chunksize=64*1024*1024, max_concurrency=10, use_threads=True)
s3.upload_file("grande.bin", "meu-bucket", "dados/grande.bin", Config=cfg,
               ExtraArgs={"ServerSideEncryption": "aws:kms", "Metadata": {"origem": "app-pedidos"}})
```

## 6. Boas práticas por linguagem (resumo)

| Linguagem | Dicas |
|---|---|
| **Python (Boto3)** | **Clients** > resources; `Config` para retries/timeouts/pool; **paginators/waiters**; **Decimal** no DynamoDB; **`botocore.exceptions.ClientError`** com `e.response["Error"]["Code"]` |
| **JavaScript v3** | **Modular** (importar só clientes necessários); `send(new Command())`; **`@aws-sdk/lib-dynamodb`**; **`marshall/unmarshall`**; `paginate*`; **`requestHandler`** (timeouts/keep-alive) |
| **Java v2** | **Builders**; **sync/async**; **HTTP client** (Apache/UrlConnection/Netty/CRT); **Enhanced DynamoDB Client** (`@DynamoDbBean`); **Waiters**; **`SdkException`/`AwsServiceException`** |
| **.NET** | **`AmazonXClient`** (`IAmazonX`), **DI**, `AWSSDK.Extensions.NETCore.Setup`; **async/await** |
| **Go v2** | **`config.LoadDefaultConfig`**, **`context`** (timeouts/cancelamento); **paginators**; **`smithy.APIError`** |
| **Geral** | **Tratar exceções por código** (não por mensagem), **logging com `RequestId`**, **timeouts**, **idempotência** |

### 6.1 Tratamento de erros (Python)

```python
from botocore.exceptions import ClientError
try:
    s3.head_object(Bucket="b", Key="k")
except ClientError as e:
    erro = e.response["Error"]; status = e.response["ResponseMetadata"]["HTTPStatusCode"]
    if erro["Code"] in ("404", "NoSuchKey", "NotFound"):
        existe = False
    else:
        raise                              # preservar contexto; não engolir erros desconhecidos
    # Log útil: erro["Code"], erro["Message"], e.response["ResponseMetadata"]["RequestId"]
```

## 7. Erros comuns

- **`float` no DynamoDB resource** (use `Decimal`).
- **Esquecer a dupla desserialização** SNS→SQS.
- **Não decodificar base64** (`isBase64Encoded`, Kinesis).
- **Não tratar `unquote_plus`** em chaves de objeto S3.
- **Criar clientes por invocação/requisição**.
- **Compartilhar sessions/resources** entre threads.
- **Carregar objetos grandes inteiros na memória**.
- **Waiters sem limites** (loop infinito).
- **Bloquear Lambda** em polling longo.
- **Comparar mensagens de erro** em vez de **códigos**.
- **Número como `N` string** esquecido no client de baixo nível.
- **Formato de data inconsistente** entre serviços.

## 8. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| `TypeError: Float types are not supported. Use Decimal` | `float` no resource DynamoDB | `Decimal(str(x))` |
| JSON de SNS “dentro de string” | Envelope SNS | `json.loads(body)` → `json.loads(Message)` ou **raw delivery** |
| Corpo ininteligível no Lambda | Base64 | Decodificar (`isBase64Encoded`) |
| Chave de S3 com `+`/`%20` | URL-encoding do evento | `unquote_plus` |
| `ParamValidationError` | Tipo/forma de parâmetro | Conferir o **modelo** da operação |
| Lentidão em Lambda | Cliente recriado/imports | Instanciar fora; imports mínimos |
| `WaiterError` | Timeout/estado de falha | Ajustar `Delay/MaxAttempts`; investigar o recurso |
| Memória alta ao ler S3 | `Body.read()` de objetos grandes | **Streaming/chunks/Range** |
| Perda de precisão em números | JS `number` | Usar **string/BigInt** |

## 9. Resumo rápido

- **Níveis**: **clients** (baixo nível, controle) vs **resources/document/enhanced** (conveniência); **utilitários**: **paginators**, **waiters**, **presigners**, **transfer managers**.
- **Serialização**: **JSON** (cuidado com **números/datas/binário**), **DynamoDB tipado** (`S/N/B/BOOL/NULL/L/M/SS/NS/BS`; **`N` é string**; **Decimal**; `TypeSerializer/Deserializer`, `marshall/unmarshall`; **Streams** chegam tipados), **base64** (Lambda/API Gateway/Kinesis/KMS), **Avro/Protobuf/Parquet** conforme caso; **versionar schemas**.
- **Eventos**: **SNS→SQS dupla desserialização**; **SQS body string**; **S3 keys URL-encoded**; **Kinesis base64**.
- **Waiters** com **limites**; em Lambda, preferir **Step Functions/eventos**.
- **Reuso de clientes** (fora do handler), **pools**, **thread-safety** (clients sim; resources/sessions não), **streaming** em S3, **TransferConfig**/CRT.
- **Erros por código** (`ClientError`), log com **RequestId**.

## 🧩 Quiz de Fixação

1. Qual a diferença entre client e resource no Boto3?
2. Por que `float` falha no resource do DynamoDB?
3. Como converter registros de DynamoDB Streams para dicts nativos?
4. Qual a dupla desserialização em SNS → SQS e como evitá-la?
5. Por que instanciar clientes fora do handler no Lambda?
6. Quando usar waiters e quando evitá-los?
7. Como ler objetos grandes do S3 sem estourar memória?

**Respostas:**

1. O client é baixo nível, 1:1 com a API (tipos explícitos); o resource é alto nível, com tipos nativos e conveniências, mas cobertura parcial.
2. O DynamoDB armazena números com precisão decimal e o resource exige Decimal para evitar perda de precisão do float.
3. Com TypeDeserializer (Python) ou unmarshall (JS), já que os registros chegam no formato tipado.
4. A mensagem SQS contém o envelope SNS e o campo Message é uma string JSON; evita-se habilitando raw message delivery na assinatura.
5. Para reaproveitar clientes, conexões e credenciais entre invocações warm, reduzindo latência e overhead.
6. Use para aguardar estados em scripts curtos com limites; evite em Lambda por minutos, preferindo Step Functions ou eventos de mudança de estado.
7. Usando streaming (iter_chunks/streams), Range GET e TransferConfig/multipart, sem chamar read() para carregar o objeto inteiro.
