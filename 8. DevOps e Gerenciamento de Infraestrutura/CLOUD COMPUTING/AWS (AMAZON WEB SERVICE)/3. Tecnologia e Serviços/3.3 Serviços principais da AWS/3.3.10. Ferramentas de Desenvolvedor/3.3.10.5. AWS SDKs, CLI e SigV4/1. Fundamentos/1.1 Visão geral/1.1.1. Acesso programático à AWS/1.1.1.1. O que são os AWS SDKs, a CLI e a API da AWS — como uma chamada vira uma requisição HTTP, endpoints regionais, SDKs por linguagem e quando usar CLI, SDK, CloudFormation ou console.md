### 1.1.1.1. O que são os AWS SDKs, a CLI e a API da AWS — como uma chamada vira uma requisição HTTP, endpoints regionais, SDKs por linguagem e quando usar CLI, SDK, CloudFormation ou console

> [!warning] Aviso
> Versões de SDKs, nomes de variáveis de ambiente, endpoints, padrões de retry e recursos de cada linguagem abaixo são **de memória e mudam com frequência**. **Confirme na documentação do AWS SDK da sua linguagem e da AWS CLI.** Código e comandos são ilustrativos e **não foram executados**. Contas, ARNs e nomes de buckets são fictícios. Esta nota cobre os pontos de **APIs e SDKs (retries, paginação, backoff)**, **serialização** e **chamadas autenticadas (SigV4)** do exame DVA-C03.

## 1. Tudo na AWS é uma API

Cada clique no console, cada comando da CLI e cada linha de SDK acabam em **uma requisição HTTPS** a um **endpoint de API** de um serviço AWS. Entender isso desmistifica **erros**, **retries**, **throttling** e **autenticação**:

```
Console / CLI / SDK / CloudFormation / Terraform
                 │  (todos chamam as MESMAS APIs)
                 ▼
   Requisição HTTPS  POST https://dynamodb.us-east-1.amazonaws.com/
   Headers: Authorization (assinatura SigV4), X-Amz-Date, X-Amz-Target, Content-Type…
   Corpo:   JSON/XML com os parâmetros da operação
                 ▼
   Serviço AWS (valida identidade/assinatura → IAM autoriza → executa → responde 200/4xx/5xx)
```

| Camada | O que é |
|---|---|
| **API do serviço** | Conjunto de **operações** (`PutItem`, `GetObject`, `RunInstances`) expostas via HTTPS |
| **SDK** | **Biblioteca** que **monta, assina, envia e interpreta** as requisições por você |
| **CLI** | **Ferramenta de linha de comando** construída **sobre o SDK** (Python/boto) |
| **Console** | Interface web que chama as **mesmas APIs** |
| **IaC (CloudFormation, CDK, Terraform)** | **Declara** recursos; por baixo, **chama APIs** |

> [!info] Em uma frase
> **SDK/CLI = cliente da API AWS: cuidam de credenciais, assinatura SigV4, serialização, retries e paginação, para você chamar serviços como funções do seu código.**

## 2. O que o SDK faz por você

| Responsabilidade | Detalhe |
|---|---|
| **Resolver credenciais** | **Credential provider chain** (variáveis, perfis, SSO, roles…) |
| **Resolver região e endpoint** | `AWS_REGION`, config, **endpoints regionais** (e FIPS/dual-stack) |
| **Serializar** | Converter objetos da linguagem em **JSON/XML/Query** do protocolo do serviço |
| **Assinar** | **SigV4** com as credenciais (headers de autenticação) |
| **Enviar** | HTTP/1.1 ou HTTP/2, **TLS**, **pool de conexões**, **timeouts** |
| **Tentar de novo** | **Retries** com **backoff exponencial e jitter** em **erros transitórios** |
| **Desserializar** | Converter a resposta em **objetos** e **exceções tipadas** |
| **Paginar** | **Paginators**/iteradores para respostas com **NextToken** |
| **Esperar** | **Waiters** (polling até um estado) |
| **Telemetria** | Logs de debug, **User-Agent**, hooks de métricas/tracing |

### 3.1 CLI v2: o que sabe fazer

```bash
aws s3 ls s3://meu-bucket --profile dev --region us-east-1
aws dynamodb scan --table-name pedidos --max-items 10 --query 'Items[].pedido_id.S' --output text
aws lambda invoke --function-name processar --payload '{"id":42}' --cli-binary-format raw-in-base64-out saida.json
aws sts get-caller-identity                      # quem sou eu para a AWS?
aws configure sso                                 # login federado (IAM Identity Center)
aws ec2 describe-instances --filters Name=tag:Ambiente,Values=prod --no-paginate
```

| Recurso | Uso |
|---|---|
| **`--query`** | Filtrar **no cliente** com **JMESPath** |
| **`--filter`/`--filters`** | Filtrar **no servidor** (quando suportado) |
| **Paginação automática** | Junta **páginas**; `--max-items`/`--page-size`/`--no-paginate` |
| **`--dry-run`** | Valida **permissões** sem executar (em alguns serviços) |
| **`--debug`** | **Log detalhado** (requisições/respostas/assinatura) |
| **`aws sts get-caller-identity`** | **Diagnóstico #1** de credenciais/permissões |
| **`--cli-binary-format raw-in-base64-out`** | **Payload JSON** no `lambda invoke` (CLI v2) |

## 4. Anatomia de uma chamada

### 4.1 Exemplo em Python

```python
import boto3
from botocore.config import Config

cfg = Config(retries={"mode": "standard", "max_attempts": 5}, connect_timeout=3, read_timeout=10,
             user_agent_extra="app-pedidos/1.4.2")
dynamodb = boto3.client("dynamodb", region_name="us-east-1", config=cfg)    # credenciais resolvidas pela chain

resp = dynamodb.get_item(TableName="pedidos", Key={"pedido_id": {"S": "123"}})
item = resp.get("Item")                                                       # sem Item = não encontrado (não é erro)
```

### 4.2 Exemplo em JavaScript (v3)

```javascript
import { DynamoDBClient, GetItemCommand } from "@aws-sdk/client-dynamodb";
const client = new DynamoDBClient({ region: "us-east-1", maxAttempts: 5 });
const { Item } = await client.send(new GetItemCommand({ TableName: "pedidos", Key: { pedido_id: { S: "123" } } }));
```

### 4.3 O que viaja na rede (simplificado)

```
POST / HTTP/1.1
Host: dynamodb.us-east-1.amazonaws.com

               SignedHeaders=content-type;host;x-amz-date;x-amz-target, Signature=<hash>
```

## 5. Endpoints e regiões

| Conceito | Detalhe (de memória — confirmar) |
|---|---|
| **Endpoint regional** | `https://<serviço>.<região>.amazonaws.com` (a **região** faz parte da **assinatura**) |
| **Resolução de região** | Parâmetro explícito > `AWS_REGION`/`AWS_DEFAULT_REGION` > **config** do perfil > **metadados** (EC2/ECS/Lambda: **`AWS_REGION`** é definida) |
| **Endpoints globais** | **IAM**, **STS** (global/regional), **CloudFront**, **Route 53** — **usar endpoints regionais do STS** reduz latência e riscos |
| **FIPS** | Endpoints **FIPS** (`use_fips_endpoint`) para **conformidade** |
| **Dual-stack** | **IPv4+IPv6** (`use_dualstack_endpoint`) |
| **VPC endpoints (PrivateLink)** | O SDK pode **usar endpoint de VPC** (`endpoint_url`) para **tráfego privado** |
| **Endpoint customizado** | `endpoint_url` (ex.: **LocalStack**, **DynamoDB Local**, **S3-compatible**) |
| **S3 especial** | **Virtual-hosted** (`bucket.s3.região.amazonaws.com`), **path-style** (legado), **Transfer Acceleration**, **Access Points**, **Multi-Region Access Points** (SigV4a) |

## 7. SDK vs chamar a API “na mão”

| Critério | **SDK** | **HTTP direto + SigV4** |
|---|---|---|
| **Assinatura** | Automática | Você implementa (**complexo e propenso a erro**) |
| **Retries/paginação/erros tipados** | **Sim** | Não |
| **Atualização de APIs** | Via **versão do SDK** | Manual |
| **Quando** | **Quase sempre** | **Linguagens sem SDK**, **gateways**, **integrações especiais** |

## 8. Pontos que o exame DVA-C03 cobra (visão geral)

| Tópico | Ideia central |
|---|---|
| **Credenciais** | **Credential provider chain**; **roles** (EC2/ECS/Lambda) em vez de chaves; **credenciais temporárias** |
| **SigV4** | **Assina** requisições com chaves derivadas; **tempo** do cliente importa (**clock skew**) |
| **Retries** | **Backoff exponencial com jitter**; SDK faz **retries automáticos** em erros **transitórios** (throttling, 5xx, timeouts) |
| **Throttling** | `ThrottlingException`/`ProvisionedThroughputExceededException`/`SlowDown` (S3 **503**)/429 |
| **Paginação** | `NextToken`/`Marker`/`ContinuationToken`/`LastEvaluatedKey` |
| **Idempotência** | **ClientToken**/`ClientRequestToken` para operações seguras de repetir |
| **Timeouts** | **connect/read**; evitar chamadas **penduradas** |
| **Serialização** | JSON/base64; **DynamoDB attribute values** (`S`, `N`, `M`, `L`) vs **Document client/TypeSerializer** |
| **Waiters** | Aguardar **estado** (ex.: `instance_running`) |
| **Região** | **Por cliente**; **endpoints regionais** |

## 9. Erros comuns

- **Chaves de acesso fixas no código/repositório** (usar **roles**).
- **Criar clientes a cada requisição** (sem **reuso** de conexão): lento, pode **esgotar recursos**.
- **Ignorar paginação** (processar só a **primeira página**).
- **Retries manuais por cima dos do SDK** (**amplificação** de carga).
- **Sem timeouts** (chamadas travadas).
- **Região errada** (recurso “não existe”).
- **Confundir erro de cliente (4xx) com transitório** (retry em erro de **validação** não resolve).
- **Assumir que `Item` ausente é erro** (DynamoDB retorna 200 sem `Item`).
- **Usar o endpoint global do STS** em vez do regional sem necessidade.
- **Não definir `User-Agent`/identificar a aplicação** (atrapalha **suporte/diagnóstico**).

## 10. Troubleshooting inicial

| Sintoma | Causas prováveis | Ações |
|---|---|---|
| `Unable to locate credentials` / `NoCredentialsError` | Chain sem credenciais | `aws sts get-caller-identity`; ver env/perfil/role |
| `AccessDenied` | IAM/SCP/resource policy | **Simulator**, CloudTrail; ver o **principal** efetivo |
| `SignatureDoesNotMatch`/`RequestTimeTooSkewed` | Relógio; região/serviço; headers alterados por proxy | **NTP**; região correta; evitar **proxies** que mudam headers |
| `Could not connect to the endpoint URL` | Rede/região/DNS/endpoint | Testar conectividade; **região**; **VPC endpoints** |
| `ThrottlingException` | Taxa acima do limite | **Backoff**, reduzir taxa, **quotas** |
| Chamadas lentas | Cliente recriado; sem pool; região distante | Reusar clientes; **região**; **timeouts** |

## 11. Resumo rápido

- **Tudo é API HTTPS**; **SDK/CLI** (e console/IaC) **chamam as mesmas APIs**; o SDK cuida de **credenciais, região/endpoint, serialização, SigV4, retries, paginação, waiters**.
- **SDKs**: Boto3, JS v3, Java v2, .NET, Go…; **CLI v2** (SSO, `--query`, paginação, `sts get-caller-identity`).
- **Região/endpoint** fazem parte da **assinatura**; preferir **endpoints regionais** (STS), FIPS/dual-stack/VPC endpoints quando preciso.
- **Usar SDK** em vez de HTTP manual; **CLI** para scripts; **IaC** para infraestrutura.
- Para o DVA-C03: **credential chain/roles**, **SigV4/clock skew**, **retries com backoff+jitter**, **throttling**, **paginação**, **idempotência**, **timeouts**, **serialização**.
