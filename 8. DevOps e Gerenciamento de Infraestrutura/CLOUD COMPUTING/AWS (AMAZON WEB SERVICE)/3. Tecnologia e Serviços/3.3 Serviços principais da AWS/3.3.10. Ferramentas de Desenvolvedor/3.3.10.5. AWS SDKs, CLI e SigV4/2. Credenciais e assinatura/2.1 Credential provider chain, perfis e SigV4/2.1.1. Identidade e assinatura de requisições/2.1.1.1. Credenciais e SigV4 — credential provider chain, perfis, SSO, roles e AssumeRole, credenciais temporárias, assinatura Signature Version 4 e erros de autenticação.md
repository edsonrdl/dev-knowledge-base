### 2.1.1.1. Credenciais e SigV4 — credential provider chain, perfis, SSO, roles e AssumeRole, credenciais temporárias, assinatura Signature Version 4 e erros de autenticação

> [!warning] Aviso
> Ordem exata da credential provider chain, nomes de variáveis, comportamento de cache/renovação e detalhes do SigV4 variam por **SDK e versão**. **Confirme na documentação “Credential provider chain” do seu SDK e na especificação “Signature Version 4”.** Código, arquivos de configuração e comandos são ilustrativos e **não foram executados**. Chaves/tokens mostrados são **placeholders**; nunca versione credenciais reais.

## 1. Credenciais: quem é você para a AWS?

Toda chamada precisa **provar identidade**. As credenciais AWS têm **três formatos**:

| Tipo | Componentes | Duração | Exemplo de prefixo |
|---|---|---|---|
| **Chaves de longo prazo** (IAM user) | `AccessKeyId` + `SecretAccessKey` | **Indefinida** (até rotacionar/excluir) | `AKIA…` |
| **Credenciais temporárias** (STS) | `AccessKeyId` + `SecretAccessKey` + **`SessionToken`** | **Minutos a horas** (15 min–12 h) | `ASIA…` |
| **Sem credencial AWS** (anônimo) | — | — | Apenas **recursos públicos** (S3 público, etc.) |

> [!info] Regra de ouro
> **Prefira credenciais temporárias (roles)** a chaves de longo prazo. **Aplicações na AWS** usam **roles** (EC2 instance profile, ECS task role, Lambda execution role, EKS IRSA/Pod Identity); **pessoas** usam **IAM Identity Center (SSO)** ou **AssumeRole**; **CI/CD** usa **OIDC** (GitHub Actions/GitLab) → **AssumeRoleWithWebIdentity**.

## 2. A credential provider chain

### 2.1 O que é

Quando você cria um cliente **sem informar credenciais**, o SDK percorre uma **cadeia de provedores** **em ordem**, parando no **primeiro** que fornecer credenciais válidas.

```
Cliente sem credenciais explícitas
   │
   ├─ 1) Parâmetros explícitos no código (se informados)            ← evitar
   ├─ 2) Variáveis de ambiente (AWS_ACCESS_KEY_ID/…SECRET…/…SESSION_TOKEN)
   ├─ 3) Web identity / OIDC (AWS_WEB_IDENTITY_TOKEN_FILE + AWS_ROLE_ARN)  ← EKS IRSA, GitHub OIDC
   ├─ 4) Perfil do arquivo de config/credenciais (~/.aws/credentials, ~/.aws/config) — inclui SSO, assume role
   ├─ 5) Credenciais de processo (credential_process)
   ├─ 6) Credenciais de container (AWS_CONTAINER_CREDENTIALS_RELATIVE_URI) ← ECS task role / EKS Pod Identity
   └─ 7) Instance metadata (IMDSv2) ← EC2 instance profile
```

(A **ordem** e os **provedores** variam por SDK/versão — Lambda injeta credenciais como **variáveis de ambiente** da **execution role**.)

### 2.2 Variáveis de ambiente importantes

| Variável | Função |
|---|---|
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_SESSION_TOKEN` | Credenciais (**temporárias** exigem o token) |
| `AWS_PROFILE` | Perfil a usar |
| `AWS_REGION` / `AWS_DEFAULT_REGION` | Região |
| `AWS_CONFIG_FILE` / `AWS_SHARED_CREDENTIALS_FILE` | Caminhos dos arquivos |
| `AWS_ROLE_ARN` / `AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_SESSION_NAME` | **OIDC/IRSA** |
| `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` / `…_FULL_URI` | **ECS/EKS** |
| `AWS_EC2_METADATA_DISABLED` | Desabilita IMDS (testes locais) |
| `AWS_MAX_ATTEMPTS` / `AWS_RETRY_MODE` | **Retries** |
| `AWS_ENDPOINT_URL` / `AWS_ENDPOINT_URL_<SERVIÇO>` | Endpoint customizado |
| `AWS_USE_FIPS_ENDPOINT` / `AWS_USE_DUALSTACK_ENDPOINT` | FIPS/dual-stack |
| `AWS_CA_BUNDLE` | **CA** customizada (proxy TLS corporativo) |

### 2.3 Lambda, ECS, EC2, EKS: onde ficam as credenciais

| Ambiente | Mecanismo |
|---|---|
| **AWS Lambda** | **Execution role** → credenciais temporárias em **variáveis de ambiente** (`AWS_ACCESS_KEY_ID`…) renovadas automaticamente |
| **Amazon ECS/Fargate** | **Task role** → **endpoint de credenciais do container** (`169.254.170.2`) |
| **Amazon EC2** | **Instance profile** → **IMDSv2** (`169.254.169.254`) com **token** de sessão |
| **Amazon EKS** | **IRSA** (web identity) ou **EKS Pod Identity** |
| **CodeBuild** | **Service role** do projeto |
| **GitHub Actions** | **OIDC** → `AssumeRoleWithWebIdentity` (sem chaves) |
| **Local (dev)** | **SSO** (`aws sso login`) ou perfil com `assume role` |

> [!warning] Cuidado: variáveis de ambiente têm precedência
> Se `AWS_ACCESS_KEY_ID` estiver **definida no shell** (esquecida), ela **sobrepõe** o perfil/role — causa de “**por que está usando a identidade errada?**”. Use `aws sts get-caller-identity` para **confirmar**.

## 3. Perfis (`~/.aws/config` e `~/.aws/credentials`)

```ini
# ~/.aws/config

[sso-session empresa]

[profile prod-readonly]

[profile ci]

```

```ini
# ~/.aws/credentials  (evitar chaves de longo prazo; se usar, restringir permissões do arquivo)

aws_secret_access_key = <segredo>
```

```bash

aws sts get-caller-identity --profile prod-readonly

```

## 4. IAM Identity Center (SSO) para desenvolvedores

| Aspecto | Detalhe |
|---|---|
| **Fluxo** | `aws sso login` → autenticação **no navegador** (IdP corporativo/MFA) → **token** → o SDK **obtém credenciais temporárias** por **conta/role** |
| **Vantagens** | **Sem chaves** no disco; **MFA**; **acesso centralizado**; **revogação** fácil |
| **Cache** | Token em `~/.aws/sso/cache`; **expira** (horas) |
| **SDKs** | Suportam via **perfil** (`sso_session`) |
| **Boas práticas** | **Perfis por conta/ambiente**, **permission sets** mínimos, **sessão curta** |

## 5. AssumeRole e STS

### 5.1 Conceitos

| API (STS) | Uso |
|---|---|
| **`AssumeRole`** | Assumir uma **role** (mesma ou outra conta) com credenciais **temporárias** |
| **`AssumeRoleWithWebIdentity`** | **OIDC** (EKS IRSA, GitHub OIDC, Cognito identity pools) |
| **`AssumeRoleWithSAML`** | **SAML** (federação corporativa) |
| **`GetSessionToken`** | Credenciais temporárias para **IAM user** (com MFA) |
| **`GetCallerIdentity`** | **Quem sou eu?** (**sem permissões** especiais) |
| **`GetFederationToken`** | Federação (usuário/broker) — uso limitado |

### 5.2 Exemplo (Python)

```python
import boto3
sts = boto3.client("sts", region_name="us-east-1")
resp = sts.assume_role(RoleArn="arn:aws:iam::999999999999:role/ProdReadOnly",
                       RoleSessionName="job-relatorio", DurationSeconds=3600,
                       ExternalId="id-compartilhado-com-terceiro")     # para acesso de terceiros (confused deputy)
c = resp["Credentials"]
s3 = boto3.client("s3", aws_access_key_id=c["AccessKeyId"], aws_secret_access_key=c["SecretAccessKey"],
                  aws_session_token=c["SessionToken"])
```

### 5.3 Trust policy e permissões

| Elemento | Detalhe |
|---|---|
| **Trust policy** (da role alvo) | **Quem** pode assumir (`Principal`: conta/role/serviço/IdP) + **condições** (`ExternalId`, `aws:MultiFactorAuthPresent`, `aws:SourceIp`, `aws:PrincipalOrgID`) |
| **Permissions policy** (do chamador) | `sts:AssumeRole` **para o ARN da role** |
| **Duração** | **15 min – 12 h** (até o **máximo** da role); **encadeamento de roles** (**role chaining**) limita a **1 h** |
| **Session policy** | **Restringe** ainda mais a sessão (interseção) |
| **Session tags** | **Atributos** para **ABAC** |
| **SourceIdentity/RoleSessionName** | **Rastreabilidade** no CloudTrail |

### 5.4 Renovação automática

Os SDKs usam **credentials providers** que **renovam automaticamente** credenciais temporárias **antes de expirar** (SSO, assume role com `source_profile`, instance profile, container). **Credenciais obtidas manualmente** (`assume_role` e passadas como strings) **não renovam** — **você** deve **renovar** (ou usar `RefreshableCredentials`/provedores).

## 6. Signature Version 4 (SigV4)

### 6.1 O que é

**SigV4** é o **protocolo de assinatura** das requisições à API AWS: prova **identidade** (possui a **secret key**) e **integridade** (a requisição **não foi alterada**) **sem enviar a chave secreta**.

```
Segredo (SecretAccessKey) ──HMAC encadeado──▶ Chave de assinatura (derivada: data + região + serviço)
Requisição canônica (método, URI, query, headers assinados, hash do payload) ──▶ String to sign ──HMAC──▶ Assinatura
Cabeçalho Authorization: AWS4-HMAC-SHA256 Credential=…, SignedHeaders=…, Signature=…
```

### 6.2 Os 4 passos

| Passo | Descrição |
|---|---|
| **1. Requisição canônica** | Normalizar: **método**, **URI canônica**, **query string ordenada**, **headers canônicos** (minúsculos, ordenados) e **hash SHA-256 do corpo** |
| **2. String to sign** | `AWS4-HMAC-SHA256` + **timestamp** + **escopo de credencial** (`data/região/serviço/aws4_request`) + **hash da requisição canônica** |
| **3. Chave de assinatura** | `kDate=HMAC("AWS4"+secret, data)` → `kRegion` → `kService` → `kSigning=HMAC(kService,"aws4_request")` |
| **4. Assinatura** | `HMAC(kSigning, stringToSign)` (hex) e **inclusão** no header `Authorization` (ou na **query string** em **presigned URLs**) |

### 6.3 Pontos que caem na prova

| Ponto | Detalhe |
|---|---|
| **Escopo da credencial** | **Data + região + serviço**: mudar a **região/serviço** **invalida** |
| **Tempo** | `X-Amz-Date`: o servidor rejeita se o relógio diferir mais de **~5 minutos** → **`RequestTimeTooSkewed`/`SignatureDoesNotMatch`** → **sincronizar com NTP** |
| **Headers assinados** | `host` e `x-amz-date` (e `x-amz-security-token` para temporárias); **proxies que alteram headers** quebram a assinatura |
| **Payload** | **Hash** do corpo (`x-amz-content-sha256`); S3 permite **`UNSIGNED-PAYLOAD`** (e **streaming chunked**) |
| **Credenciais temporárias** | Incluir **`X-Amz-Security-Token`** |
| **Presigned URL** | **Assinatura na query string** (`X-Amz-Algorithm/Credential/Date/Expires/SignedHeaders/Signature`) com **validade** limitada |
| **SigV4a** | Variante **multi-região** (ECDSA) para **S3 Multi-Region Access Points**/**CloudFront**/etc. |
| **SigV2** | **Legado/obsoleto** (S3 antigo) |
| **API Gateway com IAM auth** | O **cliente** assina com **SigV4** (serviço `execute-api`) |
| **Quem assina** | O **SDK/CLI** automaticamente; **manual** só em casos especiais |

### 6.4 Exemplo: assinar uma chamada ao API Gateway (IAM auth) em Python

```python
import requests
from botocore.auth import SigV4Auth
from botocore.awsrequest import AWSRequest
import boto3

sessao = boto3.Session(); creds = sessao.get_credentials().get_frozen_credentials()
req = AWSRequest(method="POST", url="https://abc123.execute-api.us-east-1.amazonaws.com/prod/pedidos",
                 data='{"id":42}', headers={"Content-Type": "application/json"})
SigV4Auth(creds, "execute-api", "us-east-1").add_auth(req)
r = requests.post(req.url, data=req.body, headers=dict(req.headers))
```

(Alternativa: a biblioteca **`aws-requests-auth`**/**`requests-aws4auth`** ou clientes que **assinam** por você.)

|---|---|

## 8. Erros de autenticação e autorização (e como distinguir)

| Erro | Significado | Causa/ação |
|---|---|---|
| **`NoCredentialsError` / `Unable to locate credentials`** | **Nenhuma** credencial na chain | Configurar role/perfil/env |
| **`InvalidClientTokenId`** | **Access key inexistente/inválida** | Chave errada/excluída; credenciais de outra partição |
| **`ExpiredToken` / `ExpiredTokenException`** | **Credencial temporária expirou** | Renovar; usar provider com **refresh**; `aws sso login` |
| **`UnrecognizedClientException`** | Credenciais **não reconhecidas** | Chave inválida/região/partição |
| **`SignatureDoesNotMatch`** | **Assinatura** não confere | **Secret errada**, **relógio**, **região/serviço**, **headers** alterados, **URL/encoding** |
| **`RequestTimeTooSkewed`** | **Relógio** fora de ~5 min | **NTP** |
| **`AccessDenied`/`AccessDeniedException`/`UnauthorizedOperation`** | **Autenticou, mas sem permissão** | **IAM/SCP/resource policy/boundary**; ver **mensagem** e **CloudTrail** |
| **`AuthFailure`** (EC2) | Falha de autenticação | Credenciais/região |
| **`InvalidSignatureException`** | Variação de assinatura inválida | Idem |
| **`MissingAuthenticationToken`** (API GW) | **Requisição sem assinatura** | Assinar com SigV4 / enviar token |
| **`The security token included in the request is expired/invalid`** | Token de sessão **vencido/inválido** | Renovar |

> [!tip] Autenticação vs autorização
> **401/“credenciais inválidas/expiradas/assinatura”** = problema de **autenticação**; **403/`AccessDenied`** = **autenticado, mas não autorizado** (**IAM/SCP/boundary/resource policy**). A mensagem de erro costuma indicar **qual** política **negou** (em muitos serviços).

## 10. Boas práticas

1. **Nunca** embutir chaves no código/imagens/repositórios; **detectar** com **secret scanning**.
2. **Roles** para cargas na AWS; **SSO/OIDC** para humanos e CI.
3. **Menor privilégio**; **sessões curtas**; **MFA** para papéis sensíveis.
4. **Não assinar manualmente** (usar SDK); se necessário, **bibliotecas testadas**.
5. **NTP** em todos os hosts.
6. **STS regional**; **IMDSv2** obrigatório.
7. **Trocar chaves de longo prazo** por temporárias; **rotacionar** o que restar.
8. **Identificar** sessões (`RoleSessionName`, `SourceIdentity`) para **auditoria**.
9. **Cache e renovação** corretas (providers do SDK).
10. **Não logar** credenciais/headers de autorização.

## 11. Erros comuns

- **Variáveis de ambiente esquecidas** sobrescrevendo o perfil.
- **Chaves de longo prazo** em CI/containers.
- **Credenciais temporárias “coladas” sem renovação** (expiram no meio do job).
- **Relógio dessincronizado** (VMs/containers/laptops).
- **Proxy corporativo** reescrevendo headers (quebra SigV4).
- **Confundir `AccessDenied` com assinatura inválida**.
- **Trust policy** sem condições (`ExternalId`/MFA/org).
- **Role chaining** esperando 12 h (limite 1 h).
- **Endpoint/região incorretos** na assinatura.
- **Armazenar o `aws_session_token`** de forma persistente.

## 12. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| Identidade errada no script | Env vars/perfil | `get-caller-identity`; limpar `AWS_*` |
| `ExpiredToken` em jobs longos | Sem refresh | Usar providers; renovar; sessões mais longas |
| `SignatureDoesNotMatch` local | Relógio/proxy/secret | NTP; sem proxy alterando; reconfigurar |
| `AccessDenied` só em Lambda | Execution role sem permissão | Ajustar a role; verificar **resource policies** |
| `AssumeRole` negado | Trust policy/permissão/condições | Ver trust, `sts:AssumeRole`, MFA/ExternalId |
| SSO “token expired” | Sessão SSO venceu | `aws sso login` |
| EC2: sem credenciais | IMDSv2/hop limit/role ausente | Instance profile; `HttpPutResponseHopLimit` (containers) |
| ECS: sem credenciais | Task role ausente | Definir **task role** |

## 13. Resumo rápido

- **Credenciais**: **longo prazo (AKIA)** vs **temporárias (ASIA + token)**; **preferir roles/SSO/OIDC**.
- **Credential provider chain**: **parâmetros → env vars → web identity → perfis (SSO/assume role) → process → container → IMDSv2**; **env vars têm precedência** (cuidado).
- **AssumeRole/STS**: trust policy + `sts:AssumeRole`; **ExternalId** (terceiros), **MFA**, **role chaining = 1 h**, **session policy/tags**; renovação **automática** só com providers.
- **SigV4**: requisição canônica → string to sign → chave derivada (**data/região/serviço**) → assinatura; **relógio ±5 min**, **headers assinados**, **payload hash**, **presigned** na query, **SigV4a** multi-região.
- **Erros**: `NoCredentials`, `InvalidClientTokenId`, `ExpiredToken`, `SignatureDoesNotMatch`, `RequestTimeTooSkewed`, **`AccessDenied` (autorização)**.
- **Diagnóstico**: `sts get-caller-identity`, env/perfis, NTP, `--debug`, simulator/CloudTrail.

## 🧩 Quiz de Fixação

1. Qual a diferença entre credenciais AKIA e ASIA?
2. Qual a ordem geral da credential provider chain?
3. Por que variáveis de ambiente podem causar identidade errada?
4. Quais os quatro passos do SigV4?
5. O que significa `RequestTimeTooSkewed` e como corrigir?
6. Qual a diferença entre `AccessDenied` e `SignatureDoesNotMatch`?
7. Para que serve o `ExternalId` no AssumeRole?

**Respostas:**

1. AKIA são chaves de longo prazo de IAM user; ASIA são credenciais temporárias do STS e exigem o session token.
2. Parâmetros explícitos, variáveis de ambiente, web identity, perfis (SSO/assume role), credential_process, credenciais de container (ECS/EKS) e instance metadata (IMDSv2).
3. Porque têm precedência sobre perfis e roles; credenciais esquecidas no shell sobrepõem a identidade esperada.
4. Montar a requisição canônica, criar a string to sign, derivar a chave de assinatura (data/região/serviço) e calcular/incluir a assinatura HMAC.
5. O relógio do cliente difere mais de ~5 minutos do servidor; sincronizar com NTP.
6. AccessDenied indica que autenticou mas não tem permissão (IAM/SCP/policies); SignatureDoesNotMatch indica falha de assinatura (chave, relógio, região/serviço, headers).
7. Evitar o confused deputy: um terceiro só consegue assumir a role fornecendo o identificador combinado.
