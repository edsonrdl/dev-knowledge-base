### 2.1.1.1. Template SAM em detalhe — Globals, Function, Api e HttpApi, SimpleTable, LayerVersion, StateMachine, eventos, políticas gerenciadas, parâmetros, Outputs e funções intrínsecas

> [!warning] Aviso
> Nomes de propriedades, policy templates, valores de runtime e limites abaixo são **de memória e mudam**. **Confirme na especificação do AWS SAM e na referência do CloudFormation.** Os trechos de YAML são ilustrativos e **não foram executados**. Esta nota cobre as skills de **escrever e entender templates de IaC para serverless** no DVA-C03.

## 1. Anatomia de um template SAM

Um template SAM é um template CloudFormation com a linha `Transform`. As seções são as mesmas do CloudFormation, mais a seção `Globals`:

| Seção | Obrigatória? | Função |
|---|---|---|
| `AWSTemplateFormatVersion` | Não (recomendada: `'2010-09-09'`) | Versão do formato |
| `Transform` | **Sim (para SAM)** | `AWS::Serverless-2016-10-31` |
| `Description` | Não | Texto descritivo |
| `Metadata` | Não | Informações extras (ex.: `AWS::ServerlessRepo::Application`) |
| `Parameters` | Não | Valores informados no deploy |
| `Mappings` | Não | Tabelas estáticas de lookup |
| `Conditions` | Não | Criação condicional de recursos |
| **`Globals`** | Não (**exclusiva do SAM**) | Propriedades comuns a todas as funções/APIs |
| `Resources` | **Sim** | Os recursos |
| `Outputs` | Não | Valores exportados/exibidos |

A **única seção obrigatória** é `Resources`. Em SAM, `Transform` é obrigatória para o template ser interpretado como SAM.

## 2. Globals: evitar repetição

Sem `Globals`, cada função repetiria runtime, timeout, memória, variáveis de ambiente, layers e tracing. Com `Globals`, você define uma vez:

```yaml
Globals:
  Function:
    Runtime: nodejs20.x
    Architectures: [arm64]
    Timeout: 15
    MemorySize: 512
    Tracing: Active
    Environment:
      Variables:
        LOG_LEVEL: info
        STAGE: !Ref Stage
    Layers:
      - !Ref DepsLayer
  Api:
    Cors:
      AllowOrigin: "'https://app.exemplo.com'"
      AllowHeaders: "'Content-Type,Authorization'"
  HttpApi:
    CorsConfiguration:
      AllowOrigins: ["https://app.exemplo.com"]
```

Regras de combinação entre `Globals` e a propriedade da função:

| Tipo de propriedade | Comportamento |
|---|---|
| **Escalares** (string, número, booleano) | A **função sobrescreve** o valor global |
| **Mapas** (ex.: `Environment.Variables`) | Os mapas são **mesclados**; chaves iguais, a da função vence |
| **Listas** (ex.: `Layers`, `Policies`) | As listas são **concatenadas** (global + função) |

Recursos suportados em `Globals`: `Function`, `Api`, `HttpApi`, `SimpleTable`, `StateMachine` (e outros adicionados ao longo do tempo). Nem toda propriedade pode ser global (por exemplo, `CodeUri` e `Handler` costumam ser específicos de cada função, embora seja possível definir `CodeUri` global se todas compartilharem o mesmo pacote).

> [!tip] Cuidado com `Policies` global
> Como listas são concatenadas, uma política global é **somada** às da função. Colocar uma política ampla em `Globals` concede essa permissão a **todas** as funções, o oposto do privilégio mínimo.

## 3. AWS::Serverless::Function em profundidade

As propriedades mais cobradas e usadas:

| Propriedade | Significado |
|---|---|
| `Handler` | Ponto de entrada (`arquivo.funcao` em Python, `arquivo.metodo` em Node) |
| `Runtime` | `python3.12`, `nodejs20.x`, `java21`, `dotnet8`, `provided.al2023`… |
| `CodeUri` | Pasta local (ou URI S3) com o código |
| `InlineCode` | Código embutido no template (exemplos pequenos) |
| `Architectures` | `x86_64` (padrão) ou `arm64` (Graviton, frequentemente mais barato) |
| `MemorySize` / `Timeout` | Recursos e tempo máximo (Timeout até 900 s) |
| `Environment.Variables` | Variáveis de ambiente |
| `Policies` | Lista de policy templates, ARNs de políticas gerenciadas ou documentos inline |
| `Role` | ARN de uma role **existente** (se informada, o SAM **não** cria role e ignora `Policies`) |
| `PermissionsBoundary` | ARN do limite de permissões aplicado à role gerada |
| `Events` | Gatilhos (API, filas, streams, agendamentos…) |
| `Layers` | Até 5 layers |
| `Tracing` | `Active` habilita X-Ray |
| `ReservedConcurrentExecutions` | Concorrência reservada |
| `ProvisionedConcurrencyConfig` | Concorrência provisionada (**exige alias**, via `AutoPublishAlias`) |
| `AutoPublishAlias` | Publica versão e cria alias a cada mudança de código |
| `DeploymentPreference` | Estratégia de deploy gradual via CodeDeploy |
| `DeadLetterQueue` | SQS/SNS para invocações assíncronas falhas |
| `EventInvokeConfig` | Retentativas e destinos on success/on failure |
| `VpcConfig` | Subnets e security groups |
| `FunctionUrlConfig` | URL HTTPS dedicada (`AuthType: AWS_IAM` ou `NONE`) |
| `PackageType` | `Zip` (padrão) ou `Image` |
| `ImageUri` / `ImageConfig` | Para imagens de container |
| `Tags` | Tags propagadas |

### 3.1 Função como imagem de container

```yaml
Resources:
  Processador:
    Type: AWS::Serverless::Function
    Properties:
      PackageType: Image
      MemorySize: 1024
      Timeout: 60
    Metadata:
      Dockerfile: Dockerfile
      DockerContext: ./src/processador
      DockerTag: v1
```

Com `PackageType: Image`, o `sam build` constrói a imagem usando o bloco `Metadata`, e o `sam deploy` a envia para o **ECR** (repositório gerenciado com `--resolve-image-repos` ou informado em `image_repositories`).

## 4. Políticas: policy templates, ARNs e documentos inline

A propriedade `Policies` aceita três formas, que podem ser misturadas:

```yaml
Policies:
  - DynamoDBCrudPolicy:                # policy template do SAM
      TableName: !Ref Tabela
  - AWSLambdaVPCAccessExecutionRole    # política gerenciada pela AWS (nome)
  - Statement:                         # documento inline
      - Effect: Allow
        Action: ssm:GetParameter
        Resource: !Sub "arn:aws:ssm:${AWS::Region}:${AWS::AccountId}:parameter/app/*"
```

Policy templates comuns (a lista completa fica na documentação):

| Template | Concede |
|---|---|
| `DynamoDBReadPolicy` / `DynamoDBWritePolicy` / `DynamoDBCrudPolicy` | Leitura / escrita / CRUD em **uma tabela** |
| `S3ReadPolicy` / `S3CrudPolicy` / `S3WritePolicy` | Acesso a **um bucket** |
| `SQSSendMessagePolicy` / `SQSPollerPolicy` | Enviar / consumir de **uma fila** |
| `SNSPublishMessagePolicy` | Publicar em **um tópico** |
| `LambdaInvokePolicy` | Invocar **uma função** |
| `SSMParameterReadPolicy` | Ler **parâmetros com certo prefixo** |
| `KMSDecryptPolicy` | Descriptografar com **uma chave** |
| `StepFunctionsExecutionPolicy` | Iniciar execuções de **uma state machine** |
| `EventBridgePutEventsPolicy` | Enviar eventos a **um barramento** |

A grande vantagem: cada template **restringe ao recurso** que você passa (`TableName`, `BucketName`…), então o resultado é **privilégio mínimo** sem escrever JSON de IAM.

> [!warning] Regras importantes
> - Se você define `Role`, as `Policies` são **ignoradas** (a role é sua responsabilidade).
> - Sem `Policies` nem `Role`, a função recebe apenas a `AWSLambdaBasicExecutionRole` (logs).
> - Policy templates **resolvem para políticas inline** na role gerada.

## 5. Eventos: o que dispara a função

A propriedade `Events` é um mapa de **nome lógico → tipo + propriedades**. Tipos principais:

| Tipo | Gatilho | Observações |
|---|---|---|
| `Api` | REST API (API Gateway v1) | Cria `ServerlessRestApi` implícita se não houver `RestApiId` |
| `HttpApi` | HTTP API (v2) | Cria `ServerlessHttpApi` implícita |
| `S3` | Eventos de objeto | O bucket **precisa estar no mesmo template** |
| `SNS` | Tópico | Cria subscription |
| `SQS` | Fila (event source mapping) | `BatchSize`, `MaximumBatchingWindowInSeconds`, `FunctionResponseTypes` |
| `Kinesis` / `DynamoDB` | Streams | `StartingPosition`, `BatchSize`, `BisectBatchOnFunctionError`, `DestinationConfig` |
| `Schedule` / `ScheduleV2` | Agendamento (rate/cron) | `ScheduleV2` usa o EventBridge Scheduler |
| `EventBridgeRule` / `CloudWatchEvent` | Regras de evento | Padrão de evento |
| `Cognito` | Triggers do user pool | |
| `MSK`, `MQ`, `SelfManagedKafka`, `DocumentDB` | Fontes adicionais | |

Exemplo com vários gatilhos:

```yaml
Events:
  Fila:
    Type: SQS
    Properties:
      Queue: !GetAtt FilaPedidos.Arn
      BatchSize: 10
      FunctionResponseTypes: [ReportBatchItemFailures]
  Diario:
    Type: ScheduleV2
    Properties:
      ScheduleExpression: "cron(0 3 * * ? *)"
      ScheduleExpressionTimezone: America/Sao_Paulo
  Upload:
    Type: S3
    Properties:
      Bucket: !Ref BucketEntrada
      Events: s3:ObjectCreated:*
      Filter:
        S3Key:
          Rules:
            - Name: suffix
              Value: .csv
```

## 6. APIs: Api versus HttpApi

| Característica | `AWS::Serverless::Api` (REST) | `AWS::Serverless::HttpApi` (HTTP) |
|---|---|---|
| Custo e latência | Maior | **Menor** |
| Chaves de API e usage plans | **Sim** | Não |
| Validação de request, cache, WAF direto | **Sim** | Limitado |
| Autorizadores | Lambda (token/request), Cognito, IAM | **JWT/OAuth2**, Lambda, IAM |
| Stage padrão | `Prod` (e `Stage` implícito em versões antigas) | `$default` |
| Definição por OpenAPI | `DefinitionBody` / `DefinitionUri` | idem |
| CORS | `Cors` | `CorsConfiguration` |

Um exemplo de API REST explícita com autorizador Cognito e CORS:

```yaml
Resources:
  Api:
    Type: AWS::Serverless::Api
    Properties:
      StageName: !Ref Stage
      TracingEnabled: true
      Auth:
        DefaultAuthorizer: CognitoAuth
        Authorizers:
          CognitoAuth:
            UserPoolArn: !GetAtt UserPool.Arn
      Cors:
        AllowMethods: "'GET,POST,OPTIONS'"
        AllowHeaders: "'Content-Type,Authorization'"
        AllowOrigin: "'https://app.exemplo.com'"
```

Detalhe clássico de CORS no SAM: os valores de string precisam de **aspas simples dentro das aspas duplas** (`"'valor'"`), porque o API Gateway espera o literal com aspas.

## 7. SimpleTable, LayerVersion, StateMachine e Application

### 7.1 SimpleTable

```yaml
Tabela:
  Type: AWS::Serverless::SimpleTable
  Properties:
    PrimaryKey:
      Name: pedidoId
      Type: String
    ProvisionedThroughput:
      ReadCapacityUnits: 5
      WriteCapacityUnits: 5
    SSESpecification:
      SSEEnabled: true
```

Limitação: **apenas chave de partição simples**. Para chave composta (partição + ordenação), índices secundários, streams ou TTL, use `AWS::DynamoDB::Table` normal. Por padrão, `SimpleTable` sem `ProvisionedThroughput` cria a tabela em modo **sob demanda**.

### 7.2 LayerVersion

```yaml
DepsLayer:
  Type: AWS::Serverless::LayerVersion
  Properties:
    LayerName: !Sub "${AWS::StackName}-deps"
    ContentUri: layers/deps/
    CompatibleRuntimes: [python3.12]
    RetentionPolicy: Retain
  Metadata:
    BuildMethod: python3.12
```

`RetentionPolicy: Retain` mantém versões antigas da layer após atualizações (o padrão é apagá-las, o que pode quebrar funções antigas que ainda as referenciam).

### 7.3 StateMachine

```yaml
Fluxo:
  Type: AWS::Serverless::StateMachine
  Properties:
    DefinitionUri: statemachine/fluxo.asl.json
    DefinitionSubstitutions:
      ValidarArn: !GetAtt Validar.Arn
    Policies:
      - LambdaInvokePolicy:
          FunctionName: !Ref Validar
    Events:
      Chegada:
        Type: Api
        Properties:
          Path: /iniciar
          Method: POST
```

### 7.4 Application (aninhada)

```yaml
AppPronta:
  Type: AWS::Serverless::Application
  Properties:
    Location:
      ApplicationId: arn:aws:serverlessrepo:us-east-1:123456789012:applications/exemplo
      SemanticVersion: 1.0.0
    Parameters:
      Tabela: !Ref Tabela
```

Aplicações aninhadas exigem a capability `CAPABILITY_AUTO_EXPAND` no deploy.

## 8. Parâmetros, Conditions, Mappings e funções intrínsecas

```yaml
Parameters:
  Stage:
    Type: String
    AllowedValues: [dev, hml, prod]
    Default: dev
  NivelLog:
    Type: AWS::SSM::Parameter::Value<String>
    Default: /app/nivel-log

Conditions:
  EhProd: !Equals [!Ref Stage, prod]

Mappings:
  Memoria:
    dev: { Valor: 256 }
    prod: { Valor: 1024 }
```

Funções intrínsecas mais usadas em templates SAM:

| Função | Uso |
|---|---|
| `!Ref` | Valor de parâmetro ou ID/nome do recurso (para função, o nome; para tabela, o nome) |
| `!GetAtt Recurso.Atributo` | Atributos como `.Arn` |
| `!Sub "texto ${Var}"` | Interpolação com pseudo-parâmetros (`${AWS::Region}`, `${AWS::AccountId}`, `${AWS::StackName}`) |
| `!Join`, `!Select`, `!Split` | Manipulação de listas e strings |
| `!If`, `!Equals`, `!Not` | Condicionais |
| `!FindInMap` | Consulta de Mappings |
| `!ImportValue` | Valor exportado por outra stack |

Referências dinâmicas, resolvidas no deploy, evitam gravar segredos no template:

```yaml
Environment:
  Variables:
    DB_HOST: "{{resolve:ssm:/app/db/host}}"
    DB_PASS: "{{resolve:secretsmanager:app/db:SecretString:password}}"
```

> [!warning] Segredos
> `{{resolve:secretsmanager:...}}` coloca o valor **em texto claro** na variável de ambiente da Lambda e na configuração visível a quem tem `lambda:GetFunctionConfiguration`. Para segredos sensíveis, prefira **ler o segredo em tempo de execução** (cache) e dar à função permissão de `GetSecretValue`.

`Ref` em `AWS::Serverless::Function` retorna o **nome da função**; `Ref` em `SimpleTable` retorna o **nome da tabela**; `Ref` em `Api` retorna o **ID da API**. Para obter o ARN, use `GetAtt`.

## 9. Outputs e exports

```yaml
Outputs:
  UrlApi:
    Description: URL base da API
    Value: !Sub "https://${Api}.execute-api.${AWS::Region}.amazonaws.com/${Stage}/"
    Export:
      Name: !Sub "${AWS::StackName}-UrlApi"
  ArnFuncao:
    Value: !GetAtt ListarItens.Arn
```

`Export` permite que **outras stacks** usem `!ImportValue`. Atenção: enquanto outra stack importar o valor, **não é possível alterá-lo nem apagar a stack exportadora**. Para acoplamento mais frouxo, prefira **parâmetros do SSM**.

## 10. Padrões úteis e armadilhas de template

| Tema | Recomendação / armadilha |
|---|---|
| **Nomes fixos** | `FunctionName`/`TableName` fixos bloqueiam a substituição (CloudFormation não cria o novo antes de apagar o antigo com o mesmo nome) |
| **API implícita** | Ao usar `Type: Api` sem `RestApiId`, o SAM cria `ServerlessRestApi`; para controlar stage, auth e CORS, declare a API explícita |
| **Dependência circular** | Evento `S3` com função e bucket + política de bucket referenciando a função pode gerar ciclo; use `DependsOn` ou nomes construídos com `!Sub` |
| **Ordem de recursos** | O CloudFormation deduz pela `Ref`/`GetAtt`; use `DependsOn` apenas quando não há referência |
| **`Metadata: BuildMethod`** | Define como `sam build` compila (`makefile`, `esbuild`, runtime específico) |
| **Esbuild** | `Metadata: BuildMethod: esbuild` com `BuildProperties` (Minify, Target, EntryPoints) para Node/TypeScript |
| **Transformações adicionais** | `Transform: [AWS::LanguageExtensions, AWS::Serverless-2016-10-31]` permite `Fn::ForEach` |
| **Template grande** | Dividir em **aplicações aninhadas** ou stacks por domínio |

## 11. Pegadinhas de prova (DVA-C03)

- **Seção obrigatória em um template CloudFormation/SAM?** → `Resources`. A `Transform` é obrigatória para **SAM**.
- **Onde evitar repetir configuração de funções?** → `Globals`.
- **Como conceder acesso só a uma tabela sem escrever IAM?** → policy template (`DynamoDBCrudPolicy` etc.).
- **`Role` e `Policies` juntos?** → Com `Role` definida, `Policies` é ignorada.
- **Tabela com chave composta?** → `SimpleTable` **não** suporta; usar `AWS::DynamoDB::Table`.
- **Concorrência provisionada em Lambda via SAM?** → Requer **alias** (`AutoPublishAlias`).
- **Como a função obtém um valor do SSM no deploy?** → Parâmetro do tipo `AWS::SSM::Parameter::Value<String>` ou `{{resolve:ssm:...}}`.
- **Como referenciar o ARN de uma função?** → `!GetAtt Funcao.Arn` (a `Ref` devolve o nome).

## 12. Resumo rápido

- Template SAM = seções do CloudFormation + **`Transform`** + **`Globals`**.
- `Globals` evita repetição: escalares sobrescrevem, mapas mesclam, listas concatenam.
- `Function` concentra código, runtime, eventos, permissões, alias e deploy gradual.
- `Policies` aceita **policy templates**, políticas gerenciadas e documentos inline; com `Role`, é ignorada.
- `Api` (REST, mais recursos) versus `HttpApi` (mais barata e simples).
- `SimpleTable` só tem chave simples; para mais, use `AWS::DynamoDB::Table`.
- Use **parâmetros, Conditions, `!Sub` e referências dinâmicas**, e evite nomes fixos.
- Cuidado com segredos em variáveis de ambiente e com `Export` que trava stacks.
