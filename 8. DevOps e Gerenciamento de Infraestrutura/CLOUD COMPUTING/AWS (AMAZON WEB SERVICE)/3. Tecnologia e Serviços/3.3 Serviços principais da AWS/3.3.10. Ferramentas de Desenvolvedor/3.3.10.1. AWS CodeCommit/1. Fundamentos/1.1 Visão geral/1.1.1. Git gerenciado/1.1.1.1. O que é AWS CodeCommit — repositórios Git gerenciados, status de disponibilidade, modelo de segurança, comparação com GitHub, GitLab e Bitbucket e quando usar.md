### 1.1.1.1. O que é AWS CodeCommit — repositórios Git gerenciados, status de disponibilidade, modelo de segurança, comparação com GitHub, GitLab e Bitbucket e quando usar

> [!warning] Aviso — disponibilidade do serviço
> O **AWS CodeCommit teve sua disponibilidade alterada**: a AWS **deixou de aceitar novos clientes** em julho de 2024 (contas que já tinham repositórios continuaram usando) e, depois, **anunciou a retomada** do serviço com novos investimentos. **A situação muda; confirme na página oficial do CodeCommit e no anúncio mais recente** se a sua conta pode criar repositórios. Os comandos, JSONs e valores deste material são **ilustrativos, de memória e não foram executados**. Preços e quotas devem ser conferidos na documentação.

## 1. O problema: onde guardar o código com segurança e integrado à AWS

Todo projeto de software precisa de um **repositório de código**: histórico de mudanças, branches, revisão e rastreabilidade. As equipes costumam usar **Git** hospedado em plataformas como GitHub, GitLab ou Bitbucket. Mas, em empresas que **concentram tudo na AWS** (contas, redes privadas, identidades IAM, auditoria CloudTrail), surgem requisitos específicos:

- Manter o **código-fonte dentro da própria conta AWS** (residência de dados, política de segurança).
- Controlar acesso **com IAM** (sem outro cadastro de usuários e senhas).
- **Criptografar** o repositório com **chaves KMS** do cliente.
- Integrar **nativamente** com CodePipeline, CodeBuild, Lambda e EventBridge.
- Evitar **dependência de terceiros** em ambientes regulados ou isolados.

O **AWS CodeCommit** é o serviço **gerenciado de repositórios Git** da AWS que atende a esses requisitos: você cria repositórios privados e os acessa com clientes Git padrão, enquanto a AWS cuida de **armazenamento, alta disponibilidade, escala e criptografia**.

```
 Desenvolvedor ──git push/pull (HTTPS/SSH)──▶ AWS CodeCommit (repositório Git)
                                                  │  IAM (acesso) · KMS (criptografia) · CloudTrail (auditoria)
                                                  ├─ evento ─▶ EventBridge ─▶ CodePipeline / CodeBuild / Lambda / SNS
                                                  └─ pull requests, approval rules, comentários
```

## 2. O que o CodeCommit oferece

| Capacidade | Descrição |
|---|---|
| **Repositórios Git privados** | Compatíveis com qualquer cliente Git (CLI, IDEs) |
| **Alta disponibilidade e durabilidade** | Dados replicados em várias zonas de disponibilidade da região, sem você gerenciar servidores |
| **Escala** | Sem limite prático de repositórios ou de tamanho do repositório (há limites por arquivo e por requisição) |
| **Acesso por IAM** | Usuários, roles e federação controlam quem lê, escreve ou administra |
| **Criptografia** | Em trânsito (HTTPS/SSH) e em repouso com **KMS** (chave gerenciada ou do cliente) |
| **Pull requests e aprovações** | Revisão de código com regras de aprovação obrigatórias |
| **Comentários** | Em commits, PRs e linhas de código |
| **Triggers e notificações** | SNS e Lambda em eventos do repositório; regras de notificação |
| **Eventos no EventBridge** | Automação de CI/CD a partir de push, PR e comentários |
| **Auditoria** | Chamadas de API no CloudTrail |
| **Integração CI/CD** | Origem nativa do **CodePipeline**; gatilho para **CodeBuild** |

## 3. O que o CodeCommit **não** é

| Esperado | Realidade |
|---|---|
| Plataforma completa de colaboração como GitHub | **Não**: foca em repositório, PRs e integrações AWS; sem issues, projetos, wikis, marketplace de ações ou comunidade |
| CI/CD embutido (como GitHub Actions/GitLab CI) | **Não**: CI/CD é feito com **CodePipeline/CodeBuild/CodeDeploy** (ou ferramentas externas) |
| Suporte a Git LFS | **Não** nativo (arquivos grandes exigem práticas alternativas) |
| Espelho público/open source | **Não**: repositórios são privados na conta |
| Busca de código avançada, dependabot, scanning nativo | **Não** (use Amazon Q/CodeGuru, SAST de terceiros) |

## 4. Modelo de segurança em uma frase

**Quem acessa** = **IAM** (usuários, roles, federação, MFA); **por qual canal** = HTTPS (com credenciais temporárias via `git-remote-codecommit`) ou SSH (chave associada ao usuário IAM); **o que cada um pode** = **políticas IAM** que podem restringir por **repositório, ação e até branch**; **o que está gravado** = criptografado com **KMS**; **o que aconteceu** = **CloudTrail**.

## 5. Comparação com GitHub, GitLab e Bitbucket

| Critério | **CodeCommit** | **GitHub** | **GitLab** | **Bitbucket** |
|---|---|---|---|---|
| **Hospedagem** | Na sua conta AWS/região | SaaS (ou GHES self-hosted) | SaaS ou **self-managed** | SaaS ou Data Center |
| **Identidade** | **IAM** | Contas GitHub, SSO/SAML | Contas GitLab, SSO | Atlassian |
| **CI/CD nativo** | Não (usa Code*) | **GitHub Actions** | **GitLab CI/CD** | Pipelines |
| **Pull requests** | Sim (básico + approval rules) | Sim (completo, code owners) | Merge requests completos | Sim |
| **Issues/projetos/wiki** | Não | Sim | Sim | Jira integrado |
| **Ecossistema/comunidade** | Pequeno | **Enorme** | Grande | Médio |
| **Integração AWS** | **Nativa e profunda** | Via CodeConnections/OIDC | Via OIDC | Via conexões |
| **Segurança de código** | Básica | Advanced Security, Dependabot | Scanners integrados | Opcional |
| **Custo** | Por usuário ativo (modelo AWS) | Por usuário/plano | Por usuário/plano | Por usuário/plano |
| **Soberania de dados** | Alta (região escolhida) | Depende | Alta se self-managed | Depende |

Heurística: **CodeCommit** faz sentido para **ambientes AWS-first, regulados ou isolados**, com equipes pequenas/médias que priorizam **IAM e KMS**. **GitHub/GitLab** vencem em **experiência de desenvolvedor, ecossistema e CI/CD integrado**; hoje, é comum **usar GitHub/GitLab com CodePipeline/CodeBuild** (via **AWS CodeConnections**) ou Actions com **OIDC** para assumir roles AWS.

## 6. Conceitos centrais

| Termo | Significado |
|---|---|
| **Repositório** | Contêiner Git (código, histórico, branches, tags) na região escolhida |
| **Branch** | Linha de desenvolvimento; a **default branch** é a base |
| **Commit** | Snapshot com autor, mensagem e hash |
| **Pull request** | Pedido de merge de uma branch de origem em uma de destino |
| **Approval rule (template)** | Exige N aprovações de um conjunto de aprovadores para permitir o merge |
| **Trigger** | Ação automática (SNS/Lambda) em evento do repositório |
| **Notification rule** | Notificações (SNS/Chatbot) de eventos |
| **Credential helper / GRC** | Mecanismos de autenticação Git com credenciais AWS |
| **Merge strategy** | Fast-forward, squash, three-way |

## 7. Primeiros passos (ilustrativo)

```bash
# 1) Cria um repositório
aws codecommit create-repository --repository-name app-pedidos \
  --repository-description "API de pedidos" \
  --kms-key-id arn:aws:kms:us-east-1:123456789012:key/abcd1234-... \
  --tags projeto=pedidos,ambiente=prod

# 2) Obtém a URL de clonagem
aws codecommit get-repository --repository-name app-pedidos \
  --query 'repositoryMetadata.cloneUrlHttp'

# 3) Instala o helper moderno e clona (credenciais IAM/SSO temporárias)
pip install git-remote-codecommit
git clone codecommit::us-east-1://app-pedidos

# 4) Fluxo normal
cd app-pedidos && git checkout -b feature/login
git add . && git commit -m "feat: tela de login" && git push -u origin feature/login
aws codecommit create-pull-request --title "Login" \
  --targets repositoryName=app-pedidos,sourceReference=feature/login,destinationReference=main
```

## 8. Casos de uso

| Caso | Por que CodeCommit |
|---|---|
| **Ambientes regulados** (governo, saúde, finanças) | Código fica na conta AWS, com IAM, KMS e CloudTrail |
| **Redes isoladas** (sem internet) | Acesso por **VPC endpoint** (`codecommit` e `git-codecommit`) |
| **Equipes AWS-first pequenas** | Sem outra ferramenta para pagar/administrar |
| **Pipelines Code\*** | Origem nativa de CodePipeline/CodeBuild |
| **Repositórios de IaC e configuração** | Auditoria e controle por IAM |
| **Espelho interno** | Réplica privada de repositórios críticos |

## 9. Quando **não** usar (ou migrar)

- A equipe depende de **ecossistema** (Actions, Dependabot, marketplace, code owners avançados).
- Precisa de **issues, projetos e wiki** integrados.
- Há **muitos colaboradores externos** (IAM não é pensado para isso).
- Necessidade de **Git LFS**, monorepos gigantes com recursos avançados, ou **busca de código**.
- A **disponibilidade do serviço** para a sua conta é incerta (confirmar o status atual).
- Estratégia corporativa já padronizada em GitHub/GitLab.

## 10. Erros comuns

> [!bug] Erros comuns
> 1. **Supor que o CodeCommit tem CI/CD embutido** (é preciso CodePipeline/CodeBuild).
> 2. **Usar credenciais de longo prazo** (chaves de acesso, HTTPS Git credentials) em vez de **credenciais temporárias**.
> 3. **Dar `codecommit:*` a todos** (inclusive `GitPush` em main).
> 4. **Não proteger a branch principal** (sem approval rules e sem restrição IAM por branch).
> 5. **Colocar segredos no código** (e achar que "repo privado" basta).
> 6. **Ignorar a região**: repositório existe em **uma região**; clones e pipelines devem usar a mesma.
> 7. **Não considerar a disponibilidade atual** do serviço ao planejar um projeto novo.
> 8. **Esperar Git LFS** e subir binários enormes no repositório.
> 9. **Não configurar triggers/eventos** e perder automação de CI.
> 10. **Sem backup/espelho** de repositórios críticos.

## 11. Troubleshooting inicial

| Sintoma | Causa provável | Ação |
|---|---|---|
| **403 ao clonar/push** | Falta de permissão IAM ou credenciais expiradas | Revisar políticas e renovar a sessão (SSO/role) |
| **Repositório não encontrado** | Região/conta erradas | Conferir a região e o nome |
| **Push rejeitado** | Condição IAM bloqueando a branch ou arquivo grande demais | Revisar políticas e limites |
| **`git-remote-codecommit` não encontrado** | Helper não instalado | `pip install git-remote-codecommit` |
| **Timeout em rede privada** | Sem VPC endpoint/DNS | Criar endpoints `git-codecommit` e `codecommit` |
| **Não consigo criar repositório** | Restrição de disponibilidade da conta | Verificar o status do serviço; considerar GitHub/GitLab |

## 12. Resumo rápido

- **CodeCommit** = **repositórios Git gerenciados** na sua conta AWS, com **IAM, KMS, CloudTrail** e integração nativa com Code\* e EventBridge.
- **Não é** plataforma completa de colaboração/CI-CD; **compare** com GitHub/GitLab/Bitbucket (ecossistema vs integração AWS).
- **Disponibilidade** foi restringida e depois retomada: **confirme o status atual**.
- Acesso por **HTTPS com `git-remote-codecommit`** (credenciais temporárias) ou SSH; **proteja a branch principal**.
- Ideal para **ambientes AWS-first, regulados ou isolados**; migre quando o ecossistema falar mais alto.
