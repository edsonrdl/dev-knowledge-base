### 6.1.1.1. Operação, custos e migração do CodeCommit — preços, quotas, backup e espelhamento, migração para GitHub ou GitLab, CodeConnections e checklist

> [!warning] Aviso
> Preços, franquias gratuitas, quotas e o **status de disponibilidade** do CodeCommit abaixo são **de memória e mudam**; o serviço teve **restrição a novos clientes** em 2024 e **retomada anunciada** depois. **Confirme na página de preços, no Service Quotas e no anúncio mais recente.** Scripts e comandos são ilustrativos e não foram executados. Faça **backup completo antes de qualquer migração**.

## 1. Custos

O modelo de preço do CodeCommit é **simples**: por **usuário ativo** com franquias de armazenamento e requisições.

| Componente | Cobrança (ordem de grandeza; confirmar) |
|---|---|
| **Usuário ativo** | ~**US$ 1 por usuário ativo/mês**; um usuário é "ativo" se **acessa** (push/pull/API) algum repositório no mês |
| **Franquia por usuário ativo** | **50 GB de armazenamento** e **10.000 requisições Git/mês** por usuário |
| **Excedente de armazenamento** | ~US$ 0,06 por GB-mês acima da franquia |
| **Excedente de requisições Git** | ~US$ 0,001 por requisição acima da franquia |
| **Free Tier** | **5 usuários ativos** gratuitos (confirmar se ainda vale) |
| **Transferência de dados** | Saída para a internet conforme preços padrão |
| **KMS** | Custo da chave CMK e das requisições |
| **EventBridge/SNS/Lambda/CodeBuild** | Custos próprios das automações |
| **VPC endpoints** | Por hora e por GB |

Exemplo: 30 desenvolvedores ativos → ~US$ 30/mês (com 1,5 TB de franquia de armazenamento agregada, em geral suficiente). Comparado a plataformas SaaS que cobram **por assento e plano**, o CodeCommit costuma ser **barato**, mas **menos rico**.

Dicas de custo:

- **Remova usuários inativos** (a cobrança é por ativo no mês, mas contas ociosas podem ficar ativas por automações).
- **Contas de automação (CI)** contam como usuários ativos se acessarem; considere agrupar.
- **Binários grandes** consomem armazenamento: use **S3/CodeArtifact** para artefatos.

## 2. Quotas (visão geral)

| Quota | Observação |
|---|---|
| **Repositórios por conta/região** | Alto (milhares; ajustável) |
| **Tamanho de arquivo individual** | Limite por arquivo (da ordem de 2 GB); sem Git LFS |
| **Tamanho de commit/push** | Limite por operação |
| **Branches por repositório** | Altíssimo |
| **Triggers por repositório** | 10 |
| **Approval rule templates** | Dezenas por conta |
| **Taxa de requisições de API** | Throttling por operação |
| **Regras de notificação** | Limites por conta |

Confirme no **Service Quotas** e planeje aumentos para grandes organizações.

## 4. Backup e espelhamento

O CodeCommit replica dados **entre AZs** (durabilidade alta), mas **não protege contra** **exclusão acidental**, **sobrescrita/force-push malicioso** ou **perda da região/conta**. Estratégias:

| Estratégia | Como |
|---|---|
| **Espelho para S3** | CodeBuild (agendado/por evento) faz `git clone --mirror` e envia `tar.gz` ao **S3** (versionamento + replicação) |
| **Espelho para outra região** | Pipeline que dá `git push --mirror` para um repositório de **outra região/conta** |
| **Espelho para outro provedor** | `git push --mirror` para GitHub/GitLab privado (DR e migração gradual) |
| **AWS Backup** (se suportado para o serviço, conforme disponibilidade) | Política centralizada |
| **Proteção contra exclusão** | IAM/SCP negando `DeleteRepository`; **aprovação** para exclusão |
| **Testes de restauração** | Restaurar periodicamente a partir do espelho |
| **Retenção** | Versões do S3, ciclos de vida para custo |

Exemplo de job de espelho (CodeBuild `buildspec`, ilustrativo):

```yaml
version: 0.2
phases:
  install:
    commands: [pip install git-remote-codecommit]
  build:
    commands:
      - git clone --mirror codecommit::us-east-1://pagamentos-api repo.git
      - tar czf pagamentos-api-$(date +%F).tar.gz repo.git
      - aws s3 cp pagamentos-api-$(date +%F).tar.gz s3://backup-codigo-corp/pagamentos-api/
```

## 5. Migração do CodeCommit para GitHub/GitLab/Bitbucket

Motivos comuns: **ecossistema** (Actions, Dependabot), **padronização corporativa**, **incerteza de disponibilidade**, **recursos de colaboração**.

### 5.1 Fases

```
1) INVENTÁRIO   : listar repositórios, tamanhos, branches, tags, PRs abertos, triggers, pipelines, permissões
2) PLANEJAR     : escolher destino (GitHub/GitLab/Bitbucket), modelo de organização, SSO, convenções, janela
3) PREPARAR     : criar org/grupos/equipes no destino; SSO/SAML; políticas de branch protection; secrets/OIDC
4) MIGRAR (Git) : git clone --mirror origem; git push --mirror destino  (branches, tags, histórico)
5) MIGRAR (Meta): PRs abertos (recriar), comentários (opcional/arquivar), permissões, webhooks
6) CI/CD        : recriar pipelines (Actions/GitLab CI) OU CodePipeline com CodeConnections
7) CONGELAR     : janela de corte; sincronização final; desabilitar escrita no CodeCommit
8) VALIDAR      : clones, builds, deploys, permissões; guardar o CodeCommit somente leitura por um período
9) DESCOMISSIONAR: após período de segurança, exportar e apagar com aprovação
```

### 5.2 Migração do código (exemplo)

```bash
git clone --mirror codecommit::us-east-1://pagamentos-api pagamentos-api.git
cd pagamentos-api.git
git remote add destino git@github.com:empresa/pagamentos-api.git
git push --mirror destino
```

Cuidados: **tamanho de arquivos** (limites do destino), **tags e refs** de PR do CodeCommit (`refs/pull/*`) podem não migrar; **LFS** (se usado) precisa de tratamento; **autoria** preservada pelo Git.

### 5.3 Pull requests e metadados

PRs e comentários **não fazem parte do Git**: ferramentas de migração (scripts com API, utilitários da comunidade) exportam e recriam; em muitos casos, **arquive** o histórico de revisões em S3 (JSON) e **recrie apenas os PRs abertos**.

### 5.4 Manter CodePipeline com repositório externo (CodeConnections)

O **AWS CodeConnections** (antes CodeStar Connections) conecta o **CodePipeline/CodeBuild** a **GitHub, GitHub Enterprise, GitLab, Bitbucket**:

```
GitHub (repositório) ── CodeConnections ──▶ CodePipeline (Source) ──▶ CodeBuild ──▶ CodeDeploy
                      (app OAuth instalado pela org)
```

Vantagem: **mantém o pipeline AWS** (e seus deploys) mudando só a origem. Alternativa: **GitHub Actions** com **OIDC** assumindo roles AWS (sem chaves) e implantando direto.

### 5.5 Comparativo de destino

| Critério | GitHub | GitLab | Bitbucket |
|---|---|---|---|
| **CI/CD nativo** | Actions | GitLab CI/CD (muito completo) | Pipelines |
| **Self-hosted** | GHES | **Self-managed** (forte) | Data Center |
| **Ecossistema** | Maior | Grande (DevSecOps integrado) | Médio (Atlassian) |
| **Integração AWS** | OIDC, CodeConnections | OIDC, CodeConnections | CodeConnections |
| **Soberania/air-gapped** | GHES | **GitLab self-managed** | Data Center |

## 6. Estratégias de coexistência

| Estratégia | Quando |
|---|---|
| **Migração completa** | Padronização total |
| **Espelho unidirecional** (CodeCommit → GitHub) | DR e transição |
| **CodeCommit para repos sensíveis, GitHub para o resto** | Segmentação por classificação de dados |
| **Migração por equipe/ondas** | Reduz risco (como nas ondas de migração de servidores) |

## 7. Checklist de operação e migração

**Operação contínua**
1. **Inventário** de repositórios, donos, tags e criticidade.
2. **Backup/espelho** testado (S3/outra região/provedor).
3. **Proteção** contra exclusão e force-push; **alertas** de CloudTrail.
4. **Custos** revisados (usuários ativos, armazenamento, binários).
5. **Quotas** e crescimento monitorados.
6. **Acessos** revisados trimestralmente; **chaves/credenciais** rotacionadas.
7. **Status do serviço** acompanhado (anúncios da AWS).

**Migração**
8. **Definir destino** e critérios (ecossistema, custo, compliance).
9. **Ondas piloto** com repositórios simples.
10. **Mirror** + **validação de integridade** (comparar hashes de branches/tags).
11. **CI/CD** recriado e testado (ou CodeConnections).
12. **Congelamento**, corte, **somente leitura** por período, e **descomissionamento** aprovado.

## 8. Erros comuns

> [!bug] Erros comuns
> 1. **Achar que a replicação entre AZs substitui backup.**
> 2. **Migrar sem validar** hashes e refs (perda de tags/branches).
> 3. **Esquecer pipelines, webhooks, triggers e permissões** na migração.
> 4. **Descomissionar o CodeCommit imediatamente.**
> 5. **Migrar PRs "à mão"** sem arquivar o histórico de revisões.
> 6. **Ignorar limites do destino** (tamanho de arquivo/repositório, LFS).
> 7. **Credenciais de longo prazo** durante a migração (tokens pessoais em CI).
> 8. **Não comunicar** a janela às equipes.
> 9. **Não tratar segredos** que existam no histórico antes de mover para novo ambiente.
> 10. **Manter dois sistemas sem fonte da verdade definida** (divergência).

## 9. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| `git push --mirror` rejeitado | Limites/branches protegidas no destino | Ajustar regras no destino ou migrar antes de proteger |
| Refs faltando após a migração | Refs de PR (`refs/pull/*`) não migram | Aceitar/arquivar; recriar PRs abertos |
| Arquivo grande bloqueado | Limite do destino | Usar LFS/S3 ou reescrever o histórico |
| Pipeline AWS não enxerga o novo repositório | CodeConnections não autorizado | Instalar o app na organização e autorizar |
| Custos altos no CodeCommit | Muitos usuários ativos/armazenamento | Limpar usuários, mover binários |
| Perda de acesso pós-corte | SSO/permissões no destino | Revisar equipes/papéis antes do corte |
| Divergência entre origem e destino | Escritas durante a migração | Congelar escrita e sincronizar de novo |

## 10. Resumo rápido

- **Custo**: ~**US$ 1/usuário ativo/mês** com franquia (50 GB e 10 mil requisições Git por usuário; free tier de 5 usuários — confirmar).
- **Quotas**: arquivo individual limitado, **sem LFS**, 10 triggers/repositório; confirme em Service Quotas.
- **Backup**: a replicação multi-AZ **não** protege de exclusão/force-push: faça **espelho** (S3/outra região/provedor) e teste a restauração.
- **Migração** para GitHub/GitLab/Bitbucket: **mirror** do Git + recriar PRs/CI; use **CodeConnections** para manter CodePipeline.
- **Acompanhe o status** do serviço e planeje por **ondas**, com **somente leitura** antes de descomissionar.
