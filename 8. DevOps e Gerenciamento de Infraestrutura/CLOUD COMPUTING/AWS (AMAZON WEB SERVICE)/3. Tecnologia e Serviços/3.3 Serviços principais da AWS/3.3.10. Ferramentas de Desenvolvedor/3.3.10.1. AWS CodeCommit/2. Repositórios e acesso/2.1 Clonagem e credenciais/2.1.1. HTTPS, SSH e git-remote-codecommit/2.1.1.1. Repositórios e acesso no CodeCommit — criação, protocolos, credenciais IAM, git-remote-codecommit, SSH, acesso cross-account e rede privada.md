### 2.1.1.1. Repositórios e acesso no CodeCommit — criação, protocolos, credenciais IAM, git-remote-codecommit, SSH, acesso cross-account e rede privada

> [!warning] Aviso
> Comandos, políticas IAM e URLs abaixo são **ilustrativos, de memória e não foram executados**. Mecanismos de credencial e a disponibilidade do CodeCommit para novas contas **mudam**; **confirme na documentação oficial**. Credenciais de longo prazo (chaves, senhas Git) são **risco de segurança**: prefira credenciais temporárias.

## 1. Repositórios: criação e estrutura

Um **repositório CodeCommit** vive **em uma região** de uma conta. O nome é único **na conta e região**. Cada repositório tem **branches, tags, histórico** e metadados (descrição, tags de recurso, chave KMS).

```bash
aws codecommit create-repository \
  --repository-name infra-iac \
  --repository-description "Terraform e CloudFormation da plataforma" \
  --kms-key-id alias/codecommit-corp \
  --tags equipe=plataforma,classificacao=interno

aws codecommit list-repositories --sort-by repositoryName --order ascending
aws codecommit get-repository --repository-name infra-iac
```

Recomendações de organização:

| Prática | Motivo |
|---|---|
| **Um repositório por serviço/componente** (ou monorepo com critério) | Permissões, ciclos de release e pipelines separados |
| **Nomes padronizados** (`<time>-<servico>`) | Políticas IAM por prefixo (`arn:...:time-*`) |
| **Tags** (`equipe`, `ambiente`, `classificacao`) | Alocação de custos e ABAC |
| **Default branch** `main` protegida | Fluxo de PR e aprovação |
| **Chave KMS por domínio de confiança** | Isolamento criptográfico |
| **Descrição e README** | Onboarding |

## 2. Protocolos de acesso

O CodeCommit aceita dois protocolos de transporte:

| Protocolo | Autenticação | Quando usar |
|---|---|---|
| **HTTPS** | **git-remote-codecommit (GRC)** com **credenciais AWS temporárias**; ou **credential helper**; ou **Git credentials (usuário/senha de IAM)** | **Recomendado** (principalmente GRC) |
| **SSH** | **Chave pública** associada ao **usuário IAM** | Quando a equipe prefere SSH e há usuários IAM |

### 2.1 git-remote-codecommit (GRC) — recomendado

O **GRC** é um helper do Git que **assina as requisições com credenciais da AWS** (perfil do CLI, **IAM Identity Center/SSO**, **role assumida**, variáveis de ambiente). **Não há senha para guardar**; as credenciais são **temporárias**.

```bash
pip install git-remote-codecommit

# URL especial: codecommit::<região>://[<perfil>@]<repositório>
git clone codecommit::us-east-1://infra-iac
git clone codecommit::us-east-1://meu-perfil-sso@infra-iac     # usa um perfil específico
git remote add origin codecommit::us-east-1://infra-iac
```

Vantagens: funciona com **SSO e MFA**, **roles** e **perfis múltiplos**; **sem rotação** de senhas.

### 2.2 Credential helper do AWS CLI

```bash
git config --global credential.helper '!aws codecommit credential-helper $@'
git config --global credential.UseHttpPath true
git clone https://git-codecommit.us-east-1.amazonaws.com/v1/repos/infra-iac
```

Também usa credenciais do CLI. Preferido quando se deseja a URL HTTPS padrão.

### 2.3 HTTPS Git credentials (usuário e senha)

O usuário IAM gera um **par usuário/senha específico do CodeCommit** (no console, aba *Security credentials*). Útil para **ferramentas que só entendem usuário/senha** (alguns IDEs/CI legados).

> [!warning] Cuidado
> São **credenciais estáticas de longo prazo**: guarde em cofre, **rotacione**, e **não** use em contas root nem em pipelines (use roles). Uma senha vazada dá acesso ao que o usuário IAM tiver.

### 2.4 SSH

1. O usuário IAM **envia a chave pública** (`aws iam upload-ssh-public-key`).
2. O IAM devolve um **SSH Key ID**.
3. O `~/.ssh/config` usa esse ID como usuário:

```text
Host git-codecommit.*.amazonaws.com
  User APKAEIBAERJR2EXAMPLE
  IdentityFile ~/.ssh/codecommit_rsa
```

```bash
git clone ssh://git-codecommit.us-east-1.amazonaws.com/v1/repos/infra-iac
```

SSH exige **usuário IAM** (não funciona diretamente com roles/SSO). É uma opção menos moderna do ponto de vista de segurança (chave de longa duração).

### 2.5 Comparativo

| Método | Credencial | Temporária? | Suporta SSO/roles | Recomendação |
|---|---|---|---|---|
| **GRC** | AWS (CLI/SSO/role) | **Sim** | **Sim** | **Preferido** |
| **Credential helper** | AWS (CLI/SSO/role) | **Sim** | **Sim** | Bom |
| **HTTPS Git credentials** | Usuário/senha IAM | Não | Não | Só quando necessário |
| **SSH** | Chave pública de usuário IAM | Não | Não | Aceitável com controle de chaves |

## 3. Permissões IAM

As ações têm o prefixo `codecommit:`. Principais:

| Ação | O que permite |
|---|---|
| `GitPull` | Clonar/puxar |
| `GitPush` | Enviar commits/branches |
| `CreateBranch`, `DeleteBranch` | Gerir branches |
| `CreatePullRequest`, `MergePullRequestBy*`, `UpdatePullRequestApprovalState` | Fluxo de PRs |
| `GetRepository`, `ListRepositories`, `GetBranch` | Leitura de metadados |
| `PostCommentForPullRequest` | Comentários |
| `CreateRepository`, `DeleteRepository` | Administração |
| `PutRepositoryTriggers`, `UpdateRepositoryEncryptionKey` | Configuração |

Política de **desenvolvedor** (ilustrativa): lê e envia em repositórios da equipe, mas **não** altera a branch principal diretamente:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Sid": "AcessoAosReposDaEquipe", "Effect": "Allow",
      "Action": ["codecommit:GitPull", "codecommit:GitPush", "codecommit:CreateBranch",
                 "codecommit:GetBranch", "codecommit:CreatePullRequest", "codecommit:GetPullRequest",
                 "codecommit:PostCommentForPullRequest", "codecommit:ListBranches"],
      "Resource": "arn:aws:codecommit:us-east-1:123456789012:pagamentos-*" },
    { "Sid": "NegarPushNaMain", "Effect": "Deny",
      "Action": ["codecommit:GitPush", "codecommit:DeleteBranch", "codecommit:PutFile", "codecommit:MergeBranchesBy*", "codecommit:MergePullRequestBy*"],
      "Resource": "arn:aws:codecommit:us-east-1:123456789012:pagamentos-*",
      "Condition": { "StringEqualsIfExists": { "codecommit:References": ["refs/heads/main", "refs/heads/master"] },
                     "Null": { "codecommit:References": "false" } } }
  ]
}
```

A condição **`codecommit:References`** restringe ações por **branch/tag**, base para proteger `main`. O **merge** de PRs (com aprovação) é feito por quem tem `MergePullRequestBy*`, normalmente um perfil de **release/maintainer** ou a automação.

## 4. Acesso cross-account

Para um repositório de **outra conta**:

```
Conta A (dona do repo): role "CodeCommitAcessoExterno" com política codecommit:Git* no repositório
                         trust policy: permite a conta B (ou uma role específica) assumir
Conta B (desenvolvedores/CI): permissão sts:AssumeRole na role da conta A
Cliente Git: perfil do CLI que assume a role + URL GRC com o perfil → codecommit::us-east-1://perfilA@repo
```

Em **organizações**, centralize repositórios numa conta de **"ferramentas/compartilhada"** e conceda acesso por **roles** (nunca compartilhando chaves). Para **pipelines em outra conta**, o CodePipeline/CodeBuild assumem **roles entre contas** e acessam o repositório pela role.

## 5. Acesso por rede privada (VPC endpoints)

Em redes **sem internet**, use **VPC endpoints (PrivateLink)**:

| Endpoint | Finalidade |
|---|---|
| `com.amazonaws.<região>.git-codecommit` | **Operações Git** (clone, push, pull) |
| `com.amazonaws.<região>.codecommit` | **API** do CodeCommit (PRs, branches) |

Com **DNS privado** habilitado, os nomes públicos resolvem para IPs privados. **Security groups** controlam quem alcança o endpoint (porta 443; SSH usa porta 22 via endpoint `git-codecommit`, conforme configuração). Combine com **políticas de endpoint** para limitar repositórios.

```bash
aws ec2 create-vpc-endpoint --vpc-id vpc-0abc --vpc-endpoint-type Interface \
  --service-name com.amazonaws.us-east-1.git-codecommit \
  --subnet-ids subnet-0a subnet-0b --security-group-ids sg-0abc --private-dns-enabled
```

## 6. Fluxo Git na prática

| Tarefa | Comando |
|---|---|
| Clonar | `git clone codecommit::us-east-1://repo` |
| Criar branch de feature | `git checkout -b feature/x` |
| Commitar | `git add -A && git commit -m "feat: ..."` |
| Enviar | `git push -u origin feature/x` |
| Abrir PR | `aws codecommit create-pull-request ...` (ou console) |
| Atualizar do remoto | `git fetch --all --prune && git rebase origin/main` |
| Resolver conflitos | Localmente (ou no console para casos simples) |
| Listar branches remotas | `aws codecommit list-branches --repository-name repo` |

Boas práticas:

- **Branches curtas** e PRs pequenos.
- **Commits assinados** (GPG/SSH) quando a política exigir (o CodeCommit **armazena**, mas não impõe assinatura nativamente).
- **Hooks de pré-commit** locais (lint, segredos como `git-secrets`/`gitleaks`).
- **Nunca** commitar segredos; use Secrets Manager/Parameter Store.

## 7. Limites práticos

| Aspecto | Observação |
|---|---|
| **Tamanho de arquivo individual** | Limite por arquivo (da ordem de **2 GB**; recomendável bem menos); sem Git LFS |
| **Tamanho de push** | Existe limite por operação; pushes enormes devem ser divididos |
| **Quantidade de repositórios** | Limite por conta/região (ajustável) |
| **Branches/tags** | Altos limites |
| **Taxa de requisições** | Há throttling por API |
| **Região** | O repositório é regional; replicação entre regiões é **manual/automatizada por você** |

Confirme os valores em **Service Quotas**.

## 8. Exemplo: onboarding de uma equipe

```
1) Criar grupo IAM/Permission Set "dev-pagamentos" com a política de desenvolvedor (acima).
2) Distribuir instruções: instalar AWS CLI + git-remote-codecommit; aws sso login; clonar via codecommit::...
3) Template de PR com approval rule (2 aprovadores) em todos os repositórios pagamentos-*.
4) Branch main protegida por política IAM (Deny GitPush) + merge só por PR.
5) Trigger/EventBridge disparando CodePipeline ao merge em main.
```

## 9. Erros comuns

> [!bug] Erros comuns
> 1. **Usar HTTPS Git credentials ou chaves SSH como padrão** em vez de GRC/credential helper.
> 2. **Credenciais de usuário IAM em pipelines** (use **role** do serviço).
> 3. **Política com `codecommit:*` em `*`**.
> 4. **Não negar o push direto na `main`** (basta uma política Allow ampla).
> 5. **Esquecer `UseHttpPath`** no credential helper (falha em múltiplos repositórios).
> 6. **Perfil/região errados** na URL GRC (`codecommit::<região>://<perfil>@repo`).
> 7. **Sem VPC endpoints** em redes privadas.
> 8. **Compartilhar chaves entre pessoas** ou contas.
> 9. **Repositório em região diferente** do pipeline.
> 10. **Binários grandes no repositório** (sem LFS), inflando o histórico.

## 10. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| `fatal: unable to access ... 403` | Sem permissão/credencial expirada | `aws sso login`; revisar política IAM |
| `Repository not found` | Região/conta/nome | Conferir URL GRC e a região |
| `git-remote-codecommit` falha com perfil | Perfil inexistente | Conferir `~/.aws/config` e o nome do perfil |
| SSH `Permission denied (publickey)` | Chave não associada ou SSH Key ID errado | Reenviar a chave pública e ajustar `User` |
| Push negado em `main` | Condição `Deny` por branch | Usar branch + PR |
| Timeout em rede privada | Sem endpoint/DNS privado/SG | Criar endpoints e liberar 443 |
| Pipeline cross-account sem acesso | Trust/role/KMS entre contas | Ajustar roles e permissões de chave KMS |

## 11. Resumo rápido

- Repositórios são **regionais**, com nome único por conta/região, **chave KMS** e **tags**.
- Acesso: **GRC (preferido)**, **credential helper**, **HTTPS Git credentials** ou **SSH** (menos recomendados).
- **IAM** controla `GitPull/GitPush/...`; **`codecommit:References`** protege **branches**.
- **Cross-account** por **roles**; **rede privada** com endpoints `git-codecommit` e `codecommit`.
- Evite credenciais de longo prazo, **não commite segredos** e limite binários grandes.

1. Qual método de acesso é recomendado e por quê?
2. Qual condição IAM restringe ações por branch?
3. Para que servem os endpoints `git-codecommit` e `codecommit`?
4. Como dar acesso a desenvolvedores de outra conta?
5. Por que evitar HTTPS Git credentials em pipelines?
6. SSH funciona com roles do IAM?
7. Que limite importante existe para arquivos?

**Respostas:**

1. O git-remote-codecommit, porque usa credenciais AWS temporárias (SSO/roles/MFA), sem senhas de longo prazo.
2. `codecommit:References` (por exemplo, `refs/heads/main`).
3. Acesso privado às operações Git e à API do CodeCommit, sem internet pública.
4. Com uma role na conta dona do repositório que a outra conta assume (sts:AssumeRole).
5. São credenciais estáticas e de longo prazo; pipelines devem usar roles com credenciais temporárias.
6. Não diretamente; SSH usa chave associada a um usuário IAM.
7. Há limite por arquivo (da ordem de 2 GB) e não há Git LFS; evite binários grandes.
