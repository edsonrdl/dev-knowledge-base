## Origens

Uma **origin** é o endereço de onde o CloudFront busca o conteúdo em caso de cache miss. Uma distribuição pode ter várias.

| Tipo de origem | Detalhes | Observações |
|---|---|---|
| **Bucket S3 (endpoint REST)** | `bucket.s3.região.amazonaws.com` | Use **OAC** para manter o bucket privado; suporta todos os métodos de escrita se configurado |
| **S3 website endpoint** | `bucket.s3-website-região...` | Tratado como origem **custom** (somente HTTP); sem OAC |
| **Application/Network Load Balancer** | Nome DNS do balanceador | Comum para aplicações web/API |
| **EC2** | Nome DNS público da instância | Precisa ser acessível pela internet (ou use VPC origins) |
| **API Gateway** | Endpoint regional | Use o endpoint **regional** (não edge-optimized, que já tem CloudFront próprio) |
| **Lambda function URL** | URL da função | Com OAC para Lambda |
| **VPC origin** | ALB/NLB/EC2 em **subnet privada** | Evita expor a origem à internet (recurso mais recente; ver docs) |
| **Servidor HTTP qualquer** (custom origin) | On-premises ou outro provedor | Exige acesso público e porta alcançável |
| **MediaStore / MediaPackage** | Vídeo | Streaming |

### Configurações importantes de uma origem

| Parâmetro | Função | Valores usuais |
|---|---|---|
| **Origin protocol policy** | Protocolo CloudFront → origem: `http-only`, `https-only`, `match-viewer` | `https-only` |
| **Origin path** | Prefixo anexado às requisições (`/producao`) | Opcional |
| **Custom headers** | Cabeçalhos fixos enviados à origem (ex.: `X-Origin-Verify: segredo`) | Usado para confirmar que a requisição veio do CloudFront |
| **Connection timeout / attempts** | Tempo e tentativas de conexão (ex.: 10 s, 3 tentativas) | Ajuste para falhar mais rápido |
| **Response (read) timeout** | Tempo de espera pela resposta da origem (padrão 30 s; pode ser ampliado via quota) | APIs lentas |
| **Keep-alive timeout** | Tempo de conexão ociosa mantida | 5 s padrão |
| **Origin Shield** | Camada extra de cache em uma região escolhida | Veja a nota de custo e operação |

**Restringir a origem ao CloudFront:** se a origem for um ALB público, qualquer pessoa pode acessá-lo diretamente, contornando cache e WAF. Mitigações: Security Group permitindo apenas a **managed prefix list do CloudFront** (`com.amazonaws.global.cloudfront.origin-facing`), **header secreto** validado por regra do ALB/WAF, ou **VPC origin** com ALB privado.

## Cache behaviors

Um **cache behavior** associa um **path pattern** a uma origem e a um conjunto de regras. Toda distribuição tem um behavior **Default (\*)**, obrigatório e avaliado por último; os demais são avaliados **em ordem de precedência** (o primeiro que combina vence).

```
  Requisição /api/pedidos/42 ───────────────────────────────┐
                                                            ▼
  Precedência 0:  /api/*        → Origem ALB-API   (sem cache, todos métodos)   ◄── combina, usa este
  Precedência 1:  /static/*     → Origem S3        (cache longo)
  Precedência 2:  *.jpg         → Origem S3        (cache longo, compress)
  Default (*)                   → Origem ALB-WEB   (cache curto)
```

Cada behavior define:

| Configuração | O que controla |
|---|---|
| **Path pattern** | `/api/*`, `/imagens/*.png`, `*.js`... (curingas `*` e `?`; sensível a maiúsculas e minúsculas) |
| **Origem / origin group** | Para onde vai a requisição em miss |
| **Viewer protocol policy** | `allow-all`, `redirect-to-https`, `https-only` |
| **Allowed HTTP methods** | `GET, HEAD` / `GET, HEAD, OPTIONS` / todos (`+POST, PUT, PATCH, DELETE`) |
| **Cache policy** | TTL e **cache key** (quais headers/cookies/query strings diferenciam objetos) — veja a próxima nota |
| **Origin request policy** | O que mais é enviado à origem sem entrar na cache key |
| **Response headers policy** | Headers de segurança/CORS adicionados na resposta |
| **Compress objects** | Compressão gzip/Brotli automática |
| **Function associations** | CloudFront Functions / Lambda@Edge |
| **Restrição de acesso** | Signed URLs/cookies (trusted key groups) |

### Arquitetura típica em uma única distribuição

```
        https://www.exemplo.com.br
                 │
          ┌──────┴────── CloudFront ───────────────────┐
          │                                            │
   /static/*, /img/*  →  S3 (OAC, TTL 1 ano, hash no nome)
   /api/*             →  ALB-API (sem cache, POST/PUT liberados, origin request policy
                         com Authorization e cookies de sessão)
   Default (*)        →  ALB-WEB (TTL curto ou cache por cookie)
```

Vantagem: um único domínio (sem CORS entre site e API), cache distinto por tipo de conteúdo, WAF único.

## Origin groups (failover de origem)

Um **origin group** agrupa uma origem **primária** e uma **secundária**. Se a primária responder com certos **códigos de status** (ou falhar na conexão), o CloudFront tenta a secundária automaticamente.

```
 Requisição ──► CloudFront ──► Primária (S3 região A) ── 5xx/403/404 ──► Secundária (S3 região B)
```

- Códigos configuráveis: por exemplo 500, 502, 503, 504, 403, 404.
- Funciona para **GET, HEAD e OPTIONS** (não para métodos de escrita).
- Casos típicos: bucket S3 replicado em duas regiões (CRR); ALB de uma região e outro de outra; "sorry page" estática como secundária.
- Difere do failover de DNS do Route 53: o origin group age **por requisição**, sem esperar TTL de DNS nem health check, o que dá recuperação quase instantânea para o conteúdo servido via CloudFront. (Veja o failover por DNS na nota de [[8. DevOps e Gerenciamento de Infraestrutura/CLOUD COMPUTING/AWS (AMAZON WEB SERVICE)/3. Tecnologia e Serviços/3.3 Serviços principais da AWS/3.3.4. Rede/3.3.4.5. ## Exemplo prático

Trecho ilustrativo de configuração (JSON simplificado de `DistributionConfig`; não é um arquivo completo):

```json
{
  "Origins": { "Quantity": 2, "Items": [
    { "Id": "s3-estatico",
      "DomainName": "site-estatico.s3.us-east-1.amazonaws.com",
      "S3OriginConfig": { "OriginAccessIdentity": "" },
      "OriginAccessControlId": "E1OACEXEMPLO" },
    { "Id": "alb-api",
      "DomainName": "alb-api-123.us-east-1.elb.amazonaws.com",
      "CustomOriginConfig": {
        "HTTPPort": 80, "HTTPSPort": 443,
        "OriginProtocolPolicy": "https-only",
        "OriginReadTimeout": 30, "OriginKeepaliveTimeout": 5 },
      "CustomHeaders": { "Quantity": 1, "Items": [
        { "HeaderName": "X-Origin-Verify", "HeaderValue": "troque-por-segredo" } ] } }
  ]},
  "DefaultCacheBehavior": {
    "TargetOriginId": "s3-estatico",
    "ViewerProtocolPolicy": "redirect-to-https",
    "CachePolicyId": "ID-DA-CACHE-POLICY-OTIMIZADA",
    "Compress": true
  },
  "CacheBehaviors": { "Quantity": 1, "Items": [
    { "PathPattern": "/api/*",
      "TargetOriginId": "alb-api",
      "ViewerProtocolPolicy": "https-only",
      "AllowedMethods": { "Quantity": 7, "Items":
        ["GET","HEAD","OPTIONS","PUT","POST","PATCH","DELETE"] },
      "CachePolicyId": "ID-DA-CACHE-POLICY-DESABILITADA",
      "OriginRequestPolicyId": "ID-DA-ORIGIN-REQUEST-POLICY-ALL-VIEWER" }
  ]}
}
```

Explicação: duas origens (S3 com OAC e ALB custom com `https-only` e header secreto); o behavior padrão serve o estático do S3 e força HTTPS; o behavior `/api/*` envia ao ALB, libera métodos de escrita, **desabilita o cache** (cache policy "CachingDisabled") e repassa o necessário (origin request policy). Os IDs são marcadores; as políticas gerenciadas da AWS têm IDs fixos listados na documentação.

```bash
# Obter uma distribuição, editar e atualizar (exige o ETag para controle de concorrência)
aws cloudfront get-distribution-config --id E123ABCDEF > dist.json   # contém ETag e DistributionConfig
# ... editar o DistributionConfig ...
aws cloudfront update-distribution --id E123ABCDEF \
  --if-match <ETag> --distribution-config file://config-editada.json
```

## Erros comuns e armadilhas

- **Ordem dos behaviors:** um padrão amplo (`*`) antes de um específico "engole" as requisições. Mais específicos primeiro.
- **Path pattern sem barra inicial ou com maiúsculas diferentes:** não combina.
- **POST bloqueado:** o behavior permite só GET/HEAD e a API recebe erro 403/405.
- **Cache no `/api/*`:** responses personalizadas cacheadas e entregues a outro usuário. Use cache policy desabilitada ou chave com identificação.
- **Origem pública sem restrição:** acessível diretamente, ignorando WAF/cache.
- **Timeout curto em API lenta:** erros 504 do CloudFront; ajuste o `Origin response timeout`.
- **Usar endpoint edge-optimized do API Gateway** como origem: duplica CDN e complica; prefira regional.
- **S3 website endpoint com OAC:** não é suportado.

## 🧩 Quiz de Fixação

1. Num site com estático em S3 e API em ALB sob o mesmo domínio, como configurar o CloudFront?
2. O que é um origin group e qual a diferença para o failover de DNS do Route 53?
3. Como garantir que um ALB só aceite tráfego vindo do CloudFront?

**Respostas:**
1) Duas origens (S3 com OAC e o ALB) e behaviors: `/api/*` apontando para o ALB, com métodos de escrita liberados e cache desabilitado (ou cache key adequada), e o Default (\*) para o S3 com cache longo. Evita CORS e permite regras de cache distintas num único domínio.
2) Um **origin group** tem origem primária e secundária; o CloudFront troca para a secundária **por requisição** quando a primária retorna códigos configurados (5xx, 403, 404) ou falha a conexão, só para GET/HEAD/OPTIONS. O failover do Route 53 depende de **health checks e TTL de DNS**, é mais lento e vale para todo o tráfego do nome.
3) Combinando: Security Group com a **managed prefix list do CloudFront**, um **header secreto** (custom header) validado pelo ALB/WAF, ou usando uma **VPC origin** com o ALB em subnet privada.
