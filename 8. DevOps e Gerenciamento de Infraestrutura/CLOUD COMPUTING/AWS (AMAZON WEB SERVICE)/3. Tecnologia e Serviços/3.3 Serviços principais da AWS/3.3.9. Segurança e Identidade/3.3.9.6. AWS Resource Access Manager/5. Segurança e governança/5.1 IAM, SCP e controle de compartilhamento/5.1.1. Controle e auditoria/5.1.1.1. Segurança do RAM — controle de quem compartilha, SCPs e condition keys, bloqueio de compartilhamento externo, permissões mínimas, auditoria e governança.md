### 5.1.1.1. Segurança do RAM — controle de quem compartilha, SCPs e condition keys, bloqueio de compartilhamento externo, permissões mínimas, auditoria e governança

> [!warning] Aviso
> Nomes de ações IAM (`ram:*`), chaves de condição (`ram:RequestedResourceType`, `ram:AllowsExternalPrincipals`, etc.), comportamento de SCPs sobre compartilhamento e recursos de detecção abaixo são **de memória e mudam**. **Confirme na documentação do AWS RAM e do IAM.** Políticas e comandos são ilustrativos e **não foram executados**. Compartilhar recursos **abre acesso entre contas**: um share mal configurado pode **expor rede, dados ou licenças** a quem não deveria.

## 1. Por que governar o RAM

O RAM torna o compartilhamento **fácil** — e é justamente por isso que precisa de **guardrails**. Riscos típicos:

| Risco | Exemplo | Impacto |
|---|---|---|
| **Compartilhamento externo acidental** | Subnet/TGW compartilhado com **conta fora da organização** | **Exposição de rede** a terceiros |
| **Compartilhar com a organização inteira** | `Principal = organização` quando bastava uma OU | Acesso **excessivo** |
| **Permissões amplas** | Permissão gerenciada que permite mais do que o necessário | **Escalada** de privilégio do consumidor |
| **Share não rastreado** | Sem dono/tags/documentação | **Shadow sharing**, dificuldade de auditoria |
| **Alteração/remoção maliciosa** | Excluir share/recurso | **Indisponibilidade** em várias contas |
| **Compartilhar recursos sensíveis** | Catálogo com **dados pessoais**, **Private CA**, **Aurora clone** | **Vazamento/abuso** |
| **Convites a terceiros não aprovados** | Parceiro recebe acesso por convite | Acesso persistente |
| **Contas comprometidas** | Conta dona comprometida cria shares externos | **Exfiltração/lateralidade** |
| **Permissões do consumidor** | IAM do consumidor excessivo sobre recursos compartilhados | Abuso (ex.: lançar instâncias caras em capacity reservation) |

Defesa: **permitir compartilhamento só dentro da organização**, **restringir quem cria shares**, **limitar tipos de recurso**, **SCPs**, **permissões mínimas**, **auditoria** e **detecção**.

## 2. A principal trava: compartilhamento só dentro da organização

### 2.1 Sharing com Organizations

| Ação | Efeito |
|---|---|
| **Habilitar sharing com Organizations** (conta de gestão) | Permite compartilhar com **OU/organização** (**sem convites**) |
| **`allowExternalPrincipals=false`** (por share) | **Impede** adicionar **principais externos** |
| **SCP** negando **principais externos** | **Impede** que **qualquer conta** da organização crie shares externos (**guardrail central**) |

### 2.2 SCP para bloquear compartilhamento externo

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "NegarCompartilhamentoExternoRAM",
    "Effect": "Deny",
    "Action": ["ram:CreateResourceShare", "ram:UpdateResourceShare"],
    "Resource": "*",
    "Condition": { "Bool": { "ram:RequestedAllowsExternalPrincipals": "true" } }
  }]
}
```

(Condição ilustrativa: confirme o nome exato da chave suportada — `ram:RequestedAllowsExternalPrincipals`.)

### 2.3 Bloquear principais fora da organização

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "SomentePrincipaisDaOrganizacao",
    "Effect": "Deny",
    "Action": ["ram:AssociateResourceShare", "ram:CreateResourceShare"],
    "Resource": "*",
    "Condition": { "ForAnyValue:StringNotLike": { "ram:Principal": ["arn:aws:organizations::999999999999:*/o-exemplo12345/*"] } }
  }]
}
```

(Esboço: valide as chaves/valores aceitos para **principais** — ARNs de organização/OU/conta.)

## 3. Quem pode criar e gerenciar shares (IAM)

### 3.1 Separação de funções

| Papel | Pode | Não deve |
|---|---|---|
| **Plataforma/Rede (dono)** | `ram:CreateResourceShare`, `Associate*`, `Update*` para **seus recursos de infraestrutura** | Compartilhar recursos de **outras** áreas |
| **Equipes de aplicação** | **Aceitar/usar** recursos compartilhados; criar shares **só** de recursos que **possuem** e **apenas com permissão** | Compartilhar rede/segurança/dados sensíveis fora de processo |
| **Segurança/Auditoria** | **Leitura**: `ram:Get*`, `List*` | Alterar |
| **Gestão da organização** | `ram:EnableSharingWithAwsOrganization` | Operação diária |
| **Pipeline (IaC)** | Criar/alterar shares **declarados** em IaC | Criar shares ad hoc |
| **Break-glass** | Ações emergenciais com **MFA/alarme** | Uso rotineiro |

### 3.2 Exemplos de políticas (ilustrativas)

**Leitura**:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "RamLeitura",
    "Effect": "Allow",
    "Action": ["ram:Get*", "ram:List*"],
    "Resource": "*"
  }]
}
```

**Restringir por tipo de recurso** (só podem compartilhar determinados tipos):

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "PermitirApenasTiposAprovados",
    "Effect": "Allow",
    "Action": ["ram:CreateResourceShare", "ram:AssociateResourceShare"],
    "Resource": "*",
    "Condition": { "StringEquals": { "ram:RequestedResourceType": ["ec2:Subnet", "ec2:TransitGateway", "route53resolver:ResolverRule"] } }
  }]
}
```

**SCP: proteger shares críticos contra exclusão/alteração** (por tag):

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "ProtegerSharesCriticos",
    "Effect": "Deny",
    "Action": ["ram:DeleteResourceShare", "ram:DisassociateResourceShare", "ram:UpdateResourceShare"],
    "Resource": "*",
    "Condition": {
      "StringEquals": { "aws:ResourceTag/criticidade": "alta" },
      "ArnNotLike": { "aws:PrincipalArn": "arn:aws:iam::*:role/RedeAdmin" }
    }
  }]
}
```

### 3.3 Chaves de condição úteis (de memória — confirmar)

| Chave | Uso |
|---|---|
| **`ram:RequestedResourceType`** | Limitar **tipos de recurso** compartilháveis |
| **`ram:ResourceArn`** | Restringir **recursos específicos** |
| **`ram:Principal`** | Limitar **principais** (org/OU/contas) |
| **`ram:AllowsExternalPrincipals`** / `ram:RequestedAllowsExternalPrincipals` | Bloquear **externos** |
| **`ram:ShareOwnerAccountId`** | Origem do share (para o **consumidor**) |
| **`ram:PermissionArn`** | Exigir **permissões** específicas (**menor privilégio**) |
| **`aws:ResourceTag/*`**, **`aws:RequestTag/*`** | **ABAC** (tags de governança) |
| **`aws:PrincipalOrgID`** | Em **resource policies** (outros serviços) |

## 4. Permissões gerenciadas: menor privilégio

| Prática | Detalhe |
|---|---|
| **Escolher a permissão mais restrita** | Evitar permissões amplas (ex.: **escrita** quando **leitura** basta) |
| **Customer managed permissions** | Criar permissões **sob medida** (tipos suportados) |
| **Revisar versões** | Novas versões de permissões **AWS-managed** podem **ampliar** ações: **avaliar** e **fixar** versão quando possível |
| **Exigir `ram:PermissionArn`** | SCP/IAM para **forçar** uso de permissões aprovadas |
| **Documentar** | Por que cada share usa aquela permissão |
| **Revisão** | **Trimestral** de shares e permissões |

## 5. Segurança do consumidor

O **consumidor** também precisa de **controles**:

| Controle | Detalhe |
|---|---|
| **Restringir o uso de recursos compartilhados** | SCP/IAM para usar **apenas shares** de **contas confiáveis** (`ram:ShareOwnerAccountId`) |
| **IAM do consumidor** | **Menor privilégio** sobre recursos compartilhados (ex.: só lançar EC2 em subnets **aprovadas**) |
| **Verificar donos** | Conferir `OwnerId` de **subnets** e **TGW** |
| **Aceitar convites com critério** | **Rejeitar** convites desconhecidos; **SCP** que negue `ram:AcceptResourceShareInvitation` de **fora** da organização |
| **Segmentar** | SGs/NACLs; **não confiar** em tudo na mesma VPC compartilhada |
| **Logs** | Habilitar **Flow Logs** das próprias ENIs; **CloudTrail** |

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "NegarConvitesExternos",
    "Effect": "Deny",
    "Action": "ram:AcceptResourceShareInvitation",
    "Resource": "*",
    "Condition": { "StringNotEquals": { "ram:ShareOwnerAccountId": ["111111111111", "999999999999"] } }
  }]
}
```

(Esboço; a chave e o comportamento exatos devem ser confirmados.)

## 6. Dados sensíveis e recursos de alto risco

| Recurso | Cuidados |
|---|---|
| **Glue/Lake Formation** | Compartilhar **apenas** bancos/tabelas necessários; **LF** para **coluna/linha**; **classificação (Macie)**; **sem PII** em metadados |
| **Aurora clone** | **Mascaramento**, **KMS** (chave compartilhada com cuidado), **ambientes** adequados |
| **Private CA** | **Permissões de emissão** mínimas; **auditoria** de certificados emitidos; **separar** CAs por **ambiente** |
| **Subnets/TGW** | Impacto de **rede**; compartilhar **por OU** e com **processos** de mudança |
| **License Manager** | Contratos e conformidade |
| **Capacity Reservations** | **Custos** e **abuso** (lançar muitas instâncias) |
| **Resolver/DNS Firewall/Network Firewall** | **Mudanças** afetam muitos; **versionar/testar** |

## 7. Auditoria e detecção

| O que | Fonte |
|---|---|
| **Criação/alteração/exclusão de shares** | **CloudTrail** (`CreateResourceShare`, `Update*`, `Delete*`, `Associate*`, `Disassociate*`) |
| **Convites** (criação/aceite/rejeição) | CloudTrail (`AcceptResourceShareInvitation`, etc.) |
| **Uso de recursos compartilhados** (quem fez o quê no consumidor) | CloudTrail **das contas consumidoras** (e **da dona** quando aplicável) |
| **Shares externos** | **IAM Access Analyzer** (**external access** para recursos suportados por RAM — de memória; confirmar) / consultas `ram:GetResourceShares` com `allowExternalPrincipals` |
| **Conformidade** | **AWS Config** (regras customizadas para **RAM shares externos**, tags) e **Security Hub** |
| **Eventos** | **EventBridge** (eventos do RAM/CloudTrail) → alarmes |
| **Inventário** | **Rotina** que lista **todos os shares** da organização (por conta/região) e **compara** com o **catálogo aprovado** |
| **Rede** | **Flow Logs** para tráfego em VPC compartilhada |

Alarmes sugeridos:

- **`CreateResourceShare` com principal externo** (**crítico**);
- **Shares com `allowExternalPrincipals=true`**;
- **Compartilhamento com a organização inteira** (fora de lista aprovada);
- **Exclusão/alteração** de shares críticos;
- **Mudança de permissões** (versões) em shares de rede;
- **Convites aceitos** de donos desconhecidos;
- **Novos shares** sem **tags de dono**.

### 7.1 Exemplo de regra do EventBridge

```json
{
  "source": ["aws.ram"],
  "detail-type": ["AWS API Call via CloudTrail"],
  "detail": { "eventName": ["CreateResourceShare", "AssociateResourceShare", "DeleteResourceShare", "UpdateResourceShare"] }
}
```

## 8. Governança

| Elemento | Prática |
|---|---|
| **Catálogo de shares** | **Dono**, **finalidade**, **recursos**, **principais**, **permissões**, **data de revisão**, **criticidade** |
| **Aprovação** | **Novos shares** passam por **revisão** (rede/segurança) via **PR** (IaC) |
| **Tags obrigatórias** | `dono`, `finalidade`, `ambiente`, `criticidade`, `centro-de-custo` (**SCP** exigindo tags na criação) |
| **Ciclo de vida** | **Revisão trimestral**; **remoção** de shares **obsoletos** |
| **Políticas por OU** | **Prod** mais restrito; **Sandbox** sem acesso a shares de prod |
| **Treinamento** | Equipes entendem **riscos de compartilhar** |
| **Segregação de ambientes** | **Não compartilhar** recursos de **prod** com **dev/sandbox** |
| **Evidências** | Para **auditoria** (SOC2/ISO/PCI): **inventário**, **aprovações**, **logs** |
| **Plano de resposta** | **Exposição indevida**: remover share, revisar acessos, investigar CloudTrail, notificar |

## 9. Checklist de endurecimento

- [ ] **Sharing com Organizations** habilitado; **compartilhamento externo bloqueado** (SCP + `allowExternalPrincipals=false`)
- [ ] **Quem cria shares** restrito (IAM/SCP por **papel** e **tipo de recurso**)
- [ ] **Shares por OU**, com **permissões mínimas** (customer managed quando preciso) e **versões revisadas**
- [ ] **Convites** de fora da organização **negados** (SCP) ou com **aprovação**
- [ ] **Tags obrigatórias** e **catálogo de shares**; **IaC + PR**
- [ ] **CloudTrail + EventBridge + Config/Access Analyzer** com alarmes críticos
- [ ] **Recursos sensíveis** (Glue/Aurora/CA) com **controles extras** e **LF/KMS/Macie**
- [ ] **Separação prod/não-prod** nos shares
- [ ] **SCPs** protegendo shares críticos
- [ ] **Revisões** trimestrais de shares, permissões e acessos
- [ ] **Resposta a incidentes** documentada

## 10. Erros comuns

- **Permitir compartilhamento externo por padrão**.
- **Qualquer desenvolvedor** pode criar shares.
- **Share com a organização inteira** “por simplicidade”.
- **Permissões amplas** nunca revisadas.
- **Aceitar convites** de terceiros sem validação.
- **Shares sem dono/tags**.
- **Sem alarmes** para shares externos.
- **Compartilhar prod com dev/sandbox**.
- **Tratar Private CA/Glue** como recursos “comuns”.
- **Mudanças ad hoc** (console) em shares críticos.
- **Ignorar versões** de permissões gerenciadas.

## 11. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| `AccessDenied` ao criar share | IAM/SCP (condições de tipo/principal/externo) | Ver as condições negadas; ajustar o processo |
| Não consigo adicionar principal externo | `allowExternalPrincipals=false`/SCP | Revisar a política; solicitar exceção aprovada |
| Convite não pode ser aceito | SCP negando | Revisar o `ram:ShareOwnerAccountId` aceito |
| Consumidor não usa o recurso | IAM/SCP do consumidor | Ajustar o IAM/SCP |
| Share externo detectado | Criado por exceção/erro | Remover; investigar CloudTrail; reforçar SCP |
| Permissão mudou comportamento | Nova versão de permissão gerenciada | Verificar versões; fixar/ajustar |
| Alarme de exclusão de share | Mudança indevida | Restaurar via IaC; investigar o autor |
| Shares sem tags | Criação manual | SCP exigindo tags; corrigir |

## 12. Resumo rápido

- **Trava principal**: **sharing com Organizations** + **`allowExternalPrincipals=false`** + **SCP** que **nega compartilhamento externo** (`ram:RequestedAllowsExternalPrincipals`, `ram:Principal`).
- **Controle de quem compartilha**: **IAM por papel**, **condições** (`ram:RequestedResourceType`, `ram:ResourceArn`, `ram:PermissionArn`), **IaC + PR**.
- **Menor privilégio**: **permissões mínimas/customer managed**, **revisar versões**, **shares por OU**.
- **Consumidor**: restringir **donos confiáveis** (`ram:ShareOwnerAccountId`), **rejeitar convites** externos, **IAM mínimo** sobre recursos compartilhados.
- **Sensíveis**: **Glue/Lake Formation, Aurora, Private CA** com controles extras (LF, KMS, Macie, auditoria).
- **Auditoria**: **CloudTrail/EventBridge/Config/Access Analyzer**; alarmes para **shares externos**, **org inteira**, **exclusões**, **convites**.
- **Governança**: **catálogo**, **tags**, **revisões trimestrais**, **separação prod/não-prod**, **resposta a incidentes**.

## 🧩 Quiz de Fixação

1. Quais controles impedem compartilhamento fora da organização?
2. Por que restringir quem pode criar shares e quais tipos?
3. Que riscos há em compartilhar com a organização inteira?
4. Como o consumidor pode se proteger de shares indesejados?
5. Quais eventos devem gerar alarme?
6. Por que revisar versões de permissões gerenciadas?
7. Que recursos exigem cuidados extras ao compartilhar?

**Respostas:**

1. Sharing apenas com Organizations, `allowExternalPrincipals=false` nos shares e SCPs que neguem a criação de shares externos e a associação de principais fora da organização.
2. Para evitar shadow sharing e exposição; limitando por papel e por tipo de recurso (ram:RequestedResourceType) reduz-se o risco a recursos aprovados.
3. Dá acesso excessivo a todas as contas, inclusive de sandbox ou de outras áreas, ampliando o blast radius; é preferível compartilhar por OU.
4. Restringindo por SCP/IAM os donos confiáveis (ram:ShareOwnerAccountId), negando a aceitação de convites externos, aplicando IAM mínimo e segmentação e verificando o OwnerId.
5. Criação de shares com principal externo ou allowExternalPrincipals=true, compartilhamento com a organização inteira, exclusão/alteração de shares críticos, mudanças de permissões e convites aceitos de donos desconhecidos.
6. Porque novas versões de permissões da AWS podem ampliar as ações permitidas, alterando o acesso do consumidor sem mudança no share.
7. Glue/Lake Formation (dados), Aurora clones, Private CA, Capacity Reservations, e recursos de rede/segurança como subnets, TGW, Resolver e firewalls, cujas mudanças afetam muitos.
