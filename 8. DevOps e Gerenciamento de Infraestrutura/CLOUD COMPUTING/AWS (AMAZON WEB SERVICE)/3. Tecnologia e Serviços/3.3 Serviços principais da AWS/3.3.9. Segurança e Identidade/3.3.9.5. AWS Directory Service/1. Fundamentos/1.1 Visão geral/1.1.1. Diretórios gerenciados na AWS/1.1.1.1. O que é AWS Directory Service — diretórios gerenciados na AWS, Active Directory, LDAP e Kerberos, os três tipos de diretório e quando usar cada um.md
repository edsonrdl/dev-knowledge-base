### 1.1.1.1. O que é AWS Directory Service — diretórios gerenciados na AWS, Active Directory, LDAP e Kerberos, os três tipos de diretório e quando usar cada um

> [!warning] Aviso
> Limites de objetos, tamanhos, preços, versões de Windows Server, recursos por edição e o status de cada tipo de diretório (principalmente o Simple AD) abaixo são **de memória e mudam**. **Confirme na documentação do AWS Directory Service e na página de preços.** Comandos e exemplos são ilustrativos e **não foram executados**. Nomes de domínio, IDs e usuários são fictícios (`corp.example.com`).

## 1. O problema que o Directory Service resolve

Em muitas empresas, **identidade corporativa é Microsoft Active Directory (AD)**: usuários, grupos, computadores, políticas de grupo (GPO), autenticação **Kerberos/NTLM**, consultas **LDAP**, ingresso de máquinas Windows no domínio. Ao migrar para a nuvem, surgem perguntas:

- Como as **instâncias EC2 Windows** entram em um **domínio** e usam as contas corporativas?
- Como **aplicações** (SQL Server, SharePoint, .NET) que exigem **AD** funcionam na AWS?
- Como o usuário usa **o mesmo login** no **console AWS**, **WorkSpaces**, **QuickSight** e nas aplicações?
- Como **evitar** instalar, patchear, replicar e fazer backup de **controladores de domínio** em EC2 (trabalho pesado e sensível)?
- Como manter **uma única fonte de identidade** entre **on-premises e AWS**?

O **AWS Directory Service** oferece **diretórios gerenciados** na AWS: a AWS **provisiona, replica, aplica patches, monitora e faz backup** dos controladores de domínio, e você usa o diretório com **EC2, RDS, FSx for Windows, WorkSpaces, IAM Identity Center** e outros.

> [!info] Em uma frase
> **Directory Service = Active Directory (ou compatível) gerenciado pela AWS, para que cargas de trabalho na nuvem usem identidade corporativa sem você operar controladores de domínio.**

## 2. Conceitos de diretório (revisão)

| Termo | Significado |
|---|---|
| **Diretório** | Banco hierárquico de **objetos** (usuários, grupos, computadores, impressoras) |
| **Domínio** | Fronteira administrativa/de segurança (`corp.example.com`) |
| **Controlador de domínio (DC)** | Servidor que **autentica** e guarda o diretório; há **vários** replicados |
| **Floresta (forest) / árvore** | Conjunto de domínios; **trusts** conectam florestas |
| **LDAP/LDAPS** | Protocolo para **consultar/alterar** o diretório (portas 389/636) |
| **Kerberos** | Protocolo de **autenticação** com tickets (porta 88) |
| **NTLM** | Autenticação legada |
| **DNS integrado** | O AD depende de **DNS** para localizar DCs (registros SRV) |
| **GPO (Group Policy)** | Políticas aplicadas a usuários/computadores |
| **OU (Organizational Unit)** | Contêiner para organizar e **delegar** administração |
| **Trust (relação de confiança)** | Permite que usuários de um domínio acessem recursos de outro |
| **Domain join** | Ingressar um computador no domínio |
| **Schema** | Definição de classes e atributos do diretório |
| **Service account** | Conta técnica usada por aplicações/conectores |

## 3. Os três tipos de diretório (visão geral)

O Directory Service oferece **três tipos** (mais o Cognito como serviço relacionado, porém diferente):

| Tipo | O que é | Resumo |
|---|---|---|
| **AWS Managed Microsoft AD** | **Active Directory real** (Windows Server) gerenciado pela AWS | **Mais completo**: trusts, GPO, LDAPS, esquema, multi-região |
| **AD Connector** | **Proxy** que **redireciona** requisições ao **AD on-premises** | **Não armazena** dados; exige conectividade (VPN/Direct Connect) |
| **Simple AD** | Diretório **compatível com AD** baseado em **Samba 4** | **Básico**; sem trusts/MFA; **legado** (confirmar o status atual) |

### 3.1 AWS Managed Microsoft AD

| Aspecto | Detalhe (de memória — confirmar) |
|---|---|
| **Tecnologia** | **Active Directory real** em **Windows Server** (nível funcional de floresta/domínio recente) |
| **Edições** | **Standard** (diretórios menores; ordem de **30 mil objetos**) e **Enterprise** (grandes; ordem de **500 mil objetos**; mais recursos como **multi-região**) |
| **DCs** | **Mínimo de dois** DCs em **AZs diferentes** (HA); é possível **adicionar DCs** |
| **Trusts** | **One-way** ou **two-way**, **forest** ou **external**, com **AD on-premises** (ou outro Managed AD) |
| **Recursos AD** | **GPO**, **extensões de esquema** (LDIF), **LDAPS**, **Kerberos constrained delegation**, **políticas de senha refinadas**, **replicação** |
| **Multi-região** | **Replicação** do diretório para outras regiões (Enterprise) |
| **Compartilhamento** | **Directory sharing**: compartilhar com **outras contas/VPCs** (Organizations) |
| **Administração** | Conta **Admin** e grupo **delegado** (“AWS Delegated Administrators”): **sem** acesso total de Domain Admin/Enterprise Admin (a AWS gerencia o restante) |
| **Backup/patch** | **AWS** gerencia: snapshots automáticos, patches, substituição de DCs com falha |
| **Integrações** | EC2 (domain join), RDS (SQL Server, Oracle, MySQL, PostgreSQL), FSx for Windows, WorkSpaces, Identity Center, QuickSight, Amazon Connect, etc. |
| **MFA** | **RADIUS** (para acesso a aplicações/console AWS conforme integração) |

### 3.2 AD Connector

| Aspecto | Detalhe |
|---|---|
| **O que é** | **Gateway/proxy**: recebe requisições de autenticação de serviços AWS e as **encaminha ao AD on-premises** |
| **Dados** | **Nenhum** dado do diretório é armazenado ou **cacheado** na AWS |
| **Tamanhos** | **Small** (até ~500 usuários) e **Large** (até ~5.000), conforme o desempenho; **vários conectores** para escalar |
| **Pré-requisitos** | **Conectividade** (VPN/Direct Connect) com o AD; **conta de serviço** com permissões delegadas; **DNS** resolvendo o domínio on-premises; portas liberadas |
| **Uso** | “**Quero que serviços AWS usem meu AD on-premises existente**, sem replicar nem manter um segundo diretório” |
| **Limitações** | **Dependência total** da conexão e do AD on-premises; sem **extensão de esquema**/GPO na AWS; **não cria** objetos na nuvem |
| **MFA** | Suporta **RADIUS** (de memória) |
| **Custo** | **Por hora** pelo conector (mais barato que o Managed AD) |

### 3.3 Simple AD

| Aspecto | Detalhe (de memória — confirmar) |
|---|---|
| **O que é** | Diretório **standalone** compatível com AD usando **Samba 4** |
| **Recursos** | Contas de usuário, grupos, **domain join** de instâncias, **Kerberos**, **GPO básico**, **DNS** |
| **Tamanhos** | **Small** (~500 usuários) e **Large** (~5.000) |
| **Limitações** | **Sem trusts**, **sem MFA/RADIUS**, **sem multi-região**, **sem extensão de esquema**, **sem LDAPS** nativo (confirmar), **sem integração** com alguns serviços (ex.: RDS SQL Server Windows auth) |
| **Quando** | Cenários **simples** e isolados (poucas dezenas de usuários, aplicações Linux/Samba) |
| **Status** | A AWS recomenda **Managed Microsoft AD** como padrão; o Simple AD é **legado** — **confirme a política atual de suporte/novos clientes** |

### 3.4 Serviços relacionados (não são diretórios AD)

| Serviço | Papel |
|---|---|
| **Amazon Cognito** | Identidade de **usuários de aplicações** (clientes finais), JWT/OAuth; **não** é AD |
| **IAM Identity Center** | **SSO workforce** para contas AWS e apps; usa **AD (Managed AD/AD Connector)** ou IdP externo como **fonte de identidade** |
| **IAM** | Identidades e permissões **AWS** (não substitui AD) |
| **Amazon Cloud Directory** | Diretório hierárquico genérico (serviço **descontinuado** — não usar em novos projetos; confirmar) |
| **AD em EC2 (self-managed)** | Você instala e opera DCs em EC2: **controle total**, **trabalho total** |

## 4. Como escolher (resumo)

```
Preciso de identidade AD na AWS?
├─ Meu AD está on-premises e QUERO MANTÊ-LO como fonte única, sem replicar?
│      └─ AD Connector (proxy)  [exige VPN/DX; dependência do on-prem]
├─ Preciso de AD de verdade na AWS (GPO, trusts, LDAPS, RDS SQL Server, FSx, esquema)?
│      └─ AWS Managed Microsoft AD  [com ou sem trust ao on-prem]
├─ Preciso de diretório simples e barato, poucos usuários, sem trusts/MFA?
│      └─ Simple AD (legado; considerar Managed AD)
├─ Preciso de controle total (schema/Domain Admin irrestrito/funcionalidades específicas)?
│      └─ AD self-managed em EC2
└─ Quero identidade para os clientes finais da minha aplicação (login/social)?
       └─ Amazon Cognito (não é Directory Service)
```

### 4.1 Tabela de decisão

| Critério | **Managed Microsoft AD** | **AD Connector** | **Simple AD** | **AD em EC2** |
|---|---|---|---|---|
| **Armazena diretório na AWS** | Sim | **Não** | Sim | Sim |
| **Depende do AD on-prem** | Opcional (trust) | **Total** | Não | Opcional |
| **Trusts** | **Sim** | Não (proxy) | **Não** | Sim |
| **GPO completo / esquema** | Sim | Não | Limitado | Sim |
| **LDAPS** | Sim | Via on-prem | Limitado | Sim |
| **Multi-região** | **Sim** (Enterprise) | — | Não | Manual |
| **RDS SQL Server (Windows auth)** | **Sim** | Não | Não | Via configuração própria |
| **Operação (patch/backup)** | **AWS** | AWS (conector) | AWS | **Você** |
| **Custo** | Mais alto | **Baixo** | Baixo | Instâncias + operação |
| **Domain Admin irrestrito** | Não (delegado) | — | Limitado | **Sim** |

## 5. Casos de uso típicos

1. **Migrar aplicações Windows/.NET/SQL Server** que exigem AD para a AWS (Managed AD + RDS/EC2).
2. **Híbrido**: **Managed AD com trust** ao AD on-premises → usuários corporativos acessam recursos na AWS com suas credenciais, **sem** copiar contas.
3. **Console AWS com credenciais corporativas**: **IAM Identity Center** (ou federação) com AD como fonte.
4. **WorkSpaces/AppStream**: usuários autenticam no AD.
5. **FSx for Windows File Server**: exige AD para permissões **SMB/NTFS**.
6. **Domain join sem servidor de domínio próprio**: instâncias EC2 (Windows e Linux) ingressam no domínio.
7. **Autenticação centralizada** para aplicações LDAP-aware (Linux com SSSD, ferramentas internas).
8. **Contas AWS múltiplas**: **diretório compartilhado** entre contas.
9. **DR e multi-região**: replicação de diretório para uma segunda região (Enterprise).

## 6. Como as peças se conectam (visão geral)

```

 ┌──────────────┐   VPN / Direct Connect   ┌─────────────────────────────────────────┐

 └──────────────┘                          │  ├─ EC2 (domain join) • RDS • FSx • WorkSpaces │

                                           └─────────────────────────────────────────┘
```

## 7. Primeiros passos (ilustrativo)

```bash
# Criar um AWS Managed Microsoft AD (ilustrativo; a senha vem de um cofre, nunca em texto no script)
aws ds create-microsoft-ad \
  --name corp.example.com --short-name CORP \
  --password "$(aws secretsmanager get-secret-value --secret-id ad-admin --query SecretString --output text)" \
  --description "AD gerenciado de producao" --edition Enterprise \
  --vpc-settings VpcId=vpc-0abc,SubnetIds=subnet-0a1,subnet-0b2

# Listar diretórios e ver o estado
aws ds describe-directories
aws ds describe-domain-controllers --directory-id d-1234567890

# Criar um AD Connector (proxy para o AD on-premises)
aws ds connect-directory --name corp.example.com --short-name CORP --size Small \
  --password "$(aws secretsmanager get-secret-value --secret-id adconn-svc --query SecretString --output text)" \
  --connect-settings VpcId=vpc-0abc,SubnetIds=subnet-0a1,subnet-0b2,CustomerDnsIps=10.50.0.10,10.50.0.11,CustomerUserName=svc-adconnector
```

## 8. Erros comuns

- **Escolher AD Connector** esperando que funcione **sem** conectividade ao on-premises (ele **só repassa**).
- **Achar que o Managed AD dá Domain Admin completo**: a administração é **delegada**.
- **Usar Simple AD** por custo e depois precisar de **trust/RDS SQL Server/LDAPS**.
- **Esquecer DNS**: instâncias não resolvem o domínio (a VPC deve usar os **DNS do diretório** ou regras de **Route 53 Resolver**).
- **Subnets em uma só AZ** (os DCs precisam de **AZs diferentes**).
- **Confundir Directory Service com Cognito** (clientes finais vs identidade corporativa).
- **Colocar o AD em VPC compartilhada sem planejar** a conectividade das demais.
- **Senha do Admin** em texto no script/IaC.
- **Sem backup/DR** pensando que “gerenciado” cobre tudo (há snapshots, mas **planeje** multi-região para DR crítico).
- **Esquecer licenças/CALs** de aplicações Windows específicas (confirmar o que está incluso).

## 9. Troubleshooting inicial

| Sintoma | Causas prováveis | Ações |
|---|---|---|
| Domain join falha | DNS da instância não aponta ao diretório; portas bloqueadas; credenciais | Ajustar DNS/DHCP options; liberar portas no SG; testar `nslookup` do domínio |
| AD Connector “Impaired” | VPN/DX fora, DNS on-prem inacessível, credenciais da conta de serviço | Verificar conectividade, DNS e conta de serviço |
| Login falha para contas on-prem no Managed AD | Trust quebrado; DNS condicional ausente; horário fora de sincronia | Validar o trust, **conditional forwarders** e NTP |
| Não consigo criar usuários/GPO | Permissões delegadas | Usar a conta Admin/grupo delegado; ver o escopo |
| Diretório “Inoperable/Impaired” | DC com falha, rede/SG, subnets | Ver o status dos DCs; a AWS pode substituir; abrir chamado |
| Serviço AWS não lista o diretório | Tipo/edição incompatível ou região diferente | Checar a compatibilidade e a região |

## 10. Resumo rápido

- **Directory Service** = diretórios **gerenciados** (AD ou compatível) para identidade corporativa na AWS, sem operar DCs.
- **Três tipos**: **Managed Microsoft AD** (AD real: trusts, GPO, LDAPS, esquema, multi-região), **AD Connector** (**proxy**, não armazena nada, exige VPN/DX), **Simple AD** (Samba, básico, **legado**).
- **Managed AD**: ≥ **2 DCs em 2 AZs**, edições **Standard/Enterprise**, administração **delegada**, integra **EC2, RDS, FSx, WorkSpaces, Identity Center**.
- **Escolha**: AD on-prem como fonte única → **AD Connector**; AD completo na AWS/trust → **Managed AD**; controle total → **AD em EC2**; clientes finais → **Cognito**.
- Cuidados: **DNS**, **conectividade**, **AZs**, **senhas no cofre**, **planejamento de DR**.

## 🧩 Quiz de Fixação

1. Qual a principal diferença entre Managed Microsoft AD e AD Connector?
2. O que o Managed AD exige de infraestrutura mínima (DCs e AZs)?
3. Por que o AD Connector depende de VPN/Direct Connect?
4. Que limitações do Simple AD o tornam inadequado em muitos casos?
5. Quando usar Cognito em vez de Directory Service?
6. O que significa dizer que a administração do Managed AD é delegada?
7. Cite três serviços AWS que se integram ao Managed AD.

**Respostas:**

1. O Managed AD é um Active Directory real hospedado e armazenado na AWS; o AD Connector é apenas um proxy que encaminha autenticações ao AD on-premises, sem armazenar dados.
2. Pelo menos dois controladores de domínio em AZs diferentes (alta disponibilidade), com possibilidade de adicionar mais.
3. Porque ele repassa as requisições ao AD on-premises; sem conectividade, não há autenticação.
4. Sem trusts, MFA, multi-região e extensão de esquema, com integrações limitadas (por exemplo RDS SQL Server com Windows auth); além de ser legado.
5. Quando se precisa de identidade para os usuários finais de uma aplicação (login, social, JWT/OAuth), não de identidade corporativa com AD.
6. Que você usa a conta Admin e o grupo delegado, sem privilégios irrestritos de Domain/Enterprise Admin; a AWS gerencia o restante da infraestrutura.
7. EC2 (domain join), RDS, FSx for Windows, WorkSpaces, IAM Identity Center e QuickSight (quaisquer três).
