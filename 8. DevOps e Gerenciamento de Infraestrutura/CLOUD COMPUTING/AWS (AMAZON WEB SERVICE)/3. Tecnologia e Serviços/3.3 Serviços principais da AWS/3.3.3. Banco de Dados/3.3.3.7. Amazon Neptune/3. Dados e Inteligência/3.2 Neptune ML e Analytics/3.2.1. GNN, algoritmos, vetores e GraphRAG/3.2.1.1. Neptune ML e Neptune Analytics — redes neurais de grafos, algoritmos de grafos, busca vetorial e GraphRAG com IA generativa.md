### Neptune ML e Neptune Analytics — redes neurais de grafos, algoritmos de grafos, busca vetorial e GraphRAG com IA generativa

> [!warning] Aviso
> **Neptune Analytics**, **Neptune ML**, a busca vetorial e as integrações de **GraphRAG** são **recursos recentes e em rápida evolução**: disponibilidade por região, limites, algoritmos suportados, linguagens (o Neptune Analytics usa openCypher) e preços mudam com frequência. **Confirme tudo na documentação antes de projetar.** Os exemplos são **ilustrativos e não foram executados**.

Além de consultar o grafo de forma transacional (OLTP), é possível **extrair inteligência** dele de três maneiras: **machine learning sobre grafos** (**Neptune ML**, com redes neurais de grafos — GNN), **análises e algoritmos de grafos em memória** em escala (**Neptune Analytics**), e **IA generativa fundamentada em grafos** (**GraphRAG**), que combina **busca vetorial** com **relacionamentos** para respostas mais precisas e explicáveis. Esta nota explica cada uma, quando usar e como se relacionam com o cluster Neptune "clássico".

**Analogia:** o cluster Neptune é o **mapa para navegar** (rotas e vizinhanças). O Neptune ML é o **analista que aprende padrões do mapa** e prevê (esta conta é suspeita? qual produto o cliente quer?). O Neptune Analytics é a **sala de situação** que roda cálculos gigantes sobre o mapa inteiro de uma vez (quem são os nós mais influentes? quais comunidades existem?). O GraphRAG é o **guia turístico com IA** que usa o mapa para responder com contexto.

## Visão geral das três capacidades

| Capacidade | O que faz | Onde roda | Linguagem |
|---|---|---|---|
| **Neptune ML** | Treina GNNs sobre o grafo para **prever** (classificação, regressão, ligação) | Cluster Neptune + SageMaker (treinamento/inferência) | Gremlin, SPARQL (com extensões) |
| **Neptune Analytics** | **Algoritmos** (PageRank, caminhos, comunidades), **análise em memória** e **busca vetorial** em grafos grandes | Serviço separado (graph em memória, em m-NCUs) | **openCypher** |
| **GraphRAG** | Recuperação aumentada por grafo para **IA generativa** | Neptune Analytics + Bedrock Knowledge Bases / frameworks (graphrag-toolkit) | openCypher + vetores |

## Neptune ML (machine learning em grafos)

### O que são GNNs

**Redes neurais de grafos (GNN)** aprendem representações (*embeddings*) de nós e arestas considerando **as propriedades e a vizinhança**. Isso captura padrões que modelos tabulares perdem (uma conta é suspeita por **com quem se conecta**).

### Tarefas suportadas

| Tarefa | Pergunta | Exemplo |
|---|---|---|
| **Classificação de nós** | Qual a categoria deste nó? | Conta fraudulenta ou legítima |
| **Regressão de nós** | Qual o valor numérico deste nó? | Valor esperado de um cliente |
| **Classificação/regressão de arestas** | Qual o tipo/valor desta relação? | Risco de uma transferência |
| **Predição de ligação (link prediction)** | Que relação provavelmente existe/surgirá? | Produto que o cliente comprará (recomendação) |
| **Predição de ligação com RDF** | Idem em triplas | Interação entre entidades |

### Fluxo

```
 1. Exportar dados do grafo (Neptune-Export) → S3
 2. Processar dados (SageMaker Processing): codificar propriedades, dividir treino/validação/teste
 3. Treinar o modelo (SageMaker Training; GNN com DGL) e ajustar hiperparâmetros
 4. Criar o endpoint de inferência (SageMaker)
 5. Consultar predições nas próprias consultas do grafo (Gremlin/SPARQL com extensões Neptune#ml)
```

```groovy
// Gremlin: pedir ao modelo a classificação de uma conta (extensão Neptune ML)
g.with("Neptune#ml.endpoint", "endpoint-fraude").with("Neptune#ml.iamRoleArn", "arn:aws:iam::111122223333:role/neptune-ml")
 .V('c1').properties("risco").with("Neptune#ml.classification").value()
```

| Aspecto | Detalhe |
|---|---|
| **Configuração** | Stack do CloudFormation / assistente que cria roles, buckets e SageMaker |
| **Custo** | Treinamento e endpoint no SageMaker; armazenamento S3 |
| **Quando usar** | Há muitos dados rotulados, relacionamentos informativos e as regras manuais não bastam |
| **Cuidados** | Dados de qualidade, vazamento de rótulos, retreinamento periódico, explicabilidade e viés, latência da inferência |

## Neptune Analytics

O **Neptune Analytics** é um mecanismo de **análise de grafos em memória**, separado do cluster OLTP, para **grafos grandes (bilhões de relacionamentos)** com **algoritmos paralelos**, **busca vetorial** e **carga rápida**. Pensado para análises exploratórias, ciência de dados e GenAI.

```
 Cluster Neptune (OLTP) ──export/import──► NEPTUNE ANALYTICS (grafo em memória)  ◄── S3 (CSV/Parquet/RDF)
                                               │ openCypher + algoritmos + vetores
                                               ▼
                           notebooks, SageMaker, aplicações, Bedrock (GraphRAG)
```

| Característica | Detalhe |
|---|---|
| **Capacidade** | Provisionada em **m-NCUs** (*memory-optimized* NCUs); dimensione pelo tamanho do grafo e do índice vetorial |
| **Linguagem** | **openCypher** (e chamadas de algoritmos) |
| **Carga** | Do S3 (CSV, Parquet, RDF), de um cluster Neptune ou de snapshots; carga muito rápida |
| **Algoritmos** | Centralidade (PageRank, grau, betweenness, closeness), caminhos (menor caminho, BFS), **comunidades** (Louvain, label propagation), componentes conexos, similaridade |
| **Busca vetorial** | Armazena embeddings nos nós e busca por similaridade combinada com travessias |
| **Escrita** | Suporta atualizações, mas é orientado a análise; não é substituto de um OLTP transacional |
| **Replicas e disponibilidade** | Opções de réplicas e Multi-AZ (confirme) |
| **Segurança** | VPC endpoints, IAM, KMS |

### Exemplos de algoritmos

```cypher
// PageRank: nós mais influentes
CALL neptune.algo.pageRank.mutate({writeProperty: 'pagerank'}) YIELD success
MATCH (n:Pessoa) RETURN n.nome, n.pagerank ORDER BY n.pagerank DESC LIMIT 10

// Detecção de comunidades (Louvain)
CALL neptune.algo.louvain({edgeLabels:['CONHECE']}) YIELD node, community
RETURN community, count(node) AS tamanho ORDER BY tamanho DESC LIMIT 10

// Menor caminho entre dois nós
MATCH p = shortestPath((a:Conta {id:'c1'})-[*..6]-(b:Conta {id:'c99'})) RETURN length(p)
```

(A sintaxe de chamadas de algoritmos é específica do produto; consulte a referência atual.)

### Quando usar cada um

| Necessidade | Escolha |
|---|---|
| Consultas transacionais, baixa latência, escrita contínua | **Cluster Neptune** |
| Análises pesadas e exploratórias sobre o grafo inteiro (centralidade, comunidades) | **Neptune Analytics** |
| Vetores + grafo (RAG com relacionamentos) | **Neptune Analytics** |
| Prever propriedades/ligações com aprendizado | **Neptune ML** |
| Consulta ocasional de caminho curto | Cluster (travessia) |

## Busca vetorial e GraphRAG

### Busca vetorial

**Embeddings** (vetores numéricos de texto/imagem) permitem achar itens **semanticamente similares**. No Neptune Analytics, os vetores ficam nos nós e a busca combina **similaridade** com **travessia de relacionamentos**.

### GraphRAG

O **RAG** tradicional (recuperação aumentada) busca trechos de texto por similaridade vetorial e os entrega ao LLM. O **GraphRAG** acrescenta o **grafo de conhecimento**: além dos trechos similares, recupera **entidades e relações conectadas**, o que dá **contexto estruturado**, melhora perguntas que exigem **múltiplos saltos** ("que fornecedores dos nossos clientes na região X foram afetados pelo evento Y?") e oferece **explicabilidade** (o caminho no grafo).

```
 Documentos ──LLM extrai entidades e relações──► Grafo de conhecimento (Neptune Analytics) + embeddings
 Pergunta ──embedding──► busca vetorial (entradas) ──travessia (vizinhança)──► contexto estruturado ──► LLM (Bedrock) ──► resposta com fontes
```

| Etapa | Ferramenta |
|---|---|
| **Extração** de entidades/relações | LLM (Bedrock) com prompts/esquemas; pipelines |
| **Armazenamento** | Neptune Analytics (grafo + vetores) |
| **Recuperação** | Consulta openCypher com `topK` vetorial + expansão por vizinhança |
| **Geração** | Bedrock (modelos de fundação) e **Bedrock Knowledge Bases com GraphRAG** (integração gerenciada, quando disponível) |
| **Frameworks** | `graphrag-toolkit` (open source da AWS), LangChain, LlamaIndex |
| **Avaliação** | Qualidade das respostas, citações, alucinação |

Boas práticas: esquema de entidades bem definido; deduplicação de entidades (resolução); limites de expansão no grafo para controlar contexto/custo; guardrails e controle de acesso; avaliação contínua.

## Exemplo prático

Assistente de conformidade de uma indústria farmacêutica:

1. **Fontes:** políticas, protocolos, relatórios de segurança e bulas (PDFs no S3).
2. **Extração:** pipeline com Bedrock extrai entidades (medicamentos, substâncias, eventos adversos, fornecedores, normas) e relações (CONTÉM, AFETA, REGULADO_POR, FORNECIDO_POR) com deduplicação.
3. **Neptune Analytics:** grafo com ~2 bilhões de relações e embeddings dos trechos (1.024 dimensões).
4. **Consulta GraphRAG:** "que lotes de qual fornecedor foram afetados pelo evento adverso X?": busca vetorial acha os trechos e as entidades; a travessia expande por 2-3 saltos (FORNECIDO_POR, AFETA); o contexto estruturado vai ao LLM.
5. **Algoritmos:** Louvain detecta clusters de fornecedores; PageRank prioriza os nós críticos da cadeia.
6. **Neptune ML (cluster OLTP):** modelo de classificação para risco de desvio de qualidade por lote, treinado semanalmente.
7. **Governança:** controle de acesso por projeto (IAM e filtros de propriedade), citações obrigatórias, avaliação mensal de qualidade, VPC endpoints.
8. **Custo:** m-NCUs dimensionadas pelo tamanho do grafo; pausar/redimensionar ambientes de teste.

## Erros comuns e armadilhas

- **Usar Neptune Analytics como OLTP** ou o cluster como motor de algoritmos pesados.
- **Treinar GNN sem dados rotulados suficientes** ou com vazamento de rótulos.
- **Não retreinar** modelos (drift).
- **GraphRAG sem resolução de entidades:** duplicatas fragmentam o grafo.
- **Expansão ilimitada de vizinhança:** contexto enorme, custo e alucinação.
- **Embeddings de modelos diferentes** misturados no mesmo índice.
- **Ignorar controle de acesso** em conhecimento sensível.
- **Subdimensionar m-NCUs** (grafo não cabe na memória) ou superdimensionar.
- **Assumir disponibilidade/recursos iguais em todas as regiões.**
- **Não medir qualidade** das respostas (sem avaliação).

## 🧩 Quiz de Fixação

1. O que o Neptune ML adiciona a um grafo e quais tarefas ele suporta?
2. Em que o Neptune Analytics difere do cluster Neptune?
3. O que é GraphRAG e qual sua vantagem sobre o RAG vetorial puro?
4. Quando usar algoritmos como PageRank e Louvain?

**Respostas:**
1) Permite treinar redes neurais de grafos (via SageMaker/DGL) e obter predições nas consultas; suporta classificação e regressão de nós e arestas e predição de ligações (como recomendações).
2) O Neptune Analytics é um mecanismo de análise em memória, separado, para grafos grandes, com algoritmos paralelos, busca vetorial e openCypher, voltado a análises e GenAI; o cluster Neptune é o banco transacional (OLTP) de baixa latência.
3) É a recuperação aumentada por grafo: além de trechos similares por vetor, recupera entidades e relações conectadas, dando contexto estruturado, melhor suporte a perguntas de vários saltos e explicabilidade pelo caminho no grafo.
4) Para análises sobre o grafo inteiro: PageRank para achar nós influentes/críticos, Louvain para detectar comunidades (por exemplo clusters de fornecedores ou grupos de fraude), geralmente no Neptune Analytics.
