### 3.1.1.1. Tarefas no DataSync — opções de transferência e verificação, filtros include e exclude, agendamento, modos Basic e Enhanced, task reports e execuções incrementais

> [!warning] Aviso
> Os comandos, opções e valores abaixo são **ilustrativos e não foram executados**. Opções de tarefa, modos (Basic e Enhanced), limites de arquivos e comportamento de verificação mudam entre versões do serviço; confirme na documentação oficial. Opções como `PreserveDeletedFiles=REMOVE` **apagam dados no destino**: teste em uma cópia antes de usar em produção.

## 1. A tarefa como unidade de trabalho

A **task** do DataSync é a definição de uma transferência: **origem + destino + opções + (opcional) filtros, agenda e relatório**. Cada vez que a tarefa roda, gera uma **task execution**. Pensar em tarefa como "um job repetível" ajuda: você a configura uma vez e a executa várias vezes (carga inicial e depois incrementais).

```
Task = Location origem + Location destino + Options + Filters + Schedule + Report + Logs
   └── Execution 1 (carga inicial)
   └── Execution 2 (incremental: só o que mudou)
   └── Execution N ...
```

## 2. Modos de tarefa: Basic e Enhanced

O DataSync oferece **modos de tarefa** que determinam escala e recursos.

| Aspecto | **Basic mode** | **Enhanced mode** |
|---|---|---|
| Conceito | Modo clássico, com limites de arquivos por tarefa | Modo mais novo, com **maior escala e desempenho** para alguns pares de locations |
| Escala | Limitada por tarefa (ordem de dezenas de milhões de arquivos); grandes árvores exigem dividir | Praticamente **sem limite prático de arquivos/objetos** por tarefa |
| Pares suportados | Todos os suportados | Foco em **transferências de/para S3** e entre serviços de objeto (verificar a lista atual) |
| Métricas e relatórios | Padrão | Métricas e relatórios mais detalhados e com início de transferência mais rápido |
| Custo | Por GB transferido | Modelo de preço próprio (por objeto e/ou GB; verificar a página de preços) |

> [!tip] Dica
> A disponibilidade de **Enhanced mode** depende do par de locations e da região. Consulte a documentação atual antes de decidir; se o seu par suporta Enhanced, ele costuma simplificar tarefas com **centenas de milhões de objetos**, evitando a divisão manual.

## 3. Opções de transferência

As opções (`--options`) controlam como o DataSync trata dados e metadados.

| Opção | Valores | Efeito |
|---|---|---|
| **TransferMode** | `CHANGED` (padrão) / `ALL` | Copia só o que mudou, ou **tudo** sem comparar |
| **VerifyMode** | `POINT_IN_TIME_CONSISTENT` / `ONLY_FILES_TRANSFERRED` / `NONE` | Estratégia de verificação de integridade |
| **OverwriteMode** | `ALWAYS` / `NEVER` | Sobrescreve arquivos diferentes no destino ou não |
| **PreserveDeletedFiles** | `PRESERVE` / `REMOVE` | Mantém no destino o que foi apagado na origem, ou **remove** |
| **PreserveDevices** | `NONE` / `PRESERVE` | Preserva arquivos de dispositivo (POSIX) |
| **Atime / Mtime** | `NONE` / `BEST_EFFORT` / `PRESERVE` | Preserva tempos de acesso/modificação |
| **Uid / Gid** | `NONE` / `INT_VALUE` / `NAME` / `NAME_STRING` | Preserva proprietário e grupo POSIX |
| **PosixPermissions** | `NONE` / `PRESERVE` | Preserva permissões POSIX |
| **SecurityDescriptorCopyFlags** | `NONE` / `OWNER_DACL` / `OWNER_DACL_SACL` | ACLs NTFS (SMB/FSx Windows) |
| **TaskQueueing** | `ENABLED` / `DISABLED` | Enfileira execuções da mesma tarefa |
| **LogLevel** | `OFF` / `BASIC` / `TRANSFER` | Detalhe dos logs no CloudWatch |
| **BytesPerSecond** | `-1` (sem limite) ou valor em B/s | **Limite de banda** da tarefa |
| **ObjectTags** | `PRESERVE` / `NONE` | Copia tags de objeto S3 |

### 3.1 Modo de transferência

- **CHANGED**: compara origem e destino e copia somente arquivos novos ou modificados — é o modo **incremental** e o mais usado.
- **ALL**: copia **todos** os arquivos sem verificar o destino — útil quando o destino está vazio e você quer **evitar o custo de listar/comparar**, ou ao forçar recópia.

### 3.2 Modos de verificação

| Modo | O que verifica | Quando usar |
|---|---|---|
| **POINT_IN_TIME_CONSISTENT** (padrão) | Ao final, **compara toda a origem e todo o destino** | Máxima garantia; custo maior em tempo |
| **ONLY_FILES_TRANSFERRED** | Verifica apenas os arquivos copiados nesta execução | Execuções incrementais grandes, equilíbrio |
| **NONE** | Sem verificação adicional | Quando a integridade é garantida por outros meios e a velocidade importa |

Para **migrações finais** (antes do corte), use verificação completa. Para **sincronizações diárias**, `ONLY_FILES_TRANSFERRED` costuma bastar.

### 3.3 Exclusão no destino

`PreserveDeletedFiles=PRESERVE` (padrão) mantém no destino arquivos que não existem mais na origem — seguro contra exclusões acidentais. `REMOVE` **espelha** a origem, apagando do destino o que sumiu. Em espelhamento, ative **versionamento no S3** e considere **MFA Delete/Object Lock** para recuperar erros.

## 4. Filtros: include e exclude

Filtros reduzem o escopo da tarefa por **padrões de caminho** (sem diferenciar maiúsculas de minúsculas, em geral).

```bash
aws datasync create-task \
  --source-location-arn ... --destination-location-arn ... \
  --includes FilterType=SIMPLE_PATTERN,Value="/projetos|/financeiro|/rh" \
  --excludes FilterType=SIMPLE_PATTERN,Value="*.tmp|*/cache/*|*/.snapshot/*|*~"
```

Regras úteis:

- **`--includes`** define os caminhos a considerar (por exemplo, apenas algumas pastas). Padrões separados por `|`.
- **`--excludes`** remove itens do conjunto (temporários, caches, snapshots do NAS).
- O curinga `*` casa qualquer sequência de caracteres. Teste os padrões com `list` na origem para evitar surpresas.
- Combinar include (pastas) e exclude (extensões) é comum.
- Para uma execução específica, é possível **sobrescrever** os filtros em `start-task-execution`, por exemplo, para migrar **apenas uma subpasta** em um dia.

> [!warning] Cuidado
> Filtros afetam também **o que é verificado e o que é considerado "removido"**. Mudar filtros entre execuções com `PreserveDeletedFiles=REMOVE` pode **apagar do destino** arquivos que agora estão fora do filtro. Documente e revise antes de alterar.

## 5. Agendamento

Uma tarefa pode rodar **recorrentemente** com um agendamento (expressão **cron** ou **rate**), com **intervalo mínimo de uma hora**.

```bash
aws datasync create-task ... \
  --schedule ScheduleExpression="cron(0 2 * * ? *)"   # todo dia às 02:00 UTC

aws datasync update-task --task-arn arn:... \
  --schedule ScheduleExpression="rate(12 hours)"
```

Boas práticas:

- Agende as execuções **fora do horário de pico** e combine com **limite de banda**.
- Garanta que o intervalo seja **maior que a duração** típica da execução; caso contrário, execuções se acumulam. Habilite **TaskQueueing** para enfileirar em vez de falhar quando houver execução em andamento.
- Para o **corte final**, desative o agendamento e execute **manualmente** a última sincronização.
- Para cronogramas mais complexos ou dependentes de eventos, dispare a execução por **EventBridge Scheduler** ou **Step Functions** chamando `StartTaskExecution`.

## 6. Execuções: ciclo de vida

Estados típicos de uma **task execution**:

```
QUEUED ─▶ LAUNCHING ─▶ PREPARING ─▶ TRANSFERRING ─▶ VERIFYING ─▶ SUCCESS
                                         │                 │
                                         └────────▶ ERROR ◀┘
```

- **PREPARING**: faz o inventário da origem e do destino e decide o que copiar. Em árvores enormes, essa fase pode levar tempo considerável (o **scan** é custo fixo por execução).
- **TRANSFERRING**: copia dados em paralelo.
- **VERIFYING**: confere integridade (conforme `VerifyMode`).
- Pode-se **cancelar** (`cancel-task-execution`) e **reexecutar**; o que já foi copiado não é recopiado em `CHANGED`.

Iniciar com sobrescrita de opções:

```bash
aws datasync start-task-execution \
  --task-arn arn:... \
  --override-options VerifyMode=POINT_IN_TIME_CONSISTENT,BytesPerSecond=104857600 \
  --includes FilterType=SIMPLE_PATTERN,Value="/projetos/2026"
```

Acompanhar:

```bash
aws datasync describe-task-execution --task-execution-arn arn:.../execution/exec-0abc
# Campos relevantes: Status, EstimatedFilesToTransfer, FilesTransferred, BytesTransferred,
# FilesVerified, FilesFailed (quando disponível), StartTime, Result
```

## 7. Task reports

Os **task reports** geram, em um bucket S3, **arquivos detalhados** por execução:

| Relatório | Conteúdo |
|---|---|
| **Summary** | Resumo da execução (contagens, bytes, estado) |
| **Transferred** | Lista de arquivos/objetos transferidos |
| **Verified** | Lista dos verificados e resultado |
| **Skipped** | Itens ignorados (por filtro ou sem mudança) |
| **Deleted** | Itens removidos do destino (quando há exclusão) |

Configuração ilustrativa:

```bash
aws datasync update-task --task-arn arn:... \
  --task-report-config '{"Destination":{"S3":{"Subdirectory":"relatorios/","S3BucketArn":"arn:aws:s3:::meu-bucket-relatorios","BucketAccessRoleArn":"arn:aws:iam::123456789012:role/datasync-report-role"}},"OutputType":"STANDARD","ReportLevel":"ERRORS_ONLY"}'
```

`ReportLevel=ERRORS_ONLY` reduz o volume e destaca falhas; `SUCCESSES_AND_ERRORS` dá trilha completa (útil para **auditoria** de migração). Os relatórios são ótimos insumos para **Athena**: consulte erros por tipo e por diretório.

## 8. Execuções incrementais e estratégia de corte

Fluxo clássico de migração de um file server:

```
1. Carga inicial (semanas): TransferMode=CHANGED, banda limitada, fora do pico
2. Incrementais diárias: ONLY_FILES_TRANSFERRED, agendadas à noite
3. Ensaio do corte: sincronização completa + verificação POINT_IN_TIME_CONSISTENT
4. Janela de corte:
      a) congela escrita na origem (read-only)
      b) executa a última sincronização
      c) valida (contagem, tamanho, amostras, relatório sem erros)
      d) redireciona usuários/aplicações para o destino (DNS, mapeamento de drives, montagens)
5. Mantém a origem em somente leitura por um período de segurança
```

A janela do passo 4 é curta porque as **diferenças** são pequenas depois de meses de incrementais.

## 9. Pontos finos de comportamento

- **Arquivos em uso**: um arquivo modificado durante a cópia pode ser copiado de forma inconsistente; a próxima execução corrige. Para bancos, VMs e arquivos sempre abertos, prefira **snapshots** na origem (NAS) e copie o snapshot.
- **Renomeações**: o DataSync enxerga renomear como "novo arquivo + arquivo sumido"; recopia o conteúdo. Mover grandes diretórios na origem pode gerar recópia massiva.
- **Arquivos pequenos em quantidade** reduzem o throughput efetivo: o overhead por arquivo domina. Considere empacotar (tar) quando fizer sentido.
- **Caminhos longos e caracteres especiais** podem exigir ajustes (limites de S3: 1024 bytes de chave).
- **Symlinks e hard links** têm tratamento específico por tipo de storage; valide em ambiente de teste.
- **Tempo de scan** cresce com a quantidade de arquivos, mesmo sem nada a transferir; divida tarefas por subárvore.

## 10. Exemplo completo (ilustrativo)

```bash
aws datasync create-task \
  --name nas-financeiro-para-s3 \
  --source-location-arn arn:aws:datasync:us-east-1:123456789012:location/loc-nfs \
  --destination-location-arn arn:aws:datasync:us-east-1:123456789012:location/loc-s3 \
  --options VerifyMode=ONLY_FILES_TRANSFERRED,TransferMode=CHANGED,OverwriteMode=ALWAYS,PreserveDeletedFiles=PRESERVE,PosixPermissions=PRESERVE,Uid=INT_VALUE,Gid=INT_VALUE,Mtime=PRESERVE,TaskQueueing=ENABLED,LogLevel=TRANSFER,BytesPerSecond=125000000 \
  --excludes FilterType=SIMPLE_PATTERN,Value="*.tmp|*/.snapshot/*|*/Thumbs.db" \
  --schedule ScheduleExpression="cron(0 3 * * ? *)" \
  --cloud-watch-log-group-arn arn:aws:logs:us-east-1:123456789012:log-group:/aws/datasync \
  --tags Key=projeto,Value=migracao-fileserver
```

`BytesPerSecond=125000000` equivale a ~1 Gbps (125 MB/s).

## 11. Erros comuns

> [!bug] Erros comuns
> 1. **`PreserveDeletedFiles=REMOVE` sem versionamento no destino**, apagando dados por engano.
> 2. **Alterar filtros** e provocar remoções ou recópias inesperadas.
> 3. **Agendar execuções mais frequentes que a duração real**, acumulando fila.
> 4. **Verificação `NONE` na migração final**, sem garantia de integridade.
> 5. **Ignorar os task reports** e não notar arquivos com erro.
> 6. **Uma única tarefa para a árvore inteira** e estourar limites do Basic mode.
> 7. **Não limitar a banda** e saturar o link da produção.
> 8. **Copiar bancos de dados/VMs abertos** como arquivos em vez de usar snapshots.
> 9. **Renomear grandes pastas na origem** durante a migração, causando recópia massiva.
> 10. **Esquecer o custo do scan** em árvores com centenas de milhões de arquivos.

## 12. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| Execução fica muito tempo em PREPARING | Árvore enorme, scan lento | Dividir por subárvore, ajustar recursos do agent ou usar Enhanced |
| `FilesFailed` > 0 | Permissão, caminho longo, arquivo em uso | Ler o relatório/log e tratar por categoria |
| Arquivos não aparecem no destino | Filtros ou OverwriteMode | Revisar includes/excludes e opções |
| Execução não inicia | Outra execução em andamento sem TaskQueueing | Habilitar enfileiramento ou ajustar a agenda |
| Metadados POSIX ausentes | Opções Uid/Gid/PosixPermissions em NONE | Reconfigurar opções e reexecutar |
| Custos altos | `TransferMode=ALL` repetido ou scans frequentes | Usar CHANGED e reduzir a frequência |

## 13. Resumo rápido

- **Task** = origem + destino + opções + filtros + agenda + relatório; cada rodada é uma **execution**.
- Modos **Basic** (clássico, com limites) e **Enhanced** (maior escala, para pares suportados).
- Opções-chave: **TransferMode (CHANGED/ALL)**, **VerifyMode**, **OverwriteMode**, **PreserveDeletedFiles**, **BytesPerSecond**.
- **Filtros include/exclude** e **agenda (mínimo 1 h)**; **task reports** dão auditoria.
- Estratégia de corte: **carga inicial → incrementais → ensaio → congelar e sincronizar → redirecionar**.

5. Para que servem os task reports?

**Respostas:**

1. CHANGED copia só o que mudou (incremental); ALL copia tudo sem comparar com o destino.
2. Remove do destino o que foi apagado na origem; risco de perder dados por engano, mitigado com versionamento.
3. POINT_IN_TIME_CONSISTENT, que compara toda a origem e todo o destino ao final.
4. Uma hora.
5. Gerar relatórios detalhados (transferidos, verificados, ignorados, erros) em S3 para auditoria e análise.
6. Para respeitar limites do Basic mode, reduzir o tempo de scan e permitir paralelismo com vários agents.
7. Carga inicial, incrementais agendadas, ensaio, congelar escrita, última sincronização com verificação completa e redirecionar usuários.
