### 4.1.1.1. Rastreamento e orquestração de migrações — status por aplicação, integração com MGN e DMS, Migration Hub Orchestrator e templates de workflow

> [!warning] Aviso
> Os comandos e definições de workflow abaixo são **ilustrativos e não foram executados**. Nomes de parâmetros, templates disponíveis e a própria disponibilidade do Migration Hub Orchestrator para novos clientes mudam com o tempo. Valide tudo na documentação oficial e em uma conta de teste antes de usar numa migração real.

## 1. Duas funções diferentes: rastrear e orquestrar

O Migration Hub faz duas coisas que costumam ser confundidas:

1. **Rastrear (tracking):** receber o status das migrações feitas por outras ferramentas e exibi-lo de forma consolidada.
2. **Orquestrar (orchestration):** coordenar passos de uma migração por meio de workflows (via **Migration Hub Orchestrator**), automatizando e organizando tarefas.

| Função | Quem executa o trabalho | O que o hub faz |
|---|---|---|
| Rastreamento | MGN, DMS, ferramentas de parceiros | Mostra status, não altera a migração |
| Orquestração | Orchestrator com templates e automações | Coordena passos, inclusive manuais, com aprovações |

## 2. O modelo de rastreamento

O rastreamento usa um conjunto de APIs (`mgh`) que organiza os dados assim:

```
Progress Update Stream  (um "fluxo" por ferramenta)
   └── Migration Task    (uma tarefa de migração, p.ex. replicar o servidor X)
         ├── Status: NOT_STARTED | IN_PROGRESS | FAILED | COMPLETED
         ├── Progress percent
         └── Associated resources (servidor descoberto, instância, etc.)
```

- **Progress Update Stream:** o contêiner lógico que uma ferramenta usa para reportar. MGN e DMS têm seus próprios fluxos.
- **Migration Task:** a unidade rastreada, normalmente ligada a um servidor.
- **Resource association:** liga a tarefa a um recurso descoberto, para que o hub una "o servidor do inventário" ao "estado da replicação".

Exemplo ilustrativo de uma ferramenta de parceiro reportando progresso:

```bash
# Cria um fluxo de atualização de progresso para a ferramenta
aws mgh create-progress-update-stream \
  --progress-update-stream-name MinhaFerramentaMigracao \
  --region us-west-2

# Reporta o estado de uma tarefa de migração
aws mgh notify-migration-task-state \
  --progress-update-stream MinhaFerramentaMigracao \
  --migration-task-name tarefa-app-checkout-01 \
  --task '{"Status":"IN_PROGRESS","ProgressPercent":40}' \
  --update-date-time 2026-11-10T12:00:00Z \
  --next-update-seconds 300 \
  --region us-west-2

# Associa a tarefa a um recurso descoberto
aws mgh associate-discovered-resource \
  --progress-update-stream MinhaFerramentaMigracao \
  --migration-task-name tarefa-app-checkout-01 \
  --discovered-resource ConfigurationId=d-server-0123456789abcdef0 \
  --region us-west-2
```

O parâmetro `next-update-seconds` informa ao hub quando esperar a próxima atualização; se não chegar, o status pode ser considerado desatualizado.

## 3. Integração com o MGN

O **AWS Application Migration Service (MGN)** replica servidores continuamente para a AWS e, ao integrar-se ao Migration Hub, faz com que cada servidor de origem apareça com seu estado de migração:

| Estado MGN (resumo) | Significado | No hub |
|---|---|---|
| Not ready / Initial sync | Replicação inicial em curso | Em andamento |
| Ready for testing | Replicação concluída, pode lançar instância de teste | Em andamento |
| Test in progress | Instância de teste ativa | Em andamento |
| Ready for cutover | Teste aprovado, pronto para virada | Em andamento |
| Cutover complete / Disconnected | Migrado | Concluído |

Fluxo típico por servidor:

```
Instala agente de replicação ─▶ Sincronização inicial ─▶ Replicação contínua
        ─▶ Lança instância de TESTE ─▶ Valida ─▶ Marca "pronto para cutover"
        ─▶ CUTOVER (instância de produção) ─▶ Finaliza e desconecta a origem
```

No console do MGN existe a configuração de **reportar ao Migration Hub**; em regiões onde o MGN roda, os dados fluem para a Home Region. Se o hub não mostra os servidores, o primeiro suspeito é a integração/região.

## 4. Integração com o DMS

O **AWS Database Migration Service (DMS)** também reporta o andamento de **tarefas de replicação** ao hub (por meio do fluxo `DMS`). Cada tarefa — carga completa (full load), replicação contínua (CDC) ou ambas — aparece com seu status. Para bancos, isso complementa a visão dos servidores: o hub mostra a aplicação "Checkout" com 4 servidores replicados via MGN **e** 1 banco migrado via DMS.

Resumo do ciclo de uma migração de banco no DMS: criar instância de replicação → criar endpoints de origem e destino → criar tarefa (full load + CDC) → monitorar atraso (lag) → cutover → parar a replicação. O hub só **exibe** o estado; as decisões ficam no DMS.

## 5. Visão por aplicação e relatório de progresso

No console do hub, o painel principal mostra:

- **Total de servidores** e quantos estão em cada etapa.
- **Aplicações** e seu estado (`Not started`, `In progress`, `Completed`).
- **Filtros** por tag (onda, dono, ambiente).
- **Linha do tempo** de atualizações recentes.

Para a gerência, o indicador mais útil é o percentual de **aplicações concluídas por onda**, e para a engenharia, a lista de **servidores com falha** ou **sem atualização recente**.

## 6. Migration Hub Orchestrator

O **Orchestrator** vai além de mostrar status: permite definir e executar **workflows** de migração com passos ordenados, alguns automatizados, outros manuais, com **aprovações** e **dependências** entre passos. Ele oferece **templates** prontos para cenários frequentes, como:

- Migração de **servidores** (rehost), incluindo os passos de preparação, replicação, teste e cutover com MGN.
- Migração de **aplicações SAP NetWeaver** (com passos específicos de pré-requisitos e instalação).
- Migração de **SQL Server** para EC2 ou RDS (replatform), com passos de backup/restauração.
- Apoio a **migrações de aplicações .NET** com preparação do ambiente.

Conceitos:

| Termo | Descrição |
|---|---|
| **Workflow** | Instância de um template aplicada a uma migração |
| **Step group** | Conjunto de passos agrupados por fase |
| **Step** | Ação individual (automática ou manual) |
| **Status do passo** | `AWAITING_DEPENDENCIES`, `READY`, `IN_PROGRESS`, `COMPLETED`, `FAILED`, `PAUSED` |
| **Plugin** | Agente/componente que executa passos automatizados no ambiente |
| **Template** | Modelo reutilizável com os passos de um padrão de migração |

Fluxo conceitual de um workflow:

```
Template ─▶ Cria workflow ─▶ Configura (origem, destino, credenciais)
        ─▶ Inicia ─▶ Passos automáticos executam ─▶ Passos manuais aguardam aprovação
        ─▶ Conclui ─▶ Status refletido no Migration Hub
```

Exemplo ilustrativo de operações (nomes e parâmetros devem ser confirmados):

```bash
# Lista templates disponíveis
aws migrationhuborchestrator list-templates

# Cria um workflow a partir de um template
aws migrationhuborchestrator create-workflow \
  --name "migracao-sap-prod" \
  --template-id template-0123456789 \
  --application-configuration-id d-application-0123456789abcdef0 \
  --input-parameters file://parametros.json \
  --step-targets "instance-1"

# Inicia o workflow
aws migrationhuborchestrator start-workflow --id workflow-0123456789

# Acompanha o estado
aws migrationhuborchestrator get-workflow --id workflow-0123456789
```

> [!tip] Dica
> Mesmo que o Orchestrator não esteja disponível para você, adote o **conceito**: transformar a migração em um **runbook** com passos, donos, pré-requisitos e critérios de saída, executável por Step Functions, Systems Manager Automation ou ferramentas de parceiros.

## 7. Automação complementar

Para cenários sem Orchestrator, a automação pode ser montada com:

- **AWS Systems Manager Automation** — runbooks para pré e pós-migração (instalar agentes, ajustar configurações, validar serviços).
- **AWS Step Functions** — coordenar passos de longa duração com aprovações humanas (`waitForTaskToken`).
- **Amazon EventBridge** — reagir a mudanças de estado do MGN (eventos) e disparar notificações ou ações.
- **Amazon SNS** — avisar equipes sobre falhas e marcos.

Exemplo de regra do EventBridge que notifica falhas de replicação (conceitual):

```json
{
  "source": ["aws.mgn"],
  "detail-type": ["MGN Source Server Data Replication Stalled Change"],
  "detail": { "state": ["STALLED"] }
}
```

## 8. Governança e indicadores

Defina indicadores de acompanhamento:

| Indicador | Por que importa |
|---|---|
| % de aplicações concluídas por onda | Visão executiva do avanço |
| Servidores com replicação travada | Risco imediato de atraso |
| Tempo médio entre teste e cutover | Eficiência do processo |
| Falhas por onda | Qualidade do planejamento |
| Atrasos de lag no DMS | Risco no cutover de bancos |
| Custo da dupla operação | Pressão financeira para concluir |

## 9. Erros comuns

> [!bug] Erros comuns
> 1. **Configurar MGN/DMS em região diferente da Home Region** e não ver status no hub.
> 2. **Achar que o hub corrige falhas** — ele apenas mostra; a ação é feita na ferramenta.
> 3. **Não associar tarefas a recursos descobertos**, perdendo a ligação servidor↔migração.
> 4. **Ignorar `next-update-seconds`** em integrações próprias, gerando status "fantasma".
> 5. **Tratar workflows como substituto de planejamento** — sem dependências e testes, a automação só acelera o erro.
> 6. **Deixar passos manuais sem dono**, travando a onda.
> 7. **Usar templates sem entender cada passo**, executando ações inesperadas no ambiente.
> 8. **Não revisar a disponibilidade do Orchestrator** e planejar o projeto em torno de uma funcionalidade que pode não estar disponível.

## 10. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| Servidor do MGN não aparece no hub | Integração/Home Region incorreta | Verificar a configuração de reporte e a região |
| Status travado em "In progress" | Ferramenta parou de reportar | Checar a ferramenta, agente e rede |
| Falha ao criar workflow | Falta de permissão ou parâmetros inválidos | Revisar IAM e o JSON de parâmetros |
| Passo preso em `AWAITING_DEPENDENCIES` | Passo anterior incompleto | Inspecionar o grafo de dependências |
| Tarefa DMS aparece sem recurso | Associação ausente | Associar o recurso descoberto à tarefa |
| Notificações não chegam | Regra do EventBridge/SNS mal configurada | Testar o padrão de evento e a permissão do tópico |

## 11. Resumo rápido

- O hub **rastreia** (consolida status) e, com o Orchestrator, **orquestra** workflows.
- Rastreamento usa **Progress Update Stream → Migration Task → recurso associado**.
- **MGN** e **DMS** reportam automaticamente; parceiros usam a API `mgh`.
- Orchestrator usa **templates, workflows, step groups e passos** com aprovações.
- Sem Orchestrator, replique o conceito com **Systems Manager, Step Functions, EventBridge e SNS**.

1. Rastrear consolida status vindo de outras ferramentas; orquestrar coordena e executa passos de um workflow.
