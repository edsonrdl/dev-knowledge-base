### 4.1.1.1. Armazenamento, workflows e conectores no Transfer Family — S3 e EFS, workflows gerenciados, eventos, SFTP connectors, AS2 e automação de recebimento e envio de arquivos

> [!warning] Aviso
> Passos de workflow suportados, nomes de eventos, comportamento de conectores SFTP/AS2, integração com B2B Data Interchange e limites abaixo são **de memória e mudam**. **Confirme na documentação do AWS Transfer Family.** Políticas, JSONs, funções e comandos são ilustrativos e **não foram executados**. Arquivos de parceiros são **entrada não confiável**: valide e escaneie antes de processar.

## 1. Do arquivo recebido à ação de negócio

Receber um arquivo é só o começo. O valor está em **o que acontece depois**: validar, decifrar, mover, notificar, transformar, carregar em um banco ou data lake, e **responder** ao parceiro. O Transfer Family oferece **três mecanismos** de automação:

```
Arquivo chega (SFTP/FTPS/FTP/AS2)
   ├─ [A] WORKFLOWS gerenciados do Transfer (passos pós-upload no próprio serviço)
   ├─ [B] EVENTOS: S3 Event Notifications → EventBridge/SQS/SNS/Lambda  (ou eventos do próprio Transfer)
   └─ [C] Pipelines downstream: Step Functions / Glue / Lambda / ECS / Batch
Envio a terceiros:  CONECTORES (SFTP outbound, AS2 outbound)
```

## 2. Armazenamento: S3 em detalhe

### 2.1 Como o Transfer escreve no S3

| Aspecto | Detalhe (de memória — confirmar) |
|---|---|
| **Objeto único** | Cada arquivo vira um **objeto** S3 (após **upload completo**) |
| **Multipart** | O serviço usa **multipart upload** para arquivos grandes; **fechamento** ao término |
| **Operações “de pasta”** | **Pastas** são **prefixos** (o serviço cria **marcadores** de diretório com **objetos terminados em `/`** ao **criar diretório**) |
| **Rename** | **Copy + delete** (não atômico, **custos**/tempo em arquivos grandes) |
| **Append/overwrite** | **Append** não suportado; **overwrite** substitui o objeto |
| **Versionamento** | **Recomendado** (proteção contra sobrescrita/exclusão) |
| **Metadados/tags** | Podem ser **adicionados por workflow/Lambda** |
| **Classe de armazenamento** | **Padrão** (use **lifecycle** para mover/expirar) |
| **Criptografia** | **SSE-S3/SSE-KMS** do **bucket** (a role precisa de permissão no KMS) |
| **Latência** | “Upload concluído” ao **fechar** o arquivo; **evento** do S3 após a **conclusão** |

### 2.2 Organização recomendada

```
bucket-parceiros/
  ├─ acme/entrada/    ← parceiro ACME envia (role: PutObject)
  ├─ acme/saida/      ← você disponibiliza (role: GetObject)
  ├─ acme/arquivo/    ← após processar (lifecycle → Glacier)
  └─ acme/erro/       ← inválidos/quarentena
bucket-processamento/ (interno, sem acesso de parceiros) ← workflows copiam para cá após validação
```

Boas práticas: **separar** áreas **de parceiros** (confiança baixa) de **áreas internas**; **lifecycle** por prefixo; **versionamento**; **Block Public Access**; **Object Lock** quando houver **retenção legal**.

## 3. Armazenamento: EFS em detalhe

| Aspecto | Detalhe |
|---|---|
| **Acesso** | O Transfer **monta** o EFS e atende **SFTP/FTPS/FTP** |
| **Permissões** | **POSIX** (UID/GID) + **IAM** (access point, policy do EFS) |
| **Vantagem** | **Operações POSIX** completas (rename atômico, append), **compartilhamento** com **EC2/ECS/Lambda** |
| **Desvantagem** | **Custo maior** que S3; **sem** eventos nativos de S3 (usar **EFS+EventBridge**? limitado → polling/scripts) |
| **Uso** | **Aplicações legadas** que **leem/escrevem** os mesmos arquivos |

## 4. Workflows gerenciados do Transfer Family

### 4.1 O que são

**Workflows** são **sequências de passos** executados **automaticamente** quando um arquivo **chega** (ou, em casos suportados, quando é **processado parcialmente**). Rodam **no serviço**, **sem servidores**.

| Elemento | Detalhe |
|---|---|
| **Gatilho** | **Conclusão de upload** (`OnUpload`) e **upload parcial** (`OnPartialUpload`) — **associado ao servidor** (e ao **usuário** via **role de execução**) |
| **Passos (steps)** | **COPY**, **TAG**, **DELETE**, **DECRYPT** (PGP), **CUSTOM** (Lambda) |
| **Tratamento de exceções** | **Passos de exceção** (**on-exception**) — ex.: mover para `erro/`, notificar |
| **Role de execução** | **Role** do workflow (S3/Lambda/KMS) |
| **Execuções** | **Rastreadas** (status, passos, falhas) e com **logs** |
| **Aplicação** | Por **servidor** (`WorkflowDetails`); aplica-se a **todos** ou conforme configuração |

### 4.2 Passos típicos

| Passo | Uso |
|---|---|
| **COPY** | **Copiar** o arquivo para outro **bucket/prefixo** (ex.: **entrada → arquivo** e **→ processamento**) |
| **TAG** | **Marcar** o objeto (`origem=parceiro-acme`, `status=recebido`) |
| **DELETE** | **Excluir** o original (**mover** = copy + delete) |
| **DECRYPT** | **Decifrar PGP** (chave privada no **Secrets Manager**) |
| **CUSTOM** | **Lambda** (validação, antivírus, transformação, notificação) — **retorna sucesso/falha** ao workflow |

### 4.3 Exemplo de workflow (ilustrativo)

```bash
aws transfer create-workflow --description "recepcao-de-arquivos" \
  --steps '[
    {"Type":"COPY","CopyStepDetails":{"Name":"copiar-arquivo","DestinationFileLocation":{"S3FileLocation":{"Bucket":"bucket-processamento-123456789012","Key":"recebidos/${transfer:UserName}/"}},"OverwriteExisting":"TRUE","SourceFileLocation":"${original.file}"}},
    {"Type":"TAG","TagStepDetails":{"Name":"marcar","Tags":[{"Key":"origem","Value":"sftp"},{"Key":"status","Value":"recebido"}],"SourceFileLocation":"${copiar-arquivo.file}"}},
    {"Type":"CUSTOM","CustomStepDetails":{"Name":"validar","Target":"arn:aws:lambda:us-east-1:123456789012:function:validar-arquivo","TimeoutSeconds":60,"SourceFileLocation":"${copiar-arquivo.file}"}},
    {"Type":"DELETE","DeleteStepDetails":{"Name":"remover-original","SourceFileLocation":"${original.file}"}}
  ]' \
  --on-exception-steps '[{"Type":"COPY","CopyStepDetails":{"Name":"quarentena","DestinationFileLocation":{"S3FileLocation":{"Bucket":"bucket-parceiros-123456789012","Key":"erro/"}},"OverwriteExisting":"TRUE"}}]'

aws transfer update-server --server-id s-0123456789abcdef0 \
  --workflow-details '{"OnUpload":[{"WorkflowId":"w-0abc","ExecutionRole":"arn:aws:iam::123456789012:role/TransferWorkflowRole"}]}'
```

### 4.4 Lambda de validação (esboço)

```python
import boto3, json
tf = boto3.client("transfer")
s3 = boto3.client("s3")

def handler(event, ctx):
    # event contém: serviceMetadata (executionDetails: workflowId/executionId), fileLocation (bucket/key)
    bucket = event["fileLocation"]["bucket"]; key = event["fileLocation"]["key"]
    ok = validar_conteudo(bucket, key)          # tamanho, formato, esquema, antivírus (ver nota)
    status = "SUCCESS" if ok else "FAILURE"
    tf.send_workflow_step_state(WorkflowId=event["serviceMetadata"]["executionDetails"]["workflowId"],
                                ExecutionId=event["serviceMetadata"]["executionDetails"]["executionId"],
                                Token=event["token"], Status=status)
    return {"status": status}
```

(Formato do evento e da resposta: **confirmar** na documentação. **Antivírus**: use soluções de **scan** (ex.: **GuardDuty Malware Protection for S3**, soluções de terceiros) integradas ao fluxo.)

### 4.5 Quando usar workflows vs eventos do S3

| Critério | **Workflows do Transfer** | **S3 Events + Lambda/Step Functions** |
|---|---|---|
| **Escopo** | Só arquivos recebidos **pelo Transfer** | **Qualquer** objeto no bucket (inclui outras fontes) |
| **Gatilho** | Fim do upload (sabe o **usuário/servidor**) | `ObjectCreated` |
| **Passos prontos** | COPY/TAG/DELETE/DECRYPT/CUSTOM | **Programáveis** (Lambda/ECS/Glue…) |
| **Contexto** | **Usuário/servidor/execução** | Contexto do **objeto** |
| **Complexidade** | **Baixa** (declarativo) | Média (código) |
| **Retentativas/ordem** | Gerenciadas pelo workflow | **Sua** orquestração (Step Functions) |
| **Melhor para** | **Recebimento padronizado** com poucos passos | **Pipelines complexos**, múltiplas fontes |

Muitas arquiteturas **combinam**: **workflow** (copiar/decifrar/marcar) → **evento** no bucket de processamento → **Step Functions/Glue**.

## 5. Eventos e integração downstream

### 5.1 Fontes de evento

| Fonte | Quando |
|---|---|
| **S3 Event Notifications → EventBridge** | Objeto criado/removido; **filtros por prefixo/sufixo** |
| **EventBridge (Transfer)** | **Eventos de workflow/servidor** (status de execução, falhas — confirmar) |
| **CloudWatch Logs (estruturados)** | **Eventos de sessão/arquivo** (assinatura/subscription filters) |
| **SQS/SNS** | Desacoplar consumidores |
| **CloudTrail** | Operações de **API** (administração) |

### 5.2 Padrões

```
S3 (entrada) ──ObjectCreated──▶ EventBridge ──▶ Step Functions
                                              ├─ Valida (Lambda) → Decifra → Parseia
                                              ├─ Glue/Athena/Redshift (carga)  ou  SQS → workers (ECS/Batch)
                                              └─ Notifica (SNS/SES) • Responde ao parceiro (arquivo de ACK em /saida)
```

| Padrão | Detalhe |
|---|---|
| **Idempotência** | Eventos podem ser **duplicados**: processar **por chave/ETag** e **deduplicar** |
| **Arquivos parciais** | Evitar processar **antes** do **upload completo**: usar **eventos de conclusão** (`CompleteMultipartUpload`/`ObjectCreated`) e **convenção** (`.tmp` → renomeia ao final; **marker file**) quando o cliente **não** tem atomicidade |
| **Ordem** | Sem garantia; usar **timestamps/sequências** nos nomes |
| **Validação** | Tamanho, **checksum/hash** (parceiro envia `.sha256`), **esquema**, **limites** |
| **Segurança** | **Antivírus**, **sandbox**, **limite de tamanho**, **bloqueio de tipos** |
| **Falhas** | **DLQ/quarentena**, **retry com backoff**, **alarmes** |
| **Retenção** | Lifecycle (arquivar/expirar) por prefixo |

## 6. Conectores (envio e AS2)

### 6.1 SFTP connectors (envio a servidores SFTP externos)

| Aspecto | Detalhe (de memória — confirmar) |
|---|---|
| **O que são** | **Clientes SFTP gerenciados**: **enviam** arquivos do **S3** a **servidores SFTP remotos** e **recebem** deles |
| **Config** | **URL/host** do servidor remoto, **credenciais** (**Secrets Manager**: usuário + senha/chave privada), **trusted host keys**, **role** (S3), **security policy** |
| **Operações** | **StartFileTransfer** (**enviar/baixar** arquivos), **listar** diretórios remotos (**StartDirectoryListing**) |
| **Eventos** | **Status** da transferência (EventBridge) |
| **Rede** | Saída via serviço (**IPs** públicos do conector — confirmar e **informar ao parceiro**) ou **VPC egress** (opções mais recentes) |
| **Uso** | **Enviar** relatórios a **bancos/parceiros** que só aceitam **SFTP**; **buscar** arquivos em servidores externos |

```bash
aws transfer create-connector --url "sftp://sftp.parceiro.example.com" \
  --sftp-config '{"UserSecretId":"arn:aws:secretsmanager:us-east-1:123456789012:secret:sftp-parceiro-abc","TrustedHostKeys":["sftp.parceiro.example.com ssh-ed25519 AAAAC3..."]}' \
  --access-role arn:aws:iam::123456789012:role/TransferConnectorRole --logging-role arn:aws:iam::123456789012:role/TransferLoggingRole

aws transfer start-file-transfer --connector-id c-0abc123 \
  --send-file-paths "/bucket-saida-123456789012/relatorios/diario.csv" --remote-directory-path "/entrada"
```

### 6.2 AS2 (EDI)

| Elemento | Detalhe (de memória — confirmar) |
|---|---|
| **Perfis** (`profiles`) | **Local** (você) e **parceiro**: **AS2 ID** |
| **Certificados** | **Assinatura** e **criptografia** (chaves privadas do **local** em **Secrets Manager**; **certificados públicos** do parceiro) |
| **Acordos** (`agreements`) | Ligam **perfil local ↔ parceiro**, **diretório base** (S3) e **role** |
| **Conectores AS2** | **Enviam** mensagens/arquivos ao **endpoint AS2** do parceiro e tratam **MDN** |
| **Recebimento** | **Servidor** com AS2 habilitado **recebe** mensagens; salva em **S3**; **MDN** de volta |
| **Algoritmos** | **Assinatura**: SHA-256+; **Criptografia**: AES-128/256; **compressão** opcional |
| **Eventos** | Resultado de **envio/recebimento** e **MDN** |
| **EDI** | Conversão **EDI ↔ JSON/XML** com **AWS B2B Data Interchange** (confirmar) |
| **Boas práticas** | **Gestão de validade** de **certificados**, **testes com o parceiro**, **monitorar MDN** |

## 7. Automação de ponta a ponta (exemplos)

### 7.1 Recebimento B2B com validação

```
Parceiro ─SFTP→ /acme/entrada ─workflow→ COPY p/ bucket-processamento + TAG + CUSTOM(Lambda valida) + DELETE original
   (falha → COPY p/ /acme/erro + SNS para operações)
   sucesso → EventBridge → Step Functions → Glue (carga) → Athena/Redshift → ACK em /acme/saida/
```

### 7.2 Distribuição para parceiros

```
Sistema interno gera relatório ─→ S3 (saida/<parceiro>/data.csv) ─EventBridge→ Lambda
   ├─ (parceiro conecta e baixa por SFTP — pull)   ou
   └─ (push) Conector SFTP envia ao servidor do parceiro e notifica o resultado
```

### 7.3 Ingestão de legados para data lake

```
Sistema legado ─FTPS/SFTP→ Transfer → S3 raw/ (particionado por data) ─EventBridge→ Glue Workflow → curated/ → Lake Formation
```

## 8. Segurança da automação

| Controle | Detalhe |
|---|---|
| **Arquivos não confiáveis** | **Antivírus/malware scan**; validar **formato/tamanho**; **bloquear executáveis** |
| **Roles mínimas** | Workflow/Lambda/conectores com **permissões estritas** |
| **Segredos** | **Secrets Manager** (credenciais SFTP remotas, chaves PGP/AS2) com **rotação** |
| **KMS** | Chaves por **sensibilidade**; permissões para **workflows** |
| **Isolamento** | **Buckets** de parceiros × **internos**; **sem** acesso cruzado |
| **Integridade** | **Checksums**; **versionamento**; **Object Lock** (se aplicável) |
| **PII** | **Mascarar/minimizar**; **retenção** curta |
| **Auditoria** | **Logs do Transfer**, **CloudTrail**, **EventBridge** |
| **Falhas seguras** | **Quarentena**; **alertas**; **não processar** arquivo inválido |

## 9. Erros comuns

- **Processar arquivo parcial** (antes do upload completo).
- **Sem idempotência** (eventos duplicados processam duas vezes).
- **Sem antivírus/validação** (parceiros enviam lixo/malware).
- **Workflow sem tratamento de exceções** (arquivo some ou fica preso).
- **Mover com copy+delete em arquivos gigantes** (custo/tempo).
- **Roles amplas** para workflows/conectores.
- **Segredos do conector** em texto/variáveis.
- **Esquecer MDN** (AS2) → parceiro “não recebeu”.
- **Certificados AS2 vencidos**.
- **Misturar** buckets de parceiros e internos.
- **EFS** para casos em que **S3** bastaria (custo).

## 10. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| Workflow não dispara | Não associado ao servidor/usuário; role; gatilho | Verificar `WorkflowDetails` e a role de execução |
| Passo CUSTOM “timeout” | Lambda lento/sem `send_workflow_step_state` | Ajustar o timeout; garantir a resposta ao workflow |
| Arquivo não aparece no S3 | Upload incompleto; permissões; erro de cliente | Logs do servidor; reenviar |
| Evento S3 não chega | Filtro/prefixo; regra do EventBridge | Revisar a notificação e a regra |
| Conector falha | Host key/credenciais/rede; secrets | Ver logs/EventBridge; revisar o segredo e as host keys |
| AS2 sem MDN | URL/certificados/perfis | Revisar o acordo, os certificados e as URLs |
| PGP decrypt falha | Chave errada/formato | Verificar a chave no Secrets Manager |
| Processamento duplicado | Eventos duplicados | Idempotência por chave/ETag |

## 11. Resumo rápido

- **S3** (padrão) ou **EFS** (POSIX/compartilhamento); **S3**: objeto no **fim do upload**, **rename = copy+delete**, **sem append**; **versionamento/lifecycle/KMS**.
- **Workflows**: **COPY, TAG, DELETE, DECRYPT (PGP), CUSTOM (Lambda)** + **passos de exceção**, **role de execução**, gatilhos **OnUpload/OnPartialUpload**.
- **Eventos**: **S3 → EventBridge → Step Functions/Glue/Lambda**; **idempotência**, **arquivos parciais**, **validação/antivírus**, **quarentena**.
- **Conectores**: **SFTP** (enviar/baixar com **Secrets Manager** + host keys) e **AS2** (perfis, certificados, acordos, **MDN**; EDI com B2B Data Interchange).
- **Combinar** workflow (padronizar recebimento) + eventos/pipelines (processamento).
- **Segurança**: arquivos **não confiáveis**, **roles mínimas**, **segredos** no cofre, **buckets separados**, **auditoria**.

**Respostas:**

1. COPY, TAG, DELETE, DECRYPT (PGP) e CUSTOM (Lambda), com passos de exceção para falhas.
2. Workflows são declarativos e específicos de arquivos recebidos pelo Transfer, com contexto de usuário/servidor; eventos do S3 valem para qualquer objeto e permitem pipelines programáveis (Lambda, Step Functions).
3. Usando eventos de conclusão, convenções (arquivo temporário renomeado ou marker file), checksums e validação antes de processar.
4. Enviar e baixar arquivos de servidores SFTP externos a partir do S3, com credenciais no Secrets Manager e host keys confiáveis.
5. O recibo (Message Disposition Notification) que confirma o recebimento (e a integridade) de uma mensagem AS2.
6. Porque é copy + delete, não atômico, com custo e tempo proporcionais ao tamanho do arquivo.
7. Antivírus/malware scan, validação de formato e tamanho, roles mínimas, buckets separados, KMS, quarentena e auditoria.
