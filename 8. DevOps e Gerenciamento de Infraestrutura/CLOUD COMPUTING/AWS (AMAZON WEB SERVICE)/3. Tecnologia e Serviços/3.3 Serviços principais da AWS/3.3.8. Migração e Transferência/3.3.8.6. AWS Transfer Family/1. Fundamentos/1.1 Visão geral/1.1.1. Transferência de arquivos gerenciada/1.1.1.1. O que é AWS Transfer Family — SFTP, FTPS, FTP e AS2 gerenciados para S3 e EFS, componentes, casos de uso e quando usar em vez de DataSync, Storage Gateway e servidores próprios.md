### 1.1.1.1. O que é AWS Transfer Family — SFTP, FTPS, FTP e AS2 gerenciados para S3 e EFS, componentes, casos de uso e quando usar em vez de DataSync, Storage Gateway e servidores próprios

> [!warning] Aviso
> Protocolos suportados, tipos de endpoint, limites, preços, recursos novos (web apps, conectores, regras de workflow) e comportamentos abaixo são **de memória e mudam**. **Confirme na documentação do AWS Transfer Family e na página de preços.** Comandos e JSONs são ilustrativos e **não foram executados**. Domínios, usuários, buckets e IDs são fictícios.

## 1. O problema que o Transfer Family resolve

Apesar da era das APIs, **trocar arquivos por SFTP/FTP** continua onipresente: **bancos, varejo, saúde, logística, governo, parceiros B2B** enviam e recebem **arquivos** (extratos, pedidos, notas fiscais, EDI, relatórios) por **protocolos tradicionais**. Quem recebe esses arquivos costuma ter um **servidor SFTP** (em EC2 ou on-premises) com problemas clássicos:

| Dor | Detalhe |
|---|---|
| **Operar servidores** | Patches, hardening, **disponibilidade**, backup, **escala** |
| **Armazenamento local** | Disco da instância: **capacidade**, **durabilidade**, **cópias** para o S3 por scripts |
| **Gestão de usuários** | Contas Linux, chaves SSH, **onboarding/offboarding** manual |
| **Segurança** | Algoritmos obsoletos, **auditoria** limitada, exposição direta à internet |
| **Integração** | Scripts (`cron`, `inotify`) para **disparar processamento** quando chega arquivo |
| **Alta disponibilidade** | Cluster/NFS/keepalived — complexo |
| **Clientes legados** | Parceiros **não vão mudar** o protocolo; exigem **mesmo hostname/IP/chaves** |

O **AWS Transfer Family** é o serviço **totalmente gerenciado** que oferece **endpoints SFTP, FTPS, FTP e AS2** cujos arquivos ficam **diretamente no Amazon S3 ou no Amazon EFS** — **sem servidores para administrar**, com **escala**, **alta disponibilidade (multi-AZ)**, **autenticação flexível**, **logs**, **workflows** e **integração** com o resto da AWS.

> [!info] Em uma frase
> **Transfer Family = “seu SFTP/FTPS/FTP/AS2 gerenciado, gravando direto no S3/EFS, para que parceiros e sistemas legados continuem usando os protocolos que já conhecem”.**

## 2. Protocolos suportados

| Protocolo | Descrição | Segurança | Observações (de memória — confirmar) |
|---|---|---|---|
| **SFTP** (SSH File Transfer Protocol) | Transferência de arquivos **sobre SSH** (porta **22**) | **Criptografado** (SSH) | **O mais usado**; autenticação por **chave SSH** ou **senha**; **não** é “FTP com SSL” |
| **FTPS** (FTP sobre TLS) | FTP com **TLS** (portas **21** + dados) | **Criptografado** (TLS) | Exige **certificado (ACM)**; **modo passivo** (portas de dados) |
| **FTP** (File Transfer Protocol) | FTP **clássico** (porta 21) | **Sem criptografia** | **Somente dentro de VPC** (não público); **evitar** — use só em **redes privadas** por compatibilidade |
| **AS2** (Applicability Statement 2) | **EDI** B2B sobre **HTTP(S)** com **assinatura e criptografia** de mensagens | **Assinado/criptografado** (certificados) | Para **EDI** (varejo/logística/saúde: pedidos, faturas, ASN), **MDN** (recibos) |
| **Web apps** (recurso mais recente; confirmar) | **Interface web** para **usuários finais** acessarem arquivos | HTTPS | Para **usuários humanos** sem cliente SFTP |

> [!tip] Regra de decisão
> **SFTP** para quase tudo; **FTPS** quando o parceiro exige TLS; **FTP** apenas **interno/VPC**; **AS2** para **EDI**.

## 3. Componentes e conceitos

```
 Clientes/Parceiros (SFTP/FTPS/FTP/AS2)
            │  endpoint (hostname/IP)
            ▼
 ┌────────────────────────────── AWS TRANSFER FAMILY ───────────────────────────────┐
 │  SERVER (protocolos + endpoint + identidade + security policy + logging)           │
 │     ├─ USUÁRIOS (service-managed / Directory Service / Lambda / API Gateway)       │
 │     │      └─ role IAM + home directory (mapeamento lógico) + session policy      │
 │     ├─ WORKFLOWS (pós-upload: copiar, marcar, decifrar PGP, Lambda…)              │
 │     └─ CONECTORES (SFTP outbound, AS2) + perfis/certificados                      │
 └────────────────┬──────────────────────────────────────────────────────────────────┘
                  ▼
        Amazon S3  ou  Amazon EFS   ──▶ eventos (EventBridge/S3) ──▶ Lambda/Step Functions/Glue/…
```

| Termo | Significado |
|---|---|
| **Server** | O **recurso do Transfer Family**: escolhe **protocolos**, **tipo de endpoint**, **provedor de identidade**, **política de segurança**, **logging** |
| **Endpoint** | **Ponto de acesso**: **público**, **VPC (internal/internet-facing)** |
| **Identity provider** | **Quem autentica** os usuários: **service managed**, **AWS Directory Service**, **Lambda**, **API Gateway** |
| **User** | Identidade com **role IAM**, **diretório inicial (home)** e **chaves SSH** (service managed) |
| **Home directory / logical directories** | Pasta inicial; **diretórios lógicos** mapeiam **caminhos virtuais** para **prefixos S3/EFS** |
| **Security policy** | Define **algoritmos** (SSH, TLS, KEX, MACs) |
| **Workflow** | **Sequência de passos** executados **após upload** (ou ao concluir) |
| **Connector** | **Cliente gerenciado** para **enviar** arquivos a **servidores SFTP externos** (e AS2 a parceiros) |
| **Agreement/Partner profile/Certificates** | Objetos do **AS2** (entidades, chaves, parceiros) |
| **Host key** | Chave do servidor (identidade do **servidor SFTP** perante o cliente) |

## 4. Armazenamento: S3 e EFS

| | **Amazon S3** | **Amazon EFS** |
|---|---|---|
| **Uso** | **Mais comum**: data lakes, pipelines, arquivamento | Aplicações que exigem **sistema de arquivos POSIX** |
| **Protocolos** | SFTP, FTPS, FTP, AS2 | **SFTP/FTPS/FTP** |
| **Permissões** | **IAM role** do usuário (S3) | **POSIX** (UID/GID) + **IAM** (EFS access points/policies) |
| **Vantagens** | **Durável, barato, eventos**, **lifecycle** | Compartilhamento com **instâncias/containers** |
| **Escolha** | **S3** por padrão | EFS se **aplicações** precisam **montar** os mesmos arquivos |

## 5. Casos de uso típicos

1. **Recebimento de arquivos de parceiros** (extratos bancários, pedidos, notas fiscais) → **S3** → **processamento** (Lambda/Glue/Step Functions).
2. **Distribuição de arquivos** a clientes/fornecedores (relatórios, catálogos).
3. **Migração de servidores SFTP** legados **sem mudar clientes** (mesmo hostname/chaves).
4. **EDI com AS2** (varejo/logística): receber/enviar documentos **assinados**.
5. **Ingestão para data lakes** (arquivos de sistemas legados).
6. **Integração com sistemas legados** que só falam **FTP**.
7. **Troca segura de arquivos** em **saúde/finanças** (conformidade, auditoria).
8. **Acesso de usuários internos/externos** a **arquivos no S3/EFS** (web apps).
9. **Envio de arquivos para terceiros** (conectores SFTP).

## 6. Quando usar Transfer Family (e alternativas)

| Necessidade | Solução |
|---|---|
| **Parceiros enviam/recebem por SFTP/FTPS/FTP/AS2** | **Transfer Family** |
| **Migrar dados** (grandes volumes, agendados) de on-premises para S3/EFS/FSx | **DataSync** |
| **Acesso híbrido a arquivos** (NFS/SMB) com cache | **Storage Gateway (File Gateway)** |
| **Sincronização/transferência com fontes SaaS** | **AppFlow** |
| **Upload direto de apps/usuários via HTTPS** | **S3 presigned URLs/APIs** |
| **Transferência massiva offline** | **Snow Family** |
| **Aceleração de uploads globais** | **S3 Transfer Acceleration** |
| **Replicação de bancos** | **DMS** |
| **Streaming de eventos** | **Kinesis/MSK** |
| **Controle total do servidor (custom)** | **SFTP em EC2** (mas com **operação por sua conta**) |
| **Protocolo proprietário/Managed File Transfer completo (MFT)** | **Produtos MFT** (Marketplace) ou **Transfer Family + workflows** |

### 6.1 Transfer Family vs DataSync vs Storage Gateway

| Critério | **Transfer Family** | **DataSync** | **Storage Gateway (File)** |
|---|---|---|---|
| **Modelo** | **Endpoint de protocolo** (servidor) | **Agente/serviço** de **cópia** agendada/sob demanda | **Gateway** local com cache (NFS/SMB) |
| **Quem inicia** | **Cliente externo** (parceiro) conecta ao seu endpoint | **Você** copia de A para B | **Aplicações locais** gravam como se fosse NAS |
| **Protocolos** | **SFTP/FTPS/FTP/AS2** | **NFS/SMB/HDFS/S3/EFS/FSx…** | **NFS/SMB** (FSx File Gateway) |
| **Uso típico** | **B2B**, parceiros, legados | **Migração/sync** | **Híbrido contínuo** |
| **Destino** | **S3/EFS** | S3/EFS/FSx… | **S3** (com cache) |
| **Pergunta de prova** | “**SFTP para S3**” | “**Migrar/sincronizar dados**” | “**Acesso NFS/SMB híbrido**” |

## 7. Benefícios

| Benefício | Detalhe |
|---|---|
| **Sem servidores** | **Gerenciado**, patches e HA pela AWS |
| **Multi-AZ** | Alta disponibilidade (endpoint em **múltiplas AZs**) |
| **Escala** | Aumenta com conexões/volume |
| **Dados no S3/EFS** | **Durabilidade** e **integração** |
| **Autenticação flexível** | **Chaves SSH**, **AD**, **identidade customizada** (Okta, LDAP, banco) |
| **Compatibilidade** | **Clientes existentes** continuam (SFTP/FTPS/FTP/AS2) |
| **IP fixo e domínio próprio** | Endpoints **VPC** com **Elastic IPs**; **Route 53/DNS** do parceiro |
| **Automação** | **Workflows**, **EventBridge**, **Lambda** |
| **Auditoria** | **CloudWatch**, **CloudTrail**, logs estruturados |
| **Segurança** | **Security policies**, **criptografia**, **IAM por usuário** |
| **Pay-as-you-go** | Por **hora de protocolo** + **GB transferido** |

## 8. Limitações e cuidados

| Limitação | Detalhe |
|---|---|
| **Custo por hora** | **Cobra por protocolo habilitado**, **mesmo sem uso** (24×7) |
| **FTP** | Apenas **VPC**, **sem criptografia** |
| **Operações de arquivo** | Algumas operações **não-POSIX** (rename em S3 é **copy+delete**, **append** limitado) — impactam **clientes específicos** |
| **Tamanhos/tempo** | Arquivos enormes: **timeouts/retry** do cliente; sessões longas |
| **IPs/Portas** | FTP/FTPS **modo passivo** exigem **portas** e **configuração de rede** |
| **Mudança de endpoint** | Alterar **tipo de endpoint** pode exigir **recriar** (planejar **DNS**) |
| **Cotas** | Servidores/usuários por conta/região |
| **Dependência de região** | Servidor e bucket na **mesma região** (recomendado) |

## 9. Primeiros passos (visão geral, ilustrativo)

```bash
# Criar um servidor SFTP com identidade gerenciada pelo serviço, endpoint público, log em CloudWatch
aws transfer create-server --protocols SFTP --domain S3 --endpoint-type PUBLIC \
  --identity-provider-type SERVICE_MANAGED --security-policy-name TransferSecurityPolicy-2024-01 \
  --logging-role arn:aws:iam::123456789012:role/TransferLoggingRole \
  --structured-log-destinations arn:aws:logs:us-east-1:123456789012:log-group:/aws/transfer/sftp-prod

# Criar um usuário com role, diretório lógico e chave pública
aws transfer create-user --server-id s-0123456789abcdef0 --user-name parceiro-acme \
  --role arn:aws:iam::123456789012:role/TransferUserAcme \
  --home-directory-type LOGICAL \
  --home-directory-mappings '[{"Entry":"/","Target":"/bucket-parceiros-123456789012/acme"}]' \
  --ssh-public-key-body "ssh-ed25519 AAAA... parceiro@acme"

# Conectar (cliente)
sftp -i chave_privada parceiro-acme@s-0123456789abcdef0.server.transfer.us-east-1.amazonaws.com
```

## 10. Erros comuns

- **Usar FTP** (sem criptografia) quando SFTP/FTPS são possíveis.
- **Servidor ligado 24×7** para uso esporádico sem avaliar o **custo por hora**.
- **Role do usuário com acesso a todo o bucket** (cada parceiro deve ver **só a sua pasta**).
- **Home directory sem mapeamento lógico** (usuário vê caminhos reais do bucket).
- **Esquecer a política de segurança** (algoritmos fracos).
- **Endpoint público** sem necessidade (usar **VPC + IP fixo** quando o parceiro precisa de **allowlist**).
- **Confundir Transfer Family com DataSync**.
- **Sem automação de processamento** (arquivos “ficam parados” no S3).
- **Não monitorar falhas** de login/transferência.
- **Passive mode do FTPS** mal configurado (conexões travam).

## 11. Troubleshooting inicial

| Sintoma | Causas prováveis | Ações |
|---|---|---|
| `Permission denied` | Role IAM do usuário; mapeamento de home; session policy | Revisar role/policy, **home directory** e bucket policy |
| Falha de autenticação | Chave SSH incorreta; usuário inexistente; provedor de identidade | Conferir a chave pública, o usuário e o provedor |
| Timeout na conexão | **SG/NACL** (VPC); IP/porta bloqueados; DNS | Revisar rede e firewall do parceiro |
| Cliente não lista arquivos | Diretório inicial/mapeamento; prefixo vazio | Conferir `HomeDirectoryMappings` |
| Arquivos grandes falham | Timeout/retry do cliente | Ajustar o cliente; verificar a estabilidade |
| FTPS passivo falha | Portas passivas/IP | Ver as portas e o endpoint |

## 12. Resumo rápido

- **Transfer Family** = **SFTP, FTPS, FTP e AS2 gerenciados** que gravam em **S3 ou EFS**; **sem servidores**, **multi-AZ**, **escalável**.
- **Peças**: **server** (protocolos, endpoint, identidade, security policy, logging), **usuários** (role, home/diretórios lógicos), **workflows**, **conectores** (SFTP/AS2), **security policies**, **host keys**.
- **Protocolos**: **SFTP** (padrão), **FTPS** (TLS, certificado), **FTP** (**só VPC**, sem criptografia), **AS2** (EDI).
- **Casos**: **B2B/parceiros**, **migração de SFTP legado**, **EDI**, **ingestão para data lake**.
- **Alternativas**: **DataSync** (migração/sync), **Storage Gateway** (NFS/SMB híbrido), **S3 presigned/APIs**.
- **Custo**: **por hora de protocolo + GB**; atenção a servidores ociosos.
- Pergunta de prova: “**SFTP para S3 mantendo clientes existentes**” → **Transfer Family**.

## 🧩 Quiz de Fixação

1. Quais protocolos o Transfer Family suporta e onde guarda os arquivos?
2. Quando usar AS2?
3. Por que o FTP deve ser evitado?
4. Qual a diferença entre Transfer Family e DataSync?
5. O que são diretórios lógicos?
6. Que modelos de identidade o serviço oferece?
7. Que custo fixo existe mesmo sem tráfego?

**Respostas:**

1. SFTP, FTPS, FTP e AS2 (e recursos web); armazenam os arquivos diretamente no Amazon S3 ou no Amazon EFS.
2. Para EDI B2B com mensagens assinadas e criptografadas e recibos (MDN), comum em varejo, logística e saúde.
3. Porque não é criptografado e só está disponível dentro de VPC; SFTP/FTPS são preferíveis.
4. O Transfer Family expõe endpoints de protocolo para clientes externos conectarem; o DataSync copia dados de forma agendada entre origem e destino iniciados por você.
5. Mapeamentos que apresentam caminhos virtuais ao usuário apontando para prefixos reais do S3/EFS, escondendo a estrutura e limitando o acesso.
6. Service managed (chaves SSH), AWS Directory Service (AD), e identidade customizada via Lambda ou API Gateway.
7. A cobrança por hora de cada protocolo habilitado no servidor, independentemente do uso.
