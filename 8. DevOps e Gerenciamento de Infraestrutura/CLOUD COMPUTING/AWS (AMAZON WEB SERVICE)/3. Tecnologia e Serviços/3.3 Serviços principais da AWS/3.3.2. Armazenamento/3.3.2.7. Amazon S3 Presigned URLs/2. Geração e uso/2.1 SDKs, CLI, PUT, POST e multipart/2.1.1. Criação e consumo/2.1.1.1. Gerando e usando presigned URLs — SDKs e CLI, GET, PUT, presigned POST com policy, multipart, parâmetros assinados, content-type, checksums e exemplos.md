### 2.1.1.1. Gerando e usando presigned URLs — SDKs e CLI, GET, PUT, presigned POST com policy, multipart, parâmetros assinados, content-type, checksums e exemplos

> [!warning] Aviso
> Nomes de métodos, parâmetros assináveis, comportamento de checksums, opções do presigned POST e suporte da CLI variam por **SDK e versão**. **Confirme na documentação do SDK da sua linguagem e do S3.** Código, URLs e comandos são ilustrativos e **não foram executados**. Buckets, chaves e assinaturas são fictícios.

## 1. Três formas de “pré-assinar”

| Forma | Quando usar | Controle |
|---|---|---|
| **Presigned URL (GET/PUT/…)** | **Download** ou **upload simples** de **uma chave** | **Operação + objeto + headers assinados + prazo** |
| **Presigned POST** (formulário multipart/form-data) | **Upload do navegador** com **regras** (tamanho, tipo, prefixo) | **Policy** com **condições** |
| **URLs por parte (multipart)** | **Arquivos grandes** (centenas de MB a TB) | Uma URL **por parte** + **complete** |

## 2. GET: baixando objetos

### 2.1 Python (Boto3)

```python
url = s3.generate_presigned_url(
    ClientMethod="get_object",
    Params={
        "Bucket": "relatorios-prod",
        "Key": "2026/11/fatura-123.pdf",
        "ResponseContentType": "application/pdf",
        "ResponseContentDisposition": 'attachment; filename="fatura-123.pdf"',   # força download com nome amigável
        # "VersionId": "3HL4kqtJlcpXroDTDmJ+rmSpXd3dIbrHY",                      # versão específica
    },
    ExpiresIn=300,          # 5 minutos
    HttpMethod="GET")
```

### 2.2 JavaScript v3

```javascript
import { S3Client, GetObjectCommand } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";
const s3 = new S3Client({ region: "us-east-1" });
const url = await getSignedUrl(s3, new GetObjectCommand({ Bucket: "relatorios-prod", Key: "2026/11/fatura-123.pdf" }), { expiresIn: 300 });
```

### 2.3 Java v2

```java
S3Presigner presigner = S3Presigner.builder().region(Region.US_EAST_1).build();
GetObjectPresignRequest req = GetObjectPresignRequest.builder()
    .signatureDuration(Duration.ofMinutes(5))
    .getObjectRequest(b -> b.bucket("relatorios-prod").key("2026/11/fatura-123.pdf")).build();
String url = presigner.presignGetObject(req).url().toString();
```

### 2.4 Parâmetros de resposta úteis (GET)

| Parâmetro | Efeito |
|---|---|
| `ResponseContentDisposition` | **Nome do arquivo** e `attachment`/`inline` |
| `ResponseContentType` | **Content-Type** da resposta |
| `ResponseCacheControl` / `ResponseExpires` / `ResponseContentEncoding`/`ResponseContentLanguage` | Cabeçalhos de resposta |
| `VersionId` | **Versão** específica (bucket versionado) |

> Esses parâmetros **entram na assinatura**: **alterar** na URL **invalida**.

## 3. PUT: enviando objetos

### 3.1 Python

```python
url_put = s3.generate_presigned_url(
    "put_object",
    Params={"Bucket": "uploads-prod", "Key": "usuarios/42/avatar.png", "ContentType": "image/png",
            "Metadata": {"usuario": "42"},                               # x-amz-meta-usuario (assinado)
            "ServerSideEncryption": "aws:kms", "SSEKMSKeyId": "arn:aws:kms:us-east-1:123456789012:key/<id>"},
    ExpiresIn=900)
```

```bash
curl -X PUT \
  -H "Content-Type: image/png" \
  -H "x-amz-meta-usuario: 42" \
  -H "x-amz-server-side-encryption: aws:kms" \
  -H "x-amz-server-side-encryption-aws-kms-key-id: arn:aws:kms:us-east-1:123456789012:key/<id>" \
  --upload-file avatar.png "<url_put>"
```

### 3.2 Regra de ouro: headers assinados = headers enviados

| Cabeçalho | Regra |
|---|---|
| **`Host`** | Sempre assinado |
| **`Content-Type`** | Se **incluído** nos `Params`, **deve ser enviado igual** (diferente → `SignatureDoesNotMatch`) |
| **`x-amz-meta-*`**, **`x-amz-server-side-encryption*`**, **`x-amz-acl`**, **`x-amz-tagging`**, **`x-amz-checksum-*`** | Se **assinados**, **devem** ser enviados **exatamente** |
| **`Content-Length`** | Em geral **não assinado** (limitar tamanho → **presigned POST** com policy) |
| **`Content-MD5`/checksums** | Se incluído, o cliente **deve** calcular o **mesmo valor** (integridade) |
| **Cabeçalhos extras** não assinados | **Permitidos** (mas o S3 pode **recusar** conforme o caso) |

> [!tip] Limitando o que o cliente pode fazer
> Em **PUT presigned**, **tudo o que você quer impor** (tipo, criptografia, tags, metadados) **deve ser assinado**; **o que não for assinado, o cliente controla**. Para **limitar tamanho/tipo** com robustez, prefira **presigned POST (policy)**.

## 4. Presigned POST (policy)

### 4.1 O que é

Um **formulário HTML** (`multipart/form-data`) com **campos assinados** e uma **policy** (JSON codificada em base64) que define **condições** do upload: **prefixo da chave**, **faixa de tamanho**, **Content-Type**, **metadados**, **criptografia** etc.

### 4.2 Python

```python
post = s3.generate_presigned_post(
    Bucket="uploads-prod",
    Key="usuarios/42/${filename}",                         # ${filename} = nome do arquivo enviado
    Fields={"Content-Type": "image/png", "x-amz-meta-usuario": "42", "acl": "private"},
    Conditions=[
        ["content-length-range", 1, 5 * 1024 * 1024],       # 1 B a 5 MiB
        ["starts-with", "$Content-Type", "image/"],         # só imagens
        {"x-amz-meta-usuario": "42"},
        {"acl": "private"},
    ],
    ExpiresIn=600)
# post = {"url": "https://uploads-prod.s3.amazonaws.com/", "fields": {...}}
```

### 4.3 Uso no navegador

```html
<form action="{{ post.url }}" method="post" enctype="multipart/form-data">
  <!-- campos retornados em post.fields (key, policy, x-amz-algorithm, x-amz-credential, x-amz-date, x-amz-signature, ...) -->
  <input type="hidden" name="key" value="usuarios/42/${filename}">
  <!-- ... demais hidden fields ... -->
  <input type="file" name="file">            <!-- o campo "file" DEVE ser o ÚLTIMO -->
  <input type="submit" value="Enviar">
</form>
```

### 4.4 PUT presigned vs POST presigned

| Critério | **PUT presigned** | **POST presigned** |
|---|---|---|
| **Complexidade** | **Simples** | Média |
| **Limite de tamanho** | **Não impõe** (só se assinar `Content-Length`, que é incomum) | **`content-length-range`** (**impõe** faixa) |
| **Restringir tipo/prefixo** | Só **fixando** headers/chave | **Condições** flexíveis (`starts-with`) |
| **Cliente** | `fetch`/`curl` (**raw body**) | **Formulário** `multipart/form-data` |
| **Nome do arquivo** | **Chave fixa** definida pelo backend | Pode usar `${filename}` |
| **Redirecionamento pós-upload** | Não | `success_action_redirect`/`success_action_status` |
| **Quando usar** | **APIs/apps** controlando tudo | **Upload do navegador** com **regras** |

## 5. Uploads grandes: multipart com URLs por parte

### 5.1 Fluxo

```
1) Backend: create_multipart_upload(Bucket, Key)  →  UploadId
2) Para cada parte N: gera presigned URL de upload_part (PartNumber=N, UploadId)  →  envia ao cliente
3) Cliente: PUT de cada parte (5 MiB–5 GiB; última pode ser menor) → coleta o ETag de cada resposta
4) Backend: complete_multipart_upload(Bucket, Key, UploadId, Parts=[{PartNumber, ETag}…])
   (ou abort_multipart_upload em falha → evita cobrança de partes órfãs)
```

```python
mp = s3.create_multipart_upload(Bucket="uploads-prod", Key="videos/aula.mp4", ContentType="video/mp4")
upload_id = mp["UploadId"]
urls = [s3.generate_presigned_url("upload_part",
          Params={"Bucket": "uploads-prod", "Key": "videos/aula.mp4", "UploadId": upload_id, "PartNumber": n},
          ExpiresIn=3600) for n in range(1, 21)]
# Cliente envia cada parte; backend completa:
s3.complete_multipart_upload(Bucket="uploads-prod", Key="videos/aula.mp4", UploadId=upload_id,
                             MultipartUpload={"Parts": [{"PartNumber": i+1, "ETag": etag} for i, etag in enumerate(etags)]})
```

### 5.2 Boas práticas

| Prática | Detalhe |
|---|---|
| **Tamanho de parte** | **≥ 5 MiB** (exceto a última), **até 10.000 partes**; **8–64 MiB** em geral |
| **Retentativas por parte** | O cliente **repete** partes que falham |
| **Lifecycle** | **Abortar multipart incompletos** (regra de lifecycle **`AbortIncompleteMultipartUpload`**, ex.: 7 dias) — evita **custos** |
| **Expiração** | **Maior** (muitas partes/arquivos grandes) — mas **limitada** pela **credencial** do assinante |
| **ETag/checksums** | Guardar **ETag/checksum** por parte para **completar** |
| **Validação** | **Checksum** do objeto final (SHA-256/CRC) |
| **Transfer Acceleration** | Opcional para **clientes globais** |

## 6. Checksums e integridade

| Mecanismo | Detalhe (de memória — confirmar) |
|---|---|
| **`Content-MD5`** | Integridade **clássica** (MD5 do corpo) — S3 **rejeita** se não bater |
| **Checksums adicionais** (`x-amz-checksum-crc32/crc32c/sha1/sha256`) | **Integridade** no upload/download; **assináveis** (o cliente deve enviar **o mesmo** valor) |
| **`x-amz-sdk-checksum-algorithm`** | Algoritmo preferido |
| **Uso** | **Garantir** que o arquivo **não foi corrompido** em trânsito; **validar** no **backend** após o upload |
| **Presigned + checksum** | Ao **assinar** o checksum, o cliente **precisa calculá-lo** antes do PUT |

## 7. Geração por tipo de credencial

| Quem assina | Observação |
|---|---|
| **Role de Lambda/ECS/EC2** | Credenciais **temporárias**; a URL **expira com a sessão** (ver folha de validade) |
| **IAM user (chaves de longo prazo)** | URL pode durar **até 7 dias** (limite do SigV4) |
| **SSO/AssumeRole** | Limitada pela **duração da sessão** |
| **Cognito identity pool** | Credenciais **temporárias do usuário**: o **frontend** pode **assinar** localmente **com permissões do usuário** |
| **Backend dedicado** | **Role mínima** apenas para **gerar** URLs de **buckets/prefixos específicos** |

## 8. Padrão de API (Lambda + API Gateway) para gerar URLs

```python
import boto3, json, os, uuid
s3 = boto3.client("s3", config=boto3.session.Config(signature_version="s3v4", region_name=os.environ["AWS_REGION"]))
BUCKET = os.environ["BUCKET"]

def handler(event, context):
    usuario = event["requestContext"]["authorizer"]["claims"]["sub"]            # identidade vinda do authorizer (Cognito)
    corpo = json.loads(event["body"])
    if corpo["content_type"] not in ("image/png", "image/jpeg"):
        return {"statusCode": 400, "body": json.dumps({"erro": "tipo não permitido"})}
    chave = f"usuarios/{usuario}/{uuid.uuid4()}.{'png' if corpo['content_type']=='image/png' else 'jpg'}"
    url = s3.generate_presigned_url("put_object",
            Params={"Bucket": BUCKET, "Key": chave, "ContentType": corpo["content_type"]}, ExpiresIn=300)
    return {"statusCode": 200, "headers": {"Content-Type": "application/json"},
            "body": json.dumps({"url": url, "chave": chave, "expira_em": 300})}
```

Pontos:

- **Autenticar/autorizar** o **usuário** **antes** de gerar a URL (**Cognito**, **Lambda authorizer**, **IAM**).
- **Gerar a chave no servidor** (**não** aceitar chave do cliente — evita **sobrescrever** arquivos alheios/**path traversal**).
- **Validar** tipo/tamanho **declarados** (mas **revalidar** depois do upload).
- **Registrar** a **intenção** (ex.: DynamoDB `uploads_pendentes`) para **reconciliar** com o evento do S3.
- **Expiração curta**.

## 9. Erros comuns

- **Headers diferentes** dos assinados (Content-Type, metadados, SSE).
- **Aceitar a chave do cliente**.
- **PUT presigned** esperando **limite de tamanho** (use **POST policy**).
- **Esquecer `AbortIncompleteMultipartUpload`**.
- **Gerar URL com endpoint global/região errada**.
- **Codificação de URL** (reencodar parâmetros corrompe a assinatura).
- **Reutilizar `${filename}`** sem validar o nome.
- **Expiração longa** demais.
- **Assinar com role ampla**.
- **Esquecer SigV4** em regiões que exigem (SigV2 legado falha).
- **`file` não é o último campo** no formulário do POST.

## 10. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| `SignatureDoesNotMatch` no PUT | Header diferente/ausente | Enviar **exatamente** os headers assinados |
| `AccessDenied` no POST | Condição da policy violada | Ver `content-length-range`, `starts-with`, campos |
| `EntityTooLarge`/`EntityTooSmall` | Faixa de tamanho; partes < 5 MiB | Ajustar |
| `InvalidPart` no complete | ETags/ordem errados | Conferir `PartNumber`/`ETag` |
| `NoSuchUpload` | Upload abortado/expirado | Reiniciar |
| URL com `%2B/%2F` quebrada | Re-encoding | Usar a URL **como gerada** |
| 307 TemporaryRedirect | Região/endpoint | Endpoint **regional**; `s3v4` |
| CORS no navegador | Regras CORS | Configurar CORS (PUT/POST, headers) |

## 11. Resumo rápido

- **GET** (com `ResponseContent*`, `VersionId`), **PUT** (headers **assinados = enviados**), **POST** (**policy**: `content-length-range`, `starts-with`, metadados), **multipart** (URLs por parte + **complete/abort**).
- **Assine tudo que quer impor** (tipo, SSE, metadados, tags); **o resto o cliente controla**.
- **Limite de tamanho/tipo** robusto → **presigned POST**.
- **Multipart**: partes **≥ 5 MiB**, até **10.000**, **lifecycle** de aborto, **checksums**.
- **Gerar no servidor**: **autenticar** o usuário, **chave gerada pelo servidor**, **expiração curta**, **role mínima**, registrar a **intenção**.
- **SDKs**: Boto3 `generate_presigned_url/post`, JS `getSignedUrl`/`createPresignedPost`, Java `S3Presigner`; **CLI** `aws s3 presign` (**GET**).

## 🧩 Quiz de Fixação

1. Por que o Content-Type precisa ser igual no PUT presigned?
2. Como limitar o tamanho de upload do navegador?
3. Quais são as etapas do multipart com URLs por parte?
4. Por que o servidor deve gerar a chave do objeto?
5. Para que serve `AbortIncompleteMultipartUpload`?
6. O que a CLI `aws s3 presign` gera?
7. Que parâmetros de resposta personalizam o download?

**Respostas:**

1. Porque, se foi assinado, o header faz parte da assinatura; qualquer diferença invalida (SignatureDoesNotMatch).
2. Com presigned POST e a condição `content-length-range` na policy.
3. Criar o multipart (UploadId), gerar a URL de cada parte, o cliente enviar as partes e coletar ETags, e o backend completar (ou abortar em falha).
4. Para evitar que o cliente sobrescreva objetos de outros ou use caminhos maliciosos, mantendo controle do namespace.
5. Regra de lifecycle que aborta uploads multipart incompletos, evitando custos de partes órfãs.
6. Uma presigned URL de GET para um objeto, com validade definida por `--expires-in`.
7. ResponseContentDisposition, ResponseContentType, ResponseCacheControl e similares, além de VersionId para versões específicas.
