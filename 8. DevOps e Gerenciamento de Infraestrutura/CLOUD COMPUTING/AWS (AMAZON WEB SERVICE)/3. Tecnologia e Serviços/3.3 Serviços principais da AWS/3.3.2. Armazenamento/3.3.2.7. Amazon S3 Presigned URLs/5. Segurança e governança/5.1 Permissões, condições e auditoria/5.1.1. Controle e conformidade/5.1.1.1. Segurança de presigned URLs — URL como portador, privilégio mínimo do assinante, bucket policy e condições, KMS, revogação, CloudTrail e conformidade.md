### 5.1.1.1. Segurança de presigned URLs — URL como portador, privilégio mínimo do assinante, bucket policy e condições, KMS, revogação, CloudTrail e conformidade

> [!warning] Aviso
> Chaves de condição (`s3:signatureAge`, `s3:authType`, `s3:signatureversion`, `aws:SourceIp`, `aws:SourceVpce`), comportamento de revogação e eventos de auditoria abaixo são **de memória e mudam**. **Confirme na documentação “Bucket policy examples”, “Condition keys for Amazon S3” e “Logging with CloudTrail”.** Políticas JSON e comandos são ilustrativos e **não foram executados**. ARNs, contas e buckets são fictícios.

## 1. Modelo de ameaça: a URL é um token portador

Uma presigned URL funciona como um **bearer token**: **quem a possui, usa** — sem provar identidade. Isso define o **modelo de ameaça**:

| Ameaça | Como acontece | Impacto |
|---|---|---|
| **Vazamento da URL** | Logs (proxy, CDN, app), **histórico do navegador**, **cabeçalho Referer**, e-mails/chats, **screenshots**, analytics de terceiros | Qualquer pessoa **baixa/sobe** até expirar |
| **Compartilhamento indevido** | Usuário **repassa** o link | Acesso **além do autorizado** |
| **Assinante com privilégio excessivo** | Role ampla assina URLs | Abuso **maior** se a URL for forjada/manipulada* |
| **Chave de assinatura comprometida** | **Access key** do IAM user vazada | Atacante **gera URLs ilimitadas** |
| **Upload malicioso** | Arquivo **infectado**/gigante | **Malware**, **custos**, DoS de armazenamento |
| **Sobrescrita/enumeração** | Chave previsível/aceita do cliente | **Troca de arquivos** de outros usuários |
| **Replay** | URL reutilizada dentro da validade | **Múltiplos acessos** com a mesma URL |
| **Man-in-the-middle** | **HTTP** sem TLS | Interceptação da URL |
| **Abuso de emissão** | API de emissão sem **rate limit** | **Custos**, enumeração |

\* A URL **não** pode ser “ampliada” pelo cliente (alterar chave/operação invalida a assinatura), mas **o poder máximo** de uma URL é **o do assinante** para **aquela operação/objeto**.

## 2. Camadas de defesa

```
 (1) Quem emite   → autenticação/autorização na API; rate limit/WAF; auditoria
 (2) Quem assina  → role de MENOR privilégio; credenciais temporárias; sem IAM user de longo prazo
 (3) A URL        → expiração CURTA; chave/headers fixados; HTTPS; sem persistir
 (4) O bucket     → Block Public Access; bucket policy com condições (rede, auth, SSL, criptografia)
 (5) O conteúdo   → quarentena + validação + antivírus; tags de estado
 (6) A observação → CloudTrail data events, server access logs, alarmes, reconciliação
```

## 3. Privilégio mínimo do assinante

A URL só pode fazer o que o **assinante** pode. Reduza esse teto:

| Prática | Exemplo |
|---|---|
| **Role dedicada** apenas para **emitir URLs** | `RoleEmissorPresigned` — não reutilizar a role “admin da aplicação” |
| **Ação específica** | Upload: `s3:PutObject`; download: `s3:GetObject` — **separadas** |
| **Recurso restrito** | **Prefixo** (`arn:aws:s3:::uploads-prod/usuarios/*`), **não** `*` |
| **Condições na role** | `s3:x-amz-server-side-encryption`, `s3:x-amz-acl`, tags, `aws:SourceIp` |
| **Sem `s3:*`** | Nem `s3:DeleteObject` se não for necessário |
| **Credenciais temporárias** | **Roles** (Lambda/ECS) em vez de **IAM user** |
| **Permission boundary/SCP** | **Teto** organizacional (ex.: negar `s3:PutObject` sem SSE) |

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "UploadSomenteNoPrefixoDoUsuario",
      "Effect": "Allow",
      "Action": ["s3:PutObject"],
      "Resource": "arn:aws:s3:::uploads-prod/quarentena/*",
      "Condition": {
        "StringEquals": { "s3:x-amz-server-side-encryption": "aws:kms" }
      }
    }
  ]
}
```

> [!tip] Separar “quem emite” de “quem lê”
> Use **uma role para emitir URLs de upload** (só `PutObject` em `quarentena/`) e **outra para URLs de download** (só `GetObject` em `aprovado/`). Se uma URL de upload vazar, **não** dá leitura.

## 4. Bucket policy: controles que **também** valem para presigned URLs

Como a requisição pré-assinada é **autenticada** (como o assinante), a **bucket policy** continua sendo avaliada. Use isso para **impor** regras **independentes** da aplicação.

### 4.1 Exigir TLS

```json
{
  "Sid": "NegarSemTLS",
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": ["arn:aws:s3:::uploads-prod", "arn:aws:s3:::uploads-prod/*"],
  "Condition": { "Bool": { "aws:SecureTransport": "false" } }
}
```

### 4.2 Limitar a **idade da assinatura** (`s3:signatureAge`)

Força que **presigned URLs** tenham **vida curta**, **independente** do que o código pedir:

```json
{
  "Sid": "PresignedNoMaximo10Min",
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": "arn:aws:s3:::uploads-prod/*",
  "Condition": { "NumericGreaterThan": { "s3:signatureAge": 600000 } }
}
```

(`s3:signatureAge` em **milissegundos**; **600000 = 10 min** — **de memória; confirmar** o escopo: aplica-se a requisições **autenticadas via query string**.)

### 4.3 Controlar o **tipo de autenticação** (`s3:authType`)

| Valor | Significado |
|---|---|
| **`REST-HEADER`** | Assinatura no **cabeçalho Authorization** (SDK/CLI normal) |
| **`REST-QUERY-STRING`** | Assinatura **na query string** (**presigned**) |

```json
{
  "Sid": "NegarPresignedNoBucketInterno",
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": "arn:aws:s3:::dados-internos/*",
  "Condition": { "StringEquals": { "s3:authType": "REST-QUERY-STRING" } }
}
```

Útil para **proibir presigned URLs** em buckets que **nunca** devem ser compartilhados por link.

### 4.4 Exigir **SigV4** (`s3:signatureversion`)

```json
{
  "Sid": "SoSigV4",
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": "arn:aws:s3:::uploads-prod/*",
  "Condition": { "StringNotEquals": { "s3:signatureversion": "AWS4-HMAC-SHA256" } }
}
```

### 4.5 Restringir por rede (`aws:SourceIp`, `aws:SourceVpce`, `aws:SourceVpc`)

```json
{
  "Sid": "SoDaVpcDoPartner",
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:*",
  "Resource": "arn:aws:s3:::dados-parceiro/*",
  "Condition": {
    "StringNotEquals": { "aws:SourceVpce": "vpce-0abc1234def567890" },
    "NotIpAddress": { "aws:SourceIp": ["203.0.113.0/24"] }
  }
}
```

> [!warning] Cuidado com Deny combinado
> Com **duas condições** num `Deny`, o efeito é **E** (as **duas** precisam ser verdadeiras para negar). Para “**permitir se (VPCE) OU (IP)**”, o padrão correto é **um Deny por condição** (ou `Allow` com `Null`/`ForAnyValue`) — **teste no IAM Policy Simulator**. Uma presigned URL **vazada** continua **bloqueada fora da rede permitida**: **excelente defesa em profundidade**.

### 4.6 Exigir criptografia e propriedade do objeto

| Controle | Efeito |
|---|---|
| **`s3:x-amz-server-side-encryption`** (Deny se ausente) | Uploads **sem SSE** negados |
| **`s3:x-amz-server-side-encryption-aws-kms-key-id`** | Só **chave KMS** específica |
| **Object Ownership = BucketOwnerEnforced** | **ACLs desativadas**; **dono = bucket** |
| **`s3:x-amz-acl`** | Negar ACLs públicas (`public-read`) |
| **Block Public Access** | **Sempre ligado** (presigned **não precisa** de acesso público) |

## 5. KMS e presigned URLs

Com **SSE-KMS**, quem **lê/escreve** o objeto precisa de **permissão na chave KMS** — **o assinante** (a URL herda suas permissões).

| Cenário | Exigência |
|---|---|
| **PUT com SSE-KMS** | Assinante com `kms:GenerateDataKey` (e `kms:Decrypt` em multipart) na **chave** |
| **GET de objeto SSE-KMS** | Assinante com `kms:Decrypt` |
| **Key policy** | Deve **permitir** a role assinante (ou delegar ao IAM) |
| **SSE-C** (chave do cliente) | Cliente **precisa enviar** os headers `x-amz-server-side-encryption-customer-*` — **evitar** em fluxo navegador |
| **Bucket Keys** | Reduz **chamadas ao KMS** e **custo** |
| **Erro típico** | `AccessDenied` em objeto **existente** → olhar **KMS** (não só S3) |

```json
{
  "Sid": "PermitirRoleEmissoraUsarChave",
  "Effect": "Allow",
  "Principal": {"AWS": "arn:aws:iam::123456789012:role/RoleEmissorPresigned"},
  "Action": ["kms:GenerateDataKey", "kms:Decrypt"],
  "Resource": "*"
}
```

## 6. Revogação: como “cancelar” uma URL

Presigned URLs **não têm botão de revogar**. Opções:

| Método | Efeito | Escopo |
|---|---|---|
| **Remover permissão do assinante** (alterar policy da role) | URLs **dessa role** passam a **403** | **Todas** as URLs desse assinante |
| **Revogar sessões ativas da role** (IAM → “Revoke active sessions”; adiciona **`aws:TokenIssueTime`** Deny) | Invalida **sessões anteriores** | URLs assinadas com **tokens antigos** |
| **Desativar/excluir a access key** (IAM user) | URLs dessa chave **morrem** | Todas as URLs da **chave** |
| **Bucket policy Deny** (por prefixo/objeto/tag) | Bloqueia **objeto específico** | **Granular** |
| **Mover/excluir/renomear o objeto** | GET falha | Específico |
| **Alterar tag** (`scan-status`) com policy por tag | Bloqueio **dinâmico** | Específico |
| **Expiração curta** | Reduz a **janela** | **Preventivo** |

> [!tip] Para revogação granular
> Use **tags** nos objetos + **bucket policy** que exige `s3:ExistingObjectTag/acesso = liberado`. Para **revogar**, **mude a tag** — **qualquer URL** daquele objeto deixa de funcionar **imediatamente**.

```bash
# revoga sessões anteriores de uma role (efeito: Deny com aws:TokenIssueTime)
aws iam put-role-policy --role-name RoleEmissorPresigned --policy-name AWSRevokeOlderSessions \
  --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Deny","Action":["*"],"Resource":["*"],"Condition":{"DateLessThan":{"aws:TokenIssueTime":"2026-11-12T12:00:00Z"}}}]}'
```

## 7. Proteção na camada do cliente e da aplicação

| Prática | Detalhe |
|---|---|
| **HTTPS sempre** | `aws:SecureTransport`; **HSTS** |
| **Não logar a URL completa** | **Mascarar** `X-Amz-Signature`/`X-Amz-Credential`/`X-Amz-Security-Token` em **logs/APM** |
| **`Referrer-Policy`** | `no-referrer`/`strict-origin` para evitar **vazar** a URL por Referer |
| **`Cache-Control: no-store`** | Na resposta da API que devolve a URL |
| **Não embutir URLs em páginas públicas/indexáveis** | Evitar **cache**/indexação |
| **Redirect 302** em vez de expor a URL no HTML | Menos **exposição** em fontes/logs |
| **Chave gerada pelo servidor** (UUID) | **Imprevisível**; sem sobrescrita |
| **Rate limit/WAF/CAPTCHA** | Na **API de emissão** |
| **Cotas por usuário** | Tamanho/quantidade |
| **Content-Disposition: attachment** | Evita **renderizar** HTML/SVG enviado (XSS armazenado) |
| **Domínio separado** para conteúdo de usuário | Isola **cookies/origem** |

> [!warning] XSS armazenado
> Se usuários podem **enviar HTML/SVG** e você os **serve inline** do **mesmo domínio** da aplicação, um arquivo malicioso pode **executar JavaScript** no contexto da origem. Sirva com `Content-Disposition: attachment`, **`X-Content-Type-Options: nosniff`**, e em **domínio separado** (ex.: `usercontent.exemplo.com`).

## 8. Auditoria com CloudTrail e logs de acesso

| Fonte | O que mostra | Observação |
|---|---|---|
| **CloudTrail — eventos de gerenciamento** | Alterações em **policies, CORS, lifecycle** | Ativado por padrão (histórico 90 dias) |
| **CloudTrail — data events (S3)** | **GetObject/PutObject/DeleteObject** com **principal, IP, user agent** | **Opt-in** (custo); **filtre por bucket/prefixo** |
| **S3 server access logs** | Requisições **por objeto** (IP, status, **`Authentication Type`**: `QueryString` para presigned) | **Entrega best-effort**; baixo custo |
| **CloudWatch/Athena** | Consultas sobre logs | **Particione** por data |
| **Macie** | **PII** em objetos enviados | Complementar |
| **Config/Security Hub** | **Conformidade** do bucket (BPA, SSL, SSE) | Regras gerenciadas |
| **Access Analyzer for S3** | **Acesso externo/público** | Preventivo |

Pontos para investigação:

- Em **CloudTrail**, requisições presigned aparecem com **`userIdentity`** do **assinante** (role/usuário) — **não** do portador final. O **IP de origem** (`sourceIPAddress`) é o do **portador**, o que **ajuda a detectar uso anômalo**.
- No **log de acesso do S3**, o campo **“Authentication Type”** mostra **`QueryString`** quando é presigned.
- Detectar **padrões**: **muitos GETs de IPs diferentes** para a **mesma URL/objeto** (vazamento) → **revogar** (tag/policy) e **investigar**.

```sql
-- Athena (S3 server access logs): quem baixou presigned URLs, por IP
SELECT requester, remoteip, key, httpstatus, COUNT(*) AS acessos
FROM s3_access_logs
WHERE authenticationtype = 'QueryString' AND operation = 'REST.GET.OBJECT'
  AND requestdatetime > date_add('hour', -24, now())
GROUP BY requester, remoteip, key, httpstatus
ORDER BY acessos DESC LIMIT 50;
```

## 9. Conformidade (LGPD, PCI, SOC, HIPAA — visão geral)

| Requisito | Prática com presigned URLs |
|---|---|
| **Minimização de acesso** | URLs **curtas**, **escopo estreito**, **role mínima** |
| **Rastreabilidade** | Log de **emissão** (quem pediu o quê) + **CloudTrail/server logs** |
| **Criptografia** | **TLS** em trânsito; **SSE-KMS** em repouso |
| **Retenção e descarte** | **Lifecycle**; exclusão sob solicitação (**direito ao esquecimento**) — incluir **versões** |
| **Segregação** | Buckets/contas separados por **sensibilidade** |
| **Dados pessoais em nomes de chave** | **Evitar** (URLs e logs expõem chaves) |
| **Revisão periódica** | **Access Analyzer**, **Config**, revisão de **policies** |
| **Terceiros/parceiros** | **Contrato**, **expiração**, **IP allowlist**, **auditoria** |

> [!tip] Nunca coloque PII na chave do objeto
> A **chave** aparece em **URLs**, **logs**, **eventos** e **CloudTrail**. Use **UUIDs** e guarde o **nome real/dono** no **banco**.

## 10. Checklist de segurança

1. **Block Public Access** ligado.
2. **Role emissora de menor privilégio**, **credenciais temporárias**.
3. **Chave gerada no servidor**; **sem PII** na chave.
4. **Expiração mínima**; **`s3:signatureAge`** na bucket policy.
5. **TLS obrigatório**; **SigV4** exigido.
6. **Condições de rede** (`SourceVpce`/`SourceIp`) quando aplicável.
7. **SSE-KMS** obrigatório e permissões KMS ao assinante.
8. **POST policy** (`content-length-range`, `starts-with`) para uploads de navegador.
9. **Quarentena + validação + antivírus**; **tags** de estado.
10. **Rate limit/WAF** na emissão; **cotas** por usuário.
11. **Mascarar** URLs em logs; **Referrer-Policy**; `no-store`.
12. **CloudTrail data events** (escopo estreito) e **server access logs**.
13. **Plano de revogação** (tags/policy/sessões).
14. **Domínio separado** e `attachment` para conteúdo de usuário.

## 11. Erros comuns

- **Tratar a URL como autenticada por usuário** (é portadora).
- **Role “faz-tudo”** assinando URLs.
- **IAM user com chave de longo prazo** assinando.
- **Não mascarar** URLs em logs/APM.
- **Expiração longa** “por conveniência”.
- **Aceitar chave do cliente**.
- **Sem condições na bucket policy** (TLS/SigV4/rede).
- **Misturar `Deny` com várias condições** sem testar.
- **Ignorar KMS** (AccessDenied misterioso).
- **Servir HTML/SVG** de usuário inline.
- **Sem auditoria** (data events desligados).
- **PII em chaves**.

## 12. Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| 403 após endurecer a policy | `s3:signatureAge`/SigV4/rede bloqueando | Ver condição e **idade da assinatura**; usar **Policy Simulator** |
| Presigned funciona local, falha em produção | `aws:SourceVpce`/IP | Usar o **endpoint/IP** permitido |
| `AccessDenied` só em SSE-KMS | Permissão KMS do **assinante** | Ajustar **key policy**/IAM |
| Quer revogar **uma** URL | Sem revogação individual | **Tag/policy** por objeto; trocar a chave; expiração curta |
| Suspeita de vazamento | Muitos IPs na mesma URL | Server logs/CloudTrail; **revogar**; rotacionar |
| Não vê quem baixou | Data events desligados | Habilitar **CloudTrail data events** (escopo) |
| URL aparece em logs | Logging sem máscara | **Filtrar** query string; rotacionar |

## 13. Resumo rápido

- **Presigned URL = token portador**: segurança vem de **expiração curta**, **escopo mínimo**, **TLS** e **defesa em profundidade**.
- **Assinante com privilégio mínimo** (role dedicada, prefixo, ação, **SSE obrigatória**); evitar **IAM users** de longo prazo.
- **Bucket policy** continua valendo: **`aws:SecureTransport`**, **`s3:signatureAge`**, **`s3:authType`**, **`s3:signatureversion`**, **`aws:SourceVpce/SourceIp`**, **SSE/KMS**, **BPA**.
- **KMS**: permissão do **assinante** na chave (`GenerateDataKey`/`Decrypt`).
- **Revogação**: remover permissão/revogar sessões/desativar chave (**ampla**) ou **tag + policy**/mover objeto (**granular**).
- **Cliente/app**: mascarar URLs, `Referrer-Policy`, `no-store`, `attachment`, domínio separado, **rate limit/WAF**.
- **Auditoria**: **CloudTrail data events** + **server access logs** (`QueryString`); **Access Analyzer/Config**; **sem PII na chave**.

## 🧩 Quiz de Fixação

1. Por que uma presigned URL é considerada um token portador?
2. Que condição limita a idade máxima de assinaturas presigned?
3. Como proibir presigned URLs em um bucket?
4. Como revogar o acesso a um objeto específico rapidamente?
5. Que permissão KMS o assinante precisa para PUT com SSE-KMS?
6. Quem aparece como identidade no CloudTrail para uma requisição presigned?
7. Por que nunca colocar PII na chave do objeto?

**Respostas:**

1. Porque quem possui a URL a utiliza sem provar identidade; vale até expirar com as permissões do assinante.
2. `s3:signatureAge` (em milissegundos) em uma bucket policy com Deny.
3. Negar requisições com `s3:authType` igual a `REST-QUERY-STRING` na bucket policy.
4. Usando tag no objeto combinada com bucket policy que exige a tag, ou mover/excluir o objeto, ou negar via policy por prefixo.
5. `kms:GenerateDataKey` (e `kms:Decrypt` em multipart), além de key policy que o permita.
6. A identidade do assinante (role/usuário), não do portador; o IP de origem é do portador.
7. Porque a chave aparece em URLs, logs, eventos e CloudTrail, expondo dados pessoais.
