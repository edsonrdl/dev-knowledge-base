### 6.1.1.1. Troubleshooting de presigned URLs — SignatureDoesNotMatch, AccessDenied, Request has expired, ExpiredToken, CORS, redirects 307, KMS, diagnóstico passo a passo e checklist

> [!warning] Aviso
> Códigos e mensagens de erro, textos exatos do S3 e comportamento de SDKs mudam entre versões. As mensagens abaixo são **de memória**. **Confirme na documentação “Troubleshooting Amazon S3” e “Error responses”.** Comandos e trechos de código são ilustrativos e **não foram executados**. Hosts, chaves e IDs são fictícios.

## 1. Método de diagnóstico: do sintoma à causa

Presigned URLs falham de formas **parecidas** (um “403” pode ter **dez** causas). Use **sempre** este roteiro:

```
1) Reproduzir FORA do navegador (curl -v) → separa problema da URL de problema de CORS/cliente
2) Ler o CORPO do erro (XML do S3: <Code>, <Message>, <RequestId>, <HostId>)
3) Decodificar a URL (data, expiração, credencial, headers assinados, região/host)
4) Conferir o ASSINANTE (permissões, sessão/token, chave ativa, KMS)
5) Conferir o BUCKET (policy/Deny, BPA, endpoint policy, Object Ownership, objeto existe?)
6) Conferir o CLIENTE (headers enviados, relógio, proxy, encoding, CORS)
7) Correlacionar nos LOGS (server access logs / CloudTrail) pelo RequestId
```

```bash
# 1) reproduzir e ver o corpo do erro (sempre com -v e -i)
curl -v -i "https://uploads-prod.s3.us-east-1.amazonaws.com/usuarios/42/avatar.png?X-Amz-Algorithm=...&X-Amz-Signature=..."

# PUT: enviar exatamente os headers assinados
curl -v -i -X PUT -H "Content-Type: image/png" --upload-file avatar.png "<url>"
```

> [!tip] O corpo do erro é ouro
> O S3 retorna **XML** com `<Code>`, `<Message>`, e às vezes **`<StringToSign>`**, **`<CanonicalRequest>`**, **`<SignatureProvided>`** (em `SignatureDoesNotMatch`). Compare **o que o servidor calculou** com **o que o seu código assinou**: a diferença **mostra o header/valor divergente**.

## 2. Decodificando a URL (o que ela diz)

```python
from urllib.parse import urlparse, parse_qs
import datetime

u = urlparse(url); q = parse_qs(u.query)
assinado_em = datetime.datetime.strptime(q["X-Amz-Date"][0], "%Y%m%dT%H%M%SZ")
expira_em = assinado_em + datetime.timedelta(seconds=int(q["X-Amz-Expires"][0]))
print("host:", u.netloc, "\nchave:", u.path)
print("credencial:", q["X-Amz-Credential"][0])             # AKIA.../data/região/s3/aws4_request
print("headers assinados:", q["X-Amz-SignedHeaders"][0])
print("assinado em:", assinado_em, "expira em:", expira_em, "agora:", datetime.datetime.utcnow())
print("tem token de sessão:", "X-Amz-Security-Token" in q)
```

| Campo da URL | O que verificar |
|---|---|
| **Host** (`bucket.s3.<região>...`) | **Região correta**? Host **igual** ao usado pelo cliente? |
| **`X-Amz-Credential`** | **Região** no escopo bate com a do bucket? **Data** coerente? |
| **`X-Amz-Date` + `X-Amz-Expires`** | **Já expirou**? Relógio do emissor/cliente? |
| **`X-Amz-SignedHeaders`** | Quais headers o cliente **precisa** enviar (**`host`**, **`content-type`**, `x-amz-*`)? |
| **`X-Amz-Security-Token`** | Se existe → validade **limitada pela sessão** |
| **Parâmetros extras** (`response-content-*`, `versionId`, `partNumber`, `uploadId`) | Foram **assinados**; **não** alterar |

## 3. Catálogo de erros

### 3.1 `403 SignatureDoesNotMatch`

“The request signature we calculated does not match the signature you provided.”

| Causa | Como confirmar | Correção |
|---|---|---|
| **Header diferente do assinado** (`Content-Type`, `x-amz-meta-*`, SSE, tags, checksum) | Comparar `SignedHeaders` com o que o cliente envia | Enviar **exatamente** os headers assinados (ou **remover** do `Params` ao gerar) |
| **Header assinado ausente** | `SignedHeaders` lista algo que o cliente **não enviou** | Enviar |
| **Host diferente** (proxy, CNAME, Acceleration, dualstack, path-style vs virtual-hosted) | Host da URL ≠ host da requisição | Usar o **mesmo host** |
| **Região/endpoint errado** na geração | Escopo da credencial com região ≠ bucket | Gerar com **região correta** e **SigV4** |
| **Re-encoding da URL** (`%2F`, `+`, `%20`) | URL “bonita” vs original | Usar a URL **como gerada**; **não** decodificar/recodificar |
| **Query string alterada** (parâmetros removidos/adicionados) | Diferenças | Não mexer |
| **Quebra de linha/espaços** copiando a URL | URL truncada | Copiar inteira |
| **Chave com caracteres especiais** mal codificada | Nome com acentos/espaços | Codificar **corretamente** (SDK faz); testar |
| **Credencial inválida** (secret errado) | Assinatura incorreta | Conferir **credenciais** |
| **Content-MD5/checksum** não coincide | Valor assinado ≠ calculado | Calcular **o mesmo** valor |
| **Proxy/WAF modificando headers** | Ver `curl -v` direto vs via proxy | Excluir da inspeção/reescrita |
| **HTTP→HTTPS redirect** mudando algo | Redirecionamentos | Usar **HTTPS** direto |

Exemplo de corpo (resumido):

```xml
<Error>
  <Code>SignatureDoesNotMatch</Code>
  <Message>The request signature we calculated does not match the signature you provided. Check your key and signing method.</Message>
  <AWSAccessKeyId>AKIAEXEMPLO</AWSAccessKeyId>
  <StringToSign>AWS4-HMAC-SHA256 ...</StringToSign>
  <CanonicalRequest>PUT /usuarios/42/avatar.png ... content-type:image/png ... host:uploads-prod.s3.us-east-1.amazonaws.com</CanonicalRequest>
  <RequestId>4442587FB7D0A2F9</RequestId>
</Error>
```

> Se o **`CanonicalRequest`** do servidor mostra `content-type:application/octet-stream` e você assinou `image/png`, **o cliente não enviou** o `Content-Type` esperado (muito comum com `fetch` sem header ou `XMLHttpRequest` sobrescrevendo).

### 3.2 `403 AccessDenied`

| Causa | Como confirmar | Correção |
|---|---|---|
| **Assinante sem permissão** (`s3:GetObject`/`PutObject`) | **Policy Simulator**; testar com as **mesmas credenciais** | Ajustar IAM |
| **Bucket policy `Deny`** (TLS, VPCE, IP, `signatureAge`, `authType`) | Ler a policy | Ajustar/atender condição |
| **Block Public Access/Ownership** (ACL) | Config do bucket | Ajustar (`BucketOwnerEnforced`: sem ACL) |
| **KMS** (SSE-KMS) | `AccessDenied` em objeto **existente**; CloudTrail mostra `kms:Decrypt` negado | Permissão na **key policy/IAM** |
| **Objeto de outro dono** | `GetObject` em objeto **sem** propriedade (ACLs) | **BucketOwnerEnforced**; `bucket-owner-full-control` |
| **Chave/objeto inexistente** sem `s3:ListBucket` | S3 retorna **403** (não 404) para **não vazar** existência | Dar `s3:ListBucket` ao assinante para obter **404** claro |
| **SCP/permission boundary** | Organizations | Ajustar |
| **VPC endpoint policy** | Requisição vinda da VPC | Ajustar a **endpoint policy** |
| **Sessão revogada** | `aws:TokenIssueTime` Deny | Nova sessão |
| **Access Point policy** | Se usa AP | Ajustar |

> [!warning] 403 em vez de 404
> Sem **`s3:ListBucket`**, o S3 devolve **403 AccessDenied** quando o objeto **não existe** (para não revelar existência). Um “download falha com 403” pode ser **chave errada**, **não** falta de permissão de leitura.

### 3.3 `403 Request has expired` (`AccessDenied` com mensagem)

| Causa | Correção |
|---|---|
| **Passou `X-Amz-Expires`** | Gerar **nova URL** |
| **Relógio do emissor adiantado/atrasado** (`X-Amz-Date` no futuro/passado) | **NTP/chrony** (instâncias), `timedatectl` |
| **Relógio do dispositivo do cliente** (S3 usa **o relógio do servidor**, mas o **emissor** pode estar errado) | Corrigir **no emissor** |
| **Expiração muito curta** (segundos) com fila/latência | Aumentar com **parcimônia** |
| **URL “envelhecida”** em cache/fila/e-mail | **Gerar sob demanda** |

> O S3 compara `X-Amz-Date + X-Amz-Expires` com **seu relógio**. Se o **emissor** estiver **adiantado** (data no futuro), a URL falha com **“Request is not yet valid”**/erro de data; se **atrasado**, **expira antes**.

### 3.4 `400 ExpiredToken` / “The provided token has expired”

| Causa | Correção |
|---|---|
| **Credencial temporária do assinante expirou** antes da URL | Gerar URL **com sessão válida**; **sob demanda**; **não prometer** validade > sessão |
| **Lambda reaproveitando cliente com credenciais antigas** (cache) | Deixar o SDK **renovar**; criar cliente **na inicialização** (o SDK atualiza) |
| **Role chaining** (≤ 1 h) | Planejar expiração **≤ 1 h** |
| **Credenciais do Cognito** (~1 h) | Renovar |

### 3.5 `InvalidAccessKeyId` / `InvalidToken`

| Causa | Correção |
|---|---|
| **Access key desativada/excluída** | Usar chave ativa/role |
| **Token inválido/corrompido** (URL truncada) | URL completa |
| **Mistura de partições/regiões** (China/GovCloud) | Credencial da **partição correta** |

### 3.6 `400 AuthorizationQueryParametersError`

“Query-string authentication version 4 requires the X-Amz-Algorithm, X-Amz-Credential, X-Amz-Signature, X-Amz-Date, X-Amz-SignedHeaders, and X-Amz-Expires parameters.”

| Causa | Correção |
|---|---|
| **Parâmetros perdidos** (truncamento, proxy, e-mail quebrou a URL) | Preservar a URL |
| **`X-Amz-Expires` fora do limite** (> 604800) | Reduzir |
| **Mistura SigV2/SigV4** | Forçar **`s3v4`** |
| **Região exigindo SigV4** com assinatura legada | Configurar SigV4 |

### 3.7 `400 Bad Request` / `EntityTooLarge` / `EntityTooSmall` / `InvalidPart` / `NoSuchUpload`

| Erro | Causa | Correção |
|---|---|---|
| **`EntityTooLarge`** | POST policy `content-length-range` ou **> 5 GiB** em PUT único | Reduzir/ajustar; **multipart** |
| **`EntityTooSmall`** | Parte **< 5 MiB** (exceto a última) | Aumentar partes |
| **`InvalidPart`** | ETag/PartNumber errado no `complete` | Conferir lista |
| **`InvalidPartOrder`** | Partes fora de ordem | Ordenar |
| **`NoSuchUpload`** | Upload abortado/expirado/UploadId errado | Reiniciar |
| **`MalformedPOSTRequest`** | **`file` não é o último campo** do formulário; campos faltando | Reordenar |
| **`InvalidDigest`/`BadDigest`** | **Content-MD5/checksum** não bate | Recalcular |
| **`MissingContentLength`** | Upload **chunked** sem tamanho (alguns clientes) | Enviar `Content-Length` |
| **`InvalidRequest` (SSE)** | Faltou header de SSE exigido pela policy | Incluir e assinar |

### 3.8 Redirects `307 TemporaryRedirect` / `301 PermanentRedirect`

| Causa | Explicação | Correção |
|---|---|---|
| **Endpoint global** (`s3.amazonaws.com`) para bucket de **outra região** recém-criado | DNS ainda **não propagou** o endpoint regional | Usar **endpoint regional** (`s3.<região>.amazonaws.com`) |
| **Região do cliente ≠ do bucket** | S3 redireciona; **clientes não refazem a assinatura** → falha | Gerar com a **região do bucket** (`client.meta.region_name`) |
| **Path-style em região nova** | Virtual-hosted é o padrão | Virtual-hosted |

> Redirecionar **não preserva** a assinatura (o **host muda**). **Evite** depender de redirecionamento: gere a URL **já para o endpoint correto**.

### 3.9 Erros de CORS (só no navegador)

Sintomas no console: **“blocked by CORS policy: No ‘Access-Control-Allow-Origin’ header”**, **“Response to preflight request doesn't pass”**, `net::ERR_FAILED` com status **403** aparente.

| Causa | Como confirmar | Correção |
|---|---|---|
| **Sem configuração CORS no bucket** | `aws s3api get-bucket-cors` → `NoSuchCORSConfiguration` | Aplicar CORS |
| **Origem não listada** | `AllowedOrigins` sem o domínio (**inclui esquema/porta**) | Adicionar `https://app...` |
| **Método não permitido** (PUT/POST) | `AllowedMethods` | Adicionar |
| **Header não permitido** (`Content-Type`, `x-amz-*`) | Preflight reclama de header | `AllowedHeaders: ["*"]` ou lista correta |
| **`ETag` não exposto** (multipart) | JS recebe `null` no header | `ExposeHeaders: ["ETag"]` |
| **Erro 403 “mascarado” como CORS** | Resposta de erro **sem** headers CORS (se CORS não casou) | Testar com **curl** → ver o **erro real** |
| **Cache do preflight** | `MaxAgeSeconds` antigo | Limpar cache/aguardar |
| **CloudFront/proxy** removendo `Origin`/headers | Cabeçalhos CORS ausentes | Encaminhar `Origin`/`Access-Control-*` na política de cache/origem |

```bash
aws s3api get-bucket-cors --bucket uploads-prod
# testar preflight manualmente
curl -i -X OPTIONS "https://uploads-prod.s3.us-east-1.amazonaws.com/usuarios/42/avatar.png" \
  -H "Origin: https://app.suaempresa.com" \
  -H "Access-Control-Request-Method: PUT" \
  -H "Access-Control-Request-Headers: content-type"
```

> [!tip] Regra prática
> **Funciona no `curl`, falha no navegador → CORS**. **Falha em ambos → assinatura/permissão**.

### 3.10 `404 NoSuchKey` / `NoSuchBucket`

| Causa | Correção |
|---|---|
| **Chave errada** (maiúsculas, prefixo, encoding) | Conferir a chave **exata** |
| **Objeto ainda não existe** (upload em andamento/eventual) | Aguardar/verificar evento |
| **Bucket em outra região/conta** | Verificar |
| **VersionId inexistente** | Versão correta |

### 3.11 `503 SlowDown` / `RequestTimeout`

| Causa | Correção |
|---|---|
| **Taxa muito alta no mesmo prefixo** | Distribuir prefixos; **backoff exponencial com jitter** |
| **Upload parado** (> ~20 s sem dados) | Retentar; checar rede |
| **Cliente móvel instável** | Multipart + retries |

## 4. Árvore de decisão rápida

```
A URL falha?
├─ Funciona no curl?
│   ├─ SIM → problema do CLIENTE: CORS, headers do fetch/XHR, proxy do navegador, extensão
│   └─ NÃO ─┐
│           ├─ Corpo = SignatureDoesNotMatch → comparar CanonicalRequest (headers/host/região/encoding)
│           ├─ Corpo = Request has expired / ExpiredToken → relógio / expiração / sessão do assinante
│           ├─ Corpo = AccessDenied → assinante (IAM) → bucket policy → KMS → ownership → ListBucket (404 vs 403)
│           ├─ 307/301 → região/endpoint
│           ├─ 400 AuthorizationQueryParametersError → URL truncada / SigV2
│           └─ 404 → chave/versão/bucket
```

## 5. Ferramentas de diagnóstico

| Ferramenta | Uso |
|---|---|
| **`curl -v -i`** | Ver status, headers e **corpo XML** |
| **`aws s3 presign`** + comparar | Gerar uma URL **de referência** com a CLI e comparar com a do app |
| **IAM Policy Simulator / `simulate-principal-policy`** | Testar permissões do **assinante** |
| **IAM Access Analyzer — policy validation/generation** | Revisar policies |
| **`aws sts get-caller-identity`** | Ver **quem** está assinando (role/usuário) |
| **S3 server access logs + Athena** | Ver **status/erro/IP** por requisição (`ErrorCode`) |
| **CloudTrail data events** | Ver **negações** (`errorCode`) e eventos **KMS** |
| **Logging do SDK** (`boto3.set_stream_logger`, `AWS_SDK_LOAD_CONFIG`) | Ver a **requisição canônica** |
| **DevTools do navegador (Network)** | Preflight, headers enviados, **Origin** |
| **Relógio** (`date -u`, `chronyc tracking`) | Verificar deriva |
| **X-Ray/logs da API** | Ver **emissão** (ExpiresIn, usuário, chave) |

```python
import boto3, logging
boto3.set_stream_logger("botocore", logging.DEBUG)       # mostra CanonicalRequest/StringToSign da assinatura (ambiente de teste!)
```

> [!warning] Cuidado com logs de debug
> Logs em **DEBUG** podem conter **credenciais/URLs completas**. Use **só em desenvolvimento** e **nunca** envie para ferramentas externas sem **mascarar**.

```sql
-- Athena: erros de presigned nas últimas 24 h (server access logs)
SELECT key, httpstatus, errorcode, COUNT(*) AS n
FROM s3_access_logs
WHERE authenticationtype = 'QueryString' AND httpstatus >= 400
  AND requestdatetime > date_add('hour', -24, now())
GROUP BY key, httpstatus, errorcode ORDER BY n DESC LIMIT 50;
```

## 6. Métricas e alarmes (operação contínua)

| Métrica/sinal | Onde | Alarme sugerido |
|---|---|---|
| **4xxErrors / 5xxErrors** do S3 | **Request metrics** (CloudWatch, por prefixo) | Taxa 4xx **acima do normal** |
| **Taxa de falha de upload** | Métricas da aplicação (cliente → API de status) | > limiar |
| **Emissões de URL por usuário** | Logs/metricas da API | **Anomalia** (abuso) |
| **Latência do evento de validação** | Lambda/SQS (age of oldest message) | Fila crescendo |
| **DLQ** | SQS | **> 0** |
| **Objetos em quarentena** | Contagem/idade | Acúmulo |
| **Acessos presigned de IPs incomuns** | Athena (server logs/CloudTrail) | Padrões de **vazamento** |
| **Custo de saída** | Cost Explorer/Budgets | **Anomaly detection** |

## 7. Receitas de correção rápida

| Problema | Receita |
|---|---|
| **PUT falha com SignatureDoesNotMatch** | Gerar **sem** `ContentType` e deixar o cliente enviar qualquer? **Não** — melhor: assinar `ContentType` e **enviar o mesmo** no cliente |
| **Navegador não envia o Content-Type certo** | Definir **explicitamente** em `fetch`/XHR; para `Blob`, usar `new Blob([...], {type})` |
| **Upload funciona local, falha em produção** | Proxy/WAF **alterando** headers; **`aws:SourceVpce`**; relógio |
| **Presigned “expira” cedo em Lambda** | Credencial da role; **gerar sob demanda**; ou **CloudFront signed URL** |
| **Chave com espaços/acentos falha** | Deixar o **SDK** codificar; **UUID** na chave |
| **Multipart: ETag nulo no JS** | **`ExposeHeaders: ETag`** no CORS |
| **Muitos 403 após endurecer policy** | `s3:signatureAge` curta demais vs. uploads longos → ajustar |
| **Redirect 307** | **Região/endpoint** corretos |

## 8. Checklist de troubleshooting

1. **Reproduzi com `curl -v -i`** e li o **XML de erro** (`Code`, `Message`, `RequestId`).
2. **Decodifiquei** a URL (host, região, data, expiração, `SignedHeaders`).
3. Conferi **relógio** (emissor e infraestrutura).
4. Conferi o **assinante**: identidade, sessão/token, **permissões**, KMS.
5. Conferi **bucket policy**/BPA/Ownership/endpoint policy/SCP.
6. Conferi **headers enviados × assinados** (Content-Type, metadados, SSE, checksum).
7. Conferi **host/região/endpoint**; **sem proxy** alterando.
8. Conferi **CORS** (origem, métodos, headers, `ExposeHeaders`).
9. Conferi **objeto existe** (e `s3:ListBucket` para **404** claro).
10. Correlacionei com **server access logs/CloudTrail** pelo **RequestId**.
11. Testei a **correção** em **ambiente de homologação** e **adicionei teste automatizado**.

## 9. Erros comuns de operação

- **Debugar só no navegador** (mascarando o erro real).
- **Ignorar o corpo XML**.
- **Alterar a URL** “para testar”.
- **Culpar o S3** sem checar **relógio/host/headers**.
- **Não habilitar logs** antes do incidente.
- **Não ter alarmes** de 4xx/DLQ/custos.
- **Confundir 403 de chave inexistente** com permissão.
- **Corrigir com `Allow *`** (abre segurança).
- **Não ter plano de revogação**.
- **Sem teste automatizado** da emissão + uso da URL.

## 10. Resumo rápido

- **Roteiro**: **curl** → **ler XML** → **decodificar URL** → **assinante** → **bucket/KMS** → **cliente/CORS** → **logs**.
- **`SignatureDoesNotMatch`**: headers/host/região/encoding divergentes — compare o **CanonicalRequest**.
- **`AccessDenied`**: assinante, **bucket policy**, **KMS**, ownership, **ListBucket** (403 em vez de 404).
- **`Request has expired`/`ExpiredToken`**: **relógio**, **`X-Amz-Expires`**, **sessão do assinante** — gerar **sob demanda**.
- **CORS**: **funciona no curl, falha no navegador**; configurar **origens, métodos, headers e `ExposeHeaders: ETag`**.
- **307/301**: **endpoint/região** — gerar para o **endpoint regional**.
- **Observabilidade**: **server access logs** (`QueryString`), **CloudTrail data events**, **request metrics**, alarmes de **4xx/DLQ/custo**.

## 🧩 Quiz de Fixação

1. Como saber se um erro é de CORS ou de assinatura?
2. O que comparar em um SignatureDoesNotMatch?
3. Por que um GET pode retornar 403 quando o objeto não existe?
4. O que causa “Request has expired” além do prazo vencido?
5. Por que o ETag não aparece no JavaScript durante multipart?
6. O que pode causar ExpiredToken mesmo com ExpiresIn longo?
7. Que fontes ajudam a auditar erros de presigned URLs?

**Respostas:**

1. Testar com curl: se funciona no curl e falha no navegador, é CORS; se falha em ambos, é assinatura/permissão.
2. O CanonicalRequest/StringToSign do servidor com o que foi assinado: headers, host, região, encoding e query string.
3. Porque sem s3:ListBucket o S3 devolve 403 em vez de 404 para não revelar a existência de objetos.
4. Relógio desajustado do emissor (data no futuro/passado), além de URLs envelhecidas em cache/fila.
5. Porque o bucket não expõe o header ETag no CORS; é preciso `ExposeHeaders: ["ETag"]`.
6. A credencial temporária do assinante (role/sessão) expirou antes do prazo pedido.
7. S3 server access logs (Authentication Type QueryString), CloudTrail data events, métricas de request do S3 e logs da API de emissão.
