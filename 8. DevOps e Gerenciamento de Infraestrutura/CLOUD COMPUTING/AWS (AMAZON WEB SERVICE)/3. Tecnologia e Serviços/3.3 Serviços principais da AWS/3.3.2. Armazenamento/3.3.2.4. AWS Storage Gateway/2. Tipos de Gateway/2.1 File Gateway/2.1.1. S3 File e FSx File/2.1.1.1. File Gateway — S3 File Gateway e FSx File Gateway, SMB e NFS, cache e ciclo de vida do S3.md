### File Gateway — S3 File Gateway e FSx File Gateway, SMB e NFS, cache e ciclo de vida do S3

> [!warning] Aviso
> Recursos, protocolos suportados, limites de objetos/arquivos e preços dos File Gateways mudam. Confirme na documentação. Os comandos **não foram executados**.

Os **File Gateways** entregam **compartilhamentos de arquivos** (NFS/SMB) com os dados na nuvem. Existem dois sabores: **S3 File Gateway** (arquivos viram objetos no S3) e **FSx File Gateway** (acesso local com cache a compartilhamentos do FSx for Windows File Server).

**Analogia:** o File Gateway é uma **pasta de rede no escritório** cujo conteúdo, na verdade, mora no armazém da AWS. O que você abriu recentemente fica na gaveta local para ser rápido.

## S3 File Gateway

```
 Cliente (NFS/SMB) ──► S3 File Gateway ──(HTTPS)──► Bucket S3
        arquivo /projetos/a.docx                      objeto  projetos/a.docx
                                (cache local de leitura e escrita)
```

| Característica | Detalhe |
|---|---|
| **Protocolos** | **NFS v3/v4.1** e **SMB** (v2/v3), inclusive autenticação com Active Directory |
| **Mapeamento** | **1 arquivo = 1 objeto S3** (nome do caminho = chave); metadados POSIX guardados como metadados do objeto |
| **Acesso nativo no S3** | Os objetos podem ser usados por Athena, EMR, Lambda, etc. (data lake) |
| **Classes S3** | Escolha da classe de armazenamento no share (Standard, IA, Intelligent-Tiering; Glacier com restrições) |
| **Cache** | Dados recentemente lidos/escritos ficam no disco local |
| **Escrita** | Gravada no cache local e enviada ao S3 de forma **assíncrona** |
| **Consistência** | Boa para um único escritor; **mudanças feitas direto no S3** exigem **atualização do cache** (`RefreshCache`) para aparecer |
| **Bloqueio de arquivos** | Suporte limitado a locks entre gateways diferentes; evite escrita concorrente do mesmo arquivo em gateways distintos |
| **Região/Bucket** | Um share mapeia a um bucket (e prefixo opcional) |

### Casos de uso

- **Backup de arquivos** de servidores e aplicações em S3 (via NFS/SMB).
- **Ingestão de dados** (logs, imagens, vídeo) de ambientes locais para um data lake no S3.
- **Compartilhamento de departamento** com expansão elástica.
- **Migração gradual** de NAS para nuvem.
- Fluxos em que uma aplicação gera arquivos localmente e **pipelines na AWS** processam os objetos.

### Atualização do cache e alterações diretas no S3

Se outro processo altera o bucket diretamente, o gateway pode não saber. Soluções:

```bash
# Atualizar o inventário do cache de um share (reflete objetos novos/alterados no bucket)
aws storagegateway refresh-cache --file-share-arn $SHARE_ARN \
  --folder-list "/projetos" --recursive
# Também é possível automatizar com EventBridge/Lambda ao detectar mudanças no bucket
```

### Criando um share SMB (resumo)

```bash
# NFS share (resumo; consulte a documentação para todos os parâmetros)
aws storagegateway create-nfs-file-share \
  --client-token tok-1 --gateway-arn $GW_ARN \
  --role arn:aws:iam::111122223333:role/sgw-acesso-s3 \
  --location-arn arn:aws:s3:::arquivos-escritorio \
  --default-storage-class S3_INTELLIGENT_TIERING \
  --client-list 10.0.0.0/16
# role: papel que permite ao gateway ler/gravar no bucket
# client-list: quais redes podem montar o share

# Montagem no cliente Linux (NFS)
sudo mount -t nfs -o nolock,hard $GATEWAY_IP:/arquivos-escritorio /mnt/gw
```

SMB: `create-smb-file-share`, com `Authentication=ActiveDirectory` ou `GuestAccess`. Evite guest em produção.

## Ciclo de vida do S3 e proteção dos dados

Como os dados são objetos no S3, ganha-se os recursos do S3:

| Recurso | Uso |
|---|---|
| **Lifecycle** | Mover arquivos antigos para IA/Glacier automaticamente |
| **Versionamento** | Recuperar versões anteriores/exclusões |
| **Replicação (CRR/SRR)** | DR em outra região/conta |
| **Object Lock** | Proteção contra exclusão (conformidade) |
| **Criptografia** | SSE-S3 ou SSE-KMS no share |
| **Eventos** | Acionar Lambda quando um arquivo chega |

Cuidado: objetos movidos para **Glacier Flexible/Deep Archive** não podem ser lidos pelo gateway até serem restaurados; planeje o lifecycle com isso em mente. Veja [[8. DevOps e Gerenciamento de Infraestrutura/CLOUD COMPUTING/AWS (AMAZON WEB SERVICE)/3. Tecnologia e Serviços/3.3 Serviços principais da AWS/3.3.2. Armazenamento/3.3.2.1. ## FSx File Gateway

Dá a usuários e aplicações locais **acesso SMB de baixa latência com cache** a compartilhamentos hospedados no **Amazon FSx for Windows File Server**.

```
 Escritório ──SMB──► FSx File Gateway (cache) ═══► Amazon FSx for Windows File Server (na AWS)
```

| Característica | Detalhe |
|---|---|
| **Protocolo** | SMB (ACLs NTFS, Active Directory) |
| **Dados** | Permanecem no FSx for Windows (não viram objetos S3) |
| **Vantagem** | Latência local para dados quentes; recursos do FSx (shadow copies, DFS, quotas) |
| **Uso** | Filiais acessando compartilhamentos centralizados na AWS; reduzir tráfego WAN |

Observação: a AWS vem evoluindo as opções para esse cenário (acesso direto ao FSx por Direct Connect/VPN, FSx para NetApp ONTAP, etc.); confirme o que a documentação indica hoje para novos projetos.

## S3 File Gateway × EFS × FSx × DataSync

| Critério | S3 File Gateway | EFS | FSx for Windows | DataSync |
|---|---|---|---|---|
| Local de acesso | On-premises (com cache) | Dentro da AWS (ou VPN) | AWS (ou via gateway) | Transferência, não acesso |
| Dados | Objetos S3 | Sistema de arquivos | NTFS/SMB | Copia entre origens e destinos |
| Quando | Estender NAS ao S3 | Linux em nuvem | Windows/AD em nuvem | Migração/sincronização |

## Exemplo prático

Um estúdio de vídeo grava arquivos em NFS local e quer processá-los na nuvem:

1. S3 File Gateway (VM no datacenter, 500 GB de cache em SSD).
2. Share NFS mapeado ao bucket `estudio-raw`, classe S3 Intelligent-Tiering, criptografia SSE-KMS.
3. Evento `s3:ObjectCreated` aciona Lambda/Step Functions para gerar proxies de vídeo.
4. Resultados voltam ao bucket e aparecem no share após `RefreshCache` automático (EventBridge).
5. Lifecycle arquiva material com mais de 1 ano para Glacier (fora do alcance do gateway até restaurar).

## Mapeamento arquivo ↔ objeto

```
 Cliente SMB/NFS:  /mnt/gw/financeiro/2026/relatorio.xlsx
 Objeto no S3:     s3://bucket/financeiro/2026/relatorio.xlsx     (1 arquivo = 1 objeto; pastas = prefixos)
 Metadados POSIX/ACL ficam como metadados do objeto (x-amz-meta-*) quando aplicável
 Escrita: cache local → upload assíncrono → objeto visível no S3 depois
```

| Característica | Detalhe |
|---|---|
| Atomicidade | Arquivos são enviados inteiros; não há "append" em objeto já enviado |
| Renomear pasta | Pode exigir copiar/apagar muitos objetos; custo e tempo crescem |
| Arquivos enormes | Enviados em partes (multipart); considere a banda |
| Consistência | Mudanças feitas direto no S3 só aparecem no gateway após **RefreshCache** |
| Bloqueio de arquivo | Locks valem localmente por gateway, não entre gateways |

> [!warning] Limites de arquivos por share, tamanhos máximos e comportamento de locks mudam; confirme na documentação atual.

## Padrões de uso

| Padrão | Como montar |
|---|---|
| Backup de aplicação para S3 | Share NFS com classe de armazenamento IA/Glacier IR |
| Data lake alimentado por equipamentos | Share SMB/NFS na LAN; ETL lê no S3 |
| Arquivo morto com acesso ocasional | Lifecycle S3 → Glacier; leituras de arquivados exigem restauração |
| Colaboração por filial | Um gateway por filial, mesmo bucket com prefixos distintos |

## Decisão rápida

| Se o requisito é... | Escolha |
|---|---|
| SMB para Windows com baixa latência local e dados no FSx | FSx File Gateway |
| Arquivos como objetos no S3 | S3 File Gateway |
| Migração única | DataSync |
| NFS elástico para cargas dentro da AWS | EFS |

## Troubleshooting

| Sintoma | Causa provável | Ação |
|---|---|---|
| Arquivo não aparece no S3 | Upload ainda pendente | Checar `CachePercentDirty` e fila |
| Arquivo novo no S3 não aparece no share | Cache desatualizado | RefreshCache |
| Acesso negado SMB | AD/ACL mal configurado | Revisar integração AD e permissões |
| Custos de requisição altos | Muitos arquivos pequenos | Agrupar arquivos, ajustar classe |

## Erros comuns e armadilhas

- **Escrever o mesmo arquivo em dois gateways:** conflito e sobrescrita.
- **Esquecer o `RefreshCache`** quando outros sistemas gravam direto no bucket.
- **Lifecycle para Glacier em dados que o gateway precisa ler.**
- **Grande quantidade de arquivos minúsculos:** custo de requisições S3 e latência.
- **Share SMB com acesso guest** em produção.
- **Role sem permissão no bucket/KMS:** o gateway falha ao gravar.
- **Cache pequeno + link lento:** esperas na leitura e fila de upload.
- **Renomear diretórios grandes:** vira cópia/exclusão em massa no S3 (S3 não renomeia).
- **Presumir que NFS/SMB têm semântica POSIX/NTFS completa** sobre o S3.

## 🧩 Quiz de Fixação

1. Como um arquivo do S3 File Gateway é representado no S3?
2. O que fazer quando outro sistema grava objetos direto no bucket e eles não aparecem no share?
3. Qual a diferença entre S3 File Gateway e FSx File Gateway quanto ao local dos dados?

**Respostas:**
1) Cada arquivo vira um objeto S3, com o caminho como chave e metadados POSIX como metadados do objeto.
2) Executar `RefreshCache` (manual ou automatizado via EventBridge/Lambda) para o gateway atualizar o inventário.
3) No S3 File Gateway os dados ficam como objetos no S3; no FSx File Gateway ficam no Amazon FSx for Windows File Server, com o gateway apenas fazendo cache local.

### Questões de aprofundamento

4. Um job gravou objetos direto no S3 e o share não os mostra. Por quê?
5. Por que renomear uma pasta grande pode ser lento e caro?
6. Quando preferir DataSync ao File Gateway?

**Respostas:**
4) O cache do gateway está desatualizado; execute RefreshCache (ou automatize com notificações/EventBridge).
5) No S3 pastas são prefixos; renomear implica copiar e apagar cada objeto.
6) Em migrações únicas ou transferências agendadas em massa, sem necessidade de acesso contínuo por protocolo de arquivos.
