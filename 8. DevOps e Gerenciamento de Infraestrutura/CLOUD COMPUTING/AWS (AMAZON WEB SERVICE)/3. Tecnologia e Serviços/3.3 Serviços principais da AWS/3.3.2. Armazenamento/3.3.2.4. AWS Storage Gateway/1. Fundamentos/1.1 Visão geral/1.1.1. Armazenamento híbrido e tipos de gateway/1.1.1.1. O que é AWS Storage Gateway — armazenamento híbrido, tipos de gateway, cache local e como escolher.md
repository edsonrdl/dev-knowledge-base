### O que é AWS Storage Gateway — armazenamento híbrido, tipos de gateway, cache local e como escolher

> [!warning] Aviso
> Tipos de gateway, protocolos, limites, formas de implantação e preços do Storage Gateway mudam (e alguns tipos são descontinuados com o tempo). Confirme na documentação. Os comandos **não foram executados**.

O **AWS Storage Gateway** é um serviço de **armazenamento híbrido**: um **gateway** (VM, appliance físico ou instância EC2) roda perto das suas aplicações e expõe protocolos que elas já conhecem (**NFS, SMB, iSCSI, fita virtual**), enquanto os dados ficam armazenados de forma durável na **AWS** (S3, FSx, EBS snapshots, Glacier). Com **cache local** para os dados quentes.

**Analogia:** é uma **agência dos correios no seu bairro** ligada ao centro de distribuição da AWS. Você entrega e retira encomendas (arquivos) na agência com os procedimentos de sempre; ela guarda as mais usadas na prateleira local (cache) e envia o resto ao depósito central (nuvem).

```
  Datacenter / escritório                                  AWS
 ┌───────────────────────────────┐   HTTPS / Direct Connect   ┌───────────────────────┐
 │ Aplicações ──NFS/SMB/iSCSI──► GATEWAY (cache local) ═══════►│ S3 · FSx · EBS snap.   │
 │ (servidores, backup, usuários)│                             │ Glacier (fitas)        │
 └───────────────────────────────┘                             └───────────────────────┘
```

---

## Por que usar

| Necessidade | Como o Storage Gateway ajuda |
|---|---|
| **Estender** o armazenamento on-premises para a nuvem sem reescrever aplicações | Protocolos padrão, dados na AWS |
| **Backup e arquivamento** em nuvem com a ferramenta de backup atual | Tape Gateway (biblioteca de fitas virtual) |
| **Acesso de baixa latência** a dados na nuvem a partir do local | Cache local |
| **Migração gradual** para a nuvem | Dados passam a existir no S3/FSx |
| **Recuperação de desastres** | Snapshots de volume, recuperação na AWS (EBS/EC2) |

---

## Os tipos de gateway

| Tipo | Protocolo para o cliente | Onde os dados ficam na AWS | Uso típico |
|---|---|---|---|
| **S3 File Gateway** | **NFS e SMB** | Objetos no **Amazon S3** (cada arquivo = objeto) | Compartilhamentos de arquivos, data lake, backup de arquivos, ingestão de dados |
| **FSx File Gateway** | **SMB** | **Amazon FSx for Windows File Server** | Acesso local com cache a compartilhamentos Windows na nuvem |
| **Volume Gateway** | **iSCSI** (blocos) | Volumes com snapshots no EBS/S3 | Discos para aplicações, DR com snapshots |
| **Tape Gateway** | **iSCSI VTL** (fitas virtuais) | S3 / S3 Glacier / Deep Archive | Substituir fitas físicas em software de backup (Veeam, Veritas, etc.) |

```
 Preciso de...
   compartilhamento de arquivos (NFS/SMB) com dados no S3? ─► S3 File Gateway
   compartilhamento SMB com FSx for Windows na nuvem?      ─► FSx File Gateway
   discos iSCSI (blocos) com backup/snapshots na nuvem?    ─► Volume Gateway
   substituir fitas físicas no software de backup?         ─► Tape Gateway
```

Detalhes: S3/FSx File Gateway e Volume/Tape Gateway nas próximas notas desta trilha.

---

## Componentes comuns

| Componente | Função |
|---|---|
| **Gateway** | A VM/appliance/instância que roda localmente (ou em EC2) |
| **Cache local** | Disco local que guarda dados recentes/frequentes e **buffer de upload** |
| **Upload buffer** | Área temporária para dados a caminho da AWS (Volume/Tape) |
| **Ativação** | Vincula o gateway à sua conta/região via chave de ativação |
| **Compartilhamento (file share)** | Exportação NFS/SMB mapeada a um bucket S3 ou FSx |
| **Conexão com a AWS** | Internet (HTTPS), Direct Connect ou **VPC endpoint** (PrivateLink) |

Onde pode ser executado: **VMware ESXi, Microsoft Hyper-V, Linux KVM**, **Hardware Appliance** (físico comprado da AWS), ou **instância EC2** (para acesso em nuvem, VMware Cloud on AWS ou DR).

---

## Quando não usar (e alternativas)

| Situação | Melhor ferramenta |
|---|---|
| **Migração única/agendada** de grandes volumes | **AWS DataSync** |
| Transferência por **SFTP/FTPS/FTP** | **AWS Transfer Family** |
| Compartilhamento de arquivos totalmente na nuvem (sem cache local) | **EFS** ou **FSx** diretamente |
| Aplicação já na AWS precisando de blocos | **EBS** |
| Muitos TB offline sem rede suficiente | **Snow Family** |

## Exemplo prático

Escritório com NAS antigo precisa de mais espaço sem comprar disco, e dos arquivos protegidos na nuvem.

1. Implantar um **S3 File Gateway** como VM VMware com 150 GB de disco de cache.
2. Ativar o gateway na região `sa-east-1` e criar um **file share SMB** apontando para o bucket `arquivos-escritorio`, com autenticação pelo Active Directory.
3. Usuários mapeiam a unidade `\\gateway\arquivos` e trabalham normalmente; arquivos recentes ficam em cache local, e tudo é gravado no S3.
4. No S3, **lifecycle** move arquivos antigos para classes mais baratas; versionamento e replicação protegem contra exclusão.

```bash
# Consultar gateways ativados na conta
aws storagegateway list-gateways \
  --query 'Gateways[].{Id:GatewayId,Nome:GatewayName,Tipo:GatewayType,Estado:GatewayOperationalState}'

# Listar compartilhamentos de arquivo
aws storagegateway list-file-shares
# A ativação e a criação de shares costumam ser feitas pelo console; a CLI cobre automação
```

## Os quatro tipos de gateway em comparação

| Critério | **S3 File Gateway** | **FSx File Gateway** | **Volume Gateway** | **Tape Gateway** |
|---|---|---|---|---|
| Protocolo local | NFS, SMB | SMB | iSCSI | iSCSI VTL |
| Destino na AWS | Objetos no S3 | Sistema FSx for Windows | Snapshots no EBS/S3 | Fitas virtuais no S3/Glacier |
| Cache local | Sim (dados recentes) | Sim | Cached ou Stored | Cache de leitura/upload |
| Uso típico | Backup, arquivos e data lake | Compartilhamentos Windows com baixa latência local | Blocos para apps e DR | Substituir biblioteca de fitas |
| Integração com AD | Sim (SMB) | Sim | Não se aplica | Não se aplica |
| Dados acessíveis nativamente na AWS | Sim, como objetos | Sim, no FSx | Via snapshots/volumes EBS | Via software de backup |

> [!warning] Disponibilidade de tipos (principalmente FSx File Gateway) e limites mudam; confirme na documentação atual.

## Arquitetura de referência

```
 Datacenter                                         AWS
 ┌──────────────┐   NFS/SMB/iSCSI   ┌─────────────────────┐   HTTPS (TLS)   ┌──────────────┐
 │ Servidores   │ ────────────────► │ Gateway (VM/HW/EC2) │ ──────────────► │ S3 / EBS /   │
 │ e aplicações │ ◄──────────────── │  cache local (disco)│ ◄────────────── │ Glacier / FSx│
 └──────────────┘   baixa latência  └─────────────────────┘  VPN / DX / PIV └──────────────┘
```

### Cache e consistência

```
 Leitura:  acerto no cache local ──► latência de LAN
           falta (miss) ──► busca na AWS, devolve e guarda no cache
 Escrita:  grava no cache local ──► confirma ao cliente ──► envia assíncrono à AWS
           (por isso o disco de cache e de upload precisa ser dimensionado e protegido)
```

---

## Dimensionamento e implantação

| Item | Recomendação prática |
|---|---|
| Disco de **cache** | Pelo menos o tamanho do conjunto de trabalho acessado com frequência; SSD/NVMe melhora latência |
| Disco de **upload buffer** (volume/tape) | Dimensione para absorver picos de escrita enquanto a banda de saída drena |
| Rede | Banda de saída ≥ taxa média de mudança de dados; considere Direct Connect para volume alto |
| Onde rodar | VM (VMware, Hyper-V, KVM), appliance de hardware ou **EC2** (para acesso a partir da nuvem) |
| Ativação | Gateway ativado na região via IP/porta; endpoint público ou **VPC endpoint** |
| Monitoramento | Métricas `CachePercentDirty`, `CacheHitPercent`, `UploadBufferPercentUsed` no CloudWatch |

### Exemplo de CLI (comentado, não executado)

```bash
# Criar um compartilhamento NFS em um File Gateway já ativado
aws storagegateway create-nfs-file-share \
  --client-token $(uuidgen) \
  --gateway-arn <ARN-do-gateway> \
  --role <ARN-da-role-com-acesso-ao-bucket> \
  --location-arn arn:aws:s3:::meu-bucket-backup \
  --default-storage-class S3_STANDARD_IA \
  --client-list 10.0.0.0/16
# Montagem no cliente Linux: mount -t nfs -o nolock,hard <ip-do-gateway>:/meu-bucket-backup /mnt/s3
```

## Quando escolher o Storage Gateway (e quando não)

| Cenário | Decisão |
|---|---|
| Aplicação on-premises precisa usar S3 sem reescrever código | **File Gateway** |
| Backup para a nuvem com software que fala iSCSI VTL | **Tape Gateway** |
| Migração única e grande de arquivos | **DataSync** (Storage Gateway é para acesso contínuo) |
| Aplicação já na AWS que precisa de NFS | **EFS**/FSx, não o gateway |
| Latência de LAN para dados que moram na nuvem | Gateway com cache (esta aula) |

## Custo e operação

- Cobrança por gateway/mês mais transferência e armazenamento nos serviços de destino (S3, EBS, Glacier).
- Dados que entram na AWS não pagam transferência de entrada; leituras de volta pagam saída.
- Atualize o software do gateway em janela de manutenção; mantenha o relógio sincronizado (NTP) para evitar falhas de ativação.

---

## Erros comuns e armadilhas

- **Subdimensionar o cache:** leituras vão à nuvem, com latência maior; dimensione para o conjunto de trabalho.
- **Link de rede insuficiente:** o upload fica atrasado; o gateway pode acumular dados no buffer.
- **Escolher o tipo errado** (ex.: Volume Gateway quando precisa de NFS).
- **Acesso direto ao bucket e ao gateway sem coordenação:** o gateway pode não refletir mudanças imediatas feitas direto no S3 (existe atualização do cache sob demanda).
- **Esquecer a rede/DNS e o relógio (NTP)** da VM: ativação ou autenticação falham.
- **Usar Storage Gateway para migração em massa única:** DataSync é mais indicado.
- **Não planejar a recuperação:** ter o gateway não é backup do próprio gateway; proteja dados (S3 versionamento) e a configuração.

## 🧩 Quiz de Fixação

1. Que problema o Storage Gateway resolve e qual o papel do cache local?
2. Qual tipo de gateway usar para substituir fitas físicas em um software de backup?
3. Quando preferir DataSync ao Storage Gateway?

**Respostas:**
1) Conecta aplicações on-premises a armazenamento na AWS usando protocolos conhecidos (NFS, SMB, iSCSI, fita). O cache local mantém os dados recentes/frequentes perto da aplicação, reduzindo latência e tráfego.
2) O **Tape Gateway** (biblioteca de fitas virtual iSCSI VTL), com dados em S3 e Glacier.
3) Para migração ou sincronização de grandes volumes, única ou agendada, entre sistemas de armazenamento; o Storage Gateway serve para acesso contínuo híbrido.

### Questões de aprofundamento

4. Qual gateway usar para trocar uma biblioteca de fitas física sem mudar o software de backup?
5. O que significa `CachePercentDirty` alto e como tratar?
6. Por que o Storage Gateway não é a melhor ferramenta para uma migração única de 200 TB?

**Respostas:**
4) **Tape Gateway**: apresenta uma biblioteca de fitas virtual por iSCSI VTL; as fitas ficam no S3/Glacier.
5) Muitos dados escritos ainda não foram enviados à AWS: a banda de saída é insuficiente ou há um pico. Aumente a banda (Direct Connect), reduza a escrita ou dimensione o buffer; monitore para não esgotar o cache.
6) Ele serve para acesso contínuo e híbrido, limitado pela banda do gateway; para migração em massa usam-se DataSync ou a Snow Family.
