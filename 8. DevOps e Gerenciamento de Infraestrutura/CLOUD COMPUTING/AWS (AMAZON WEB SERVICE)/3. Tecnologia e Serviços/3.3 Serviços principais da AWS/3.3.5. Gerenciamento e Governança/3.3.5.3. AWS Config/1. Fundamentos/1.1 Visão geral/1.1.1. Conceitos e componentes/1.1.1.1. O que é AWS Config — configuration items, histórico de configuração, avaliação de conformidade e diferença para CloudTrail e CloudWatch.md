### O que é AWS Config — configuration items, histórico de configuração, avaliação de conformidade e diferença para CloudTrail e CloudWatch

> [!warning] Aviso
> Tipos de recurso suportados, preços, limites, nomes de regras gerenciadas e funcionalidades mudam. Os números aqui são referências de estudo; confirme na documentação oficial. Os comandos de CLI são exemplos e **não foram executados**.

O **AWS Config** é o serviço que **registra e avalia a configuração** dos recursos AWS da sua conta. Ele responde a perguntas como: **"como este recurso está configurado agora?"**, **"como estava na terça-feira passada?"**, **"o que mudou entre ontem e hoje?"** e **"este recurso está em conformidade com a política da empresa?"**. Em vez de olhar *o que foi feito* (CloudTrail) ou *como está o desempenho* (CloudWatch), o Config olha o **estado da configuração ao longo do tempo**.

**Analogia:** o Config é o **inventário fotográfico de um prédio**. Todo dia alguém fotografa cada sala e anota como ela está (móveis, portas, trancas). Se algo mudar, há uma nova foto e uma comparação com a anterior. Além disso, uma **lista de regras** (ex.: "toda sala de servidores deve ter porta trancada") é checada contra as fotos, e cada sala recebe o selo **conforme** ou **não conforme**.

---

## O que o Config faz

| Capacidade | Descrição |
|---|---|
| **Inventário** | Lista os recursos existentes na conta/região e suas propriedades |
| **Histórico de configuração** | Guarda cada versão da configuração de cada recurso |
| **Linha do tempo de mudanças** | Mostra *o que* mudou entre duas versões |
| **Avaliação de conformidade** | Compara a configuração com **regras** (config rules) |
| **Notificação e automação** | Avisa e **remedia** recursos fora de conformidade |
| **Relacionamentos** | Mostra dependências (instância ↔ security group ↔ VPC) |
| **Consulta SQL** | *Advanced queries* sobre o inventário atual |
| **Visão multi-conta** | *Aggregators* consolidam várias contas e regiões |

## Conceitos centrais

```
 Recurso (EC2, SG, S3, IAM...)
        │ muda
        ▼
 ┌────────────────────┐
 │ Configuration      │  ← Configuration Recorder grava
 │ Item (CI)          │
 └─────────┬──────────┘
           │
   ┌───────┼──────────────────────────┐
   ▼       ▼                          ▼
 Histórico  Delivery channel        Config Rules
 (timeline) (S3 / SNS)              (avaliam o CI)
                                       │
                                       ▼
                              COMPLIANT / NON_COMPLIANT
                                       │
                                       ▼
                       Remediação (SSM) / Notificação (EventBridge)
```

| Conceito | O que é |
|---|---|
| **Configuration item (CI)** | "Foto" da configuração de um recurso em um instante: atributos, relacionamentos, metadados |
| **Configuration recorder** | Componente que **detecta mudanças** e grava os CIs |
| **Configuration history** | Sequência de CIs de um recurso; arquivos entregues ao S3 |
| **Configuration snapshot** | Foto do **conjunto** de recursos em um momento |
| **Delivery channel** | Onde entregar histórico/snapshots (S3) e notificações (SNS) |
| **Config rule** | Regra que avalia se o recurso atende a um critério |
| **Compliance** | Resultado da avaliação: `COMPLIANT`, `NON_COMPLIANT`, `NOT_APPLICABLE`, `INSUFFICIENT_DATA` |
| **Conformance pack** | Conjunto de regras e remediações implantado como unidade |
| **Aggregator** | Visão consolidada de várias contas/regiões |

### Exemplo de configuration item (resumido)

```json
{
  "configurationItemStatus": "OK",
  "resourceType": "AWS::EC2::SecurityGroup",
  "resourceId": "sg-0123456789abcdef0",
  "awsRegion": "us-east-1",
  "configurationItemCaptureTime": "2026-11-09T12:00:00Z",
  "configuration": {
    "groupName": "web-sg",
    "ipPermissions": [
      {"fromPort": 22, "toPort": 22, "ipRanges": [{"cidrIp": "0.0.0.0/0"}]}
    ]
  },
  "relationships": [{"resourceType": "AWS::EC2::VPC", "resourceId": "vpc-0abc"}],
  "tags": {"Ambiente": "producao"}
}
```

Esse CI mostraria, para uma regra de "SSH não pode ficar aberto ao mundo", um recurso **NON_COMPLIANT**.

## Config vs CloudTrail vs CloudWatch

| Serviço | Foco | Pergunta típica |
|---|---|---|
| **AWS Config** | **Estado/configuração** dos recursos ao longo do tempo | "Como estava o security group ontem? Está conforme?" |
| **CloudTrail** | **Quem fez qual chamada de API** | "Quem abriu a porta 22?" |
| **CloudWatch** | **Desempenho, saúde e logs** | "A CPU está alta? Há erros?" |

```
 Security group ficou aberto ao mundo
   Config     → "sg-123 está NON_COMPLIANT desde as 10:03; antes só aceitava 10.0.0.0/8"
   CloudTrail → "O usuário maria executou AuthorizeSecurityGroupIngress às 10:03 do IP X"
   CloudWatch → "Houve pico de tráfego na porta 22 às 10:20"
```

Os três **se complementam** em uma investigação: o Config mostra **o que mudou e o impacto na conformidade**, o CloudTrail mostra **quem**, o CloudWatch mostra **o efeito observável**.

## Como a avaliação funciona

| Etapa | O que acontece |
|---|---|
| 1. Mudança | Um recurso é criado/alterado |
| 2. Gravação | O recorder gera um novo **CI** |
| 3. Disparo | Uma regra **acionada por mudança** avalia o CI; regras **periódicas** rodam no intervalo configurado |
| 4. Resultado | O recurso fica `COMPLIANT` ou `NON_COMPLIANT` |
| 5. Reação | Evento ao **EventBridge**; notificação **SNS**; **remediação** automática (SSM Automation) |

> [!tip] Config avalia, não bloqueia
> O Config é **detetivo**: ele **detecta** e **corrige depois** (remediação). Para **impedir** a criação de recursos fora da política use controles **preventivos**: **SCPs**, **IAM**, **permission boundaries** e **CloudFormation Guard/hooks**.

## Primeiros comandos

```bash
# Liga a gravação (cria recorder e canal de entrega devem existir)
aws configservice start-configuration-recorder --configuration-recorder-name default

# Histórico de configuração de um recurso
aws configservice get-resource-config-history \
  --resource-type AWS::EC2::SecurityGroup --resource-id sg-0123456789abcdef0

# Quais recursos estão fora de conformidade para uma regra
aws configservice get-compliance-details-by-config-rule \
  --config-rule-name restricted-ssh --compliance-types NON_COMPLIANT

# Inventário por SQL (advanced query)
aws configservice select-resource-config --expression \
  "SELECT resourceId, configuration.instanceType WHERE resourceType = 'AWS::EC2::Instance'"
```

## Casos de uso

| Caso | Como o Config ajuda |
|---|---|
| **Auditoria e conformidade** | Evidência do estado e do histórico; relatórios por norma (CIS, PCI, ISO) |
| **Inventário de ativos** | Lista de recursos com propriedades e tags |
| **Análise de impacto** | "Se eu mudar este security group, quem é afetado?" (relacionamentos) |
| **Investigação de incidentes** | Comparar a configuração antes e depois |
| **Detecção de desvio (drift)** | Recursos que divergem do padrão esperado |
| **Governança de custo** | Achar volumes não anexados, IPs ociosos, instâncias grandes |
| **Segurança** | Buckets públicos, discos sem criptografia, usuários sem MFA |

## Escopo: regional e por recurso

O AWS Config é **regional**: o recorder, as regras e os dados de cada região são **independentes**. Para **cobrir toda a organização** é preciso habilitar o Config em **cada região e conta** (o **Control Tower**, o **Organizations** e **conformance packs/aggregators** ajudam). **Recursos globais** (como IAM) são registrados em uma região principal ou conforme a configuração do recorder.

| Aspecto | Observação |
|---|---|
| Regional | Habilitar em cada região usada (e vigiar as não usadas) |
| Recursos globais | IAM e similares: configurar onde registrá-los |
| Tipos suportados | Muitos serviços, mas **nem todos**; consulte a lista atual |
| Retenção do histórico | Gravada no S3 (você define o ciclo de vida) |

## Linha do tempo de um recurso

Cada mudança gera um novo CI, e a sequência forma a **linha do tempo** do recurso. Isso permite comparar versões e entender a evolução.

```
 sg-web — linha do tempo
 ───────────────────────────────────────────────────────────────►
  08:00 CI#1: porta 443 aberta a 0.0.0.0/0, porta 22 a 10.0.0.0/8   (COMPLIANT)
  10:03 CI#2: porta 22 aberta a 0.0.0.0/0                             (NON_COMPLIANT)
  10:41 CI#3: porta 22 volta a 10.0.0.0/8 (remediação)                (COMPLIANT)
```

| Pergunta de auditoria | Como o Config responde |
|---|---|
| "Quanto tempo o recurso ficou fora da política?" | Diferença entre CI#2 e CI#3 (38 minutos) |
| "O que exatamente mudou?" | Comparação campo a campo entre CIs |
| "Em 1º de outubro, qual era a configuração?" | CI vigente naquela data |

## Modelo mental: quatro perguntas, quatro serviços

| Pergunta | Serviço |
|---|---|
| **Quem** fez? | CloudTrail |
| **O que mudou** na configuração? | **AWS Config** |
| **Está dentro da política?** | **AWS Config (regras)** |
| **Como está o desempenho?** | CloudWatch |

---

> [!tip] Regra de bolso para provas e entrevistas
> Se a pergunta fala em **"histórico de configuração"**, **"conformidade"** ou **"drift"**, a resposta é **AWS Config**. Se fala em **"quem executou"** ou **"auditoria de API"**, é **CloudTrail**. Se fala em **"métricas, alarmes e logs"**, é **CloudWatch**.

## Exemplo prático: bucket público

1. A regra gerenciada `s3-bucket-public-read-prohibited` está ativa.
2. Um desenvolvedor torna o bucket `relatorios` público para um teste.
3. O recorder grava o novo CI; a regra marca o bucket como **NON_COMPLIANT** em poucos minutos.
4. O **EventBridge** dispara um aviso ao canal de segurança.
5. Uma **remediação automática** (SSM Automation) reativa o *Block Public Access*.
6. O **CloudTrail** informa quem fez a mudança e de onde; o histórico do Config mostra a configuração antes e depois.

## Erros comuns e armadilhas

- **Achar que o Config registra "quem fez"**: isso é do CloudTrail.
- **Esperar que o Config impeça** a criação de recursos fora da regra (ele é detetivo).
- **Habilitar só em uma região** e deixar as demais sem visibilidade.
- **Gravar todos os recursos de todas as regiões** sem avaliar custo.
- **Ligar regras sem plano de tratamento** do que está `NON_COMPLIANT`.
- **Esquecer o bucket de entrega** (permissões ou ciclo de vida).
- **Confundir regras periódicas e acionadas por mudança.**
- **Não tratar recursos globais** (IAM) na configuração do recorder.

## 🧩 Quiz de Fixação

1. O que é um configuration item?
2. Qual a diferença entre Config e CloudTrail?
3. O que a regra do Config faz com um recurso?
4. O Config bloqueia a criação de recursos fora da política?
5. O que faz o configuration recorder?
6. O Config é regional ou global?

**Respostas:**
1) Uma "foto" da configuração de um recurso em um instante, com atributos, relacionamentos e metadados.
2) O Config registra e avalia o estado/configuração ao longo do tempo; o CloudTrail registra quem fez cada chamada de API.
3) Avalia a configuração e a classifica como COMPLIANT, NON_COMPLIANT, NOT_APPLICABLE ou INSUFFICIENT_DATA.
4) Não; ele é detetivo e pode remediar depois. Para prevenir usam-se SCPs, IAM e controles preventivos.
5) Detecta mudanças nos recursos e grava os configuration items.
6) Regional: cada região tem recorder, regras e dados próprios, sendo preciso habilitar em cada uma.
