### Gravação no AWS Config — configuration recorder, escopo de recursos, delivery channel, snapshots, advanced queries e custo por item

> [!warning] Aviso
> Modos de gravação, preços por configuration item, limites de recursos e opções de entrega mudam. Os números aqui são referências de estudo; confirme na documentação. Os comandos **não foram executados**.

Tudo no AWS Config começa pela **gravação**: sem um **configuration recorder** ligado, não há histórico, nem avaliação, nem inventário. Esta folha cobre como o recorder funciona, **que recursos gravar**, para **onde entregar** os dados (S3, SNS), como tirar **snapshots** do inventário e como **consultar** a configuração atual com SQL, além do ponto que mais pesa no bolso: o **custo por configuration item**.

**Analogia:** o recorder é o **fotógrafo do inventário**. Você decide **quais salas fotografar** (escopo), **quando** (a cada mudança ou por rotina diária) e **onde guardar os álbuns** (delivery channel). Cada foto tem um custo; fotografar tudo, o tempo todo, sai caro.

---

## Configuration recorder

| Aspecto | Detalhe |
|---|---|
| Quantidade | **Um recorder por região por conta** |
| Função | Detecta mudanças nos recursos e cria **configuration items** |
| Estado | Pode ser iniciado (`start`) e parado (`stop`) |
| Perfil IAM | Usa uma **role** (service-linked role do Config) para ler os recursos |
| Escopo | Todos os recursos suportados **ou** tipos selecionados |

```bash
# Cria o recorder (grava tudo, incluindo recursos globais)
aws configservice put-configuration-recorder --configuration-recorder '{
  "name": "default",
  "roleARN": "arn:aws:iam::123456789012:role/aws-service-role/config.amazonaws.com/AWSServiceRoleForConfig",
  "recordingGroup": {
    "allSupported": true,
    "includeGlobalResourceTypes": true
  }
}'

aws configservice start-configuration-recorder --configuration-recorder-name default
aws configservice describe-configuration-recorder-status
```

---

## O que gravar: escopo do recording group

| Opção | Efeito | Quando usar |
|---|---|---|
| **`allSupported: true`** | Todos os tipos suportados, inclusive novos | Visibilidade máxima; atenção ao custo |
| **Tipos específicos** | Só os tipos listados (ex.: EC2, S3, IAM, RDS) | Controlar custo; foco em risco |
| **Excluir tipos** (exclusion by resource type) | Tudo **menos** os tipos listados | Evitar tipos ruidosos de alta rotatividade |
| **`includeGlobalResourceTypes`** | Inclui IAM e outros globais | Habilite em **uma** região (evita duplicidade) |

> [!tip] Recursos globais em uma região só
> IAM (usuários, roles, políticas) é global. Se o recorder de **todas** as regiões gravar recursos globais, você paga o **mesmo recurso várias vezes**. Habilite `includeGlobalResourceTypes` apenas na **região principal**.

### Frequência de gravação

| Modo | Comportamento | Custo |
|---|---|---|
| **Contínuo** | Um CI a **cada mudança** | Maior; histórico completo |
| **Diário** | No máximo **um CI por dia** por recurso (se houver mudança) | Menor; perde mudanças intermediárias |

O modo **diário** serve para tipos que mudam muito e cujo histórico fino não importa (por exemplo, certos recursos de rede ou instâncias muito dinâmicas). Pode ser definido **por tipo de recurso** com *recording strategy* de substituição.

## Delivery channel: para onde vão os dados

```
 Recorder ──► CI ──► Delivery channel ──┬──► S3 (histórico e snapshots)
                                        └──► SNS (notificações de mudança/conformidade)
```

| Destino | Conteúdo |
|---|---|
| **Bucket S3** | Arquivos de **histórico de configuração** (por recurso e dia) e **snapshots** |
| **Tópico SNS** (opcional) | Notificações de mudança e avaliação |
| **Prefixo S3** | Organiza os dados por conta/região |
| **Frequência do snapshot** | De 1 hora a 24 horas |

```bash
aws configservice put-delivery-channel --delivery-channel '{
  "name": "default",
  "s3BucketName": "meu-bucket-config",
  "s3KeyPrefix": "config",
  "snsTopicARN": "arn:aws:sns:us-east-1:123456789012:config-notificacoes",
  "configSnapshotDeliveryProperties": {"deliveryFrequency": "TwentyFour_Hours"}
}'
```

O bucket precisa de uma **política** permitindo ao serviço `config.amazonaws.com` gravar objetos e ler a ACL. Em organizações, usa-se um **bucket central** em conta de **log archive**, com **Object Lock**, versionamento, criptografia e ciclo de vida.

> [!warning] Sem política de bucket correta, o delivery channel falha
> O sintoma é o recorder "ligado", mas **sem entrega** (`lastStatus: Failure`). Verifique `describe-delivery-channel-status`.

## Snapshots e histórico

| Item | O que é | Uso |
|---|---|---|
| **Configuration history** | Arquivo por recurso e período com as mudanças | Linha do tempo e auditoria |
| **Configuration snapshot** | Foto **completa** dos recursos num momento | Inventário "em um ponto no tempo", comparações |

```bash
# Pede um snapshot sob demanda
aws configservice deliver-config-snapshot --delivery-channel-name default

# Lê o histórico de um recurso (CIs em ordem)
aws configservice get-resource-config-history \
  --resource-type AWS::EC2::Instance --resource-id i-0123456789abcdef0 \
  --limit 5
```

O histórico fica em **S3**; para consultas em larga escala, combine com **Athena** (tabelas sobre os arquivos do Config).

## Advanced queries (SQL sobre o inventário atual)

O Config permite consultar o **estado atual** dos recursos com uma sintaxe tipo SQL, sem montar infraestrutura.

```sql
-- Instâncias EC2 por tipo
SELECT resourceId, configuration.instanceType, availabilityZone
WHERE resourceType = 'AWS::EC2::Instance'

-- Volumes EBS sem criptografia
SELECT resourceId, configuration.size
WHERE resourceType = 'AWS::EC2::Volume'
  AND configuration.encrypted = false

-- Buckets sem tag de dono
SELECT resourceId, tags
WHERE resourceType = 'AWS::S3::Bucket'
  AND NOT tags.tag LIKE 'Dono%'

-- Contagem de recursos por tipo
SELECT resourceType, COUNT(*)
GROUP BY resourceType
ORDER BY COUNT(*) DESC
```

| Característica | Detalhe |
|---|---|
| Escopo | Estado **atual** (não o histórico completo) |
| Multi-conta | Com **aggregator**, consulta toda a organização |
| Uso | Inventário, caça a riscos, relatórios rápidos |
| Limite | Sintaxe restrita (sem *joins* complexos) |

> [!tip] Inventário de graça para perguntas de rotina
> Perguntas como "onde estão todos os volumes sem criptografia?" ou "quantas instâncias de cada tipo temos?" se respondem em segundos com advanced queries, sem Athena nem planilhas.

## Relacionamentos entre recursos

O Config registra **relacionamentos**: instância ↔ volume, security group ↔ VPC, role ↔ políticas. Isso permite **análise de impacto**.

```
 sg-web ──associado a──► i-aaa, i-bbb (instâncias)
        └──pertence a──► vpc-0abc
```

```bash
aws configservice get-resource-config-history --resource-type AWS::EC2::SecurityGroup \
  --resource-id sg-web --query 'configurationItems[0].relationships'
```

Útil para responder "se eu alterar este security group, quais instâncias são afetadas?" antes de uma mudança.

## Custo: o fator decisivo

| Componente | Como é cobrado (referência) |
|---|---|
| **Configuration items gravados** | Por CI (cada mudança em cada recurso gravado) |
| **Gravação contínua vs diária** | Diária é mais barata (menos CIs) |
| **Avaliações de regras** | Por avaliação (por recurso por regra) |
| **Conformance packs** | Por avaliação de regra do pack |
| **Advanced queries** | Sem custo adicional (consulte a política atual) |
| **S3, SNS** | Pelo uso desses serviços |

```
 custo de gravação ≈ nº de recursos gravados × mudanças por recurso × preço por CI
```

### Alavancas de otimização

| Alavanca | Efeito |
|---|---|
| Gravar **tipos relevantes** em vez de tudo | Menos CIs |
| **Modo diário** para tipos de alta rotatividade | Menos CIs |
| Excluir tipos ruidosos (ex.: certos recursos temporários) | Menos ruído e custo |
| Recursos globais em **uma região** | Evita duplicação |
| **Não habilitar** regiões não utilizadas (ou bloquear por SCP) | Menos custo e superfície |
| Revisar regras duplicadas | Menos avaliações |
| Ciclo de vida no S3 | Menos armazenamento |

> [!warning] Alta rotatividade explode o custo
> Ambientes com **muitos recursos efêmeros** (instâncias de Auto Scaling, tarefas, ENIs, snapshots) geram um fluxo enorme de CIs. Estime o volume e use modo diário ou exclusões para tipos de baixo valor.

## Exemplo prático: configuração inicial enxuta

1. Região principal: recorder **contínuo** com recursos globais (IAM) e tipos de risco (EC2, SG, S3, RDS, KMS, VPC).
2. Demais regiões: recorder com os mesmos tipos, **sem** recursos globais.
3. Tipos de alta rotatividade (ENIs, snapshots) em **modo diário** ou excluídos.
4. Delivery channel para o **bucket central** (Object Lock, KMS, ciclo de vida de 1 ano).
5. Aggregator na conta de segurança para visão consolidada.
6. Painel de custo: acompanhar CIs/dia e avaliações/dia.

## Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| Recorder "ligado" sem dados | Delivery channel com falha | `describe-delivery-channel-status`; ajustar política do bucket |
| Recursos ausentes no inventário | Tipo não gravado ou não suportado | Revisar `recordingGroup` |
| IAM duplicado em várias regiões | `includeGlobalResourceTypes` em todas | Manter só na região principal |
| Custo alto de CIs | Gravação contínua de tipos efêmeros | Modo diário/exclusões |
| Advanced query vazia | Tipo não gravado ou nome de campo incorreto | Verificar o schema do recurso |
| Snapshot não chega | Falta permissão no bucket | Corrigir política e KMS |
| Região sem cobertura | Config não habilitado ali | Habilitar ou usar StackSet/Organizations |

## Erros comuns e armadilhas

- **Gravar tudo em todas as regiões** sem estimar o volume de CIs.
- **Recursos globais gravados em cada região** (cobrança duplicada).
- **Esquecer a política do bucket de entrega.**
- **Não habilitar regiões sem uso** e permitir atividade invisível.
- **Confundir snapshot com histórico**: o snapshot é uma foto; o histórico é a linha do tempo.
- **Usar advanced queries esperando histórico** (elas consultam o estado atual).
- **Sem ciclo de vida no S3**, acumulando histórico caro.
- **Parar o recorder sem perceber**, interrompendo auditoria e regras.

## 🧩 Quiz de Fixação

1. Quantos configuration recorders existem por região?
2. Para onde o delivery channel entrega os dados?
3. Qual a diferença entre gravação contínua e diária?
4. Por que habilitar recursos globais em uma única região?
5. Para que servem as advanced queries?
6. O que mais influencia o custo da gravação?

**Respostas:**
1) Um por região, por conta.
2) Para um bucket S3 (histórico e snapshots) e, opcionalmente, para um tópico SNS (notificações).
3) A contínua cria um CI a cada mudança; a diária cria no máximo um CI por dia por recurso, reduzindo custo e granularidade.
4) Para evitar gravar e pagar o mesmo recurso global (como IAM) várias vezes.
5) Consultar o estado atual dos recursos com SQL, para inventário e identificação de riscos, inclusive multi-conta com aggregator.
6) O número de configuration items gravados, que depende da quantidade de recursos e da frequência de mudança.
