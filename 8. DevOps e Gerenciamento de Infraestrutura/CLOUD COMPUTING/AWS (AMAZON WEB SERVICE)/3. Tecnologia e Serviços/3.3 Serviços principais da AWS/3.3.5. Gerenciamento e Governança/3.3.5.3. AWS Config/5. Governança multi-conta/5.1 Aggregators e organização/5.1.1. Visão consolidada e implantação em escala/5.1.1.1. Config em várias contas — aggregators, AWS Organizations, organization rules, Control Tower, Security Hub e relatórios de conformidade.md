### Config em várias contas — aggregators, AWS Organizations, organization rules, Control Tower, Security Hub e relatórios de conformidade

> [!warning] Aviso
> Funcionalidades de integração com Organizations, Control Tower e Security Hub, limites de contas, preços e nomes de recursos mudam. Os detalhes aqui são referências de estudo; confirme na documentação. Os comandos **não foram executados**.

Em uma empresa real não existe uma conta e uma região: existem **dezenas ou centenas de contas** em **várias regiões**. O AWS Config é regional e por conta; sozinho, cada um deixaria o time de segurança sem visão global. As ferramentas desta folha resolvem isso: **aggregators** (consolidação de dados), **AWS Organizations** (implantação centralizada), **organization rules e conformance packs** (políticas em escala) e integrações com **Control Tower** e **Security Hub** para governança e relatórios.

**Analogia:** é uma **rede de franquias**. Cada loja (conta) tem seu próprio inventário e fiscal (Config local). A matriz (conta de segurança) precisa de um **painel único** com a conformidade de todas as lojas (aggregator) e de um **manual de padrões obrigatório** aplicado a todas (organization conformance pack), sem depender de cada gerente configurar tudo à mão.

## Arquitetura recomendada

```
 ┌──────────────────────────────────────────────────────────────┐
 │  AWS Organizations                                           │
 │                                                              │
 │  Management ──► habilita acesso confiável do Config          │
 │      │          delega administração ──► Conta de Segurança  │
 │      │                                                       │
 │  Contas-membro (várias regiões)                              │
 │   ├─ Config recorder + regras (via org conformance packs)    │
 │   └─ dados ─────────┐                                        │
 │                     ▼                                        │
 │          Aggregator (Conta de Segurança)                     │
 │          visão única: inventário + conformidade              │
 │                     │                                        │
 │                     ▼                                        │
 │      Dashboards, advanced queries, Security Hub, relatórios  │
 └──────────────────────────────────────────────────────────────┘
```

| Peça | Papel |
|---|---|
| **Conta de gerenciamento** | Habilita acesso confiável e delega administração; uso mínimo |
| **Conta de segurança/auditoria** | **Administrador delegado**: aggregator, regras, relatórios |
| **Contas-membro** | Executam o recorder e as regras |
| **Bucket central** | Recebe histórico e snapshots (conta de log archive) |

## Aggregators

Um **aggregator** **coleta dados de configuração e conformidade** de **várias contas e regiões** em **um só lugar**, **sem mover o recorder**: as contas de origem continuam gravando; o aggregator apenas **consolida a visão**.

| Aspecto | Detalhe |
|---|---|
| **Fontes** | Contas individuais **ou toda a organização** |
| **Regiões** | Todas ou uma lista |
| **Dados** | Inventário (configuration items) e resultados de conformidade |
| **Somente leitura** | Não altera os recursos nem as regras de origem |
| **Autorização** | Com Organizations, automática; sem Organizations, cada conta **autoriza** o aggregator |

```bash
# Aggregator da organização (na conta de segurança/administrador delegado)
aws configservice put-configuration-aggregator \
  --configuration-aggregator-name org-aggregator \
  --organization-aggregation-source '{
    "RoleArn": "arn:aws:iam::111111111111:role/ConfigAggregatorRole",
    "AllAwsRegions": true
  }'

# Conformidade consolidada por regra
aws configservice describe-aggregate-compliance-by-config-rules \
  --configuration-aggregator-name org-aggregator

# Inventário de toda a organização por SQL
aws configservice select-aggregate-resource-config \
  --configuration-aggregator-name org-aggregator \
  --expression "SELECT accountId, awsRegion, resourceId
                WHERE resourceType = 'AWS::S3::Bucket'
                  AND configuration.publicAccessBlockConfiguration.blockPublicAcls = false"
```

> [!tip] Aggregator não substitui o recorder
> Se uma conta/região **não grava** (recorder desligado), o aggregator **não tem o que mostrar**. Garanta a gravação em todas as contas e regiões; o aggregator só consolida.

## Implantação em escala

| Recurso | Escopo | Uso |
|---|---|---|
| **Organization Config rules** | Regra implantada em **todas as contas** da organização | Controle uniforme (ex.: `cloudtrail-enabled`) |
| **Organization conformance packs** | Pacote de regras para toda a organização | Padrões de norma (CIS, PCI) e boas práticas |
| **CloudFormation StackSets** | Habilitar o recorder e o delivery channel em todas as contas/regiões | Cobertura inicial |
| **Control Tower** | Habilita o Config nas contas do *landing zone* e aplica controles detectivos | Governança pronta |

```bash
# Regra para toda a organização
aws configservice put-organization-config-rule \
  --organization-config-rule-name org-cloudtrail-enabled \
  --organization-managed-rule-metadata '{
    "RuleIdentifier": "CLOUD_TRAIL_ENABLED"
  }' \
  --excluded-accounts 999999999999

# Conformance pack para toda a organização
aws configservice put-organization-conformance-pack \
  --organization-conformance-pack-name seguranca-base \
  --template-s3-uri s3://bucket-packs/seguranca-base.yaml
```

| Vantagem | Observação |
|---|---|
| Novas contas recebem automaticamente | Sem trabalho manual |
| Contas-membro **não podem alterar** | Evita que o dono da conta desligue a regra |
| Exclusões controladas | `excluded-accounts` para casos justificados |
| Um ponto de verdade | Templates em Git |

## Control Tower e Security Hub

| Serviço | Integração com o Config |
|---|---|
| **AWS Control Tower** | Configura Config/CloudTrail no landing zone; **controles detectivos** são Config rules gerenciadas; mostra desvios no painel |
| **AWS Security Hub** | Consome resultados do Config (CSPM) em **padrões** como AWS Foundational Security Best Practices e CIS; consolida achados com GuardDuty, Inspector etc. |
| **AWS Audit Manager** | Usa dados do Config e CloudTrail como **evidência** automatizada de auditoria |
| **Amazon Detective** | Complementa investigações com contexto de configuração |

> [!warning] Security Hub usa o Config
> Os controles de CSPM do Security Hub **dependem do Config gravando os recursos**. Sem recorder ligado nas regiões e contas, os controles aparecem sem dados ou com cobertura incompleta.

## Relatórios de conformidade

| Necessidade | Ferramenta |
|---|---|
| Visão executiva da conformidade | Dashboard do aggregator; Security Hub |
| Relatórios por norma | Conformance pack scores; Audit Manager |
| Consulta ad hoc de inventário | Advanced queries no aggregator |
| Análise histórica em larga escala | Athena sobre o bucket de histórico |
| Evidência para auditores | Exportar snapshots e histórico; Audit Manager |

```
 Auditor: "Mostre que todos os volumes de produção estão criptografados"
 ├─ Aggregator: regra encrypted-volumes → 100% COMPLIANT (filtro tag Ambiente=producao)
 ├─ Histórico: quando cada volume passou a ser criptografado
 └─ Audit Manager: pacote de evidências automático
```

## Preparando a organização passo a passo

| Passo | Ação |
|---|---|
| 1 | Habilitar o **acesso confiável** do Config na Organizations (conta de gerenciamento) |
| 2 | **Delegar** a administração do Config à conta de segurança |
| 3 | Implantar **recorder e delivery channel** em todas as contas/regiões (StackSet) |
| 4 | Criar o **aggregator da organização** na conta delegada |
| 5 | Implantar **organization conformance packs** (piso de segurança) |
| 6 | Integrar com **Security Hub** e **Audit Manager** |
| 7 | Definir **donos por conta** e processo de exceções |

```bash
aws organizations enable-aws-service-access --service-principal config.amazonaws.com
aws organizations register-delegated-administrator \
  --account-id 111111111111 --service-principal config.amazonaws.com
```

> [!tip] Conta nova, controles já aplicados
> Com organization rules e packs, **contas criadas depois** herdam os controles automaticamente, sem esforço manual e sem janela de risco.

## Padrões de governança

| Padrão | Descrição |
|---|---|
| **Piso mínimo obrigatório** | Conformance pack organizacional que ninguém altera |
| **Camadas por ambiente** | Regras mais rígidas em produção que em desenvolvimento |
| **Exceções com prazo** | Contas/recursos excluídos com justificativa e data de vencimento |
| **Dono por conta** | Contato de segurança por conta para tratar não conformes |
| **Revisão trimestral** | Ajuste de regras, remoção de ruído, novas normas |

## Exemplo prático: de 60 contas sem visão a uma visão única

1. A conta de gerenciamento habilita **acesso confiável** do Config e delega a **conta de segurança**.
2. Um **StackSet** habilita recorder e delivery channel em todas as contas e regiões usadas.
3. O **aggregator da organização** consolida todas as contas e regiões.
4. Um **organization conformance pack** aplica o piso de segurança (MFA, criptografia, sem público, CloudTrail).
5. O **Security Hub** consome os resultados e alimenta o painel executivo.
6. Uma consulta avançada lista, em segundos, todos os buckets públicos da organização; um fluxo de remediação trata os achados.

## Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| Aggregator vazio | Recorder desligado nas origens ou autorização ausente | Habilitar gravação; autorizar/organização |
| Conta nova sem regras | Pack não organizacional | Usar organization rules/packs |
| Falha ao implantar org pack | Template ou permissões inválidos | Ver status por conta |
| Região sem dados | Config não habilitado ali | StackSet para todas as regiões |
| Security Hub sem controles | Config não grava os recursos | Habilitar o recorder |
| Conta-membro alterou a regra | Regra local, não organizacional | Migrar para organization rule |
| Custo alto em escala | Muitas regras/regiões | Revisar escopo, packs e modo de gravação |

## Erros comuns e armadilhas

- **Achar que o aggregator grava**: ele só consolida.
- **Esquecer regiões não usadas**, onde uma atividade maliciosa passaria despercebida.
- **Regras locais por conta**, permitindo que desliguem controles.
- **Não delegar a administração**, usando a conta de gerenciamento para tudo.
- **Ignorar o custo** de avaliar centenas de regras em centenas de contas.
- **Exceções sem prazo** que viram permanentes.
- **Security Hub ligado sem Config** nas contas.
- **Sem donos por conta**, deixando os achados sem tratamento.

## 🧩 Quiz de Fixação

1. O que faz um aggregator?
2. Qual a vantagem de organization rules e conformance packs?
3. O aggregator substitui o recorder nas contas?
4. Quem é o administrador delegado do Config e por que usá-lo?
5. Como o Security Hub depende do Config?
6. Por que habilitar o Config em regiões não usadas?

**Respostas:**
1) Consolida dados de configuração e conformidade de várias contas e regiões em uma única visão, sem alterar as origens.
2) Implantam automaticamente regras e pacotes em todas as contas (inclusive novas), sem que as contas-membro possam alterá-los.
3) Não; as contas continuam precisando gravar, e o aggregator apenas consolida.
4) Uma conta de segurança/auditoria designada para administrar o Config da organização, evitando usar a conta de gerenciamento.
5) Os controles de CSPM do Security Hub usam os dados gravados e avaliados pelo Config; sem recorder, ficam sem dados.
6) Para ter visibilidade de atividade em qualquer região, inclusive onde um invasor poderia agir sem ser notado.
