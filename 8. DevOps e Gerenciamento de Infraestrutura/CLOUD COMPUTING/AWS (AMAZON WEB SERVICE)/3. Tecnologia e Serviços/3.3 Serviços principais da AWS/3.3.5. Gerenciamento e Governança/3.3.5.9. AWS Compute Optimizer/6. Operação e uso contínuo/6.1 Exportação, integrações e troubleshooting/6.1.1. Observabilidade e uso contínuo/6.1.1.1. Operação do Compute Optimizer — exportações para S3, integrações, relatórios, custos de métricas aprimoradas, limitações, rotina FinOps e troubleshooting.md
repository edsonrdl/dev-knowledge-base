### 6.1.1.1. Operação do Compute Optimizer — exportações para S3, integrações, relatórios, custos de métricas aprimoradas, limitações, rotina FinOps e troubleshooting

> [!warning] Aviso
> Preços de métricas aprimoradas, cadência de atualização das recomendações, formatos de exportação, limites de API e integrações abaixo são **de memória e mudam**. **Confirme na documentação e na página de preços do AWS Compute Optimizer.** Valores monetários são **ordens de grandeza para raciocínio**, não cotação. Comandos, consultas SQL e scripts são ilustrativos e **não foram executados**.

## 1. O que significa operar o Compute Optimizer

O serviço é **de baixa manutenção** (não há cluster para cuidar), mas o **valor depende do uso contínuo**: recomendações **envelhecem**, cargas mudam e **ninguém age** se o processo não existir. Operar é manter **o ciclo FinOps**:

```
Dados saudáveis ─▶ Relatórios e exportações ─▶ Triagem e decisão ─▶ Execução segura ─▶ Medição ─▶ Revisão de preferências ─▶ (repetir)
```

Perguntas do dia a dia:

1. **O serviço está ativo e cobrindo** todas as contas/regiões/recursos?
2. **Há dados suficientes** (memória, janela, métricas aprimoradas onde preciso)?
3. **Quais recomendações** estão abertas, de quem e há quanto tempo?
4. **Quanto foi economizado** (realizado) e quanto ainda há (potencial)?
5. **Houve incidentes** decorrentes de right-sizing?
6. **Estamos pagando** por métricas aprimoradas só onde vale a pena?

## 2. Cobertura e saúde dos dados

### 2.1 Checagens

| Checagem | Como |
|---|---|
| **Ativação** | `get-enrollment-status` / `get-enrollment-statuses-for-organization` — contas novas entram? |
| **Cobertura por recurso** | **% de recursos com finding** vs **sem dados** (`Unavailable`/sem recomendação) |
| **Cobertura de memória** | **% de instâncias com `mem_used_percent`** (CloudWatch Agent) |
| **Regiões** | Recursos em regiões **habilitadas**; novas regiões incluídas |
| **Recursos novos** | Aguardar **~30 h / 14 dias** de dados |
| **Tipos não suportados** | Instâncias especiais (confirmar suporte), grupos mixed — acompanhar **lacunas** |
| **Qualidade** | Recomendações **estáveis** ou oscilando muito (carga variável) |

```bash
aws compute-optimizer get-recommendation-summaries --region us-east-1 \
  --query 'recommendationSummaries[].[recommendationResourceType,summaries[].[name,value]]' --output json
```

### 2.2 Indicadores de cobertura

| Indicador | Meta |
|---|---|
| **% de contas ativas** | 100% |
| **% de EC2 com memória** | ~100% da frota produtiva |
| **% de recursos com recomendação** (vs sem dados) | Alto (explique os “Unavailable”) |
| **% de recursos com tags de dono/ambiente** | Alto (para atribuição) |

## 3. Exportações e relatórios

### 3.1 Exportar para S3 (CSV)

```bash
# Instâncias EC2 (inclui contas-membro)
aws compute-optimizer export-ec2-instance-recommendations --region us-east-1 \
  --s3-destination-config bucket=finops-exports-123456789012,keyPrefix=co/ec2/ \
  --include-member-accounts --file-format Csv
# Outros tipos
aws compute-optimizer export-ebs-volume-recommendations     ...
aws compute-optimizer export-lambda-function-recommendations ...
aws compute-optimizer export-auto-scaling-group-recommendations ...
aws compute-optimizer export-ecs-service-recommendations    ...
aws compute-optimizer export-rds-database-recommendations   ...
aws compute-optimizer export-idle-recommendations           ...
aws compute-optimizer describe-recommendation-export-jobs
```

| Aspecto | Detalhe |
|---|---|
| **Formato** | **CSV** (com metadados de jobs) |
| **Conteúdo** | **Todas** as colunas: ARN, conta, finding, motivos, **opções 1–3** (tipo, risco, economia, esforço), **métricas de utilização**, **tags**, **janela de análise** |
| **Frequência** | **Agendar** exportações (semanal/mensal) via **EventBridge Scheduler + Lambda** |
| **Filtros** | Por **conta**, **região**, **finding**, **tag** |
| **Destino** | Bucket **seguro** (ver segurança) |
| **Histórico** | **Mantenha snapshots** mensais para **tendências** (as recomendações **mudam**) |

### 3.2 Analisar com Athena/QuickSight

```sql
-- Exemplo ilustrativo: top economias de EC2 superdimensionadas (tabela criada sobre os CSVs)
SELECT accountid, instancename, currentinstancetype, finding,
       recommendationoptions_1_instancetype AS opcao1,
       recommendationoptions_1_savingsopportunity_percentage AS economia_pct,
       recommendationoptions_1_estimatedmonthlysavings_value AS economia_mensal,
       recommendationoptions_1_performancerisk AS risco,
       recommendationoptions_1_migrationeffort AS esforco
FROM compute_optimizer.ec2_recommendations
WHERE finding = 'Overprovisioned' AND recommendationoptions_1_performancerisk <= 2
ORDER BY economia_mensal DESC
LIMIT 50;
```

| Painel (QuickSight) | Conteúdo |
|---|---|
| **Economia potencial** | Por **conta/equipe/app/tag**, por **tipo de recurso** |
| **Distribuição de findings** | Under/Over/Optimized (tendência mensal) |
| **Quick wins** | Risco ≤ 2 **e** esforço baixo |
| **Idade das recomendações** | Há quanto tempo abertas |
| **Cobertura** | Recursos sem dados; sem memória |
| **Realizado vs potencial** | Economia aplicada vs ainda aberta |
| **Graviton** | Elegíveis vs migrados |

### 3.3 Entrega aos donos

- **Relatórios por equipe** (filtrados por **tag/conta**), enviados **mensalmente** (e-mail/Slack/Jira).
- **Top 10 de cada equipe** (valor × baixo risco).
- **Contexto**: link para o console do recurso, **gráficos de utilização projetada**, instruções de **mudança segura**.

## 5. Custos

### 5.1 O que é cobrado (de memória — confirmar)

| Item | Cobrança |
|---|---|
| **Compute Optimizer (recomendações padrão)** | **Sem custo adicional** |
| **Métricas aprimoradas** (janela de até 93 dias) | **Por recurso/hora** (valor baixo por **vCPU/hora**; ex.: ~US$ 0,0003 por vCPU-hora — **confirmar**), **só** para recursos com a preferência **ativa** |
| **CloudWatch Agent (métricas custom de memória)** | **Métricas customizadas** do CloudWatch (por métrica/mês) |
| **Métricas externas** | Custos do **terceiro** (APM) |
| **Exportações S3** | Armazenamento S3 (pequeno) |
| **Athena/QuickSight** | Consultas/usuários |
| **Automação** | Lambda/Step Functions/SSM (pequeno) |
| **Cost Optimization Hub** | Sem custo adicional (confirmar) |

### 5.2 Exemplo de decisão sobre métricas aprimoradas (raciocínio, **não cotação**)

```
Frota crítica sazonal: 200 instâncias × 8 vCPU = 1.600 vCPU
Métricas aprimoradas: 1.600 × ~US$ 0,0003 × 730 h  ≈ US$ 350/mês
Benefício: evitar UM erro de subdimensionamento (incidente) ou justificar redução segura de 20% em 200 instâncias
           (ex.: economia de US$ 6.000/mês) ⇒ ROI alto
Frota estável de dev/test (1.000 vCPU): janela de 14 dias basta ⇒ não ativar
```

Regra: ative **onde há sazonalidade ou alto valor**; **não** em toda a frota.

### 5.3 Custo × benefício do programa

| Elemento | Observação |
|---|---|
| **Custo da ferramenta** | Muito baixo |
| **Custo principal** | **Tempo das equipes** (triagem, testes, mudanças) |
| **Retorno** | Frequentemente **10–30%** de redução em compute/storage **sem otimização prévia** (ordem de grandeza; varia) |
| **Risco** | Incidentes por mudanças mal testadas |
| **Gargalo** | **Execução**, não **descoberta** |

## 6. Limitações e como contorná-las

| Limitação | Contorno |
|---|---|
| **Sem memória por padrão** | CloudWatch Agent / métricas externas |
| **Sazonalidade longa** | Métricas aprimoradas; análise manual do período crítico |
| **Grupos mixed/instance weighting** | Avaliar por instância/tipo; testes |
| **Cargas intermitentes** | Considerar **escala/serverless** em vez de right-size |
| **Recursos sem suporte** | Ferramentas complementares (Cost Explorer, Trusted Advisor, métricas próprias) |
| **Estimativas em preço público** | **Estimativa após descontos** |
| **Não aplica mudanças** | Automação própria + governança |
| **Contexto de negócio ausente** | **Revisão humana**, tags de exceção |
| **Regiões** | Consolidar via Organizations/exportações |
| **Lag de dados** | Recursos novos precisam de **tempo**; recomendações atualizam **diariamente** |

## 7. Rotina FinOps (cadência)

| Frequência | Atividade |
|---|---|
| **Semanal** | Automação: gerar **tickets** de quick wins (dev/test) e enviar resumo |
| **Mensal** | **Revisão FinOps** com donos: top economias, idade das recomendações, incidentes, **exceções** |
| **Mensal** | **Exportação** para histórico (Athena/QuickSight); atualizar painéis |
| **Mensal** | **Medir economia realizada** (CUR/tags) vs estimada |
| **Trimestral** | **Revisar preferências** (headroom, janela, famílias), **métricas aprimoradas**, cobertura de memória |
| **Trimestral** | **Revisão de acessos** e integrações |
| **Antes de compras** | **Right-size → então** Savings Plans/RIs |
| **Após grandes migrações/lançamentos** | Reavaliar tamanhos |
| **Anual** | Revisar **programa** (metas, processo, ferramentas) |

### 7.1 Governança de recomendações abertas

| Regra | Detalhe |
|---|---|
| **SLA de resposta** | Quick wins: **30 dias**; produção: **60–90 dias** |
| **Rejeição justificada** | Registrar **motivo** (DR, sazonalidade, licença) e **validade** |
| **Escalonamento** | Recomendações > X dias sem ação vão ao **gestor** |
| **Não deixar “para sempre”** | Reavaliar **rejeições** a cada trimestre |

## 8. Troubleshooting operacional

### 8.1 Árvore: “não há recomendações”

```
Sem recomendações?
├─ Serviço ativado na conta/organização e região?                    ── não ─▶ opt-in
├─ Recurso suportado (tipo/engine/ASG com tipo único)?               ── não ─▶ avaliar manualmente/outra ferramenta
├─ Dados suficientes (≥ 30 h EC2; ≥ 50 invocações Lambda em 14 d)?   ── não ─▶ aguardar/mais uso
├─ Métricas do CloudWatch existem (monitoring habilitado)?           ── não ─▶ habilitar; checar permissões
├─ Recurso excluído por preferências/escopo?                         ── sim ─▶ revisar preferências
└─ Conta-membro incluída na organização?                             ── não ─▶ incluir
```

### 8.2 Árvore: “a recomendação parece errada”

```
Recomendação suspeita?
├─ Há métricas de memória (CloudWatch Agent)?                        ── não ─▶ instalar; reavaliar
├─ A janela cobre a sazonalidade (14 vs 93 dias)?                    ── não ─▶ métricas aprimoradas
├─ Headroom/percentil adequados ao risco?                            ── não ─▶ ajustar preferências
├─ Carga mudou recentemente (deploy, campanha)?                      ── sim ─▶ aguardar/reanalisar
├─ A carga é de memória/IO/rede (não só CPU)?                        ── sim ─▶ verificar finding reasons
└─ Recurso é DR/standby/batch raro?                                  ── sim ─▶ marcar exceção (tag)
```

### 8.3 Tabela de sintomas

| Sintoma | Causa provável | Ação |
|---|---|---|
| Recomendação muda a cada semana | Carga variável/janela curta | Janela maior; preferências; confiar em tendências |
| Economia não aparece na fatura | SPs/RIs; estimativa em preço público; outras mudanças | Medir por tag/CUR; estimativa após descontos |
| Incidente após a mudança | Pico não capturado; memória ausente; compatibilidade | Rollback; rever janela/headroom; testes |
| Export job `Failed` | Permissões do bucket/KMS | Ajustar a policy; verificar o erro em `describe-recommendation-export-jobs` |
| Throttling em APIs | Automação intensiva | Backoff/paginação |
| Conta nova sem dados | Opt-in da organização/tempo | Verificar o status; aguardar |
| Muitos “Unavailable” (Lambda) | Baixo uso | Esperado; ignorar/avaliar por outros meios |
| Divergência com Cost Explorer | Metodologias diferentes (CPU simples vs multi-métricas) | Preferir Compute Optimizer/Hub; validar |
| Recurso ocioso é DR | Falso positivo | Tag de exceção; documentar |
| Gráficos/relatórios desatualizados | Exportação não agendada | Agendar; automatizar |

## 9. Métricas do programa

| Métrica | Fórmula/uso |
|---|---|
| **Economia potencial aberta** | Σ economia das recomendações abertas (risco ≤ 2) |
| **Economia realizada (mensal/acumulada)** | Custo antes − depois (CUR/tags) |
| **Taxa de implementação** | Implementadas / total (por risco) |
| **Tempo médio até a ação** | Dias entre a recomendação e a mudança |
| **% de frota “Optimized”** | Tendência |
| **Incidentes por mudança** | ~0 |
| **Cobertura de memória** | ~100% |
| **Custo do programa** | Métricas aprimoradas + horas |

## 10. Checklist de produção

- [ ] **Ativação** para a organização; **contas novas** incluídas automaticamente
- [ ] **Cobertura de memória** (CloudWatch Agent) e **tags** de dono/ambiente/exceção
- [ ] **Preferências** por ambiente (headroom/janela/famílias/estimativa após descontos) **como código**
- [ ] **Métricas aprimoradas** somente onde há sazonalidade/valor
- [ ] **Exportações agendadas** + Athena/QuickSight; **histórico** mensal
- [ ] **Cost Optimization Hub** habilitado; integração com **tickets**
- [ ] **Cadência FinOps** mensal; **SLAs** de resposta; **política de exceções**
- [ ] **Pipeline seguro** (aprovação em prod, rollback, monitoramento pós-mudança)
- [ ] **Medição** de economia realizada (CUR/tags) e **KPIs**
- [ ] **Right-size antes** de comprar Savings Plans/RIs
- [ ] **Revisões** trimestrais (preferências, acessos, integrações)

## 11. Erros comuns

- **Ativar e esquecer**: recomendações nunca consumidas.
- **Medir só potencial** (não o realizado).
- **Sem histórico** (impossível ver tendências).
- **Métricas aprimoradas em toda a frota**.
- **Sem cobertura de memória**.
- **Recomendações antigas** aplicadas sem reavaliar.
- **Rejeições sem registro** (retrabalho eterno).
- **Sem relatórios por equipe** (ninguém se reconhece como dono).
- **Comprar compromissos antes do right-sizing**.
- **Exportações em bucket exposto**.
- **Ignorar o custo humano** (tempo de teste/mudança).

## 12. Resumo rápido

- Operar = **cobertura**, **qualidade dos dados** (memória/janela), **relatórios**, **ação segura**, **medição** e **revisões** — a ferramenta é barata; **a execução é o gargalo**.
- **Exportações CSV para S3** (por tipo de recurso, com contas-membro) + **Athena/QuickSight**; **agendar** e **manter histórico**; painéis de **economia potencial/realizada**, **idade**, **cobertura**.
- **Integrações**: **Cost Optimization Hub**, **Trusted Advisor**, **Cost Explorer**, **Budgets**, **EventBridge/SSM**, **tickets**.
- **Custos**: serviço **gratuito**; **métricas aprimoradas** pagas (apenas onde sazonal/valioso); **CW Agent** (métricas custom); custo real = **tempo de equipe**.
- **Limitações**: memória, sazonalidade, mixed ASG, contexto de negócio, preço público → **contornos** (agente, métricas aprimoradas, preferências, tags, estimativa após descontos).
- **Cadência**: semanal (tickets), mensal (revisão/medição), trimestral (preferências/acessos); **right-size → Savings Plans**.
- **Troubleshooting**: sem recomendações (ativação/suporte/dados), recomendação suspeita (memória/janela/headroom/exceção), economia ausente (SPs/preços), incidentes (rollback e lições).

## 🧩 Quiz de Fixação

1. Que dados estão nas exportações e como usá-las?
2. Quando vale pagar por métricas aprimoradas?
3. Qual a diferença entre economia potencial e realizada, e como medir a realizada?
4. Que limitações exigem contorno manual?
5. Por que manter histórico mensal das recomendações?
6. Qual a cadência de operação recomendada?
7. Quais as causas mais comuns de “sem recomendação”?

**Respostas:**

1. Colunas com ARN, conta, finding, motivos, até 3 opções (tipo, risco, economia, esforço), métricas e tags; usam-se com Athena/QuickSight para priorizar, medir cobertura e acompanhar tendências por equipe.
2. Em frotas sazonais ou de alto valor/criticidade, onde a janela de 14 dias não captura os picos e o ganho ou a redução de risco superam o custo.
3. Potencial é a estimativa das recomendações abertas; realizada é o que foi efetivamente economizado, medida comparando custos antes e depois por tag/recurso no CUR/Cost Explorer.
4. Memória ausente, sazonalidade longa, grupos mixed/instance weighting, falta de contexto de negócio e estimativas em preço público.
5. Porque as recomendações mudam; o histórico permite ver tendências, medir realizado e auditar decisões.
6. Semanal (tickets de quick wins), mensal (revisão FinOps, exportação e medição) e trimestral (preferências, acessos, integrações), além de reavaliar antes de compras de Savings Plans e após grandes mudanças.
7. Serviço não ativado, recurso não suportado, dados insuficientes (poucas horas/invocações), métricas ausentes, exclusão por preferências ou conta não incluída na organização.
