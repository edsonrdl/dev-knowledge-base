### Anatomia de um template — Parameters, Mappings, Conditions, Resources, Outputs, funções intrínsecas, pseudo parameters e referências dinâmicas

> [!warning] Aviso
> Funções intrínsecas, tipos de parâmetro, limites (número de parâmetros, outputs, tamanho) e sintaxe de recursos mudam. Os exemplos aqui são referências de estudo; confirme na documentação. Os comandos **não foram executados**.

Um template do CloudFormation tem uma **estrutura fixa** de seções. Só **`Resources`** é obrigatória; as demais tornam o template **flexível, reutilizável e seguro**: **Parameters** (entradas), **Mappings** (tabelas de consulta), **Conditions** (lógica condicional), **Outputs** (saídas), além de **funções intrínsecas** que calculam valores em tempo de implantação. Dominar essas peças é o que separa um template **copiado e colado** de um template **profissional**.

**Analogia:** um template é como um **formulário de pedido de uma obra**. **Parameters** são os campos que o cliente preenche (tamanho, cor); **Mappings** são tabelas de preço por região; **Conditions** são regras do tipo "se for obra comercial, inclua elevador"; **Resources** é a lista do que será construído; **Outputs** é o recibo final com endereços e chaves.

---

## As seções do template

```yaml
AWSTemplateFormatVersion: '2010-09-09'   # opcional (única versão válida)
Description: Texto descritivo              # opcional
Metadata:                                  # opcional: informações extras (interface do console)
Parameters:                                # entradas
Rules:                                     # validações entre parâmetros
Mappings:                                  # tabelas chave/valor
Conditions:                                # condições booleanas
Transform:                                 # macros / SAM
Resources:                                 # OBRIGATÓRIA
Outputs:                                   # saídas
```

| Seção | Obrigatória? | Função |
|---|---|---|
| **Resources** | **Sim** | Declara os recursos a criar |
| **Parameters** | Não | Valores informados na criação/atualização |
| **Mappings** | Não | Consulta estática (ex.: AMI por região) |
| **Conditions** | Não | Criar recursos/valores conforme condições |
| **Outputs** | Não | Valores exibidos ou exportados |
| **Transform** | Não | Aplica macros (ex.: `AWS::Serverless`, `AWS::Include`) |
| **Metadata / Rules** | Não | Organização de parâmetros e validações |

## Parameters

Parâmetros tornam o template **reutilizável**: o mesmo arquivo cria dev e prod.

```yaml
Parameters:
  Ambiente:
    Type: String
    Description: Ambiente de implantação
    AllowedValues: [dev, homolog, prod]
    Default: dev

  TipoInstancia:
    Type: String
    Default: t3.micro
    AllowedPattern: '^[a-z][0-9][.][a-z]+$'
    ConstraintDescription: Informe um tipo válido, como t3.micro

  VpcId:
    Type: AWS::EC2::VPC::Id          # lista suspensa no console, validada

  ChaveAmi:
    Type: AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>
    Default: /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64

  SenhaBanco:
    Type: String
    NoEcho: true                      # mascara o valor nos consoles e logs
    MinLength: 12
```

| Atributo | Função |
|---|---|
| `Type` | `String`, `Number`, `List<Number>`, `CommaDelimitedList`, **tipos AWS** (`AWS::EC2::KeyPair::KeyName`) e **SSM** |
| `Default` | Valor padrão |
| `AllowedValues` / `AllowedPattern` | Restringem as entradas |
| `MinLength`, `MaxLength`, `MinValue`, `MaxValue` | Limites |
| `NoEcho` | Oculta o valor (use para dados sensíveis, mas prefira referências dinâmicas) |
| `ConstraintDescription` | Mensagem de erro amigável |

> [!tip] Tipos AWS-specific e SSM
> Parâmetros como `AWS::EC2::VPC::Id` ou `AWS::SSM::Parameter::Value<...>` **validam** a existência do recurso e **evitam** IDs de AMI fixos que ficam obsoletos. É a forma segura de pedir uma AMI "sempre atual".

## Mappings

Tabelas **estáticas** de consulta, úteis para valores que variam por **região** ou **ambiente**.

```yaml
Mappings:
  TamanhoPorAmbiente:
    dev:  {Instancia: t3.micro,  MultiAz: 'false'}
    prod: {Instancia: m6i.large, MultiAz: 'true'}

  AmisPorRegiao:
    us-east-1: {Padrao: ami-0123456789abcdef0}
    sa-east-1: {Padrao: ami-0fedcba9876543210}

Resources:
  Servidor:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: !FindInMap [TamanhoPorAmbiente, !Ref Ambiente, Instancia]
      ImageId: !FindInMap [AmisPorRegiao, !Ref 'AWS::Region', Padrao]
```

`!FindInMap [NomeDoMapa, Chave1, Chave2]` retorna o valor. **Prefira parâmetros SSM** para AMIs: mapas de AMI precisam de manutenção constante.

## Conditions

Condições decidem **se um recurso é criado** ou **qual valor usar**.

```yaml
Conditions:
  EhProducao: !Equals [!Ref Ambiente, prod]
  CriaReplica: !And
    - !Condition EhProducao
    - !Equals [!Ref HabilitaReplica, 'true']
  NaoEhProducao: !Not [!Condition EhProducao]

Resources:
  BancoReplica:
    Type: AWS::RDS::DBInstance
    Condition: CriaReplica          # só existe se a condição for verdadeira
    Properties: ...

  Servidor:
    Type: AWS::EC2::Instance
    Properties:
      InstanceType: !If [EhProducao, m6i.large, t3.micro]
      Monitoring: !If [EhProducao, true, false]
```

| Função de condição | Uso |
|---|---|
| `!Equals [a, b]` | Igualdade |
| `!And`, `!Or`, `!Not` | Lógica booleana |
| `!If [cond, valorSe, valorSenão]` | Valor condicional |
| `!Condition nome` | Referência a outra condição |
| `AWS::NoValue` | Remove uma propriedade quando a condição falha |

```yaml
Properties:
  KmsKeyId: !If [EhProducao, !Ref ChaveKms, !Ref 'AWS::NoValue']
```

## Resources

Cada recurso tem um **ID lógico** (nome no template), um **`Type`** e **`Properties`**.

```yaml
Resources:
  BucketDados:                          # ID lógico
    Type: AWS::S3::Bucket               # tipo: Serviço::Recurso
    DeletionPolicy: Retain              # atributos do recurso
    UpdateReplacePolicy: Retain
    DependsOn: PoliticaLogs             # dependência explícita (quando não há referência)
    Properties:
      VersioningConfiguration: {Status: Enabled}
      Tags:
        - {Key: Ambiente, Value: !Ref Ambiente}
```

### Atributos de recurso (fora de `Properties`)

| Atributo | Função |
|---|---|
| **`DependsOn`** | Força ordem quando não há referência implícita |
| **`DeletionPolicy`** | `Delete` (padrão), **`Retain`** (mantém ao excluir), **`Snapshot`** (cria snapshot antes de excluir) |
| **`UpdateReplacePolicy`** | O mesmo para quando o recurso é **substituído** em atualização |
| **`CreationPolicy`** | Aguarda **sinais** (`cfn-signal`) antes de considerar criado |
| **`UpdatePolicy`** | Controla atualizações de Auto Scaling, Lambda alias etc. |
| **`Condition`** | Cria o recurso só se a condição for verdadeira |
| **`Metadata`** | Dados auxiliares (ex.: `AWS::CloudFormation::Init`) |

> [!warning] Sempre proteja dados críticos
> Em **bancos, buckets, volumes e chaves KMS**, use `DeletionPolicy` e `UpdateReplacePolicy` com **`Retain`** ou **`Snapshot`**. Sem isso, excluir a stack ou uma substituição apaga os dados **sem volta**.

## Outputs

Saídas **exibem valores** e podem ser **exportadas** para outras stacks.

```yaml
Outputs:
  VpcId:
    Description: ID da VPC
    Value: !Ref Vpc
    Export:
      Name: !Sub '${AWS::StackName}-VpcId'    # outras stacks usam !ImportValue

  UrlDoSite:
    Value: !Sub 'https://${Distribuicao.DomainName}'
```

| Uso | Observação |
|---|---|
| Mostrar resultado ao usuário | Console e `describe-stacks` |
| **`Export`** + **`!ImportValue`** | Compartilha valores entre stacks na **mesma região/conta** |
| Limitação | Uma stack **não pode ser excluída** enquanto outra importar seus exports |

> [!tip] Alternativa aos exports
> Para desacoplar stacks, grave valores em **Parameter Store** e leia-os com parâmetros SSM. Exports criam **acoplamento rígido** entre stacks.

## Funções intrínsecas

Funções calculam valores **na implantação**. Em YAML há **forma curta** (`!Ref`) e **forma longa** (`Fn::Ref`).

| Função | O que faz | Exemplo |
|---|---|---|
| **`!Ref`** | Retorna o **parâmetro** ou o **ID físico** do recurso | `!Ref BucketDados` (nome do bucket) |
| **`!GetAtt`** | Atributo de um recurso | `!GetAtt BucketDados.Arn` |
| **`!Sub`** | Substitui `${variáveis}` em strings | `!Sub 'arn:aws:s3:::${BucketDados}/*'` |
| **`!Join`** | Junta valores | `!Join ['-', [app, !Ref Ambiente]]` |
| **`!Select`** | Escolhe um item de lista | `!Select [0, !GetAZs '']` |
| **`!Split`** | Divide string em lista | `!Split [',', 'a,b,c']` |
| **`!GetAZs`** | Zonas de disponibilidade da região | `!GetAZs !Ref 'AWS::Region'` |
| **`!ImportValue`** | Importa um export | `!ImportValue rede-VpcId` |
| **`!FindInMap`** | Consulta mapping | veja acima |
| **`!Base64`** | Codifica em Base64 | User data |
| **`!Cidr`** | Calcula blocos CIDR | Subnets |
| **`!If`, `!Equals`, ...** | Condições | veja acima |
| **`Fn::Transform`** | Aplica macro | `AWS::Include` |
| **`Fn::ForEach`** | **Repete** blocos (extensão `AWS::LanguageExtensions`) | Vários recursos a partir de uma lista |
| **`Fn::ToJsonString`, `Fn::Length`** | Utilidades (Language Extensions) | Conversões |

```yaml
Resources:
  Funcao:
    Type: AWS::Lambda::Function
    Properties:
      FunctionName: !Sub '${AWS::StackName}-${Ambiente}-processa'
      Role: !GetAtt FuncaoRole.Arn
      Environment:
        Variables:
          BUCKET: !Ref BucketDados
          SUBNETS: !Join [',', [!Ref SubnetA, !Ref SubnetB]]
```

> [!tip] `!Sub` quase sempre vence `!Join`
> `!Sub` deixa as strings legíveis e permite referenciar `${Recurso.Atributo}` diretamente, sem `!GetAtt` separado.

### Dependências implícitas vs explícitas

| Tipo | Como surge |
|---|---|
| **Implícita** | Qualquer `!Ref`/`!GetAtt` cria a dependência automaticamente |
| **Explícita** | `DependsOn` quando não há referência (ex.: Internet Gateway attachment antes de uma instância) |

## Pseudo parameters

Valores fornecidos pelo próprio CloudFormation:

| Pseudo parâmetro | Valor |
|---|---|
| `AWS::AccountId` | ID da conta |
| `AWS::Region` | Região da stack |
| `AWS::StackName` / `AWS::StackId` | Nome/ID da stack |
| `AWS::Partition` | `aws`, `aws-cn`, `aws-us-gov` |
| `AWS::URLSuffix` | Sufixo de domínio (`amazonaws.com`) |
| `AWS::NoValue` | "Remove" uma propriedade |
| `AWS::NotificationARNs` | ARNs de notificação da stack |

```yaml
Resource: !Sub 'arn:${AWS::Partition}:s3:::${BucketDados}/*'   # portável entre partições
```

## Referências dinâmicas (`{{resolve:...}}`)

Permitem buscar **valores externos** na implantação, **sem expô-los** no template.

| Sintaxe | Fonte |
|---|---|
| `{{resolve:ssm:/caminho}}` | Parameter Store (String) |
| `{{resolve:ssm-secure:/caminho}}` | Parameter Store **SecureString** (somente em propriedades suportadas) |
| `{{resolve:secretsmanager:nome:SecretString:chave}}` | Secrets Manager |

```yaml
Resources:
  Banco:
    Type: AWS::RDS::DBInstance
    Properties:
      MasterUsername: '{{resolve:secretsmanager:prod/db:SecretString:username}}'
      MasterUserPassword: '{{resolve:secretsmanager:prod/db:SecretString:password}}'
```

> [!warning] Nunca coloque segredos em Parameters sem `NoEcho`... nem com ele, se puder evitar
> Mesmo com `NoEcho`, o valor trafega pelo CloudFormation. **Prefira** referências dinâmicas ou **geração de segredo** pelo Secrets Manager (`AWS::SecretsManager::Secret` com `GenerateSecretString`).

## Transform, macros e módulos (visão rápida)

| Recurso | Função |
|---|---|
| **`Transform: AWS::Serverless-2016-10-31`** | Habilita **SAM** (atalhos para Lambda, API, tabelas) |
| **`Transform: AWS::LanguageExtensions`** | `Fn::ForEach`, `Fn::Length`, etc. |
| **`AWS::Include`** | Inclui trechos de templates do S3 |
| **Macros** | Funções Lambda que **reescrevem o template** antes da execução |
| **Módulos** | Blocos reutilizáveis registrados no CloudFormation Registry |

## Um template completo e comentado

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Description: API simples - função Lambda com tabela DynamoDB

Parameters:
  Ambiente: {Type: String, AllowedValues: [dev, prod], Default: dev}

Conditions:
  EhProducao: !Equals [!Ref Ambiente, prod]

Resources:
  Tabela:
    Type: AWS::DynamoDB::Table
    DeletionPolicy: !If [EhProducao, Retain, Delete]
    UpdateReplacePolicy: !If [EhProducao, Retain, Delete]
    Properties:
      BillingMode: PAY_PER_REQUEST
      AttributeDefinitions: [{AttributeName: id, AttributeType: S}]
      KeySchema: [{AttributeName: id, KeyType: HASH}]
      PointInTimeRecoverySpecification:
        PointInTimeRecoveryEnabled: !If [EhProducao, true, false]

  FuncaoRole:
    Type: AWS::IAM::Role
    Properties:
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - {Effect: Allow, Principal: {Service: lambda.amazonaws.com}, Action: 'sts:AssumeRole'}
      ManagedPolicyArns:
        - !Sub 'arn:${AWS::Partition}:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole'
      Policies:
        - PolicyName: AcessoTabela
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action: ['dynamodb:GetItem', 'dynamodb:PutItem']
                Resource: !GetAtt Tabela.Arn

  Funcao:
    Type: AWS::Lambda::Function
    Properties:
      Runtime: python3.12
      Handler: index.handler
      Role: !GetAtt FuncaoRole.Arn
      Environment: {Variables: {TABELA: !Ref Tabela}}
      Code:
        ZipFile: |
          def handler(event, context):
              return {"ok": True}

Outputs:
  NomeTabela: {Value: !Ref Tabela}
  ArnFuncao:  {Value: !GetAtt Funcao.Arn}
```

## Exemplo prático: o mesmo template em dev e prod

1. Um único arquivo com `Parameters.Ambiente` e `Conditions.EhProducao`.
2. Em **dev**: tabela sem backup, `DeletionPolicy: Delete`, instância pequena.
3. Em **prod**: backup contínuo, `Retain`, instância maior e monitoramento detalhado.
4. Segredos vêm de **referências dinâmicas** do Secrets Manager.
5. O pipeline executa `deploy` com `--parameter-overrides Ambiente=dev` e depois `prod`.
6. Outputs alimentam os próximos passos (URL de teste, ARN da função).

## Erros comuns e armadilhas

- **Nomes físicos fixos** (`TableName`, `BucketName`), impedindo reuso e causando conflitos em *replacement*.
- **Esquecer `DeletionPolicy`** em dados críticos.
- **`DependsOn` em excesso**, serializando o que poderia ser paralelo.
- **Usar `!Join` quando `!Sub` seria mais claro.**
- **Mapas de AMI** desatualizados em vez de parâmetros SSM.
- **Segredos em `Parameters`** sem referência dinâmica.
- **Exports demais**, criando acoplamento que impede excluir stacks.
- **Condição aplicada só ao recurso** esquecendo as referências a ele em outros pontos (erro de referência a recurso inexistente).

## 🧩 Quiz de Fixação

1. Qual é a única seção obrigatória de um template?
2. Qual a diferença entre `!Ref` e `!GetAtt`?
3. Para que serve `DeletionPolicy: Retain`?
4. Como obter uma AMI sempre atual sem mapa fixo?
5. O que são referências dinâmicas?
6. Como evitar o acoplamento causado por exports?

**Respostas:**
1) `Resources`.
2) `!Ref` retorna o parâmetro ou o ID físico do recurso; `!GetAtt` retorna um atributo específico (como Arn ou DomainName).
3) Mantém o recurso (e seus dados) quando a stack é excluída, evitando perda.
4) Com um parâmetro do tipo `AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>` apontando para o parâmetro público da AWS.
5) Sintaxe `{{resolve:...}}` que busca valores do SSM ou do Secrets Manager na implantação, sem expô-los no template.
6) Gravando valores no Parameter Store e lendo-os por parâmetros SSM, em vez de usar Export/ImportValue.
