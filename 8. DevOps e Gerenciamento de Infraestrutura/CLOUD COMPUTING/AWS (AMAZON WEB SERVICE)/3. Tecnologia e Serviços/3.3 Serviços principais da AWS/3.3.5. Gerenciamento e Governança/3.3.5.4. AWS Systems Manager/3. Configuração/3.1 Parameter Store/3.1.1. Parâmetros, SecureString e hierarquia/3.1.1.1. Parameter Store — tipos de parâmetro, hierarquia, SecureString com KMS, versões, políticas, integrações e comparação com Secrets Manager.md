### Parameter Store — tipos de parâmetro, hierarquia, SecureString com KMS, versões, políticas, integrações e comparação com Secrets Manager

> [!warning] Aviso
> Limites de parâmetros, tamanhos, throughput, preços e diferenças de camada mudam. Os números aqui são referências de estudo; confirme na documentação. Os comandos **não foram executados**.

O **AWS Systems Manager Parameter Store** é um **armazenamento seguro e hierárquico de configurações e segredos**. Em vez de espalhar **strings de conexão, URLs, flags e senhas** em arquivos, variáveis de ambiente ou no código, você as guarda como **parâmetros** nomeados, com **controle de acesso por IAM**, **versionamento**, **criptografia opcional com KMS** e **auditoria**. Aplicações, scripts, pipelines e serviços AWS leem esses valores em tempo de execução.

**Analogia:** é um **cofre de documentos organizado em pastas**. Cada gaveta (parâmetro) tem etiqueta e caminho (`/producao/api/db/host`), pode guardar um valor comum ou um **segredo lacrado** (SecureString), mantém o **histórico de versões** e só abre para quem tem a **credencial certa** (IAM). Todo acesso é registrado.

---

## Tipos de parâmetro

| Tipo | O que guarda | Criptografia | Exemplo |
|---|---|---|---|
| **String** | Texto simples | Não | `https://api.exemplo.com`, `us-east-1` |
| **StringList** | Lista separada por vírgulas | Não | `10.0.0.1,10.0.0.2,10.0.0.3` |
| **SecureString** | Valor **sensível** | **Sim, com KMS** | Senhas, tokens, chaves de API |

```bash
# String comum
aws ssm put-parameter --name /producao/api/url \
  --value "https://api.exemplo.com" --type String

# Segredo criptografado com a chave KMS padrão do SSM
aws ssm put-parameter --name /producao/api/db/senha \
  --value "S3nh@Forte!" --type SecureString

# Com chave KMS própria
aws ssm put-parameter --name /producao/api/db/senha \
  --value "S3nh@Forte!" --type SecureString \
  --key-id alias/chave-parametros --overwrite
```

> [!warning] Cuidado com histórico de shell e logs
> Ao passar o valor pela linha de comando, ele pode ficar no **histórico do terminal** e em logs. Para segredos reais, leia de arquivo ou entrada segura (`file://`) e evite colocá-los em scripts versionados.

## Hierarquia de nomes

Parâmetros usam **caminhos** (como diretórios), o que permite organizar, buscar e **conceder permissões por prefixo**.

```
 /
 ├─ producao/
 │   ├─ api/
 │   │   ├─ url                (String)
 │   │   └─ db/
 │   │       ├─ host           (String)
 │   │       └─ senha          (SecureString)
 │   └─ web/
 │       └─ cdn/dominio
 └─ desenvolvimento/
     └─ api/db/host
```

| Boa prática | Motivo |
|---|---|
| `/ambiente/aplicacao/componente/chave` | Navegação e permissões previsíveis |
| Separar **por ambiente** no primeiro nível | IAM por `/producao/*` vs `/desenvolvimento/*` |
| Nomes em minúsculas e consistentes | Facilita automação |
| Evitar segredos e não segredos misturados na mesma folha | Permissões distintas |

```bash
# Lê um parâmetro (descriptografando)
aws ssm get-parameter --name /producao/api/db/senha --with-decryption \
  --query Parameter.Value --output text

# Lê todos de um caminho, recursivamente
aws ssm get-parameters-by-path --path /producao/api/ --recursive --with-decryption
```

## Camadas (tiers): padrão, avançada e inteligente

| Camada | Para quê | Observações |
|---|---|---|
| **Standard** | Uso comum | Valor até poucos KB; sem custo por parâmetro; quantidade limitada por conta/região |
| **Advanced** | Mais parâmetros, valores maiores, **políticas** | Cobrada por parâmetro por mês |
| **Intelligent-Tiering** | Escolhe automaticamente a camada necessária | Evita decisão manual |

Recursos exclusivos da **camada avançada** (confirme na documentação): **parameter policies** (expiração, notificação de expiração, notificação sem alteração), valores maiores e quotas maiores.

## Versionamento e rótulos

Cada vez que você altera um parâmetro, o Parameter Store cria uma **nova versão**.

```bash
aws ssm put-parameter --name /producao/api/url --value "https://api2.exemplo.com" --overwrite
aws ssm get-parameter-history --name /producao/api/url
aws ssm get-parameter --name /producao/api/url:2      # versão 2 específica
```

| Conceito | Função |
|---|---|
| **Versão** | Número incremental a cada mudança (histórico preservado até um limite) |
| **Rótulo (label)** | Apelido para uma versão (`estavel`, `canary`) |
| **Referência por rótulo** | `/producao/api/url:estavel` retorna a versão rotulada |

Isso permite **promover** uma versão testada (`estavel`) sem alterar o código que a lê, e **reverter** rapidamente.

## Políticas de parâmetro (camada avançada)

```json
[
  {"Type": "Expiration", "Version": "1.0", "Attributes": {"Timestamp": "2027-01-01T00:00:00Z"}},
  {"Type": "ExpirationNotification", "Version": "1.0",
   "Attributes": {"Before": "15", "Unit": "Days"}},
  {"Type": "NoChangeNotification", "Version": "1.0",
   "Attributes": {"After": "90", "Unit": "Days"}}
]
```

| Política | Efeito |
|---|---|
| **Expiration** | Apaga o parâmetro em uma data |
| **ExpirationNotification** | Avisa (via EventBridge) antes de expirar |
| **NoChangeNotification** | Avisa se o parâmetro não for alterado em N dias (ex.: segredo que deveria ser rotacionado) |

## Criptografia e controle de acesso

### SecureString e KMS

O valor de um **SecureString** é criptografado com uma **chave KMS**:

| Opção | Característica |
|---|---|
| **Chave gerenciada pela AWS** (`alias/aws/ssm`) | Simples; sem controle fino |
| **Chave gerenciada pelo cliente (CMK)** | Política da chave define **quem descriptografa**; permite auditoria e rotação |

Para ler um SecureString, o chamador precisa de **duas permissões**: `ssm:GetParameter` **e** `kms:Decrypt` na chave.

### Política IAM por caminho

```json
{
  "Effect": "Allow",
  "Action": ["ssm:GetParameter", "ssm:GetParameters", "ssm:GetParametersByPath"],
  "Resource": "arn:aws:ssm:us-east-1:123456789012:parameter/producao/api/*"
}
```

| Padrão | Efeito |
|---|---|
| App A só lê `/producao/appA/*` | Isolamento entre aplicações |
| Desenvolvedores leem `/desenvolvimento/*`, mas **não** `/producao/*` | Separação de ambientes |
| Pipelines escrevem, aplicações só leem | Menor privilégio |
| Negar `GetParameter` sem MFA em produção | Proteção extra |

## Parameter Store vs Secrets Manager

| Critério | Parameter Store | Secrets Manager |
|---|---|---|
| Foco | Configuração geral + segredos simples | **Segredos** com ciclo de vida |
| **Rotação automática** | Não nativa (faça com Lambda/Automation) | **Sim**, integrada (RDS, Redshift, etc.) |
| Custo | Standard **gratuito**; avançada paga | Pago por segredo/mês + chamadas |
| Tamanho | Menor (padrão) | Até dezenas de KB |
| Replicação entre regiões | Não nativa | **Sim** |
| Versionamento | Sim (versões e rótulos) | Sim (estágios `AWSCURRENT`, `AWSPREVIOUS`) |
| Integrações | CloudFormation, ECS, Lambda, EC2 | Idem + rotação e compartilhamento entre contas |
| Hierarquia | **Sim**, caminhos | Nomes (sem hierarquia verdadeira) |

```
 É só configuração (URL, flag, id)?                ─► Parameter Store (String)
 É segredo estático e pouco crítico, custo mínimo? ─► Parameter Store (SecureString)
 Preciso de ROTAÇÃO automática, replicação, compartilhamento entre contas?
                                                    ─► Secrets Manager
```

> [!tip] Combinação comum
> Use **Parameter Store** para **configurações** e referências, e **Secrets Manager** para **credenciais de banco** com rotação. O Parameter Store pode até **referenciar** um segredo do Secrets Manager (`/aws/reference/secretsmanager/<nome>`).

## Como as aplicações consomem parâmetros

| Origem | Como ler |
|---|---|
| **SDK/CLI** | `GetParameter`, `GetParametersByPath` |
| **Lambda** | SDK ou **extensão** com cache (menos chamadas) |
| **ECS/Fargate** | Campo `secrets` da task definition (`valueFrom` com o ARN do parâmetro) |
| **EKS** | Secrets Store CSI Driver (ASCP) |
| **CloudFormation** | Tipo `AWS::SSM::Parameter::Value<String>` ou *dynamic references* `{{resolve:ssm:/caminho}}` |
| **EC2/User data** | CLI no *boot* |
| **SSM Documents** | `{{ssm:/caminho}}` e `{{ssm-secure:/caminho}}` |
| **AMIs** | Parâmetros públicos da AWS: `/aws/service/ami-amazon-linux-latest/...` |

```yaml
# CloudFormation: busca a AMI mais recente do Amazon Linux via parâmetro público
Parameters:
  ImagemId:
    Type: AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>
    Default: /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64
```

```json
// ECS task definition: injeta segredo do Parameter Store
"secrets": [
  {"name": "DB_SENHA",
   "valueFrom": "arn:aws:ssm:us-east-1:123456789012:parameter/producao/api/db/senha"}
]
```

> [!tip] Use cache
> Em alto volume (Lambda, microsserviços), **cacheie** os parâmetros por alguns minutos. Isso reduz custo, latência e o risco de **throttling** (o Parameter Store tem limites de requisições por segundo).

## Parâmetros públicos da AWS

A AWS publica parâmetros prontos para **AMIs recentes**, **regiões**, **zonas** e **versões de serviços**.

```bash
aws ssm get-parameter \
  --name /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64 \
  --query Parameter.Value --output text
```

Isso elimina a necessidade de manter IDs de AMI fixos em templates e scripts, que ficam obsoletos.

## Eventos e auditoria

| Mecanismo | Uso |
|---|---|
| **CloudTrail** | Registra `GetParameter`, `PutParameter`, `DeleteParameter` (quem, quando) |
| **EventBridge** | Eventos de **mudança** e de **expiração** de parâmetros |
| **Config** | Histórico de configuração de parâmetros (conforme suporte) |

```json
{
  "source": ["aws.ssm"],
  "detail-type": ["Parameter Store Change"],
  "detail": {"name": [{"prefix": "/producao/"}], "operation": ["Update", "Delete"]}
}
```

Alarmes sobre **alterações em parâmetros de produção** são úteis para detectar mudanças indevidas.

## Exemplo prático: configuração por ambiente

1. Estrutura: `/producao/loja/db/host`, `/producao/loja/db/senha` (SecureString com CMK), `/producao/loja/feature/novo-checkout`.
2. A **role da aplicação** lê só `/producao/loja/*`; os desenvolvedores não têm acesso a `/producao/*/db/senha`.
3. A task do **ECS** injeta a senha pela definição de `secrets`.
4. A **flag** `novo-checkout` muda de `false` para `true` sem novo deploy; o **rótulo** `estavel` permite reverter.
5. Um **EventBridge** avisa o canal de operações quando algo em `/producao/*` é alterado.
6. A senha do banco migra depois para o **Secrets Manager** com rotação automática; o parâmetro passa a referenciá-lo.

## Troubleshooting

| Sintoma | Causa provável | Como resolver |
|---|---|---|
| `ParameterNotFound` | Nome/caminho/região incorretos | Conferir caminho completo e região |
| `AccessDeniedException` no SecureString | Falta `kms:Decrypt` | Ajustar política da chave e da role |
| Valor aparece cifrado | Faltou `--with-decryption` | Adicionar a opção |
| `ThrottlingException` | Muitas leituras por segundo | Cache; aumentar throughput; reduzir chamadas |
| `ParameterMaxVersionLimitExceeded` | Limite de versões com rótulos | Remover rótulos antigos |
| Valor grande rejeitado | Excede o limite da camada | Usar camada avançada ou outro armazenamento |
| ECS não inicia a task | Role de execução sem acesso ao parâmetro/KMS | Conceder permissões à execution role |
| Parâmetro "sumiu" | Política de expiração | Revisar parameter policies |

## Erros comuns e armadilhas

- **Guardar senhas como String** (texto claro) em vez de SecureString.
- **Chave KMS padrão** quando é preciso controle fino sobre quem descriptografa.
- **Permissão `ssm:GetParameter*` em `*`** em vez de por caminho.
- **Colocar segredos na linha de comando** e vazá-los no histórico.
- **Sem cache** em cargas de alto volume.
- **Misturar ambientes** na mesma árvore, dificultando o IAM.
- **Esperar rotação automática** que o Parameter Store não faz sozinho.
- **Ignorar alertas de alteração** em parâmetros críticos.

## 🧩 Quiz de Fixação

1. Quais são os três tipos de parâmetro?
2. Quais permissões são necessárias para ler um SecureString?
3. Para que servem os rótulos de versão?
4. Quando preferir Secrets Manager?
5. Como a hierarquia ajuda no controle de acesso?
6. Por que usar cache ao ler parâmetros?

**Respostas:**
1) String, StringList e SecureString.
2) `ssm:GetParameter` (ou variantes) e `kms:Decrypt` na chave que protege o parâmetro.
3) Dar apelidos às versões (como "estavel"), permitindo promover e reverter sem alterar o código que lê o parâmetro.
4) Quando é preciso rotação automática, replicação entre regiões ou compartilhamento entre contas de segredos como credenciais de banco.
5) Permite conceder permissões por prefixo de caminho (por exemplo, /producao/appA/*), isolando aplicações e ambientes.
6) Para reduzir custo, latência e risco de throttling, já que o serviço tem limites de requisições por segundo.
