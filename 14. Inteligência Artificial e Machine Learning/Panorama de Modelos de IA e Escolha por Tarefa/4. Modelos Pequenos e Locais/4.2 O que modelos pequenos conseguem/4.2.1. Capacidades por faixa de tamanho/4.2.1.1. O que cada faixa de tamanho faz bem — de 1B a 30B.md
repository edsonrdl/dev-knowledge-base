# 4.2.1.1. O que cada faixa de tamanho faz bem — de 1B a 30B
#ia #llm #slm #capacidades

> [!warning] Heurísticas
> As faixas abaixo combinam o que os comparativos de 06/nov/2026 relatam (por exemplo, que o tool calling melhora bastante de menos de 2B para ~4B) com a prática geral. **Teste na sua tarefa e no seu idioma.** Modelos pequenos variam muito de uma família para outra.

## Ideia central

Tamanho não define tudo, mas dá uma boa **primeira estimativa** do que esperar. Modelos pequenos são bons em tarefas **estreitas, bem especificadas e com formato fixo**; ficam para trás em raciocínio aberto e conhecimento amplo.

> **Analogia:** especialistas. Um técnico faz muito bem o que treinou; um professor titular entende o contexto geral.

## Faixas e capacidades

| Faixa | Faz bem | Faz mal |
|---|---|---|
| **≤ 1B** (ex.: Qwen3.5-0.8B, Llama 3.2 1B, LFM2.5 1.2B) | Classificação simples, detecção de intenção, reescrita curta, autocompletar; roda em celular e CPU | Tool calling confiável, raciocínio, instruções longas |
| **2B a 4B** | Extração em formato fixo, resumo, tool calling básico, RAG simples | Raciocínio de várias etapas, código complexo |
| **7B a 9B** | Agentes locais simples, resumo e Q&A sobre documentos, código de apoio, tool calling decente | Tarefas muito longas ou ambíguas |
| **12B a 15B** | Bom uso geral, mais robustez em instruções, multimodal em alguns casos (Gemma 4 12B) | Fronteira em raciocínio e código agêntico |
| **20B a 35B** | Assistente de código privado, análise, escrita de boa qualidade (Qwen3.8-27B) | Ainda atrás dos modelos de topo em tarefas longas |
| **> 70B / MoE grande** | Perto da fronteira, mas exige servidor | Custo de hospedagem |

```
 Qualidade em tarefa aberta
   ▲
   │                                  ╭──── fronteira
   │                       ╭──────────╯
   │              ╭────────╯   ← 20-35B
   │        ╭─────╯  ← 7-15B
   │  ╭─────╯  ← 2-4B
   │──╯  ← ≤1B
   └──────────────────────────────► tamanho
```

## Estratégias para extrair mais de um modelo pequeno

- **Especialize:** prompt curto, formato fixo e exemplos (few-shot).
- **Saída estruturada:** JSON com esquema, gramática ou *constrained decoding*.
- **Ajuste fino** leve (LoRA) para uma tarefa estreita.
- **RAG:** entregue o conhecimento no contexto em vez de esperar que ele o tenha memorizado.
- **Cascata:** o pequeno tenta primeiro; se a confiança for baixa, escala para um modelo maior.

## Exemplo prático

Classificação de e-mails de suporte em 12 categorias: um modelo de 4B com few-shot e saída JSON atinge acurácia próxima de um modelo de fronteira por uma fração do custo. Os e-mails ambíguos (confiança < 0,7) sobem para um modelo intermediário.

## Erros comuns e armadilhas

- Esperar conhecimento enciclopédico de modelos pequenos.
- Avaliar só em inglês e usar em português.
- Usar modelo ≤ 2B para tool calling com muitas ferramentas.
- Esquecer o limite de contexto efetivo, que é menor que o anunciado.

## 🧩 Quiz de Fixação

1. Em que tipo de tarefa um modelo pequeno brilha?
2. A partir de que tamanho o tool calling costuma ficar utilizável?
3. Cite duas estratégias para melhorar um modelo pequeno.
4. O que é uma cascata?

<details><summary>Respostas</summary>

1. Tarefas estreitas, bem especificadas e com formato fixo (classificação, extração).
2. Por volta de 4B.
3. Few-shot, saída estruturada, LoRA ou RAG.
4. O pequeno tenta primeiro e só escala para um modelo maior se a confiança for baixa.
