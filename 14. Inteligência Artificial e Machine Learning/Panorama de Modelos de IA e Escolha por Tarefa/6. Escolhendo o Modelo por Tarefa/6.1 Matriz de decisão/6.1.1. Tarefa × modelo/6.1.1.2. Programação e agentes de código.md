# 6.1.1.2. Programação e agentes de código
#ia #código #agentes #modelos

> [!warning] Dados de 06/nov/2026
> Papéis dos modelos vêm da documentação oficial (Anthropic, OpenAI, Google). Números de SWE-bench vêm de **blogs e relatos de fornecedores**, com harnesses diferentes e valores que variam entre fontes. Decida com um teste no **seu** repositório.

## Ideia central

Programar com IA tem três intensidades, e cada uma pede um tipo de modelo:

```
 Autocompletar   ──► rápido, latência de milissegundos
 Chat / edição   ──► intermediário
 Agente (horas)  ──► topo, com ferramentas e verificação
```

> **Analogia:** corretor ortográfico, revisor de texto e coautor. Cada um exige um nível diferente de confiança.

## Por intensidade

| Cenário | Tier | Exemplos do momento |
|---|---|---|
| **Autocompletar no editor** | Rápido/pequeno | Haiku 5.5, GPT-6 Luna, Flash-Lite, modelos de 7B a 27B locais |
| **Código do dia a dia, testes, explicações** | Intermediário | Sonnet 5.5, GPT-6.1 Sol, Gemini 3.8 Flash |
| **Refatoração grande, agentes de horas, depuração difícil** | Topo | Opus 5.5, Fable 5.1, GPT-6 Astra |
| **Repositório privado/offline** | Aberto | Qwen3.8-27B, Qwen3 Coder, Devstral 2, DeepSeek V4, GLM, Kimi, MiniMax |
| **Custo muito baixo em escala** | Aberto via API | DeepSeek V4 Flash, MiniMax M3 Flash |

A Anthropic descreve o Opus 5.5 como feito para "código agêntico de longa duração" e o Sonnet 5.5 como o melhor equilíbrio para código e agentes cotidianos. A Google posiciona o Gemini 3.8 Flash para código de longa duração e agentes autônomos.

## O que realmente diferencia modelos de código

1. **Persistência em tarefas longas:** continuar corretamente após dezenas de passos.
2. **Uso de ferramentas:** ler, editar, rodar testes, usar o terminal.
3. **Respeito às convenções** do projeto (CLAUDE.md, AGENTS.md).
4. **Honestidade:** dizer "não consegui" em vez de inventar.
5. **Custo por tarefa concluída**, e não por token.

## Esforço de raciocínio

Antes de subir de modelo, aumente o esforço (`effort`). Para depuração difícil, vale usar esforço alto; para renomear variáveis, esforço baixo.

## Exemplo prático

Migrar uma API de REST para gRPC em 40 serviços:

- Opus 5.5 planeja a migração e define o padrão.
- Subagentes Sonnet/Haiku aplicam o padrão serviço a serviço.
- Testes automáticos decidem o que passou; o que falha volta para o Opus.

## Erros comuns e armadilhas

- Escolher pelo ranking de SWE-bench sem testar no seu código.
- Usar o topo para tarefas que o intermediário resolve com testes.
- Aceitar código gerado sem rodar testes e revisão.
- Ignorar o custo do **contexto repetido** em sessões longas (use cache e compactação).

## 🧩 Quiz de Fixação

1. Que modelo para autocompletar no editor?
2. Antes de subir de modelo, que ajuste fazer?
3. Cite duas características que diferenciam modelos para agentes de código.
4. Por que medir custo por tarefa concluída?

<details><summary>Respostas</summary>

1. Um modelo rápido e pequeno, com latência baixa.
2. Aumentar o esforço de raciocínio.
3. Persistência em tarefas longas, uso de ferramentas, respeito às convenções, honestidade.
4. Um modelo barato que erra e refaz pode sair mais caro que um forte que acerta de primeira.
