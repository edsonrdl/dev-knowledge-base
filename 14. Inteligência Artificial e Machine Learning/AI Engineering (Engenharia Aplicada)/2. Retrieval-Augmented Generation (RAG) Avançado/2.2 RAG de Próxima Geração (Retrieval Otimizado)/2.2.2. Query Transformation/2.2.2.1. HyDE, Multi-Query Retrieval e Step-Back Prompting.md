### HyDE, Multi-Query Retrieval e Step-Back Prompting

Os tópicos anteriores melhoram **como buscar**. Este melhora **o que se busca**: a pergunta do usuário. Perguntas reais são curtas, ambíguas, mal formuladas ou usam vocabulário diferente do dos documentos. **Query transformation** é a família de técnicas que usa um LLM para **reescrever, expandir ou abstrair** a pergunta antes do retrieval.

---

## O problema: a pergunta não se parece com a resposta

```
Usuário:  "meu pc tá lento depois da atualização"
Documento: "Após a atualização 24H2, o serviço SysMain pode elevar o uso de disco,
            reduzindo o desempenho. Desative-o em Serviços."

Problemas:
 • vocabulário diferente ("pc lento" × "reduzindo o desempenho");
 • a pergunta é curta e vaga;
 • pergunta e resposta têm "formas" diferentes (uma interrogativa, outra afirmativa).
```

Em embeddings, uma **pergunta** tende a estar mais perto de **outras perguntas** do que de **trechos de resposta**. Query transformation reduz essa lacuna.

**Analogia:** é um bom bibliotecário de referência. O leitor diz algo vago; o bibliotecário o reformula ("você quer saber sobre desempenho do Windows após updates?"), tenta termos alternativos e, se preciso, procura primeiro o assunto geral antes do detalhe.

---

## 1. HyDE (Hypothetical Document Embeddings)

### A ideia

Em vez de embutir a **pergunta**, o LLM escreve uma **resposta hipotética** (um documento fictício que responderia à pergunta). Embute-se **esse texto** e busca-se por ele. O trecho hipotético pode conter fatos errados; não importa: ele só precisa **parecer** com os documentos reais (mesmo estilo, vocabulário e estrutura) para que os vetores fiquem próximos.

```
Pergunta ─► LLM ─► "Resposta" hipotética (pode ter erros)
                          │ embedding
                          ▼
               busca nos vetores dos documentos REAIS
                          │
                          ▼
             trechos reais mais parecidos com a resposta hipotética
             (a resposta final é gerada só com os trechos REAIS)
```

Fluxo comparado:

```
RAG padrão:  embed(pergunta)                    ──► busca ──► trechos
HyDE:        embed(LLM(pergunta) = doc fictício) ──► busca ──► trechos
```

### Implementação

```python
PROMPT_HYDE = """Escreva um parágrafo curto, no estilo de um manual técnico, que responderia
à pergunta abaixo. Não se preocupe em ser exato; seja plausível e use terminologia técnica.

Pergunta: {pergunta}"""

def busca_hyde(pergunta: str, k: int = 10):
    hipotetico = chamar_llm(PROMPT_HYDE.format(pergunta=pergunta), temperature=0.3)
    vetor = embutir(hipotetico)                   # embeda o texto hipotético, não a pergunta
    return banco.buscar(vetor, k=k)

# Variante: embutir pergunta + hipotético juntos (média dos vetores) para mais robustez
```

### Quando funciona bem ou mal

| Cenário | HyDE |
|---|---|
| Perguntas curtas/vagas sobre um domínio que o LLM conhece | **Bom**: gera vocabulário técnico |
| Corpus com estilo uniforme (manuais, artigos) | Bom |
| Busca zero-shot sem dados de fine-tuning | Bom (aumenta recall sem treino) |
| Domínios muito **específicos/privados** (o LLM não conhece) | **Arriscado**: o hipotético inventa termos e desvia a busca |
| Perguntas já detalhadas e com termos exatos | Pouco ganho; pode piorar |
| Sensível a latência/custo | Adiciona uma chamada de LLM por consulta |

> [!warning] Alucinação como ferramenta, com cuidado
> O texto hipotético serve só como "isca" de busca e **nunca** deve ser usado como fonte da resposta final. Se o LLM não conhece o domínio, a isca pode puxar documentos errados: meça no golden dataset.

## 2. Multi-Query Retrieval

### A ideia

Uma única formulação pode falhar. O **Multi-Query** pede ao LLM várias **reformulações** da pergunta (ângulos, sinônimos, níveis de detalhe), executa **uma busca por variação** e **funde** os resultados (tipicamente com RRF, tópico 2.2.1.1).

```
Pergunta: "meu pc tá lento depois da atualização"
                │ LLM gera N variações
                ▼
  v1: "desempenho reduzido do Windows após atualização"
  v2: "alto uso de disco ou CPU após update do sistema"
  v3: "como reverter ou corrigir lentidão pós-atualização"
                │ busca para cada variação (em paralelo)
                ▼
  lista1  lista2  lista3 ──► RRF / união com deduplicação ──► top-N final
```

**Analogia:** é perguntar a mesma coisa a três pessoas usando palavras diferentes: quem sabe a resposta tende a aparecer em pelo menos uma delas.

### Implementação

```python
from concurrent.futures import ThreadPoolExecutor

PROMPT_MQ = """Gere {n} reformulações diferentes da pergunta abaixo para busca em uma base técnica.
Varie vocabulário, nível de detalhe e ângulo. Uma por linha, sem numeração.

Pergunta: {pergunta}"""

def multi_query(pergunta: str, n: int = 4, k: int = 20, top: int = 10):
    variacoes = chamar_llm(PROMPT_MQ.format(n=n, pergunta=pergunta), temperature=0.7).splitlines()
    consultas = [pergunta] + [v.strip() for v in variacoes if v.strip()]     # inclui a ORIGINAL
    with ThreadPoolExecutor() as pool:
        listas = list(pool.map(lambda q: [d["id"] for d in busca_hibrida(q, k=k)], consultas))
    return rrf(listas, k=60, top=top)                                         # funde os rankings
```

Linha a linha: a pergunta original é **sempre mantida** entre as consultas; as buscas rodam em paralelo para não somar latência; a fusão por RRF premia documentos achados por várias formulações.

### Variações

| Variação | Descrição |
|---|---|
| **Decomposição (sub-perguntas)** | Quebra uma pergunta composta em partes: "Compare o plano A e o B" → "O que inclui o plano A?" + "O que inclui o plano B?" |
| **Query rewriting conversacional** | Reescreve a pergunta usando o histórico: "e o prazo?" → "qual o prazo de rescisão do contrato Acme?" |
| **RAG-Fusion** | Multi-query + RRF (exatamente o padrão acima) |
| **Expansão de termos** | Acrescenta sinônimos e siglas expandidas (LGPD → Lei Geral de Proteção de Dados) |

A **reescrita conversacional** merece destaque: em chatbots, perguntas de acompanhamento ("e o valor?") são inúteis para o retrieval sem o contexto da conversa. Resolver correferências antes de buscar é uma das melhorias mais simples e valiosas.

```python
PROMPT_REESCRITA = """Dada a conversa e a última pergunta, reescreva a última pergunta para que seja
compreensível sozinha (sem pronomes ou referências implícitas). Responda apenas com a pergunta.

Conversa: {historico}
Última pergunta: {pergunta}"""
```

### Trade-offs

| Aspecto | Efeito |
|---|---|
| **Recall** | Aumenta, especialmente para perguntas ambíguas |
| **Custo/latência** | +1 chamada de LLM + N buscas (paralelizáveis) |
| **Ruído** | Variações ruins puxam resultados irrelevantes; o reranker (2.2.1.2) mitiga |
| **Número de variações** | 3 a 5 é suficiente; mais traz retornos decrescentes |

## 3. Step-Back Prompting

### A ideia

Dá um **passo atrás**: em vez de buscar pela pergunta específica, gera-se uma pergunta **mais geral e conceitual** sobre os princípios por trás dela. Busca-se com **ambas** (a original e a abstrata) e junta-se o contexto: **fatos específicos + conhecimento de base**.

```
Pergunta específica:  "O que acontece com a pressão de um gás ideal se o volume
                       cair pela metade a temperatura constante?"
Pergunta step-back:   "Quais são as leis que relacionam pressão e volume de gases ideais?"

Busca (específica) ─► exemplos e casos          ┐
Busca (step-back)  ─► Lei de Boyle, princípios  ├─► contexto combinado ─► LLM raciocina e responde
```

**Analogia:** antes de resolver um problema de física específico, você revisa a fórmula geral. Entender o princípio ajuda a resolver o caso.

### Implementação

```python
PROMPT_STEPBACK = """Reformule a pergunta como uma pergunta mais geral e conceitual, que busque os
princípios ou o contexto necessários para respondê-la.

Exemplos:
Pergunta: "Qual era o presidente do Brasil quando a empresa X foi fundada em 1998?"
Mais geral: "Qual a história e a data de fundação da empresa X?"

Pergunta: {pergunta}
Mais geral:"""

def busca_stepback(pergunta: str, k: int = 6):
    geral = chamar_llm(PROMPT_STEPBACK.format(pergunta=pergunta), temperature=0)
    especificos = busca_hibrida(pergunta, k=k)
    conceituais = busca_hibrida(geral, k=k)
    return deduplicar(especificos + conceituais)                 # contexto com os dois níveis
```

### Quando ajuda

| Cenário | Step-back? |
|---|---|
| Perguntas de raciocínio em ciência, direito, regras (precisam do princípio geral) | **Sim** |
| Perguntas muito específicas cuja resposta depende de um conceito geral | Sim |
| Perguntas factuais diretas ("qual o telefone da filial?") | Não |
| Perguntas em que o contexto geral aumenta o ruído | Cuidado |

## Roteamento: escolher a técnica conforme a pergunta

Aplicar todas as técnicas em toda consulta é caro. Um **roteador** (classificador barato) escolhe:

```
Pergunta ──► classificador (LLM pequeno)
               │
               ├─ "follow-up conversacional"  ─► reescrita com histórico
               ├─ "composta / comparativa"    ─► decomposição em sub-perguntas
               ├─ "vaga / curta"              ─► multi-query ou HyDE
               ├─ "conceitual / de princípio" ─► step-back
               └─ "específica, com termos exatos" ─► busca direta (híbrida), sem transformação
```

Esse padrão é a ponte para o **RAG adaptativo/agêntico** (domínio 4), em que o próprio agente decide como buscar.

## Comparativo

| Técnica | Atua sobre | Melhora | Custo extra | Risco |
|---|---|---|---|---|
| **Reescrita conversacional** | Correferências do chat | Perguntas de acompanhamento | 1 chamada barata | Baixo |
| **Multi-Query / RAG-Fusion** | Formulação | Recall em perguntas ambíguas | 1 chamada + N buscas | Ruído |
| **Decomposição** | Perguntas compostas | Perguntas multi-parte | 1 chamada + N buscas | Sub-perguntas mal feitas |
| **HyDE** | Representação vetorial | Lacuna pergunta↔documento | 1 chamada | Isca errada em domínios desconhecidos |
| **Step-back** | Nível de abstração | Perguntas de raciocínio | 1 chamada + 1 busca | Contexto genérico demais |

---

## Medindo o efeito

```
1. Golden dataset com perguntas REAIS (curtas, vagas, com erros), não perguntas limpas.
2. Linha de base: busca direta (híbrida + reranking).
3. Teste cada técnica isoladamente: Recall@k, MRR, Hit Rate e qualidade final (Ragas).
4. Registre também latência p95 e custo por consulta.
5. Adote apenas o que melhora a métrica de forma que justifique custo e latência.
```

## Exemplo prático: central de ajuda de software

```
Perguntas reais: "não consigo exportar", "e se for pelo celular?", "diferença entre o plano pro e o business".

Pipeline:
 1. Reescrita conversacional: "e se for pelo celular?" → "como exportar relatório pelo app no celular?".
 2. Roteador:
      "não consigo exportar"        → multi-query (formatos, permissões, erros comuns)
      "diferença entre pro e business" → decomposição (2 sub-perguntas) + RRF
      "como funciona a política de privacidade de dados?" → step-back (princípios) + específica
 3. Busca híbrida + reranking nos candidatos de cada consulta.
 4. LLM responde só com os trechos reais, citando a fonte.

Resultado esperado: Recall@10 maior nas perguntas curtas/vagas; latência +300–800 ms
                    (medir e decidir se compensa por tipo de pergunta).
```

## Erros comuns e armadilhas

- **Descartar a pergunta original**: sempre inclua-a entre as consultas.
- **Usar o texto hipotético do HyDE como resposta ou fonte**.
- **HyDE em domínio privado/desconhecido** sem validar: a isca desvia a busca.
- **Variações demais** (10+) sem reranking: ruído e custo.
- **Aplicar todas as técnicas sempre**: latência e custo sem ganho; use roteamento.
- **Não resolver correferências** em chats ("e o prazo?").
- **Avaliar só com perguntas bem escritas**: o ganho aparece nas perguntas reais, ruins.
- **Esquecer deduplicação** ao juntar resultados de várias buscas.
- **Temperature alta na reescrita** que altera o sentido da pergunta.

## 🧩 Quiz de Fixação

1. Como o HyDE melhora a busca e por que o texto hipotético não pode ser usado como fonte da resposta?
2. Qual a diferença entre multi-query e decomposição de pergunta?
3. Em que tipo de pergunta o step-back prompting ajuda e como o contexto é montado?

**Respostas:**
1) O LLM gera uma resposta hipotética, e o embedding dela (em vez da pergunta) é usado na busca, aproximando-se do estilo e vocabulário dos documentos reais e reduzindo a lacuna entre pergunta e resposta. O texto pode conter fatos errados, servindo só como isca de busca; a resposta final deve ser gerada apenas a partir dos trechos reais recuperados.
2) Multi-query gera várias reformulações da mesma pergunta (sinônimos, ângulos) para aumentar o recall e funde os resultados (RAG-Fusion, RRF). A decomposição divide uma pergunta composta em sub-perguntas diferentes, cada uma com seu retrieval, cobrindo partes distintas do problema (ex.: comparar dois planos).
3) Ajuda em perguntas de raciocínio que dependem de princípios ou conceitos gerais (ciência, regras, direito). Gera-se uma pergunta mais abstrata, busca-se com ela e com a original, e combina-se o contexto de fatos específicos com o conhecimento conceitual para o LLM raciocinar.
