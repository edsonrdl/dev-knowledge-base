### Tabela de Decisão Consolidada — Qual Ferramenta de Extração Usar para Cada Necessidade

Nos tópicos 2.3.1 e 2.3.2 você conheceu seis ferramentas isoladamente. Este arquivo as **reúne em um instrumento de decisão**: tabelas, fluxogramas e cenários para escolher a ferramenta certa (ou a combinação certa) sem reler tudo.

> [!note] Pré-requisitos
> Detalhes de cada ferramenta: *Crawl4AI, FireCrawl e Scrape GraphAI* (2.3.1.1) e *MegaParser, Docling, LlamaParse e Extract Thinker* (2.3.2.1). Visão introdutória das categorias: 0.2.4.1.

---

## Passo 0: a pergunta que vem antes da ferramenta

Antes de comparar ferramentas, responda **quatro perguntas**. Elas eliminam a maioria das opções.

| # | Pergunta | Por que importa |
|---|---|---|
| 1 | **Qual é a fonte?** Web (HTML) ou arquivo (PDF/Office/imagem)? | Separa crawlers de parsers |
| 2 | **Qual é o objetivo?** Indexar o conteúdo inteiro (RAG) ou extrair campos específicos (dados)? | Separa "texto estruturado" de "objeto tipado" |
| 3 | **Qual a restrição de dados?** Podem sair da empresa? | Elimina APIs de terceiros se não |
| 4 | **Qual a escala e o orçamento?** Dezenas, milhões de páginas? Custo por página aceitável? | Separa SaaS de self-hosted |

```
                        FONTE?
              ┌───────────┴────────────┐
            WEB                     ARQUIVO
              │                        │
        OBJETIVO?                  OBJETIVO?
     ┌────────┴────────┐        ┌─────┴──────────┐
   TEXTO p/ RAG     CAMPOS    INDEXAR (RAG)    CAMPOS
     │                 │         │                │
 Crawl4AI /      ScrapeGraphAI  Docling /      Extract
 Firecrawl       (ou Crawl4AI   LlamaParse /   Thinker
                  c/ CSS)       MegaParser
```

## Mapa geral: ferramenta × característica

| Ferramenta | Fonte | Objetivo | Execução | Custo | Ponto forte | Ponto fraco |
|---|---|---|---|---|---|---|
| **Crawl4AI** | Web | Texto/Markdown (e CSS) | Self-hosted | Infra | Escala, controle, privacidade | Você opera; anti-bot por sua conta |
| **Firecrawl** | Web | Texto/Markdown, extract | API (+ self-host) | Por página | Rapidez de adoção, anti-bot | Custo em escala; dados em terceiros |
| **ScrapeGraphAI** | Web | JSON por prompt | Lib + LLM | Tokens | Sem seletores frágeis | Custo/variabilidade; pouca escala |
| **MegaParser** | Arquivos | Texto/JSON estruturado | Local | Infra | Multi-formato | Menos documentado; validar |
| **Docling** | Arquivos | Markdown/JSON estruturado | **Local** | Infra (grátis) | PDF complexo, privacidade | Mais pesado/lento |
| **LlamaParse** | Arquivos (PDF+) | Markdown rico | **API** | Por página | Interpreta tabelas/gráficos | Dados saem; custo |
| **Extract Thinker** | Arquivos | **Objeto tipado** | Lib + LLM | Tokens | Campos validados (Pydantic) | Não indexa o documento |

## Tabela de decisão por necessidade

| Necessidade | Ferramenta recomendada | Alternativa | Justificativa curta |
|---|---|---|---|
| Documentação/blog em **Markdown** para RAG, volume alto | **Crawl4AI** | Firecrawl | Sem custo por página; recoleta barata |
| **Protótipo rápido** de RAG sobre um site | **Firecrawl** | Crawl4AI | Poucas linhas de código, sem infraestrutura |
| Site com **forte proteção anti-bot** | **Firecrawl** (gerenciado) | Crawl4AI + proxies | O serviço trata proxies e bloqueios |
| **Listar todas as URLs** de um site | Firecrawl *Map* / sitemap.xml | Crawl4AI | Sem baixar o conteúdo |
| Campos de **produtos** (nome, preço) em layout estável, alto volume | **Crawl4AI com extração CSS** | — | Determinístico e sem custo de LLM |
| Campos de **vários sites com layouts diferentes/instáveis** | **ScrapeGraphAI** | Firecrawl Extract | Descreve-se em linguagem natural; sobrevive a mudanças |
| **PDF simples** (texto corrido) | Docling | LlamaParse | Ambos servem; escolha por privacidade/custo |
| **PDF complexo** (colunas, tabelas aninhadas, equações) | **Docling** | LlamaParse | Análise de layout por visão computacional |
| PDF com **gráficos** que precisam ser descritos | **LlamaParse** (ou Docling + LLM multimodal) | — | Interpretação semântica por LLM |
| **PDF escaneado** | Docling (OCR integrado) | LlamaParse | Texto inexistente sem OCR |
| **Vários formatos** (PDF, DOCX, PPTX, XLSX) no mesmo corpus | **MegaParser** ou **Docling** | — | Pipeline único e metadados uniformes |
| **Notas fiscais, formulários, contratos** → campos | **Extract Thinker** | LLM + structured outputs direto | Schema Pydantic + validação |
| **Dados sensíveis** (jurídico, saúde, financeiro) | **Docling / MegaParser / Crawl4AI** (locais) | LLM local | Nada sai da infraestrutura |
| **Time pequeno**, sem capacidade de operar infra | Firecrawl + LlamaParse | — | Gerenciado; paga-se por conveniência |
| **Planilhas** (XLSX) com dados tabulares | MegaParser / leitura direta (pandas) | Docling | Dados tabulares merecem tratamento estruturado, não texto |

## Fluxogramas de decisão

### A) Dados da web

```
Preciso de dados da WEB
  │
  ├─ O site oferece API, feed, sitemap ou dados abertos? ──► USE-OS (mais estável e legal)
  │
  ├─ Quero o TEXTO do site para um RAG
  │     ├─ Prototipando / poucas páginas / anti-bot ──► Firecrawl
  │     └─ Milhares+ de páginas / recoleta frequente / privacidade ──► Crawl4AI
  │
  └─ Quero CAMPOS estruturados (preço, especificações)
        ├─ Layout estável e volume alto ──► Crawl4AI (CSS/XPath)
        └─ Layouts variados ou instáveis, volume baixo/médio ──► ScrapeGraphAI
```

### B) Arquivos

```
Preciso processar ARQUIVOS
  │
  ├─ Quero CAMPOS específicos (NF, contrato) ──► Extract Thinker
  │      (parser/OCR por baixo: Docling ou OCR de nuvem)
  │
  └─ Quero INDEXAR o conteúdo (RAG)
        ├─ Dados sensíveis OU alto volume ──► Docling (local)
        ├─ Gráficos/tabelas precisam ser "explicados" E dados podem ir à nuvem ──► LlamaParse
        └─ Corpus misto de formatos Office/PDF ──► MegaParser (ou Docling)
```

## Padrões de combinação (arquiteturas reais)

| Padrão | Composição | Quando |
|---|---|---|
| **Base de conhecimento web** | Crawl4AI → limpeza → chunking por títulos → embeddings | Documentação pública de produto |
| **Base documental corporativa** | Docling → HybridChunker → embeddings (+ metadados de acesso) | Políticas, contratos, relatórios |
| **Automação de documentos** | Docling (parse) → Extract Thinker (campos) → validação → ERP | Notas fiscais, formulários |
| **Monitoramento de preços** | Crawl4AI (CSS) + ScrapeGraphAI para sites problemáticos | Concorrência, e-commerce |
| **Pesquisa web sob demanda** | Firecrawl Search → LLM resume com citações | Agentes com acesso à web |
| **Relatórios com gráficos** | LlamaParse (nuvem) em dados não sensíveis + Docling nos sensíveis | Corpus misto por classificação de dados |

```
Exemplo "Automação de documentos":

PDF da nota fiscal ─► Docling (OCR + layout) ─► texto/tabelas
                                                   │
                                                   ▼
                              Extract Thinker + schema Pydantic NotaFiscal
                                                   │
                              ┌── soma(itens) == total? CNPJ válido? ──┐
                              ▼ sim                                     ▼ não
                          grava no ERP                         fila de revisão humana
```

## Checklist de decisão (use antes de fechar a escolha)

1. [ ] A fonte e o **objetivo** (indexar × extrair) estão claros?
2. [ ] Os dados **podem** sair da infraestrutura? (jurídico/LGPD validado)
3. [ ] Estimei o **volume** e o **custo por mês** (por página ou por token)?
4. [ ] Testei **2 candidatos** em 30–50 páginas reais difíceis?
5. [ ] Medi o **efeito no RAG** (Recall@k, faithfulness), não só a "beleza" do Markdown?
6. [ ] Há **validação** dos dados extraídos (formato, somas, dígitos verificadores)?
7. [ ] Defini **recoleta/reprocessamento incremental** (hash, versão do parser)?
8. [ ] Verifiquei **termos de uso, robots.txt e LGPD** (web) e licenças (software)?
9. [ ] O conteúdo extraído passa por **sanitização** contra prompt injection?
10. [ ] Registrei no catálogo a **versão da ferramenta** e a **decisão** (ADR)?

## Armadilhas de decisão

| Armadilha | Correção |
|---|---|
| Escolher por **popularidade** ("todo mundo usa X") | Testar nos seus documentos |
| Comparar só **qualidade**, ignorando custo e privacidade | Usar a matriz de critérios |
| Usar **uma ferramenta para tudo** | Combinar: parser para indexar + extrator para campos |
| Avaliar com **documentos limpos** | Incluir páginas difíceis e escaneadas |
| **SaaS em volume massivo** sem calcular o custo recorrente | Simular o custo mensal |
| **Self-hosted sem capacidade de operar** | Considerar gerenciado enquanto o time amadurece |
| Tratar **gráficos e tabelas** como texto | Escolher ferramenta com interpretação ou usar LLM multimodal |
| Esquecer **manutenção** (seletores CSS quebram) | Monitorar taxa de sucesso e ter alertas |

## Exemplo prático: três demandas, três decisões

```
Demanda 1: "Chatbot sobre nossa central de ajuda pública (1.800 artigos)."
  Fonte: web | Objetivo: indexar | Dados: públicos | Escala: média, recoleta semanal
  → Crawl4AI (custo zero por página; recoleta incremental por hash). Piloto inicial com Firecrawl.

Demanda 2: "Conferir 40 mil notas fiscais por mês e lançar no ERP."
  Fonte: arquivos | Objetivo: campos | Dados: sensíveis | Escala: alta
  → Docling local (parse/OCR) + Extract Thinker com LLM local ou contrato de privacidade;
    validação de totais; revisão humana para falhas (~3%).

Demanda 3: "Perguntar em linguagem natural sobre 5 mil relatórios trimestrais com gráficos."
  Fonte: arquivos | Objetivo: indexar | Dados: internos não regulados | Escala: média
  → LlamaParse (interpreta gráficos) para os relatórios; Docling para os documentos sensíveis;
    comparar Recall@5 nos dois caminhos antes de padronizar.
```

## Erros comuns e armadilhas

- **Pular o Passo 0** e começar pela ferramenta.
- **Confundir indexar com extrair**: parsers de indexação não entregam campos validados; extratores não indexam o documento.
- **Decidir sem medir** o efeito no retrieval e na resposta final.
- **Ignorar privacidade** ao escolher APIs.
- **Subestimar a manutenção** de scrapers por seletor.
- **Não prever reprocessamento** quando o parser é atualizado.
- **Deixar a escolha sem registro** (ninguém sabe por que se usa X).

## 🧩 Quiz de Fixação

1. Quais são as quatro perguntas do "Passo 0" e que decisão cada uma elimina?
2. Uma empresa precisa lançar campos de 40 mil notas fiscais por mês no ERP, com dados sensíveis. Que combinação você recomenda e que validação é indispensável?
3. Por que não se deve escolher uma ferramenta de extração apenas pela qualidade do Markdown gerado?

**Respostas:**
1) Fonte (web ou arquivo): separa crawlers de parsers; objetivo (indexar ou extrair campos): separa parsers/crawlers de extratores de campos; restrição de dados (podem sair da empresa?): elimina APIs de terceiros quando não podem; escala e orçamento: separa SaaS por página de soluções self-hosted.
2) Docling local para parsing/OCR e Extract Thinker com schema Pydantic para extrair os campos, com LLM local ou contrato de privacidade adequado. É indispensável validar o resultado: soma dos itens igual ao total, CNPJ com dígitos verificadores válidos, formatos de data, e enviar falhas a revisão humana.
3) Porque o que importa é o efeito final no sistema: Markdown bonito pode ocultar tabelas erradas, ordem de leitura trocada, alto custo por página ou violação de privacidade. A escolha deve combinar qualidade medida com Recall@k/faithfulness, custo, privacidade, escala e manutenção.
