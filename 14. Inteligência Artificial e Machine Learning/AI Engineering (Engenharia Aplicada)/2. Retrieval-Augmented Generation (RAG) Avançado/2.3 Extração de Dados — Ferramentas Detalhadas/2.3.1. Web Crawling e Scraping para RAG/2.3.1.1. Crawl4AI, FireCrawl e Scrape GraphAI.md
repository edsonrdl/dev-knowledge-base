### Crawl4AI, FireCrawl e Scrape GraphAI — Quando Usar Cada Ferramenta de Coleta Web

Muito do conhecimento que um RAG precisa está na web: documentação de produtos, base de ajuda, blogs, catálogos, legislação. Mas HTML bruto é cheio de menus, anúncios, scripts e rodapés. Ferramentas de **web crawling e scraping para RAG** transformam páginas em **texto limpo e estruturado** (geralmente Markdown ou JSON), pronto para chunking e embeddings.

---

## Crawling, scraping e o que muda para RAG

| Termo | Significado |
|---|---|
| **Crawling** | **Descobrir e percorrer** páginas seguindo links (de um site inteiro, por exemplo) |
| **Scraping** | **Extrair** conteúdo de uma página específica |
| **Mapping** | Listar as URLs de um site (sitemap) sem baixar tudo |
| **Extração estruturada** | Converter a página em campos tipados (JSON) segundo um schema |

**Analogia:** o crawler é o carteiro que percorre todas as ruas de um bairro (descoberta); o scraper abre uma caixa de correio específica e copia a carta (extração); a extração estruturada preenche um formulário com os dados da carta.

### O que o RAG precisa dessas ferramentas

```
Página web (HTML ruidoso)
  │  renderizar JavaScript (sites modernos carregam o conteúdo via JS)
  │  remover menus, anúncios, rodapés, cookies
  │  preservar título, hierarquia, listas, tabelas, links
  ▼
Markdown limpo  ──►  chunking (2.1.1)  ──►  embeddings  ──►  banco vetorial
  + metadados: url, título, data da coleta, hash do conteúdo
```

Formato preferido: **Markdown**. Mantém estrutura (títulos viram âncoras de chunking), consome poucos tokens e é legível por LLMs.

---

## As três ferramentas em foco

| Ferramenta | Natureza | Ideia central |
|---|---|---|
| **Crawl4AI** | Open-source (Python), roda local/self-hosted | Crawler assíncrono, otimizado para LLM, com navegador headless (Playwright) |
| **Firecrawl** | API (serviço gerenciado) e versão open-source auto-hospedável | "Transforme um site inteiro em Markdown pronto para LLM" via API simples |
| **ScrapeGraphAI** | Biblioteca Python open-source (+ API) | Scraping **guiado por prompt**: você descreve em linguagem natural o que extrair; o LLM monta o grafo de extração |

> [!warning] Recursos e preços mudam rápido
> Nomes de endpoints, limites de planos, modelos de preço e funcionalidades evoluem com frequência. Use este arquivo como guia de **quando escolher**; confirme detalhes na documentação atual.

---

## 1. Crawl4AI

### Características

- **Open-source e gratuito**, sem custo por página (você paga a infraestrutura e, se usar, o LLM).
- **Assíncrono** (alto desempenho em muitas URLs).
- Controla um **navegador headless** (Playwright): executa JavaScript, rola páginas, clica em botões, lida com carregamento dinâmico.
- Gera **Markdown limpo** com filtros de conteúdo (remove "ruído" por heurísticas e por relevância BM25).
- Extração estruturada por **CSS/XPath** (sem LLM, barato e determinístico) ou por **LLM** com schema.
- Suporta sessões, cookies e perfis de navegador (páginas atrás de login, quando permitido).
- Pode rodar em **Docker** como serviço.

### Exemplo básico

```python
import asyncio
from crawl4ai import AsyncWebCrawler

async def principal():
    async with AsyncWebCrawler() as crawler:
        resultado = await crawler.arun(url="https://docs.exemplo.com/guia")
        print(resultado.markdown)          # Markdown limpo da página
        print(resultado.metadata)          # título, descrição etc.

asyncio.run(principal())
```

### Extração estruturada sem LLM (CSS)

```python
import json
from crawl4ai import AsyncWebCrawler, CrawlerRunConfig
from crawl4ai.extraction_strategy import JsonCssExtractionStrategy

esquema = {
    "name": "produtos",
    "baseSelector": "div.produto",                      # cada item da lista
    "fields": [
        {"name": "nome",  "selector": "h2.titulo", "type": "text"},
        {"name": "preco", "selector": "span.preco", "type": "text"},
        {"name": "link",  "selector": "a",          "type": "attribute", "attribute": "href"},
    ],
}
config = CrawlerRunConfig(extraction_strategy=JsonCssExtractionStrategy(esquema))
# resultado.extracted_content → JSON com todos os produtos (custo zero de LLM)
```

(API ilustrativa; a sintaxe varia entre versões do Crawl4AI.)

### Prós e contras

| Prós | Contras |
|---|---|
| Gratuito, controle total, sem enviar dados a terceiros | Você opera infraestrutura (navegadores consomem RAM/CPU) |
| Muito flexível (JS, interação, sessões) | Curva de aprendizado maior; ajuste fino por site |
| Extração CSS barata e rápida | Anti-bot/CAPTCHAs: você resolve (ou não) por conta própria |
| Ideal para volume alto | Sem SLA/suporte comercial |

**Quando escolher:** volume grande, orçamento limitado, dados sensíveis (self-hosted), necessidade de controle fino e equipe técnica capaz de operar.

## 2. Firecrawl

### Características

- **API pronta**: você envia a URL e recebe Markdown, HTML ou JSON; a infraestrutura (navegadores, proxies, retentativas) fica com o serviço.
- Principais operações:

| Operação | O que faz |
|---|---|
| **Scrape** | Uma URL → conteúdo limpo (Markdown/JSON/screenshot) |
| **Crawl** | Percorre um site inteiro seguindo links, com limites de profundidade e padrões de URL |
| **Map** | Lista rapidamente todas as URLs de um site |
| **Extract** | Extrai dados estruturados por schema/prompt com LLM |
| **Search** | Busca na web e já devolve o conteúdo das páginas |

- Lida com **JavaScript**, conteúdo dinâmico e muitas proteções comuns (por conta do serviço gerenciado).
- Existem **SDKs** (Python, Node) e integrações nativas com LangChain, LlamaIndex, Dify, etc.
- Há opção **open-source/self-hosted** (com menos recursos que o serviço gerenciado).

### Exemplo

```python
from firecrawl import FirecrawlApp

app = FirecrawlApp(api_key="...")                       # chave via variável de ambiente, nunca no código

# Uma página
pagina = app.scrape_url("https://docs.exemplo.com/guia", formats=["markdown"])

# Site inteiro (limitado)
site = app.crawl_url("https://docs.exemplo.com", limit=100,
                     scrape_options={"formats": ["markdown"]})
for doc in site.data:
    indexar(doc.markdown, metadados={"url": doc.metadata["sourceURL"]})
```

(Assinaturas variam por versão do SDK.)

### Prós e contras

| Prós | Contras |
|---|---|
| **Mais rápido de colocar no ar**: poucas linhas de código | **Custo por página/crédito** (escala cara com milhões de páginas) |
| Sem operar navegadores e proxies | Dados passam por serviço de terceiros |
| Bom tratamento de sites difíceis | Menos controle fino que ferramenta própria |
| Crawl/map/search no mesmo serviço | Dependência de fornecedor e de limites de plano |

**Quando escolher:** prototipagem rápida, equipes pequenas, volume moderado, sites com defesas anti-bot, quando o tempo de entrega pesa mais que o custo por página.

## 3. ScrapeGraphAI

### Características

- **Scraping orientado por prompt:** você diz *o que* quer, não *como* extrair.
- Usa um **LLM** para interpretar a página e montar o fluxo de extração (um "grafo" de passos: buscar, analisar, gerar resposta).
- Retorna **JSON estruturado** conforme sua descrição (ou schema Pydantic).
- Aceita fontes diversas: URLs, HTML local, XML, e pode combinar **várias páginas** (multi) ou **busca web** (SearchGraph).
- Funciona com LLMs da nuvem ou **locais** (Ollama).

### Exemplo

```python
from scrapegraphai.graphs import SmartScraperGraph

config = {
    "llm": {"model": "openai/gpt-4o-mini", "api_key": "..."},   # ou um modelo local via Ollama
    "verbose": False,
}
scraper = SmartScraperGraph(
    prompt="Liste o nome, o preço e a avaliação de cada produto da página",
    source="https://loja.exemplo.com/categoria/notebooks",
    config=config,
)
resultado = scraper.run()      # dict/JSON com os campos pedidos
```

Linha a linha: o `prompt` descreve a informação desejada; o `source` aponta a página; o LLM lê o conteúdo e devolve o JSON, sem seletores CSS escritos à mão.

### Prós e contras

| Prós | Contras |
|---|---|
| **Sem seletores frágeis**: sobrevive a mudanças de layout | **Custo de LLM por página** (tokens) |
| Ideal para extração **estruturada** com poucos exemplos | Mais lento e **não determinístico** (resultados podem variar) |
| Rápido para protótipos de dados de nicho | Risco de alucinação/omissão: valide com schema |
| Aceita LLM local (privacidade) | Menos adequado para crawl em massa de milhões de páginas |

**Quando escolher:** extrair **campos específicos** de poucos sites ou de layouts que mudam muito, sem querer manter seletores; volumes pequenos a médios.

## Comparativo direto

| Critério | **Crawl4AI** | **Firecrawl** | **ScrapeGraphAI** |
|---|---|---|---|
| **Modelo** | Open-source, self-hosted | API gerenciada (+ self-host limitado) | Open-source + API |
| **Foco** | Crawl + Markdown em escala | Crawl + Markdown + extract "pronto" | Extração estruturada por prompt |
| **Custo** | Infra própria (sem custo por página) | Por crédito/página | Tokens de LLM por página |
| **Facilidade de início** | Média | **Alta** | Alta |
| **Controle fino** | **Alto** | Médio | Médio |
| **Escala (milhões de páginas)** | **Excelente** (custo baixo) | Boa, porém cara | Fraca (custo de LLM) |
| **JS/dinâmico** | Sim (Playwright) | Sim | Sim (via navegador/fetch) |
| **Anti-bot** | Por sua conta | **Gerenciado** | Por sua conta |
| **Privacidade** | **Total** (local) | Dados passam pelo serviço | Total com LLM local |
| **Saída principal** | Markdown / JSON | Markdown / JSON | JSON |
| **Determinismo** | Alto (CSS) ou médio (LLM) | Médio | Baixo/médio |

### Árvore de decisão

```
O que você precisa?
 │
 ├─ Conteúdo de DOCUMENTAÇÃO/BLOG em Markdown para um RAG, site inteiro
 │    ├─ Volume grande ou dados sensíveis ou orçamento apertado ──► Crawl4AI
 │    └─ Protótipo rápido, equipe enxuta, site com anti-bot ─────► Firecrawl
 │
 ├─ Campos ESTRUTURADOS (preço, nome, especificações) de poucos sites
 │    ├─ Layout estável, volume alto ──► Crawl4AI com extração CSS (barato, determinístico)
 │    └─ Layout instável / muitos sites diferentes ──► ScrapeGraphAI (ou Firecrawl Extract)
 │
 └─ Só preciso da lista de URLs ──► Firecrawl Map / sitemap.xml
```

Em muitos projetos reais, as ferramentas se **combinam**: Firecrawl/Crawl4AI para a coleta em massa e um LLM com *structured outputs* (tópico 1.2.2.1) para extrair campos do Markdown já limpo.

## Boas práticas e aspectos legais/éticos

### Legalidade e etiqueta (essencial)

| Cuidado | Detalhe |
|---|---|
| **Termos de uso do site** | Muitos proíbem scraping automatizado; leia antes |
| **robots.txt** | Respeite as regras de rastreamento (`Disallow`, `Crawl-delay`) |
| **Direitos autorais** | Coletar não é o mesmo que poder reutilizar/redistribuir o conteúdo |
| **Dados pessoais (LGPD/GDPR)** | Evite coletar dados pessoais sem base legal |
| **Carga no servidor** | Limite a taxa de requisições (rate limit), use *User-Agent* identificável |
| **APIs oficiais** | Se o site oferece API/feed/sitemap/dados abertos, **prefira-os** |
| **Conteúdo atrás de login** | Só com autorização explícita |

> [!warning] Isto não é aconselhamento jurídico
> Regras variam por país e por site. Em projetos corporativos, valide com o jurídico antes de coletar em escala.

### Boas práticas técnicas

| Prática | Motivo |
|---|---|
| **Coleta incremental** (hash do conteúdo, `Last-Modified`, ETag) | Recoleta só o que mudou; economiza custo |
| **Guardar metadados** (`url`, `titulo`, `data_coleta`, `hash`) | Citação, atualização e remoção |
| **Deduplicar** (URLs canônicas, hash de conteúdo) | Evita vetores repetidos |
| **Filtrar por padrões de URL** | Evita áreas irrelevantes (login, carrinho, tags) |
| **Limitar profundidade e número de páginas** | Controle de custo e de escopo |
| **Tratar erros e retentativas** (backoff exponencial) | Robustez |
| **Limpar boilerplate** (menus, rodapé) | Menos ruído nos embeddings |
| **Agendar recrawls** conforme a volatilidade do conteúdo | Mantém o RAG atualizado |
| **Sanitizar o conteúdo coletado** | Páginas web podem conter *prompt injection* indireta (texto malicioso que tenta instruir o LLM) |

A última linha é crítica: **conteúdo coletado da web é dado não confiável**. Ao entregá-lo ao LLM, trate-o como dado, nunca como instrução (domínio 9.2 aborda segurança).

## Exemplo prático: RAG sobre a documentação de um produto

```
Objetivo: assistente de suporte baseado em docs.exemplo.com (~2.500 páginas, atualizadas semanalmente).

1. Descoberta: sitemap.xml (ou Firecrawl Map) → lista de URLs; filtro: /docs/** e /blog/**.
2. Coleta: Crawl4AI (self-hosted) em lote, 5 requisições concorrentes, respeitando robots.txt.
3. Limpeza: Markdown com filtro de conteúdo (remove nav/rodapé).
4. Metadados: url, titulo, secao, data_coleta, hash_conteudo.
5. Chunking recursivo por títulos (2.1.1.1) + parent-child (2.1.1.2).
6. Recoleta semanal incremental: compara hash; reindexa só páginas alteradas e remove as apagadas (404).
7. Segurança: sanitização de HTML oculto; o prompt do LLM trata o contexto como dado.
8. Avaliação: golden dataset de 80 perguntas reais de suporte (Recall@5, faithfulness).

Decisão de ferramenta: Crawl4AI pelo volume e pela recoleta frequente (custo por página do SaaS
seria recorrente); Firecrawl seria adequado para um piloto de 1 semana.
```

---

## Erros comuns e armadilhas

- **Ignorar robots.txt e termos de uso**: risco legal e bloqueio de IP.
- **Não renderizar JavaScript**: páginas SPA retornam HTML vazio.
- **Indexar HTML bruto**: menus e rodapés poluem os embeddings.
- **Recrawl total a cada atualização** (em vez de incremental): custo e tempo desperdiçados.
- **Não tratar páginas removidas**: o RAG continua citando conteúdo que não existe mais.
- **Usar LLM-scraper (ScrapeGraphAI) em milhões de páginas**: custo de tokens explosivo.
- **Seletores CSS frágeis** em sites que mudam: manutenção constante; considere extração por LLM.
- **Colocar chaves de API no código**.
- **Confiar no conteúdo web como instrução** (prompt injection indireta).
- **Coletar dados pessoais** sem base legal.

## 🧩 Quiz de Fixação

1. Qual a diferença entre crawling, scraping e mapping?
2. Para coletar 2 milhões de páginas de documentação com orçamento limitado e dados sensíveis, qual ferramenta é mais indicada e por quê? E para um piloto de uma semana?
3. Por que o conteúdo coletado da web deve ser tratado como "dado não confiável" ao ser enviado ao LLM?

**Respostas:**
1) Crawling é descobrir e percorrer páginas seguindo links; scraping é extrair o conteúdo de uma página específica; mapping é listar as URLs de um site sem baixar o conteúdo de todas.
2) Crawl4AI: open-source e self-hosted, sem custo por página, com controle total e sem enviar dados a terceiros, ideal para grande volume e dados sensíveis. Para um piloto rápido, o Firecrawl é mais indicado: API pronta, sem operar infraestrutura e com bom tratamento de sites difíceis, com custo por página aceitável em baixo volume.
3) Porque páginas web podem conter texto malicioso (prompt injection indireta) que tenta instruir o LLM a vazar dados ou mudar o comportamento. O conteúdo deve ser passado como dado delimitado, com instruções do sistema claras de que não deve ser obedecido como comando, além de sanitização e validação das saídas.
