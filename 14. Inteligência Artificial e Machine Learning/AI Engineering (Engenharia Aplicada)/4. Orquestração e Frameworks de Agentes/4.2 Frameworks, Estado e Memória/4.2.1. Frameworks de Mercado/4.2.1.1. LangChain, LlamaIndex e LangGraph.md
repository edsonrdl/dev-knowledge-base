### LangChain, LlamaIndex e LangGraph

Você já sabe **o que** um sistema de IA aplicada precisa fazer (domínios 1 a 3) e **como** um agente raciocina (4.1.1.1). A pergunta agora é **com que ferramenta** orquestrar tudo isso: carregar dados, chamar modelos, conectar ferramentas, manter estado, tratar erros. Este arquivo apresenta três frameworks centrais do ecossistema Python/TypeScript: **LangChain** e **LlamaIndex** (integração rápida, nível iniciante/intermediário) e **LangGraph** (produção, fluxos como grafos cíclicos com estado).

> [!warning] Frameworks mudam rápido
> APIs, nomes de módulos e recomendações oficiais desses projetos mudam com frequência (houve reorganizações importantes de pacotes e de interfaces de agentes). Os exemplos abaixo são **ilustrativos do conceito**; confirme a sintaxe na documentação da versão que for usar e fixe versões no `requirements`.

---

## Por que usar um framework (e quando não usar)

```
Sem framework:  você escreve o laço de chamadas, o parsing, os retries, o histórico, o roteamento,
                a integração com 20 provedores/bancos/ferramentas, o tracing...

Com framework:  ganha integrações prontas, abstrações padronizadas e observabilidade,
                ao custo de uma camada a mais (curva de aprendizado, abstrações que "vazam", mudanças de versão).
```

| Quando um framework ajuda | Quando pode atrapalhar |
|---|---|
| Muitas integrações (modelos, bancos vetoriais, loaders) | Caso simples: uma chamada de API + um prompt |
| Prototipagem rápida | Abstrações que escondem o que vai ao modelo (dificulta depurar custo e prompt) |
| Fluxos com estado, ramificações e retentativas | Dependência de um projeto que muda rápido |
| Equipe que compartilha convenções | Desempenho e controle finos necessários |

> Um caminho sensato: comece com o **SDK do provedor** para entender o essencial; adote framework quando a complexidade (integrações, estado, ramificações) justificar.

**Analogia:** frameworks são **ferramentas elétricas**. Para pendurar um quadro, um martelo (SDK direto) basta; para construir uma casa, a furadeira, a serra e o nível poupam semanas, mas exigem treino e cuidado.

   Alto nível     │  LlamaIndex                   │    │  LangChain (agentes, cadeias)     │

## 1. LangChain

### O que é

Framework de código aberto (Python e JavaScript/TypeScript) que oferece **componentes padronizados** e **integrações** para construir aplicações com LLM: modelos de chat, prompts, parsers de saída, retrievers, bancos vetoriais, ferramentas e agentes. Seu grande trunfo é o **ecossistema**: centenas de integrações com provedores, bancos de dados e serviços.

### Conceitos principais

| Conceito | O que é |
|---|---|
| **Chat Models** | Interface unificada para modelos de vários provedores (troca de modelo em uma linha) |
| **Prompt Templates** | Prompts parametrizados |
| **Output Parsers / Structured Output** | Convertem a saída em objetos tipados (Pydantic) |
| **Document Loaders / Text Splitters** | Carregam e dividem dados (PDF, web, bancos), base do RAG |
| **Embeddings / Vector Stores / Retrievers** | Camada de busca semântica |
| **Tools** | Funções que o modelo pode chamar |
| **Runnables e LCEL** (*LangChain Expression Language*) | Composição de componentes com o operador `|` (pipe) |
| **Agents** | LLM + ferramentas em laço (ReAct, 4.1.1.1) |
| **LangSmith** | Plataforma de observabilidade e avaliação (traces, datasets, testes) |

### Exemplo: cadeia com LCEL (RAG simples)

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough
from langchain.chat_models import init_chat_model

llm = init_chat_model("claude-sonnet-5-5", model_provider="anthropic", temperature=0)   # troca fácil de provedor
retriever = vector_store.as_retriever(search_kwargs={"k": 5})

prompt = ChatPromptTemplate.from_messages([
    ("system", "Responda SOMENTE com base no contexto. Se não souber, diga que não encontrou.\n\nContexto:\n{contexto}"),
    ("human", "{pergunta}"),
])

def formatar(docs): return "\n\n".join(d.page_content for d in docs)

cadeia = (
    {"contexto": retriever | formatar, "pergunta": RunnablePassthrough()}   # monta as entradas em paralelo
    | prompt                                                                # preenche o template
    | llm                                                                   # chama o modelo
    | StrOutputParser()                                                     # extrai o texto
)
resposta = cadeia.invoke("Qual o prazo de rescisão sem multa?")
```

Linha a linha: o `|` encadeia componentes (cada um é um *Runnable*, com `invoke`, `stream` e `batch` padronizados); o dicionário inicial executa o retriever e repassa a pergunta; o resultado flui até o parser.

### Exemplo: agente com ferramenta

```python
from langchain_core.tools import tool
from langchain.agents import create_agent          # nome e módulo variam entre versões

@tool
def consultar_estoque(sku: str) -> str:
    """Retorna a quantidade em estoque de um SKU."""
    return f"{buscar_estoque(sku)} unidades"

agente = create_agent(model="anthropic:claude-sonnet-5-5", tools=[consultar_estoque],
                      system_prompt="Você é um assistente de logística.")
resultado = agente.invoke({"messages": [{"role": "user", "content": "Quanto temos do SKU A-123?"}]})
```

(Interfaces de agentes do LangChain foram reformuladas em versões recentes, com os agentes construídos sobre o LangGraph; confirme a API vigente.)

### Pontos fortes e fracos

| Pontos fortes | Pontos fracos |
|---|---|
| **Maior ecossistema** de integrações | Abstrações em camadas podem **esconder** o prompt real e dificultar depuração |
| Troca de provedor/banco com poucas mudanças | Histórico de **mudanças frequentes** de API |
| Ótimo para prototipar | Para fluxos complexos com estado, o LangGraph é mais adequado |
| LangSmith para observabilidade | Dependências numerosas |

**Quando usar:** prototipagem rápida, RAG e agentes simples, quando se quer aproveitar integrações prontas.

## 2. LlamaIndex

### O que é

Framework (Python e TypeScript) **especializado em conectar LLMs aos seus dados**: ingestão, indexação, recuperação e geração de respostas. Nasceu como "GPT Index" e permanece a referência em **RAG** e em **agentes sobre dados e documentos**.

### Conceitos principais

| Conceito | O que é |
|---|---|
| **Data Connectors (LlamaHub)** | Centenas de loaders (PDF, Notion, Slack, bancos, web) |
| **Documents e Nodes** | Documentos e seus **chunks (nós)** com metadados e relações (pai/filho) |
| **Node Parsers** | Estratégias de chunking (frase, janela, hierárquico, semântico), tópicos 2.1.1 |
| **Indexes** | `VectorStoreIndex`, índices de resumo, de grafo de propriedades (GraphRAG), de palavras-chave |
| **Retrievers / Postprocessors** | Recuperação, reranking, substituição por janela (Small-to-Big), tópicos 2.2.1 |
| **Query Engines** | Pipeline "pergunta → recuperar → sintetizar resposta" |
| **Chat Engines** | Query engine com memória de conversa |
| **Agents / Workflows** | Agentes com ferramentas; **Workflows** orientados a eventos para fluxos assíncronos |
| **LlamaParse / LlamaCloud** | Parsing de documentos e serviços gerenciados (2.3.2.1) |
| **Ingestion Pipeline** | Transformações reutilizáveis com **cache** e deduplicação |

### Exemplo: RAG em poucas linhas

```python
from llama_index.core import SimpleDirectoryReader, VectorStoreIndex, Settings
from llama_index.llms.anthropic import Anthropic
from llama_index.embeddings.huggingface import HuggingFaceEmbedding

Settings.llm = Anthropic(model="claude-sonnet-5-5")
Settings.embed_model = HuggingFaceEmbedding(model_name="BAAI/bge-m3")

documentos = SimpleDirectoryReader("./contratos").load_data()      # carrega PDFs/arquivos
indice = VectorStoreIndex.from_documents(documentos)               # chunking + embeddings + índice
motor = indice.as_query_engine(similarity_top_k=5)                 # pipeline de pergunta e resposta

resposta = motor.query("Qual o prazo de rescisão sem multa no contrato Acme?")
print(resposta)                                                    # texto
for no in resposta.source_nodes:                                   # fontes para citação
    print(no.metadata.get("file_name"), no.score)
```

Poucas linhas entregam um RAG funcional, com **fontes** rastreáveis (`source_nodes`). Para produção, troque o índice em memória por um banco vetorial (Qdrant, pgvector) e adicione reranker e metadados (domínio 2).

### Pontos fortes e fracos

| Pontos fortes | Pontos fracos |
|---|---|
| **Melhor ergonomia para RAG** e dados | Menos amplo que o LangChain fora do universo de dados |
| Muitas estratégias de indexação/recuperação prontas | Abstrações de alto nível escondem detalhes; ajuste fino exige descer de nível |
| Ótimo ecossistema de parsing e conectores | API também evolui rápido |
| Rastreabilidade das fontes nativa | Para orquestração complexa de agentes, combina-se com outros |

**Quando usar:** o problema central é **dados e RAG** (muitos formatos, indexação sofisticada, citações).

### LangChain × LlamaIndex: sobreposição e complementaridade

Os dois projetos cresceram até se **sobrepor** (ambos têm RAG e agentes) e podem ser **usados juntos** (ex.: loaders e índices do LlamaIndex dentro de um fluxo LangGraph). Heurística: **LlamaIndex** quando o foco é **dados/RAG**; **LangChain** quando o foco é **ecossistema/integrações e agentes simples**.

## 3. LangGraph

### O problema que ele resolve

Cadeias lineares (LCEL) e agentes em laço simples funcionam até certo ponto. Aplicações reais pedem:

- **Ramificações condicionais** (se a classificação for X, vá por A; senão, por B);
- **Ciclos** (tentar, verificar, voltar e tentar de novo, tópico 4.1.1.1);
- **Estado compartilhado** entre etapas, persistente e recuperável;
- **Pausas para aprovação humana** (Human-in-the-Loop);
- **Paralelismo** e **retomada após falhas**.

Esses requisitos descrevem um **grafo com estado**, não uma cadeia. O **LangGraph** modela o fluxo exatamente assim.

### O modelo mental: grafo de estados

```
                  ┌────────────── ESTADO (compartilhado) ──────────────┐
                  │ {mensagens, documentos, tentativas, aprovado, ...} │
                  └─────────────────────────────────────────────────────┘
                       ▲  lido e atualizado por cada nó
   START ──► [classificar] ──► (condição) ──► [buscar] ──► [gerar] ──► [verificar]
                                    │                          ▲            │
                                    └─► [responder direto]     │       ok? ─┤
                                                               └── não ─────┘   ◄ CICLO (reflexão/retry)
                                                                          │ sim
                                                                          ▼
                                                                         END
```

| Conceito | O que é |
|---|---|
| **State (estado)** | Estrutura tipada (TypedDict/Pydantic) que carrega os dados entre nós; define como cada campo é combinado (**reducers**, ex.: acrescentar mensagens) |
| **Node (nó)** | Função que recebe o estado e retorna **atualizações** (um LLM, uma ferramenta, uma regra) |
| **Edge (aresta)** | Liga nós; pode ser **condicional** (função que decide o próximo nó) |
| **Cycle (ciclo)** | Arestas que voltam a nós anteriores: base de agentes e de loops de verificação |
| **Checkpointer** | **Persiste o estado** a cada passo (memória, SQLite, Postgres): permite retomar, voltar no tempo e conversar por *threads* |
| **Interrupt / HITL** | Pausa o grafo para aprovação ou edição humana e retoma depois |
| **Subgraphs** | Grafos aninhados (um agente especialista dentro de um supervisor) |
| **Send / paralelismo** | Dispara execução paralela (map-reduce) de nós |
| **Streaming** | Fluxo de tokens, eventos e atualizações de estado |
| **LangGraph Platform / LangSmith** | Implantação, execução durável e observabilidade (serviços opcionais) |

**Analogia:** é um **fluxograma executável** em que cada caixa é uma função, as setas decidem o caminho (inclusive voltar atrás) e uma **prancheta compartilhada** (o estado) registra tudo, com cópia de segurança a cada passo (checkpoint).

### Exemplo: agente de RAG com verificação e ciclo

```python
from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver

class Estado(TypedDict):
    pergunta: str
    documentos: list[str]
    resposta: str
    tentativas: int

def buscar(e: Estado) -> dict:
    return {"documentos": retriever_hibrido(e["pergunta"])}

def gerar(e: Estado) -> dict:
    resp = llm_responder(e["pergunta"], e["documentos"])
    return {"resposta": resp, "tentativas": e["tentativas"] + 1}

def verificar(e: Estado) -> str:                      # função de ROTEAMENTO (aresta condicional)
    fundamentada = checar_fidelidade(e["resposta"], e["documentos"])
    if fundamentada or e["tentativas"] >= 3:          # TETO de tentativas: evita ciclo infinito
        return "fim"
    return "refazer"

g = StateGraph(Estado)
g.add_node("buscar", buscar)
g.add_node("gerar", gerar)
g.add_edge(START, "buscar")
g.add_edge("buscar", "gerar")
g.add_conditional_edges("gerar", verificar, {"fim": END, "refazer": "buscar"})   # CICLO

app = g.compile(checkpointer=MemorySaver())           # em produção: Postgres/SQLite checkpointer
saida = app.invoke({"pergunta": "Qual o prazo de rescisão?", "tentativas": 0},
                   config={"configurable": {"thread_id": "usuario-42"}})          # memória por conversa
```

Linha a linha: o `Estado` define o que circula; cada função-nó devolve só as **atualizações** do estado; `add_conditional_edges` implementa o roteamento e o **ciclo** (reescrever a busca se a resposta não for fiel); o `tentativas >= 3` impede loops infinitos; o **checkpointer** salva o estado por `thread_id`, dando memória à conversa e permitindo retomar.

(Sintaxe e módulos do LangGraph evoluem; confirme na documentação atual.)

### Human-in-the-Loop com `interrupt`

```python
from langgraph.types import interrupt, Command

def aprovar_acao(e: Estado) -> dict:
    decisao = interrupt({"acao_proposta": e["acao"], "pergunta": "Aprovar execução?"})   # PAUSA o grafo
    return {"aprovado": decisao == "sim"}

# 1ª execução: o grafo para no interrupt e devolve a proposta ao humano.
# Depois:  app.invoke(Command(resume="sim"), config=mesma_thread)   → retoma de onde parou
```

Isso só é possível graças aos **checkpoints**: o estado fica salvo enquanto se espera horas ou dias pela aprovação.

### Padrões multi-agente no LangGraph

| Padrão | Estrutura |
|---|---|
| **Supervisor** | Um nó supervisor decide qual agente especialista chama (roteamento) e consolida |
| **Rede/Swarm** | Agentes transferem o controle entre si (*handoffs*) |
| **Hierárquico** | Supervisores de times dentro de um supervisor geral (subgrafos) |
| **Plan-and-Execute / Reflection / LATS** | Padrões de 4.1.1.1 implementados como grafos |

(Aprofundamento em topologias de grafos de agentes: domínio 4.4, Graph Engineering.)

### Pontos fortes e fracos

| Pontos fortes | Pontos fracos |
|---|---|
| **Controle explícito** do fluxo: nada de "mágica" do agente | Mais código e **curva de aprendizado** maior |
| **Estado persistente**, retomada e *time travel* (depurar voltando ao checkpoint) | Mais conceitos (estado, reducers, checkpointers) |
| **HITL** nativo | Ecossistema de plataforma/observabilidade atrelado ao LangSmith (opcional) |
| Ciclos, paralelismo e subgrafos | Para tarefas triviais, é excesso de engenharia |
| **Padrão de produção** de agentes de LLM em muitas empresas | API em evolução |

**Quando usar:** agentes e fluxos **de produção** com ramificações, ciclos, estado persistente, aprovação humana e necessidade de auditoria.

## Comparativo direto

| Critério | **LangChain** | **LlamaIndex** | **LangGraph** |
|---|---|---|---|
| **Foco** | Integrações e componentes; agentes simples | **Dados e RAG** | **Orquestração com estado** |
| **Abstração** | Alto nível | Alto nível (camadas) | **Baixo nível**, controle explícito |
| **Modelo de fluxo** | Cadeias (LCEL), agentes em laço | Query/Chat engines, Workflows | **Grafo com estado e ciclos** |
| **Estado persistente** | Limitado (memória básica) | Memória de chat / workflows | **Nativo** (checkpointers) |
| **Human-in-the-Loop** | Via LangGraph | Possível (workflows) | **Nativo** (interrupt) |
| **Ciclos/ramificações** | Limitado em cadeias | Workflows | **Central** |
| **Curva de aprendizado** | Baixa-média | Baixa-média | Média-alta |
| **Prototipagem** | **Muito rápida** | **Muito rápida (RAG)** | Média |
| **Produção complexa** | Servível; migrar para LangGraph se crescer | Servível para RAG | **Ideal** |
| **Observabilidade** | LangSmith | LlamaTrace/Arize/Langfuse e outros | LangSmith e outros |

### Árvore de decisão

```
Qual é o centro do problema?
 │
 ├─ DADOS e RAG (muitos formatos, indexação, citações)
 │     └─► LlamaIndex (RAG pronto)  ──(precisa de fluxo complexo?)──► orquestre com LangGraph
 │
 ├─ Prototipar RAG/agente simples com muitas integrações
 │     └─► LangChain
 │
 └─ Fluxo de PRODUÇÃO: ramificações, ciclos, estado, aprovação humana, retomada
       └─► LangGraph  (usando componentes do LangChain/LlamaIndex dentro dos nós)
```

### Combinação recomendada na prática

```
LangGraph (orquestra o fluxo e o estado)
   ├─ nó "recuperar"    → retriever do LlamaIndex (índices, reranking, parent-child)
   ├─ nó "gerar"        → modelo via LangChain (init_chat_model, structured output)
   ├─ nó "ferramentas"  → tools via MCP (4.1.2.1)
   ├─ nó "aprovar"      → interrupt (HITL)
   └─ checkpointer Postgres + traces no LangSmith/Langfuse
```

## Boas práticas

| Prática | Motivo |
|---|---|
| **Fixar versões** e ler *changelogs* | APIs mudam rápido |
| **Começar simples** (SDK/LCEL) e **migrar** para LangGraph quando surgir ciclo/estado/HITL | Evita over-engineering |
| **Ver o prompt final** (traces, LangSmith/Langfuse) | Abstrações escondem o que vai ao modelo |
| **Tetos em ciclos** (tentativas, tokens, tempo) | Evita loops e custo infinito |
| **Estado enxuto e tipado** | Menos tokens, menos bugs |
| **Checkpointer persistente em produção** (Postgres), não em memória | Sobrevive a reinícios |
| **Isolar a lógica de negócio** das abstrações do framework | Facilita trocar de framework |
| **Testes por nó** (funções puras) + avaliação ponta a ponta | Qualidade e regressão |
| **Observabilidade desde o início** | Depuração e custo |
| **Segurança nas ferramentas** (permissões mínimas, validação) | Domínio 5 |

## Exemplo prático: assistente de suporte com RAG, verificação e aprovação

```
Requisitos: responder dúvidas com base na base de conhecimento (citando fontes), verificar fidelidade,
            e, quando o cliente pedir reembolso, exigir aprovação humana antes de executar.

Arquitetura:
  • LlamaIndex: ingestão (Docling/LlamaParse), índice híbrido no Qdrant, retriever com reranker.
  • LangGraph: grafo com nós classificar → (duvida) buscar → gerar → verificar (ciclo ≤ 2)
                                           └ (reembolso) preparar_acao → interrupt(aprovação) → executar
  • LangChain: init_chat_model (troca de provedor), saída estruturada para a classificação.
  • Persistência: checkpointer Postgres (thread_id = ID do cliente), HITL assíncrono pela fila do atendente.
  • Observabilidade: traces (LangSmith/Langfuse), custo por thread, métricas de fidelidade (Ragas).

Evolução: começou como RAG de 20 linhas (LlamaIndex); o grafo entrou quando surgiram o ciclo de verificação
          e a aprovação de reembolso, os dois pontos que cadeias lineares não resolvem bem.
```

## Erros comuns e armadilhas

- **Adotar framework para um caso trivial** (uma chamada de API) e pagar a complexidade sem ganho.
- **Não conferir o prompt final**: custos e comportamento inesperados por abstrações ocultas.
- **Misturar versões** de pacotes LangChain/LangGraph/LlamaIndex incompatíveis.
- **Ciclos sem teto** no LangGraph: loops caros e infinitos.
- **Checkpointer em memória em produção**: estado perdido a cada reinício.
- **Estado enorme** (documentos inteiros em cada passo): custo e lentidão.
- **Usar LangChain para fluxos complexos com estado** em vez de migrar para o LangGraph.
- **Ignorar a observabilidade**: impossível depurar agentes sem traces.
- **Acoplar a regra de negócio ao framework**: dificulta migrar.
- **Seguir tutoriais antigos** com APIs descontinuadas.

## 🧩 Quiz de Fixação

1. Qual o foco principal de cada framework (LangChain, LlamaIndex, LangGraph) e como se complementam?
2. Que necessidades de uma aplicação indicam o uso do LangGraph em vez de uma cadeia LCEL?
3. Por que o checkpointer é essencial para Human-in-the-Loop e que precaução se deve ter com ciclos?

**Respostas:**
1) LangChain: integrações e componentes para aplicações com LLM (prototipagem e agentes simples). LlamaIndex: dados e RAG (conectores, indexação, recuperação e citações). LangGraph: orquestração de fluxos como grafos com estado, ciclos, HITL e persistência.
