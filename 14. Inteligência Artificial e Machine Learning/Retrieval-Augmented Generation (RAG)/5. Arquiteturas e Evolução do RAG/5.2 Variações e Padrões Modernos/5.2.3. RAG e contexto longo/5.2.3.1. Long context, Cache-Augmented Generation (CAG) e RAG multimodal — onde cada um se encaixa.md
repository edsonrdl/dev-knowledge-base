### Long context, Cache-Augmented Generation (CAG) e RAG multimodal — onde cada um se encaixa

À medida que os modelos ganham janelas de contexto enormes e caching de prompt, surgem perguntas legítimas: "ainda preciso de RAG?", "posso pré-carregar a base inteira no modelo?", "e se meus dados forem imagens e áudio?". Este arquivo posiciona três abordagens vizinhas do RAG — **contexto longo**, **CAG** e **RAG multimodal** — e mostra onde cada uma se encaixa, sem substituir o RAG, mas redefinindo quando ele é necessário.

> [!warning] Aviso
> Janelas de contexto, preços de cache e capacidades multimodais mudam rapidamente — os números abaixo são ordens de grandeza didáticas. O tópico **RAG Multimodal — Imagens, Áudio e Vídeo** tem guia próprio no Glossário; aqui só se faz o posicionamento. O código **não foi executado**.

## 1. Long context (contexto longo)

### A ideia
Em vez de recuperar trechos, **colocar documentos inteiros (ou a base inteira) no prompt**, aproveitando janelas de centenas de milhares ou milhões de tokens.

### Forças

| Força | Explicação |
|---|---|
| **Simplicidade** | Sem chunking, embeddings, índice nem retrieval |
| **Sem perda por retrieval** | Não existe o risco de "o trecho certo não foi recuperado" |
| **Raciocínio global** | O modelo vê relações entre partes distantes do documento |
| **Bom para tarefas de um único documento** | Resumir, comparar versões, revisar contrato, analisar relatório |

### Fraquezas

| Fraqueza | Explicação |
|---|---|
| **Custo por consulta** | Paga-se a base toda a cada chamada (mitigável com caching) |
| **Latência** | Processar centenas de milhares de tokens leva segundos a dezenas de segundos |
| **Atenção diluída** | A precisão pode cair em contextos enormes ("lost in the middle", ver 4.1.1.2) |
| **Limite de tamanho** | Bases corporativas costumam exceder qualquer janela |
| **Controle de acesso** | Difícil entregar "só o que o usuário pode ver" se tudo está no prompt |
| **Atualização** | Qualquer mudança exige remontar o contexto |
| **Citação** | Possível, mas depende de o modelo localizar o trecho exato |

**Analogia:** é entregar ao analista a pasta inteira do caso para ele ler tudo antes de responder. Ótimo para um caso; inviável para o arquivo da empresa inteira a cada pergunta.

## 2. CAG — Cache-Augmented Generation

### A ideia
Pré-carregar uma base **estável e relativamente pequena** no contexto **uma única vez**, e **reutilizar o estado computado** (KV cache / prompt caching) em todas as consultas seguintes. Assim se evita reprocessar o mesmo conteúdo e elimina-se a etapa de retrieval.

```
 RAG:  cada pergunta ─► busca ─► trechos ─► LLM
 CAG:  [conhecimento pré-carregado + cache] ──┐
       cada pergunta ────────────────────────┴─► LLM (reusa o cache; sem retrieval)
```

### Como se materializa

| Forma | Descrição |
|---|---|
| **Prompt caching de provedores** | O prefixo fixo (base de conhecimento) é cacheado; chamadas seguintes pagam menos pelo trecho reutilizado |
| **KV cache em modelos auto-hospedados** | O estado de atenção do prefixo é mantido em memória/GPU e reaproveitado |
| **Contexto fixo + perguntas variáveis** | A base fica no início do prompt (prefixo estável); a pergunta vai no final |

### Quando o CAG faz sentido

| Condição | Por quê |
|---|---|
| Base **pequena/média** que cabe na janela | Precisa caber inteira |
| Base **estável** (muda pouco) | Mudanças invalidam o cache |
| **Muitas consultas** sobre a mesma base | Amortiza o custo do carregamento |
| Latência de retrieval indesejada | Remove a etapa de busca |
| Mesmo conhecimento para todos os usuários | Sem diferenças de permissão |

### Limites

| Limite | Explicação |
|---|---|
| **Escala** | Não serve para bases grandes |
| **Frescor** | Atualizar = recarregar/recomputar o cache |
| **Permissões** | Cache compartilhado não distingue usuários — cuidado com conteúdo restrito |
| **Validade do cache** | Caches de provedores expiram em minutos/horas e têm regras de prefixo exato |
| **Qualidade em contexto enorme** | Valem os mesmos cuidados de atenção e "lost in the middle" |

```python
# Pseudocódigo didático — NÃO executado. A API de caching varia por provedor.

BASE = carregar_base_estavel()          # ex.: manual de produto de 120 mil tokens, pouco alterado

def responder_cag(pergunta, llm):
    mensagens = [
        {"role": "system", "content": INSTRUCOES},              # parte fixa
        {"role": "user", "content": [
            {"type": "text", "text": BASE, "cache": True},      # PREFIXO ESTÁVEL marcado p/ cache
            {"type": "text", "text": f"Pergunta: {pergunta}"},   # parte variável vem DEPOIS
        ]},
    ]
    return llm(mensagens)   # chamadas seguintes reaproveitam o cache do prefixo (se válido)
# Regra de ouro: tudo que é fixo no INÍCIO, tudo que varia no FIM — senão o cache não é reaproveitado.
```

## 3. RAG multimodal

### A ideia
Estender o RAG para **fontes e consultas que não são só texto**: imagens, diagramas, tabelas em imagem, áudio, vídeo, slides, PDFs escaneados.

### Abordagens principais

| Abordagem | Como funciona | Exemplo |
|---|---|---|
| **Converter para texto** | Transcrever áudio/vídeo (ASR), legendar imagens, OCR em documentos; indexar o texto | Reuniões gravadas viram transcrições indexadas |
| **Embeddings multimodais** | Um modelo (ex.: família CLIP e sucessores) mapeia texto e imagem para o mesmo espaço vetorial | Buscar imagens por descrição textual |
| **Recuperar páginas como imagem** | Indexa **imagens de páginas** de PDF com modelos de visão-linguagem para recuperação | Documentos com layout, gráficos e tabelas complexas |
| **Geração com modelo multimodal** | Passa imagens/trechos visuais recuperados a um LLM multimodal | "O que mostra este gráfico?" |

```
 Fontes: texto · imagens · áudio · vídeo · slides
              │
     ┌────────┴──────────────────────────────┐
     ▼                                       ▼
 conversão para texto                 embeddings multimodais
 (OCR, ASR, legenda)                  (texto e imagem no mesmo espaço)
     └────────────────┬──────────────────────┘
                      ▼
               índice (vetorial/híbrido) ─► retrieval ─► LLM (texto ou multimodal) ─► resposta
```

### Desafios

| Desafio | Observação |
|---|---|
| **Qualidade da conversão** | Erros de OCR/ASR/legenda propagam-se ao índice |
| **Granularidade** | Como "chunkar" vídeo e áudio (por tempo, cena, tópico)? |
| **Custo** | Processar mídia é caro (transcrição, visão) |
| **Citação** | Referenciar timestamp, página ou região da imagem |
| **Avaliação** | Métricas e conjuntos de teste multimodais são menos maduros |
| **Privacidade** | Imagens e áudio costumam conter dados pessoais |

## Onde cada um se encaixa

| Critério | RAG | Long context | CAG | RAG multimodal |
|---|---|---|---|---|
| **Tamanho da base** | Grande a enorme | Até o limite da janela | Pequena/média | Qualquer (depende do índice) |
| **Frequência de mudança** | Alta tolera | Alta tolera (remonta) | Baixa (estável) | Variável |
| **Custo por consulta** | Baixo/médio | Alto | Baixo (com cache válido) | Médio/alto |
| **Latência** | Média | Alta | Baixa | Média/alta |
| **Permissões por usuário** | Fácil (filtros) | Difícil | Difícil | Fácil (filtros) |
| **Citação precisa** | Natural | Possível | Possível | Natural (com metadados) |
| **Raciocínio global no documento** | Limitado | **Forte** | **Forte** | Depende |
| **Tipos de dado** | Texto (e estruturado) | Texto/imagem (modelo-dependente) | Texto | Imagem, áudio, vídeo, texto |

### Árvore de decisão simplificada

```
 Os dados são só texto?
   não ─► considerar RAG MULTIMODAL (conversão para texto e/ou embeddings multimodais)
   sim
    │
    A base cabe na janela E é estável E é a mesma para todos os usuários?
      sim ─► CAG (long context + cache)   [teste qualidade e custo]
      não
       │
       Tarefa sobre UM documento (resumir, revisar, comparar)?
         sim ─► LONG CONTEXT direto
         não ─► RAG (híbrida + reranking + filtros)
```

### Combinações

| Combinação | Quando |
|---|---|
| **RAG + long context** | Recuperar **documentos inteiros** relevantes (poucos) e usar janela grande, em vez de chunks pequenos |
| **CAG + RAG** | Conhecimento nuclear estável em cache + RAG para conteúdo extenso/mutável |
| **RAG multimodal + RAG textual** | Roteamento por tipo de pergunta/fonte |
| **Long context para verificar** | Passar o documento citado inteiro ao modelo para checar a resposta |

## "RAG está morto?" — uma resposta equilibrada

Janelas longas reduzem a necessidade de RAG em **bases pequenas e tarefas de documento único**, mas RAG continua essencial quando há: bases grandes, dados mutáveis, **controle de acesso**, necessidade de **citação e auditoria**, **custo/latência sensíveis** e muitas consultas. O movimento real é de **convergência**: sistemas mistos que escolhem a estratégia por pergunta (ver roteamento, 5.1.1.3).

---

## Erros comuns e armadilhas

- **Declarar o RAG obsoleto** sem medir custo, latência e qualidade do contexto longo na sua carga real.
- **Usar CAG com base mutável**, invalidando o cache e perdendo a economia.
- **Cachear conteúdo restrito** e servi-lo a usuários sem permissão.
- **Colocar parte variável no início do prompt**, destruindo o reuso do prefixo cacheado.
- **Presumir que cabe na janela** sem contar tokens (e sem reservar espaço para a resposta).
- **RAG multimodal sem validar OCR/transcrição**, indexando erros.
- **Ignorar privacidade** em imagens e áudios.

## 🧩 Quiz de Fixação

1. Que condições favorecem o CAG em relação ao RAG?
2. Por que o contexto longo não substitui o RAG em bases corporativas grandes com permissões diferentes por usuário?
3. Cite duas abordagens para indexar conteúdo em áudio/vídeo/imagem e um desafio de cada.

**Respostas:**
1) Base pequena ou média que cabe na janela, estável (muda pouco), mesma para todos os usuários e consultada muitas vezes — assim o custo de carregar é amortizado e o retrieval é dispensado. Se a base é grande, muda sempre ou tem permissões distintas, o RAG é preferível.
2) Porque a base excede a janela ou fica cara e lenta a cada consulta, há risco de atenção diluída, e é difícil entregar ao prompt apenas o conteúdo que cada usuário pode ver; o RAG permite filtrar por ACL, atualizar incrementalmente, citar fontes e controlar custo.
3) (a) Converter para texto (OCR, transcrição, legendas) e indexar o texto — desafio: erros de conversão se propagam e é preciso decidir a granularidade (por tempo/cena). (b) Embeddings multimodais (texto e imagem no mesmo espaço) — desafio: custo, avaliação menos madura e citação (regiões/timestamps).
