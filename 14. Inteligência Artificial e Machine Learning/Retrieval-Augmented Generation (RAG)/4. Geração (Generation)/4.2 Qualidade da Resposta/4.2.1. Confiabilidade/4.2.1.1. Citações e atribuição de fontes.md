### Citações e atribuição de fontes

Uma das maiores vantagens do RAG sobre um LLM puro é a possibilidade de **dizer de onde veio a informação**. Citações permitem que o usuário confie *e verifique*, que o time audite e corrija erros e que o sistema seja avaliado. Mas citar bem é mais difícil do que parece: o modelo pode citar fontes erradas, inventar referências ou citar sem que o trecho sustente a afirmação. Este arquivo trata do projeto de citações — do metadado à validação.

> [!warning] Aviso
> Recursos de citação nativa (APIs de "citations" ou "grounding" de alguns provedores) mudam e variam; consulte a documentação atual. O código é ilustrativo e **não foi executado**.

---

## Por que citar

| Benefício | Explicação |
|---|---|
| **Verificabilidade** | O usuário confere a fonte antes de agir (contratos, saúde, finanças) |
| **Confiança calibrada** | Respostas com fonte clicável geram confiança justificada, não cega |
| **Auditoria e conformidade** | Registro de qual documento embasou qual resposta |
| **Depuração** | Se a resposta está errada, vê-se qual trecho/documento causou o erro |
| **Avaliação** | Permite medir se a resposta é sustentada pelas fontes (fidelidade, ver 6.1.1.2) |
| **Redução de alucinação** | Exigir citação desencoraja afirmações sem suporte |

**Analogia:** é a nota de rodapé de um trabalho acadêmico. Sem ela, é opinião; com ela, é afirmação checável.

---

## Níveis de granularidade

| Nível | Exemplo | Prós | Contras |
|---|---|---|---|
| **Lista de fontes ao final** | "Fontes: manual_v3.pdf, faq.md" | Fácil | Não liga afirmação → fonte |
| **Citação por resposta/parágrafo** | "... [1][2]" no fim do parágrafo | Equilíbrio | Granularidade média |
| **Citação por afirmação (inline)** | "O prazo é de 14 dias [1]. A solicitação é feita no app [2]." | Rastreabilidade máxima | Mais difícil de garantir |
| **Citação com trecho (quote)** | Cita o **trecho literal** que sustenta a afirmação | Verificação imediata | Respostas mais longas |
| **Link profundo** | Aponta para a página/âncora/timestamp exato | Melhor experiência | Exige metadados precisos |

## Como implementar: do índice à resposta

```
 INDEXAÇÃO                      RETRIEVAL                   GERAÇÃO                    PÓS-PROCESSO
 chunk guarda metadados:  ──►  trecho chega com     ──►  prompt numera [1],[2]  ──►  valida os [n] e
 titulo, url, pagina,          id, fonte, página         e exige citar [n]           converte em links
 secao, versao                                                                        para o usuário
```

### 1. Guardar metadados na indexação
`titulo`, `url`, `pagina`, `secao`, `versao`, `autor`, `atualizado_em` (ver 2.1.1.3). Sem isso, não há o que citar.

### 2. Numerar os trechos no prompt
Cada trecho recebe um id curto (`[1]`, `[2]`) e o prompt exige que as afirmações sejam seguidas pelos ids correspondentes (ver 4.1.1.1).

### 3. Pedir um formato verificável
Texto com marcadores `[n]` ou saída estruturada (JSON com afirmações e ids).

### 4. Validar e renderizar
O código **não deve confiar cegamente** no modelo: valide que cada `[n]` existe, e transforme em link/rodapé com os metadados reais (não os que o modelo "escreveu").

> [!info] Princípio fundamental
> **O modelo cita ids; o sistema resolve os ids em referências reais.** Nunca peça ao modelo que escreva URLs ou títulos por conta própria — ele pode inventá-los. Ele só escolhe entre ids que você forneceu.

## Modos de falha das citações

| Falha | Descrição | Mitigação |
|---|---|---|
| **Citação inexistente** | Cita `[7]` quando só há 5 trechos | Validação de ids no código |
| **Referência inventada** | Escreve um título/URL que não existe | Resolver ids no sistema, não aceitar texto livre |
| **Citação "decorativa"** | O id é real, mas o trecho **não sustenta** a afirmação | Verificação de entailment (NLI/LLM-juiz) ou avaliação de fidelidade |
| **Citação omitida** | Afirma sem citar | Regra no prompt + checagem de cobertura |
| **Fonte errada** | Atribui ao trecho [2] algo dito em [1] | Citações por afirmação + verificação |
| **Citar documento obsoleto** | Fonte desatualizada | Metadados de versão/data + filtro de vigência (ver 2.1.1.2) |
| **Excesso de citações** | Poluição visual | Agrupar por parágrafo; mostrar fontes sob demanda |

## Exemplo prático: validar e renderizar citações

```python
# Pseudocódigo didático — NÃO executado.
import re   # expressões regulares

def extrair_ids(resposta):
    # Encontra todos os marcadores [n] no texto, ex.: "[1]" ou "[2]".
    return sorted({int(n) for n in re.findall(r"\[(\d+)\]", resposta)})

def validar_e_renderizar(resposta, trechos):
    ids_validos = set(range(1, len(trechos) + 1))             # ids realmente fornecidos
    usados = extrair_ids(resposta)

    invalidos = [i for i in usados if i not in ids_validos]   # citou algo que não existe?
    if invalidos:
        return {"ok": False, "motivo": f"citações inexistentes: {invalidos}"}  # reprompt/fallback

    if not usados:
        return {"ok": False, "motivo": "resposta sem citações"}               # regra de cobertura

    # Converte [n] em referências REAIS a partir dos metadados guardados na indexação.
    referencias = []
    for i in usados:
        m = trechos[i - 1]                                    # trecho n -> metadados
        referencias.append(f"[{i}] {m['titulo']}, p.{m.get('pagina', '-')} — {m['url']}")
    return {"ok": True, "texto": resposta, "referencias": referencias}
```

**Pontos a observar:** a validação cobre citações inexistentes e a falta de citações; as referências exibidas vêm do **metadado**, não do texto do modelo; em caso de falha, o sistema pode refazer a geração (com instruções reforçadas) ou apresentar um fallback seguro.

## Verificando se a citação sustenta a afirmação

Validar que `[1]` existe não prova que `[1]` **diz** aquilo. Para checar o suporte:

| Técnica | Como funciona | Custo |
|---|---|---|
| **LLM-juiz** | Pergunta a um modelo: "O trecho sustenta esta afirmação? Sim/Não/Parcial" | Médio; sujeito a erro do juiz |
| **NLI (inferência textual)** | Modelo especializado classifica: suporta / contradiz / neutro | Baixo/médio |
| **Sobreposição lexical/semântica** | Mede quanto da afirmação aparece no trecho | Baixo; menos preciso |
| **Citação com trecho literal** | O modelo extrai o *quote*; o sistema confere que o quote existe no chunk | Baixo; verificação objetiva |

> [!tip] Padrão de alta confiança
> Exigir que o modelo forneça, para cada afirmação-chave, o **trecho literal** (quote) e o id. O código confirma que o quote está **de fato** no chunk (busca de substring). Isso elimina citações inventadas e facilita a verificação humana.

## Boas práticas de apresentação ao usuário

- Mostre as fontes de forma **clicável**, com título e, quando possível, link profundo (página/âncora).
- Exiba **data/versão** do documento citado.
- Permita expandir o **trecho original** usado.
- Diferencie o que veio das fontes do que é **conhecimento geral do modelo**, se o modo for flexível.
- Registre (log) as citações para auditoria e feedback.

---

## Erros comuns e armadilhas

- **Deixar o modelo escrever a referência completa** (título, URL): é fonte comum de links falsos.
- **Não validar os ids** devolvidos pelo modelo.
- **Achar que citar = estar correto.** A citação pode ser decorativa; avalie a fidelidade.
- **Metadados pobres** na indexação (sem página/URL), impossibilitando links úteis.
- **Citar chunks e não documentos** (usuário vê "chunk 4812"): traduza para algo compreensível.
- **Poluir a resposta** com citações a cada frase quando o contexto não exige.
- **Ignorar atualidade:** citar corretamente um documento obsoleto continua sendo erro.

## 🧩 Quiz de Fixação

1. Por que o modelo deve citar ids numéricos e o sistema resolver as referências, em vez de o modelo escrever títulos e URLs?
2. Cite dois modos de falha de citações e como mitigá-los.
3. Como o uso de "trecho literal" (quote) ajuda a verificar uma citação?

**Respostas:**
1) Porque o modelo pode inventar títulos, URLs ou páginas plausíveis porém falsos. Se ele apenas escolhe ids fornecidos, o sistema valida esses ids e monta as referências a partir dos metadados reais guardados na indexação.
2) Por exemplo: citação inexistente (cita [7] sem haver 7 trechos) — mitigada validando os ids no código; citação decorativa (o trecho citado não sustenta a afirmação) — mitigada com verificação de suporte (LLM-juiz, NLI) ou avaliação de fidelidade. Também: omissão de citação (regra de cobertura) e documento obsoleto (metadados de versão e filtro de vigência).
3) O modelo extrai o trecho exato que sustenta a afirmação; o código confere que esse texto realmente existe no chunk citado (substring), eliminando citações inventadas, e o usuário pode verificar rapidamente a afirmação lendo o quote.
