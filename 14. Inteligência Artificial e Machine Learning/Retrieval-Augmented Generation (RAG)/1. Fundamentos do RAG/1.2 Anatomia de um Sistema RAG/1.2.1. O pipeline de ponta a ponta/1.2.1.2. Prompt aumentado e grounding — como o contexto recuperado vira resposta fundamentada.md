### Prompt aumentado e grounding — como o contexto recuperado vira resposta fundamentada

Recuperar bons trechos é só metade do caminho: é preciso **entregá-los ao modelo do jeito certo** e **instruí-lo a se basear neles**. O prompt que junta instruções, contexto recuperado e pergunta é o *prompt aumentado*, e a propriedade de a resposta se apoiar nas evidências fornecidas chama-se **grounding** (ancoragem). Este arquivo mostra a anatomia desse prompt; os detalhes de template, orçamento e citações vêm no domínio 4.

> [!warning] Aviso
> Formatos de mensagem (roles, system prompt, tags) variam por provedor e mudam com versões. Os exemplos são ilustrativos e **não foram executados**.

---

## O que é o prompt aumentado

É o prompt "normal" (pergunta do usuário) **acrescido** de material recuperado. Em geral tem quatro blocos:

```
┌──────────────────────────────────────────────────────────┐
│ 1. INSTRUÇÕES (papel e regras)                           │
│    "Você é um assistente de suporte. Responda apenas     │
│     com base no contexto. Se faltar informação, diga."   │
├──────────────────────────────────────────────────────────┤
│ 2. CONTEXTO (trechos recuperados, com identificação)     │
│    [1] (manual_v3.pdf, p.12) "Reembolso em 14 dias..."   │
│    [2] (faq.md) "Para reembolso, abra o menu Pedidos..." │
├──────────────────────────────────────────────────────────┤
│ 3. HISTÓRICO (opcional: turnos anteriores da conversa)   │
├──────────────────────────────────────────────────────────┤
│ 4. PERGUNTA DO USUÁRIO                                   │
│    "Como peço reembolso e em quanto tempo?"              │
└──────────────────────────────────────────────────────────┘
```

**Analogia:** é como entregar a um advogado um dossiê com (1) as regras do caso, (2) os documentos relevantes numerados e (3) a pergunta do cliente — e exigir que ele responda *citando o dossiê*, sem recorrer a "achismos".

---

## Grounding: o que significa e como se obtém

**Grounding** = a resposta é **sustentada pelas evidências fornecidas**, não pela memória do modelo. Uma resposta *grounded* tem afirmações que podem ser rastreadas até trechos do contexto. Uma resposta *ungrounded* mistura fatos externos ou inventados.

O grounding não é automático. Ele surge de uma combinação de:

| Alavanca | Como ajuda |
|---|---|
| **Instrução explícita** | "Use SOMENTE o contexto" reduz mistura com a memória do modelo |
| **Saída para ausência** | Permitir "não encontrei essa informação" evita que o modelo invente |
| **Contexto identificado** | Numerar/rotular trechos permite citar e conferir |
| **Contexto relevante e limpo** | Trechos bons geram respostas boas; ruído gera confusão |
| **Formato de saída** | Pedir citações ou JSON com campos de fonte força rastreabilidade |
| **Avaliação** | Medir *faithfulness* detecta quando o modelo se desvia (ver 6.1.1.2) |

### Grounding estrito vs flexível

| Modo | Instrução típica | Quando usar |
|---|---|---|
| **Estrito** | "Responda SOMENTE com o contexto; senão diga que não sabe" | Jurídico, saúde, suporte com política oficial |
| **Flexível** | "Prefira o contexto, mas pode complementar com conhecimento geral, sinalizando o que vem de fora" | Assistentes de pesquisa, tutores |

## Exemplo prático: montando o prompt aumentado

```python
# Pseudocódigo didático — NÃO executado. Formato de mensagens varia por provedor.

SISTEMA = (
    "Você é o assistente de suporte da Acme. "          # papel do modelo
    "Responda SOMENTE com base no CONTEXTO fornecido. " # regra de grounding estrito
    "Cite as fontes no formato [n]. "                   # exige rastreabilidade
    "Se o contexto não tiver a resposta, diga exatamente: "
    "'Não encontrei essa informação na base.'"          # saída segura p/ ausência
)

def formatar_contexto(trechos):
    # Cada trecho vira uma linha numerada com sua origem, p.ex.:
    # [1] (manual_v3.pdf, p.12) Reembolso em até 14 dias...
    linhas = []
    for n, t in enumerate(trechos, start=1):        # numeração começa em 1
        linhas.append(f"[{n}] ({t['fonte']}) {t['texto']}")
    return "\n".join(linhas)                        # junta tudo em um bloco

def montar_mensagens(pergunta, trechos, historico=()):
    contexto = formatar_contexto(trechos)           # bloco CONTEXTO
    usuario = f"CONTEXTO:\n{contexto}\n\nPERGUNTA: {pergunta}"  # contexto + pergunta
    return [
        {"role": "system", "content": SISTEMA},     # instruções fixas
        *historico,                                 # turnos anteriores (se houver)
        {"role": "user", "content": usuario},       # prompt aumentado
    ]

trechos = [
    {"fonte": "manual_v3.pdf, p.12", "texto": "Reembolso em até 14 dias corridos no app."},
    {"fonte": "faq.md", "texto": "Para pedir reembolso, abra Pedidos > Ajuda > Reembolso."},
]
mensagens = montar_mensagens("Como peço reembolso e em quanto tempo?", trechos)
# Resposta esperada do modelo (ilustrativa):
# "Abra Pedidos > Ajuda > Reembolso [2]. O prazo é de até 14 dias corridos [1]."
```

**Leitura linha a linha dos pontos-chave:** `SISTEMA` concentra as regras estáveis; `formatar_contexto` dá a cada trecho um número e uma fonte (base das citações); `montar_mensagens` coloca o contexto **junto da pergunta**, não escondido; o modelo, ao citar `[1]` e `[2]`, permite que o usuário confira cada afirmação.

## Contraste: o mesmo contexto, com e sem instrução de grounding

| Situação | Prompt | Resultado provável |
|---|---|---|
| Sem instrução | "Contexto: … Pergunta: …" | Pode misturar o contexto com a memória; pode ignorar o contexto |
| Com grounding estrito | "Responda só com o contexto… senão diga que não sabe" | Respostas fiéis; "não sei" quando faltar evidência |
| Contexto vazio **sem** saída para ausência | "Responda com o contexto: (vazio)" | O modelo tende a inventar para "cumprir a tarefa" |
| Contexto vazio **com** saída para ausência | idem + "se vazio, diga que não encontrou" | Recusa segura |

## Limites do grounding

- **Contexto errado → resposta errada fundamentada.** O modelo pode seguir fielmente um trecho desatualizado ou irrelevante.
- **Contexto demais** dilui a atenção do modelo e pode esconder o trecho decisivo (ver 4.1.1.2).
- **Instruções não são garantias.** Modelos podem violar a regra; por isso se complementa com avaliação, validação de citações e guardrails.
- **Conflito entre trechos** exige regras de desempate (data, hierarquia de fontes) — tema de 4.2.1.2.
- **Injeção de prompt via documento:** um trecho recuperado pode conter texto malicioso do tipo "ignore as instruções anteriores"; o contexto deve ser tratado como **dado**, não como instrução (ver 7.1.2.1).

---

## Erros comuns e armadilhas

- **Colar o contexto sem rótulos**, impossibilitando citações e conferência.
- **Esquecer a saída para "não sei"**, forçando o modelo a inventar quando o retrieval falha.
- **Enviar o histórico inteiro + muitos trechos** sem considerar o limite de contexto e o custo.
- **Instruir "use o contexto" mas deixar a pergunta ambígua** (por exemplo, referências como "isso" sem resolver o histórico), o que prejudica o retrieval e a resposta.
- **Não versionar o prompt.** Pequenas mudanças alteram o comportamento; trate o template como código (versionado e testado).

## 🧩 Quiz de Fixação

1. Quais são os blocos de um prompt aumentado?
2. O que é grounding e por que ele não acontece automaticamente?
3. Por que é importante prever no prompt uma saída para quando o contexto não contiver a resposta?

**Respostas:**
1) Instruções (papel e regras), contexto recuperado (trechos identificados), histórico opcional da conversa e a pergunta do usuário.
2) Grounding é a resposta se apoiar nas evidências fornecidas, e não na memória do modelo. Não é automático porque o LLM tende a combinar contexto com conhecimento próprio; é preciso instruir explicitamente, rotular o contexto, prever a ausência de resposta e avaliar a fidelidade.
3) Porque, se o retrieval falhar (contexto vazio ou irrelevante), um modelo sem essa saída tende a inventar uma resposta plausível para cumprir a tarefa. Com a instrução "diga que não encontrou", o sistema falha de forma segura e transparente.
