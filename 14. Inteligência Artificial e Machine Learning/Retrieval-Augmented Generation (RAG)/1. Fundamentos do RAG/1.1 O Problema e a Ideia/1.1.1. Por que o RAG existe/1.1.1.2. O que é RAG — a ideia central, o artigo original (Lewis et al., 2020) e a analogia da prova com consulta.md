### O que é RAG — a ideia central, o artigo original (Lewis et al., 2020) e a analogia da prova com consulta

**RAG (Retrieval-Augmented Generation)** é um padrão de arquitetura em que, antes de o LLM responder, o sistema **busca** informação relevante em uma base externa e a **entrega ao modelo junto com a pergunta**. O modelo então gera a resposta *a partir* desse material, e não apenas da sua memória. Este arquivo define o conceito, conta de onde veio e mostra uma implementação mínima.

> [!warning] Aviso
> Bibliotecas, APIs, nomes de modelos e preços mudam. O código abaixo é didático, usa apenas a biblioteca padrão do Python e **não foi executado** — valide antes de reutilizar.

---

## A ideia em uma frase

> **Em vez de fazer o modelo *lembrar*, deixamos o modelo *consultar*.**

**Analogia — a prova com consulta:**

| Prova sem consulta (LLM puro) | Prova com consulta (RAG) |
|---|---|
| O aluno responde só de memória | O aluno pode abrir o material de apoio |
| Esquece detalhes, inventa quando não lembra | Procura o trecho certo e responde com base nele |
| Não sabe o que mudou depois que estudou | O material de apoio pode estar atualizado |
| Não cita a página | Pode dizer "conforme a página 42" |

O aluno é o mesmo; o que muda é o acesso ao material. E repare: **encontrar a página certa rápido** é metade do trabalho — um aluno com o livro errado aberto responde errado com a mesma confiança. É por isso que, em RAG, a qualidade da busca importa tanto quanto a qualidade do modelo.

```
        SEM RAG                              COM RAG
  ┌──────────┐                       ┌──────────┐
  │ Pergunta │                       │ Pergunta │
  └────┬─────┘                       └────┬─────┘
       ▼                                  ▼
  ┌──────────┐                       ┌───────────┐     ┌──────────────┐
  │   LLM    │                       │ Retriever │────►│ Base externa │
  │ (pesos)  │                       └─────┬─────┘     │ (docs, BD..) │
  └────┬─────┘                             │ trechos   └──────────────┘
       ▼                                   ▼
  ┌──────────┐                       ┌───────────┐
  │ Resposta │                       │ LLM + ctx │
  └──────────┘                       └─────┬─────┘
                                           ▼
                                  ┌──────────────────┐
                                  │ Resposta + fontes│
                                  └──────────────────┘
```

## Origem: o artigo de Lewis et al. (2020)

O termo foi cunhado no artigo **"Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"**, de Patrick Lewis e colegas (Facebook AI Research, University College London e NYU), apresentado na conferência NeurIPS em 2020.

Ideias principais do artigo:

- Combinar **memória paramétrica** (os pesos de um modelo seq2seq pré-treinado) com **memória não paramétrica** (um índice vetorial da Wikipédia consultado por um recuperador neural, o DPR — Dense Passage Retrieval).
- Treinar retriever e gerador de forma conjunta (*end-to-end*) para tarefas intensivas em conhecimento, como perguntas e respostas de domínio aberto.
- Mostrar que a abordagem produz respostas mais factuais e específicas e que **a base externa pode ser atualizada sem retreinar o modelo**.

| Conceito do artigo | Equivalente no RAG moderno |
|---|---|
| Memória paramétrica | Pesos do LLM (conhecimento geral, linguagem, raciocínio) |
| Memória não paramétrica | Base de documentos + índice (vetorial, lexical ou híbrido) |
| Retriever (DPR) | Modelo de embedding + busca por similaridade (+ reranker) |
| Gerador (BART) | LLM de propósito geral recebendo o contexto no prompt |

> [!info] Nota histórica
> No artigo original, retriever e gerador eram treinados juntos. Na prática atual, a maioria dos sistemas usa um **LLM pronto (sem treino adicional)** e apenas injeta o contexto recuperado no prompt — uma versão mais simples e barata, mas com a mesma ideia. Por isso hoje "RAG" costuma significar o *padrão arquitetural*, não o método de treino do artigo.

---

## Os três verbos do RAG

1. **Recuperar (Retrieve):** dada a pergunta, achar os trechos mais relevantes na base.
2. **Aumentar (Augment):** inserir esses trechos no prompt, com instruções de como usá-los.
3. **Gerar (Generate):** o LLM produz a resposta com base no prompt aumentado.

```
 Pergunta ─► [1. RECUPERAR] ─► trechos ─► [2. AUMENTAR] ─► prompt ─► [3. GERAR] ─► resposta
              (retrieval)                  (montar prompt)             (LLM)
```

## Exemplo prático: um RAG mínimo em Python puro

Para fixar o fluxo, o exemplo usa uma "busca" por sobreposição de palavras (em vez de embeddings) — suficiente para mostrar o esqueleto. Em produção, troca-se esse passo por busca vetorial/híbrida (ver [[14. Inteligência Artificial e Machine Learning/AI Engineering (Engenharia Aplicada)/2. Retrieval-Augmented Generation (RAG) Avançado/2.1 Ingestão e Processamento (Pipeline de Dados)/2.1.2. Embeddings e Bancos Vetoriais/2.1.2.1. Modelos de Embedding Modernos e Matryoshka|Modelos de Embedding Modernos]]).

```python
# Exemplo didático — NÃO executado. Usa só a biblioteca padrão.

DOCS = [  # Base de conhecimento fictícia (cada item é um "chunk").
    "Reembolso: o cliente tem 14 dias corridos para pedir reembolso no app.",
    "Frete: pedidos acima de R$ 200 têm frete grátis para todo o Brasil.",
    "Suporte: o atendimento funciona de segunda a sexta, das 9h às 18h.",
]

def tokenizar(texto):
    # Minúsculas, remove pontuação simples e separa em palavras.
    limpo = texto.lower().replace(":", " ").replace(",", " ").replace(".", " ").replace("?", " ")
    return set(limpo.split())  # set: só interessa se a palavra existe

def recuperar(pergunta, docs, k=1):
    q = tokenizar(pergunta)  # palavras da pergunta
    # Pontua cada documento pelo nº de palavras em comum com a pergunta.
    pontuados = [(len(q & tokenizar(d)), d) for d in docs]
    # Ordena do maior para o menor score e fica com os k primeiros.
    pontuados.sort(key=lambda par: par[0], reverse=True)
    return [d for score, d in pontuados[:k] if score > 0]  # descarta score 0

def montar_prompt(pergunta, trechos):
    contexto = "\n".join(f"- {t}" for t in trechos)  # lista de trechos
    return (
        "Responda usando SOMENTE o contexto. Se não houver resposta, diga que não sabe.\n"
        f"Contexto:\n{contexto}\n\nPergunta: {pergunta}"
    )

def rag(pergunta, llm):
    trechos = recuperar(pergunta, DOCS, k=1)   # 1) RECUPERAR
    prompt = montar_prompt(pergunta, trechos)  # 2) AUMENTAR
    return llm(prompt)                         # 3) GERAR (llm = função que chama o modelo)

# Uso (llm seria um cliente real de LLM):
# print(rag("Qual o prazo de reembolso no app?", llm))
```

**Leitura do fluxo:** a pergunta compartilha "reembolso" e "app" com o primeiro documento, que ganha o maior score e vai para o prompt. O modelo recebe a evidência e responde "14 dias corridos". Se a pergunta fosse "vocês entregam em Marte?", nenhum documento pontuaria, `trechos` ficaria vazio e a instrução "diga que não sabe" entraria em ação — um comportamento que um RAG bem feito deve garantir.

## O que RAG é e o que não é

| RAG **é** | RAG **não é** |
|---|---|
| Um padrão de arquitetura (recuperar → aumentar → gerar) | Um produto, biblioteca ou banco de dados específico |
| Uma forma de dar **conhecimento** ao modelo em tempo de consulta | Uma forma de treinar/alterar os pesos do modelo |
| Dependente da qualidade da busca **e** do modelo | Garantia contra alucinação |
| Compatível com qualquer LLM (hospedado ou local) | Exclusivo de bancos vetoriais (há RAG com SQL, grafos, busca lexical…) |

---

## Erros comuns e armadilhas

- **Reduzir RAG a "banco vetorial + LLM".** O retriever pode ser lexical, híbrido, SQL ou grafo; o banco vetorial é só uma das opções.
- **Achar que RAG substitui fine-tuning (ou vice-versa).** Resolvem problemas diferentes: conhecimento mutável vs. comportamento/estilo (comparativo em 1.2.2.1).
- **Culpar o LLM por erros do retriever.** Na prática, a maior parte das respostas ruins de RAG vem de recuperar o trecho errado ou incompleto.
- **Não instruir o modelo a usar o contexto.** Sem instrução de grounding, o modelo pode misturar o contexto com a própria memória (ver 1.2.1.2).
- **Esperar que o artigo de 2020 descreva a prática atual.** A ideia se manteve; a implementação típica mudou (LLMs prontos, embeddings, bancos vetoriais, reranking).

## 🧩 Quiz de Fixação

1. Defina RAG usando os três verbos do padrão.
2. Na analogia da prova com consulta, o que representam o "aluno", o "material de apoio" e "achar a página certa"?
3. Qual a diferença entre o RAG do artigo de Lewis et al. (2020) e o RAG mais comum hoje em dia?

**Respostas:**
1) RAG é recuperar (buscar trechos relevantes numa base externa), aumentar (inserir esses trechos no prompt com instruções) e gerar (o LLM responder com base no prompt aumentado).
2) O aluno é o LLM; o material de apoio é a base de conhecimento externa; achar a página certa é o retrieval — se for mal feito, o aluno responde errado com a mesma confiança, por isso a qualidade da busca é decisiva.
3) No artigo, retriever (DPR) e gerador (BART) eram treinados conjuntamente, combinando memória paramétrica e não paramétrica. Hoje, em geral, usa-se um LLM pronto sem treino adicional e o contexto recuperado é apenas injetado no prompt; a ideia (consultar uma base externa em tempo de inferência) é a mesma, mas a implementação é mais simples e modular.
